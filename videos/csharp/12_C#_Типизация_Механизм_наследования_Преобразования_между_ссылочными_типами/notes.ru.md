Держите эти термины в голове по ходу чтения; каждый из них разбирается заново, когда становится полезным:

- **Структура и тип значения** (`struct`): значение содержит свои данные, и копирование значения копирует эти данные. **Класс и ссылочный тип** (`class`): переменная ссылается на выделенный объект, и копирование ссылки сохраняет ссылку на тот же объект. **Поле** — это данные, принадлежащие значению или экземпляру.
- **Объект и экземпляр**: экземпляр — это конкретный объект, созданный из типа. **Ссылка** идентифицирует объект; в записи она изображена как числовой **адрес** в **динамической памяти** — памяти, используемой для выделенных объектов.
- **Статический, или объявленный, тип**: тип, который компилятор использует для переменной или выражения. **Тип времени выполнения**: фактический тип ссылающегося экземпляра. «Динамическая типизация» в этом уроке касается именно этой информации времени выполнения, а не отдельной возможности `dynamic` в C#.
- **Информация о типе, или метаданные**: описание типа, включающее его имя, поля и связи. **Объект типа**, доступный через `System.Type`, предоставляет это описание. **Рефлексия** — это исследование метаданных через управляемые API. **Скрытая ссылка на тип**, или **заголовок типа**, в записи моделирует связь между экземпляром и его типом.
- **`GetType()`, `Name`, `BaseType` и `typeof`**: получают тип времени выполнения экземпляра, имя описанного типа, его непосредственный базовый тип и описание типа по имени типа соответственно. **Строка** (`string`) — это ссылочный тип, представляющий текст; строковое поле хранит ссылку на текстовый объект.
- **Упаковка (boxing)**: представление значения типа значения внутри объекта. Здесь она упоминается лишь для очерчения границ урока и откладывается на потом.
- **Наследование, базовый класс и производный класс**: наследование расширяет базовый класс производным классом. **Братские классы** имеют общее основание, но остаются разными конкретными типами. **Множественное наследование классов** дало бы классу несколько непосредственных базовых классов. **Интерфейс** — это реализуемый контракт; механизмы интерфейсов выходят за рамки урока.
- **Совместимость и полиморфизм**: совместимость разрешает использовать объект через запрошенный тип; полиморфизм позволяет получить единое типизированное представление с поведением, зависящим от фактического объекта. Поведение полиморфных методов упоминается, но здесь не разрабатывается. **Смещение поля (field offset)** — это величина смещения, используемая для нахождения поля относительно моделируемого начала данных объекта.
- **`object` (`System.Object`)**: встроенный корневой класс, пригодный в качестве общего ссылочного типа. **Преобразование** даёт значение, пригодное для использования как другой тип. **Неявное преобразование** не требует синтаксиса cast; **явный cast** записывается как `(TargetType)expression`. **Приведение вверх (upcast)** использует ссылку на производный объект через базовый тип.
- **Блок, локальная переменная и область видимости**: фигурные скобки ограничивают блок, а локальное имя доступно только в своей области видимости. **Значение по умолчанию** — это начальное значение, передаваемое полю без другого инициализатора. **Определённое присваивание** требует, чтобы локальной переменной было присвоено значение до её чтения. **Переприсваивание** заменяет значение, сохранённое в переменной.
- **Null, nullable-ссылка и анализ nullable**: null означает отсутствие ссылки на объект; nullable-ссылка вида `Type?` допускает null, а анализ nullable проверяет возможное использование null. **Оператор подавления nullable**, постфиксный `!`, снимает предупреждение о nullable; никакой проверки времени выполнения он не выполняет. **Равенство типов**, `==` между значениями `Type`, сравнивает представляемые типы.
- **Ошибка компиляции, ошибка времени выполнения, проверка времени выполнения и `InvalidCastException`**: ошибка компиляции не даёт собрать проект; ошибка времени выполнения возникает во время исполнения, а проверка времени выполнения исследует фактический объект. Несовместимый cast ссылки бросает `InvalidCastException`; необработанное исключение останавливает демонстрируемую программу.
- **Синтаксис примеров**: `new` создаёт экземпляр; `var` просит компилятор вывести статический тип локальной переменной; `int` хранит целое число; `public` разрешает показанный доступ к полю. `=` присваивает, `.` выбирает член, а `Console.WriteLine` печатает значение. **Инициализатор** задаёт начальное значение поля.

Граница темы — наследование классов и преобразования между ссылками. Поля структуры принадлежат самому значению; переменная класса же ссылается на объект, содержащий поля его экземпляра. Именно это объясняет разные последствия копирования и последующего изменения; структуре необязательно быть неизменяемой. Структуры не могут объявлять показанное здесь наследование классов, хотя могут реализовывать интерфейсы. ## Получить тип времени выполнения

Начните с пустого класса и спросите у выделенного экземпляра его тип. **Объект типа**, представленный `System.Type`, описывает класс; он отличается от экземпляра класса. **`GetType()`** возвращает фактический тип времени выполнения непустого объекта, у которого он вызван. Начальное состояние из видео: [00:01:03](https://www.youtube.com/watch?v=t2T88IiiP48&t=63s) [00:01:12](https://www.youtube.com/watch?v=t2T88IiiP48&t=72s)

```csharp
using System;

var c = new Class();
Type t = c.GetType();
Console.WriteLine(t);

class Class { }
```

Разберём три операции:

1. `new Class()` создаёт **экземпляр**. `var c` объявляет **локальную переменную**, выведенный статический тип которой равен `Class`; `=` сохраняет ссылку на экземпляр.
2. `c.GetType()` выбирает и вызывает метод объекта. Результат — ссылка на информацию о типе, сохраняемая в `Type t`.
3. `Console.WriteLine(t)` печатает текстовое представление этого типа. Запуск выводит `Class`. Это подтверждает, что описание типа времени выполнения может сообщить своё имя. [00:01:55](https://www.youtube.com/watch?v=t2T88IiiP48&t=115s)

Информация о типе позволяет проверить, является ли объект экземпляром ожидаемого типа. **Совместимость** означает, что его можно использовать через этот тип, в том числе через базовый, а не только через собственный точный тип; к базовым типам урок вернётся после этого осмотра. Та же информация поддерживает **полиморфизм**, то есть определение поведения по типу фактического объекта, хотя здесь полиморфный метод не создаётся. Она также позволяет получить имена и описания полей. **`Name`** — свойство, дающее имя описанного типа; начальная программа печатает сам `t`. ## Дать описаниям типов собственный тип

**Объект типа** сам является объектом, поэтому у него тоже есть тип времени выполнения. Расширьте рисунок, чтобы ответить, что описывает описание `Class`. [00:04:26](https://www.youtube.com/watch?v=t2T88IiiP48&t=266s)

Дополнительное описание занимает ещё один иллюстративный адрес. Его имя снова живёт в отдельном **строковом объекекте**, доступном через ссылку в поле имени. Это замыкает концептуальную цепочку, не требуя бесконечного числа различных типов. **Рефлексия** — это управляемый API, через который исследуются метаданные типов. `System.Type` — его публичная абстракция; у реально возвращаемых объектов тип времени выполнения может быть производным от неё. ## Отделить описание типа от данных экземпляра

Вернитесь к первому вызову и проследите две разные ссылки. Соответствующее состояние из видео: [00:05:46](https://www.youtube.com/watch?v=t2T88IiiP48&t=346s)

```csharp
var c = new Class();
Type t = c.GetType();
Console.WriteLine(t); // Class

class Class { }
```

1. `c` идентифицирует экземпляр пользовательского класса.
2. На рисунке его скрытая ссылка на тип содержит `6000`.
3. `GetType()` проходит по этой ссылке и возвращает ссылку на описание типа; `t` получает `6000`. Копию экземпляра он не получает. [00:05:46](https://www.youtube.com/watch?v=t2T88IiiP48&t=346s)
4. Печать `t` проходит по описанию типа к его строковому имени, а затем печатает имя класса. Это сокращает управляемую операцию: печать `Type` использует его текстовое представление. [00:06:04](https://www.youtube.com/watch?v=t2T88IiiP48&t=364s)

Теперь добавьте поле с **инициализатором** — выражением, задающим начальное значение. `int` — целочисленный тип, а `public` делает это поле доступным в окружающем примере. Соответствующее изменение в видео: [00:06:32](https://www.youtube.com/watch?v=t2T88IiiP48&t=392s)

```csharp
var c = new Class();
Type t = c.GetType();
Console.WriteLine(c.Field); // 10
// Console.WriteLine(t.Field); // не скомпилируется

class Class
{
    public int Field = 10;
}
```

Новое поле появляется после моделируемого начала экземпляра и содержит `10`. Оно принадлежит единственному экземпляру `Class` и не становится полем объекта `Type`. У `t` статический тип `Type`, поэтому это поле экземпляра ему недоступно. Описание полей класса и хранение значений полей конкретного экземпляра — разные операции. ## Построить экземпляры Base и Derived

Следующий шаг — **наследование**, расширение существующего класса. **Базовый класс** предоставляет наследуемые члены; **производный класс** расширяет его своими собственными членами. «Base» описывает отношение, а не запрет создавать экземпляры базового класса: этот пример создаёт его напрямую. [00:07:12](https://www.youtube.com/watch?v=t2T88IiiP48&t=432s) [00:07:21](https://www.youtube.com/watch?v=t2T88IiiP48&t=441s)

В `class Derived : Base` объявляемый класс — `Derived`, до двоеточия; названный базовый — `Base`, после него. Наследуемое открытое поле доступно на экземпляре производного класса рядом с его новым полем. Начальное состояние видео с наследованием, приведённое к единому написанию полей: [00:07:35](https://www.youtube.com/watch?v=t2T88IiiP48&t=455s) [00:07:56](https://www.youtube.com/watch?v=t2T88IiiP48&t=476s)

```csharp
var d = new Derived();
d.derField = 10;

var b = new Base();
b.baseField = 11;

Console.WriteLine(d.derField); // 10
Console.WriteLine(b.baseField); // 11

class Base
{
    public int baseField;
}
class Derived : Base
{
    public int derField;
}
```

Создавайте объекты по порядку:

1. Объявите `d` и выделите экземпляр `Derived` с помощью `new`. Отношение после двоеточия означает, что этот экземпляр содержит и наследуемое `baseField`, и `derField`. [00:08:25](https://www.youtube.com/watch?v=t2T88IiiP48&t=505s) [00:08:37](https://www.youtube.com/watch?v=t2T88IiiP48&t=517s)
2. Нарисуйте его скрытую ссылку на тип, затем данные: сначала `baseField`, затем `derField`. Этот фиксированный порядок «сначала базовые» объясняет последующие представления через ссылки в модели урока; это не обещание общего порядка байтов для произвольных классов C#. [00:08:46](https://www.youtube.com/watch?v=t2T88IiiP48&t=526s)
3. Присвойте `d.derField` значение `10`. Наследуемое целочисленное поле не записывалось и всё ещё хранит своё **значение по умолчанию**, ноль. [00:09:13](https://www.youtube.com/watch?v=t2T88IiiP48&t=553s)
4. Выделите отдельный объект `Base`. На его рисунке есть скрытая ссылка и ровно одно объявленное поле — `baseField`. Присвойте этому полю `11`. [00:09:30](https://www.youtube.com/watch?v=t2T88IiiP48&t=570s)

Оба экземпляра имеют информацию о типе, поэтому на рисунке есть также описания `Base` и `Derived`. В концептуальной модели сами эти описания имеют тип `Type`. Их ссылки на описание `Type` здесь намеренно опущены, чтобы удержать внимание на наследовании. [00:08:16](https://www.youtube.com/watch?v=t2T88IiiP48&t=496s) [00:08:23](https://www.youtube.com/watch?v=t2T88IiiP48&t=503s)

Наследуемое поле в `d` является частью этого экземпляра производного класса. Оно независимо от поля в отдельно выделенном объекте `b`; никакой существующий базовый объект в `d` не копировался. Документация [по наследованию](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/object-oriented/inheritance) описывает это отношение базового и производного классов.

## Скопировать одну ссылку в две типизированные переменные

**Приведение вверх (upcast)** использует ссылку на производный объект через базовый тип. Поскольку наследование делает экземпляр производного класса пригодным в качестве базового, переменная базового типа может хранить ту же ссылку. [00:11:27](https://www.youtube.com/watch?v=t2T88IiiP48&t=687s) [00:11:41](https://www.youtube.com/watch?v=t2T88IiiP48&t=701s)

Более раннее устное описание допустимых присваиваний не следует понимать так, будто произвольную ссылку базового типа можно неявно присвоить переменной производного типа. Из производного в базовый преобразование неявное; обратное требует cast и совместимого фактического объекта. ```

## Потребовать отношение наследования

**Явный cast** помещает целевой тип в скобки перед выражением. Здесь компилятор уже знает отношение наследования, поэтому явно записанное приведение вверх всё так же достигает наследуемого поля и печатает `12`. Внешние скобки группируют преобразованную ссылку перед выбором её поля. Состояние из видео: [00:14:54](https://www.youtube.com/watch?v=t2T88IiiP48&t=894s)

```csharp
var d = new Derived();
d.baseField = 12;
Console.WriteLine(((Base)d).baseField); // 12

class Base { public int baseField; }
class Derived : Base { public int derField; }
```

Далее вводится несвязанный класс `A` с теми же двумя полями. **Совместимость** следует из отношений типов, а не из совпадения имён или размеров полей. Соответствующее изменение в видео: [00:15:07](https://www.youtube.com/watch?v=t2T88IiiP48&t=907s) [00:15:22](https://www.youtube.com/watch?v=t2T88IiiP48&t=922s)

```csharp
var a = new A();
// Base b = (Base)a;       // compile-time error
// Derived d = (Derived)a; // compile-time error

class Base { public int baseField; }
class Derived : Base { public int derField; }
class A
{
    public int baseField;
    public int derField;
}
```

Совпадающие данные не дают `A` преобразования ни в один из классов. Удаление всех полей у `A` не помогло бы. Компилятор смотрит, что наследует `A`, а она не наследует этот `Base` или `Derived`. [00:15:49](https://www.youtube.com/watch?v=t2T88IiiP48&t=949s) [00:16:03](https://www.youtube.com/watch?v=t2T88IiiP48&t=963s) [00:16:15](https://www.youtube.com/watch?v=t2T88IiiP48&t=975s)

Более раннее преобразование сработало потому, что двоеточие явно объявляло отношение. Если два класса имеют общего пользовательского базового класса, любой из них можно передать через него, но это не делает их взаимозаменяемыми как конкретные братские типы. «Нет общего базового» здесь означает отсутствие пользовательского базового класса, дающего нужные члены; эти классы всё ещё разделяют встроенный корневой класс `object`. ## Хранить несвязанные экземпляры в object

Замените пример с наследованием на `A` и `B`, каждый из которых объявляет одно поле. Побуждающая задача — хранить ссылку на любой из объектов в одной переменной. **`object`**, имя `System.Object` в C#, — это общий корневой ссылочный тип, который это позволяет. Начальное состояние из видео и последующее переприсваивание, упрощённые вместе: [00:16:39](https://www.youtube.com/watch?v=t2T88IiiP48&t=999s) [00:16:57](https://www.youtube.com/watch?v=t2T88IiiP48&t=1017s) [00:17:06](https://www.youtube.com/watch?v=t2T88IiiP48&t=1026s)

```csharp
var a = new A();

object ob = a; // первое состояние

class A { public int FieldA; }
class B { public int FieldB; }
```

Каждый `new` создаёт отдельный объект со своим единственным целочисленным полем и со своей связью с типом. Оба незаписанных поля имеют **значение по умолчанию** ноль. Наряду с экземплярами и их описаниями типов рисунок добавляет описание специального встроенного типа `object`. Оно доступно автоматически, без объявления пользователем. Это описание не является третьим пользовательским экземпляром, созданным невидимой операцией `new object()`. [00:17:36](https://www.youtube.com/watch?v=t2T88IiiP48&t=1056s) [00:17:43](https://www.youtube.com/watch?v=t2T88IiiP48&t=1063s)

Рассмотрение её через `object` ограничивает члены, видимые через ссылку; оно не создаёт отдельное выделение только заголовка и не усекает экземпляр. Фраза записи «учитывается только типовая часть» описывает именно это суженное представление. [00:18:23](https://www.youtube.com/watch?v=t2T88IiiP48&t=1103s) [00:18:35](https://www.youtube.com/watch?v=t2T88IiiP48&t=1115s) [00:18:44](https://www.youtube.com/watch?v=t2T88IiiP48&t=1124s)

Уточнение говорит, что **`ob` содержит ссылку на экземпляр `4000`**; экземпляр по этому адресу записывает конкретный тип, а не объявленный тип локальной переменной. `99000` — не адрес экземпляра, новым образом сохранённый в `ob`. ## Восстановить ссылку на B с помощью cast

Переменная типа `object` не может предоставить поле, специфичное для `B`, только потому, что она случайно ссылается на `B`. Используйте **явный cast ссылки**, запрашивая целевое представление и проверяя, что фактический объект его поддерживает. Новый синтаксис в состоянии из видео: [00:20:23](https://www.youtube.com/watch?v=t2T88IiiP48&t=1223s) [00:20:31](https://www.youtube.com/watch?v=t2T88IiiP48&t=1231s) [00:20:43](https://www.youtube.com/watch?v=t2T88IiiP48&t=1243s)

```csharp
object ob = new B();
B b1 = (B)ob;
Console.WriteLine(b1.FieldB);

class B { public int FieldB; }
```

`(B)ob` читается как «преобразовать значение `ob` в ссылку, пригодную как `B`». После успешной проверки `b1` хранит ссылку на `B`, и доступ к полю разрешён. Cast не создаёт ни нового объекта, ни копии его полей. [00:20:43](https://www.youtube.com/watch?v=t2T88IiiP48&t=1243s) [00:20:54](https://www.youtube.com/watch?v=t2T88IiiP48&t=1254s)

Объявленный тип `object` обещает только общее представление объекта. Он не обещает наличия какого-либо конкретного поля, поэтому более специфичное представление требует проверки. [00:20:59](https://www.youtube.com/watch?v=t2T88IiiP48&t=1259s)

## Сохранить объект после выхода локальных имён из области видимости

Зачем делать cast, если конкретная переменная `b` уже была доступна? Перенесите её выделение в **блок**, ограниченный фигурными скобками. **Область видимости** локальной переменной — это область, в которой можно использовать её имя. Вне блока имя `b` недоступно, но внешняя локальная переменная может сохранять достижимость объекта. Первое состояние из видео с блоком реконструировано здесь: [00:21:11](https://www.youtube.com/watch?v=t2T88IiiP48&t=1271s) [00:21:27](https://www.youtube.com/watch?v=t2T88IiiP48&t=1287s)

```csharp
object ob;
{
    var b = new B();
    b.FieldB = 18;
    ob = b;
}

B b1 = (B)ob;
Console.WriteLine(b1.FieldB); // 18

class B { public int FieldB; }
```

Сохранённая в `ob` ссылка читается, проверяется на совместимость с `B` и копируется в `b1`. Затем поле читается через эту конкретную ссылку. Показанное значение поля — `18`, а после изменения примера — `20`. Это последовательные значения, а не успешные cast от несвязанного `A` к `B`. [00:21:39](https://www.youtube.com/watch?v=t2T88IiiP48&t=1299s)

Следующий разбор по памяти вводит два объекта и промежуточную перезапись. Соответствующее состояние из видео: [00:21:47](https://www.youtube.com/watch?v=t2T88IiiP48&t=1307s) [00:21:57](https://www.youtube.com/watch?v=t2T88IiiP48&t=1317s) [00:22:16](https://www.youtube.com/watch?v=t2T88IiiP48&t=1336s)

```csharp
object ob; // присвоено до любого чтения
{
    var a = new A();
    var b = new B();
    a.FieldA = 18;
    b.FieldB = 20;
    ob = a; // промежуточно: экземпляр A
    ob = b; // итог: экземпляр B
}

B b1 = (B)ob;
Console.WriteLine(b1.FieldB); // 20

class A { public int FieldA; }
class B { public int FieldB; }
```

Проследите каждое состояние:

1. `object ob;` объявляет неинициализированную локальную переменную. **Определённое присваивание** требует, чтобы она получила значение до чтения; это отличается от автоматической инициализации нового целочисленного поля нулём. [00:21:47](https://www.youtube.com/watch?v=t2T88IiiP48&t=1307s)
2. Выделите `A`, затем `B`. Каждый начинается со своего поля в нуле и с типа времени выполнения, заданного его выделением. Сохраните ссылки в локальных `a` и `b` блока. [00:21:57](https://www.youtube.com/watch?v=t2T88IiiP48&t=1317s) [00:22:12](https://www.youtube.com/watch?v=t2T88IiiP48&t=1332s)
3. Запишите целочисленные значения `18` и `20` в поля. Это данные, а не ссылки на объекты. Копирование ссылок происходит отдельно, в присваиваниях `ob`. [00:22:13](https://www.youtube.com/watch?v=t2T88IiiP48&t=1333s)
4. Сначала скопируйте `a` в `ob`, затем перезапишите его значением `b`. Итоговая сохранённая ссылка идентифицирует `B`. [00:22:16](https://www.youtube.com/watch?v=t2T88IiiP48&t=1336s)
5. Блок заканчивается. Локальные имена выходят из области видимости, но достижимый объект `B` не исчезает. `ob` больше не сохраняет достижимость перезаписанного `A`. Выход из области видимости сам по себе не уничтожает оба выделенных объекта. [00:22:22](https://www.youtube.com/watch?v=t2T88IiiP48&t=1342s)
6. Восстановите конкретное представление с помощью проверки времени выполнения. `object` как статический тип не обещает `B`, а потеря локального имени не делает сохранённое значение неведомым для работающей программы. При выполнении cast использует фактический ссылающийся экземпляр. [00:22:31](https://www.youtube.com/watch?v=t2T88IiiP48&t=1351s) [00:22:41](https://www.youtube.com/watch?v=t2T88IiiP48&t=1361s)

**Выражение приведения** — это целевой тип в скобках, за которым следует преобразуемое выражение. Его результат имеет статический тип `B`, поэтому его можно присвоить локальной переменной типа `B` и использовать для последующего доступа к полю. Дополнительные скобки группировки сохраняют этот смысл. Пояснение синтаксиса из видео: [00:22:45](https://www.youtube.com/watch?v=t2T88IiiP48&t=1365s) [00:22:55](https://www.youtube.com/watch?v=t2T88IiiP48&t=1375s)

```csharp
B b1 = (B)ob;
// Эквивалентная группировка, как альтернативный оператор:
// B b1 = ((B)(ob));
```

Пример с областью видимости мотивирует проверку; компилятор не получает разрешение на доступ к `FieldB` через `object` просто потому, что программист видит более раннее присваивание в исходном тексте.

## Выполнить несовместимый cast

**Ошибка компиляции** не даёт построить программу; **ошибка времени выполнения** возникает во время её исполнения. Измените цель на несвязанный `A`, оставив источник объявленным как `object`. Компилятор разрешает такой cast, потому что ссылка типа `object` в общем случае может указывать на `A`, но в этом запуске передаётся `B`. Изменённое состояние из видео: [00:25:13](https://www.youtube.com/watch?v=t2T88IiiP48&t=1513s)

```csharp
object ob = new B();
A b1 = (A)ob; // компилируется, затем бросает InvalidCastException

class A { }
class B { }
```

Запуск проекта сообщает об ошибке в месте приведения. Среда выполнения проходит по сохранённой ссылке на экземпляр, обнаруживает его тип `B` и проверяет его на соответствие ожидаемому `A`. Отношение наследования не допускает такого преобразования. Ни похожие поля, ни общий `object` не делают классы взаимозаменяемыми. [00:25:22](https://www.youtube.com/watch?v=t2T88IiiP48&t=1522s) [00:25:32](https://www.youtube.com/watch?v=t2T88IiiP48&t=1532s) [00:25:42](https://www.youtube.com/watch?v=t2T88IiiP48&t=1542s) [00:26:02](https://www.youtube.com/watch?v=t2T88IiiP48&t=1562s)

Это противопоставляется более раннему прямому приведению, исходное выражение которого уже было статически типизировано как несвязанный `A`: то преобразование было отклонено при компиляции. Здесь более общее объявление источника оставляет совместимость фактического объекта исполнению.

## Отличить братские классы от их общего базового

Теперь вводится **базовый класс** с двумя **братскими производными классами**: каждый расширяет тот же базовый класс, но ни один не является другим. Выделите `Derived` и запросите конкретное представление братского класса, а общий базовый класс рассмотрите отдельно. Изменения из видео: [00:26:12](https://www.youtube.com/watch?v=t2T88IiiP48&t=1572s) [00:26:24](https://www.youtube.com/watch?v=t2T88IiiP48&t=1584s)

```csharp
object ob = new Derived();

// Проверьте эти варианты в отдельных запусках:
A b1 = (A)ob;             // неудача: Derived — это не A
// Base b1 = (Base)ob;    // успех

class Base { }
class Derived : Base { }
class A : Base { }
```

Запись задаёт экземпляру один адрес, около `5000`, и различает описания `Derived` и `A` по иллюстративным адресам `10000` и `9000`. Приведение экземпляра к братскому `A` не удаётся; приведение к `Base` успешно, даже хотя его точный тип времени выполнения — `Derived`. Необработанное неудачное приведение останавливает исполнение, поэтому успешную альтернативу нельзя ставить после него и ожидать её выполнения. [00:26:35](https://www.youtube.com/watch?v=t2T88IiiP48&t=1595s) [00:26:51](https://www.youtube.com/watch?v=t2T88IiiP48&t=1611s)

**Совместимость** — это отношение типов, позволяющее запрошенное представление. Модель рисует список совместимых типов, включая ссылку на описание `Base`. Это объяснение отношений времени выполнения, а не записываемый скрытый список, контролируемый кодом приложения. Среда выполнения обращается к таким отношениям, чтобы установить, возможен ли cast. [00:27:08](https://www.youtube.com/watch?v=t2T88IiiP48&t=1628s) [00:27:34](https://www.youtube.com/watch?v=t2T88IiiP48&t=1654s)

Открытое свойство **`Type.BaseType`** предоставляет описание непосредственного базового типа без необходимости приведения экземпляра. Соответствующее состояние из видео: [00:27:20](https://www.youtube.com/watch?v=t2T88IiiP48&t=1640s)

```csharp
object ob = new Derived();
Type actual = ob.GetType();
Type? parent = actual.BaseType; // описывает Base

class Base { }
class Derived : Base { }
```

`actual` описывает `Derived`; `parent` описывает `Base`. **Nullable-ссылка**, помеченная знаком `?`, допускает null, поскольку у некоторых типов нет базового. Получение метаданных не преобразует `ob` и не заменяет его экземпляр. Оно делает отношение доступным для исследования, и именно такие отношения среда выполнения использует для проверки совместимого приведения к базовому типу.

## Достичь того же базового типа двумя путями

**`typeof`** получает описание типа по имени типа, а не от экземпляра. Сравните этот прямой путь с проходом по **`BaseType`**, то есть описанию непосредственного базового типа фактического типа. Сопоставление из видео: [00:27:40](https://www.youtube.com/watch?v=t2T88IiiP48&t=1660s) [00:27:54](https://www.youtube.com/watch?v=t2T88IiiP48&t=1674s)

```csharp
object ob = new Derived();
Type? viaInstance = ob.GetType().BaseType;
Type direct = typeof(Base);
// viaInstance и direct описывают один и тот же тип Base.

class Base { }
class Derived : Base { }
```

Один путь — «`ob` → экземпляр `Derived` → описание типа `Derived` → описание типа `Base`». Другой запрашивает `Base` напрямую по имени. Оба приходят к одному и тому же описанному типу, поэтому ссылки можно сравнивать. [00:28:04](https://www.youtube.com/watch?v=t2T88IiiP48&t=1684s) [00:28:13](https://www.youtube.com/watch?v=t2T88IiiP48&t=1693s)

Полученная переменная описывает **базовый тип** экземпляра, а не его точный тип времени выполнения. Экземпляр остаётся `Derived`. Это сравнение между описаниями типов, а не между ссылкой на экземпляр и ссылкой на метаданные. [00:28:22](https://www.youtube.com/watch?v=t2T88IiiP48&t=1702s)

## Применить BaseType и typeof

Сохраните описание базового типа в переменную типа `Type`, не допускающую null типа `Type`, напечатайте её имя, запросите тот же тип напрямую и сравните. **Оператор подавления nullable** — это постфиксный `!` на выражении; это не знак препинания в имени переменной. Изменение из видео: [00:28:29](https://www.youtube.com/watch?v=t2T88IiiP48&t=1709s) [00:28:38](https://www.youtube.com/watch?v=t2T88IiiP48&t=1718s)

```csharp
object ob = new Derived();

Type b = ob.GetType().BaseType!;
Console.WriteLine(b.Name); // Base

Type direct = typeof(Base);
Console.WriteLine(b == direct); // True

class Base { }
class Derived : Base { }
```

1. Получите тип `Derived`, затем его непосредственный базовый тип. В этом известном примере базовый тип существует. `!` говорит **анализу nullable** принять выражение как не допускающее null; он не добавляет никакой гарантии времени выполнения и не изменил бы значение null. **Null** означает, что ни на какой объект нет ссылки. [00:28:38](https://www.youtube.com/watch?v=t2T88IiiP48&t=1718s) Вот точный [контракт оператора подавления nullable](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/null-forgiving).
2. **`Name`** читает имя описанного типа — `Base`. На рисунке программа проходит по ссылке на описание типа к его строковому полю и передаёт эту ссылку на строку в `Console.WriteLine`. **Строка** представляет текст в отдельном ссылочном объекте. [00:28:48](https://www.youtube.com/watch?v=t2T88IiiP48&t=1728s)
3. **`typeof(Base)`** запрашивает описание названного типа и сохраняет его в другой переменной типа `Type`. Он не создаёт экземпляр `Base`. [00:29:00](https://www.youtube.com/watch?v=t2T88IiiP48&t=1740s)
4. **Равенство типов**, выраженное через `==`, сравнивает два описания. Рисунок представляет оба пути как приводящие к `8000`, превращая сравнение числовой модели в `8000 == 8000`. Код приложения сравнивает значения `Type`, а не доступные адреса памяти. [00:29:17](https://www.youtube.com/watch?v=t2T88IiiP48&t=1757s) [00:29:28](https://www.youtube.com/watch?v=t2T88IiiP48&t=1768s)
5. Запись печатает `True`, подтверждая, что оба пути дают один и тот же тип `Base`. Напечатанное сравнение завершает этот эксперимент перед следующим примером о наследовании. [00:29:25](https://www.youtube.com/watch?v=t2T88IiiP48&t=1765s) [00:29:40](https://www.youtube.com/watch?v=t2T88IiiP48&t=1780s)

Описание, найденное через `BaseType`, объясняет, почему совместимое приведение к базовому типу может сработать без точного равенства типов. Оно не означает, что точный тип экземпляра `Derived` стал `Base`.

<details>
<summary>Почему b равно typeof(Base) и какую защиту добавляет восклицательный знак?</summary>

GetType сначала описывает Derived, затем BaseType выбирает описание его базового типа Base. typeof(Base) запрашивает то же описание напрямую. Восклицательный знак снимает предупреждения о nullable; он не даёт никакой защиты времени выполнения.

</details>

## Попытка указать два базовых класса

**Множественное наследование классов** означало бы наследование напрямую более чем от одного класса. C# этого не допускает. Последний эксперимент временно предполагает объединение `Base1` и `Base2`, а затем объясняет, почему это конфликтует с простой моделью ссылок из записи. Гипотетическое состояние из видео, намеренно невалидный C#: [00:29:43](https://www.youtube.com/watch?v=t2T88IiiP48&t=1783s) [00:29:58](https://www.youtube.com/watch?v=t2T88IiiP48&t=1798s)

```csharp
class Base1 { public int Field1; }
class Base2 { public int Field2; }

// Недопустимо: Base1 и Base2 — оба классы.
class Derived : Base1, Base2
{
    public int Field3;
}
```

Задача состояла бы в том, чтобы использовать один объект через любой из базовых типов, сохранив корректный доступ к полям и определение типа. Нарисуйте его поля в таком предполагаемом порядке: `Field1`, `Field2`, `Field3`, изначально все нули, с меткой типа перед ними. Это мысленный эксперимент, а не успешно скомпилированное выделение невалидного класса. [00:30:20](https://www.youtube.com/watch?v=t2T88IiiP48&t=1820s) [00:30:34](https://www.youtube.com/watch?v=t2T88IiiP48&t=1834s)

Проследите два предполагаемых представления:

1. Представьте выделение объединённого объекта и сохранение его ссылки, показанной как `5000`, в переменной производного типа. Его первое поле приходит из `Base1`, следующее — из `Base2`, последнее — из `Derived`. [00:30:20](https://www.youtube.com/watch?v=t2T88IiiP48&t=1820s)
2. Рассмотрим трактовку этой ссылки как `Base1`. В предполагаемом отношении наследования преобразование скопировало бы тот же адрес в переменную базового типа. Его ожидаемое первое поле занимает моделируемую позицию первого поля. [00:30:45](https://www.youtube.com/watch?v=t2T88IiiP48&t=1845s) [00:30:59](https://www.youtube.com/watch?v=t2T88IiiP48&t=1859s)
3. Поэтому запись `Field1` через это представление достигает нужного поля. Первое базовое представление пока выглядит согласованным. [00:31:08](https://www.youtube.com/watch?v=t2T88IiiP48&t=1868s)
4. Теперь представьте, что представление `Base2` тоже получает `5000`. Ни новый объект, ни смещённый адрес не вводились. Но первое поле, ожидаемое `Base2`, — не то поле, которое расположено в точке этой ссылки на объединённом рисунке. [00:31:14](https://www.youtube.com/watch?v=t2T88IiiP48&t=1874s) [00:31:28](https://www.youtube.com/watch?v=t2T88IiiP48&t=1888s)

Эти операции — гипотетические рассуждения урока. Само объявление никогда не даёт настоящей программе на C# законных преобразований к двум непосредственным базовым классам.

## Проверить второе базовое представление

**Смещение поля** находит поле относительно моделируемой позиции ссылки. В объединённом наброске собственное поле `Base2` начинается после данных другого базового класса. Поэтому его связь с типом и его собственное поле не могут считаться той же непрерывной отдельной частью, которую ожидает простая модель. Наследование призвано сделать экземпляр производного класса пригодным как экземпляр базового; именно в сохранении этого обещания и состоит трудность. [00:31:31](https://www.youtube.com/watch?v=t2T88IiiP48&t=1891s) [00:31:46](https://www.youtube.com/watch?v=t2T88IiiP48&t=1906s)

У отдельного изображения `Base2` метка типа непосредственно предшествует `Field2`. В объединённом объекте это поле смещено. Обычные преобразования ссылок C# не предоставляют настраиваемого смещения базового подобъекта, которым можно было бы закодировать гипотетическое второе представление. [00:31:58](https://www.youtube.com/watch?v=t2T88IiiP48&t=1918s) [00:32:10](https://www.youtube.com/watch?v=t2T88IiiP48&t=1930s)

Разберите предложенные исправления:

1. **Сохранить исходный адрес.** Представление `Base2` ожидает своё первое поле на стандартной позиции, тогда как объединённый рисунок помещает туда поле `Base1`. Простое копирование ссылки оставляет рассогласование раскладки. [00:31:58](https://www.youtube.com/watch?v=t2T88IiiP48&t=1918s) [00:32:10](https://www.youtube.com/watch?v=t2T88IiiP48&t=1930s)
2. **Сохранить вместо этого адрес второй части.** Запись предлагает ссылку, указывающую в середину объекта, и обозначает эту альтернативу сокращённо как «5», а не `5000`. Считайте это число иллюстративной смещённой позицией, а не числовым результатом законного cast в C#. [00:32:16](https://www.youtube.com/watch?v=t2T88IiiP48&t=1936s)
3. **Попробовать преобразовать смещённую ссылку обратно.** Модель находит информацию о типе непосредственно перед сохранённой ссылкой. При смещении настоящая метка оказывается дальше назад, отделённая данными первого базового класса. Преобразование через общее представление `object` и обратно уже не восстановило бы весь экземпляр по этому правилу. 4. **Дублировать метку типа перед каждой базовой частью.** Это изменило бы представление. Проход по пользовательским полям теперь должен был бы пропускать промежуточную ячейку метаданных вместо продвижения по исходной непрерывной последовательности пользовательских данных. Простое повторение типа времени выполнения не говорит, как восстановить начало полного объекта по этой части `Base2`. Они объясняют проблему именно этого выбранного представления, а не доказывают невозможность для любого языка или среды выполнения. ## Наблюдать границу компиляции

**Ошибка компиляции** не даёт построить программу. Запись завершает исследование раскладки тем, что открытые вопросы и конкурирующие подходы привели к запрету этой конструкции. Читайте это как объяснение, предложенное рисунком урока; компилятор обеспечивает правило языка, а не действительно проверяет каждый возможный порядок полей. [00:33:37](https://www.youtube.com/watch?v=t2T88IiiP48&t=2017s)

Итоговое состояние из видео по-прежнему является невалидным объявлением класса: [00:34:01](https://www.youtube.com/watch?v=t2T88IiiP48&t=2041s)

```csharp
class Base1 { }
class Base2 { }
class Derived : Base1, Base2 { } // ошибка компиляции
```

Показанный отказ компилятора противопоставляется более раннему несовместимому cast типа `object`: тот cast скомпилировался и затем упал во время выполнения, тогда как два непосредственных базовых класса не компилируются вовсе. Финальная устная сводка связывает это ограничение с неспособностью простой модели разместить оба набора полей базовых классов и сохранить поведение поиска по ссылке и типу. [00:34:03](https://www.youtube.com/watch?v=t2T88IiiP48&t=2043s) [00:34:12](https://www.youtube.com/watch?v=t2T88IiiP48&t=2052s)

Граница языка — это **один непосредственный базовый класс**, а не «только одно имя может стоять после двоеточия». **Интерфейс** — это реализуемый контракт, а не второй базовый класс; механизмы интерфейсов находятся за пределами этого урока. Документация [по наследованию в C#](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/object-oriented/inheritance) излагает правило одного базового класса и различает реализацию интерфейсов.

Урок останавливается на преобразованиях ссылок и этой границе наследования классов. Он откладывает подробную типизацию структур и упаковку, полиморфную диспетчеризацию методов, дополнительные данные заголовка объекта, реализацию интерфейсов и полное описание раскладки времени выполнения. Его числовые наброски памяти объясняют примеры, но не дают коду приложения операций с сырыми адресами.
