# Управление потоком и логические выражения в C#

## Цель урока и словарь

[00:00:00](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=0s) Цель — объяснить синтаксис решений и повторений, которые предыдущие уроки использовали лишь вскользь. Небольшая игра «угадай число» даёт задачу: выбрать загаданное число, прочитать догадку, выдать подсказку и в конце концов повторять, пока догадка не окажется верной.

[00:00:11](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=11s) Проверка даёт значение, которое можно сохранить и использовать повторно. Понимание этого значения связывает две темы урока: выражения типа `bool` и управление потоком.

Встретившийся словарь:

- **Управление потоком** определяет, какой оператор выполнится следующим. **Оператор** (statement) — это инструкция; **блок** объединяет операторы внутри `{ }`. **Ветвление** — альтернативный путь выполнения. **Отступ** — ведущие пробельные символы, делающие структуру читаемой.
- **Выражение** вычисляет значение. **Оператор** (operator) выполняет операцию над своими **операндами** — выражениями, которые он получает. **Присваивание** (`=`) сохраняет значение; **равенство** (`==`) сравнивает значения; **неравенство** (`!=`) проверяет, что они различаются. **Операторы сравнения** `<`, `>`, `<=` и `>=` сравнивают порядок.
- **`bool`**, сокращение от *boolean*, — тип с двумя простыми логическими значениями **`true`** и **`false`**. **Логическое выражение** вычисляет одно из этих значений. **Условие** использует это значение, чтобы решить, выполнять ли код.
- **Отрицание** (`!`) меняет логическое значение на противоположное. **Логическое И** (`&&`) требует истинности обоих операндов; **логическое ИЛИ** (`||`) требует истинности хотя бы одного из них. Их **сокращённое**, или **ленивое**, вычисление пропускает операнд, когда результат уже известен. **Побочный эффект**, например вывод в консоль, — наблюдаемое действие во время вычисления.
- **`if`** выполняет присоединённый к нему оператор, когда условие истинно. **`else`** задаёт ветку для ложного случая. **`else if`** — это `if`, используемый как оператор, присоединённый к `else`. **Вложенность** помещает один оператор или блок внутрь другого.
- **Цикл** повторяет оператор или блок, называемый его **телом**. **Итерация** — один проход. **`while`** проверяет условие перед каждым проходом; у **`while (true)`** нет собственного условия остановки. **`do ... while`** проверяет условие после тела, поэтому тело выполняется хотя бы один раз. **`for`** — ещё одна форма цикла, названная во вступлении.
- **`break`** выходит из ближайшего объемлющего цикла. **`continue`** пропускает остаток текущей итерации и переходит к следующей проверке условия в используемых здесь циклах. **`return`** выходит из всей функции, при необходимости возвращая результат.
- **Переменная** хранит типизированное значение. **Объявление** вводит её; **инициализация** задаёт начальное значение. **Определённое присваивание** означает, что компилятор может установить: локальная переменная имеет значение до первого чтения. **Область видимости** — это область, где имя доступно. **Сентинел** — искусственное значение, помечающее особое состояние.
- **Функция** — вызываемый код. **Вызов функции** вычисляет её **аргументы**, переданные значения; **параметры** принимают эти значения внутри функции. **Возвращаемое значение** функции — её результат.
- **`Random`** поставляет псевдослучайные числа через `Next`. Его **параметр `maxValue`** — исключающая верхняя граница. **Оператор остатка** `%` даёт остаток от деления.
- **Ввод из консоли** приходит как текст. **Разбор** пытается преобразовать этот текст в число. **`int.TryParse`** сообщает об успехе логическим значением и записывает число через **`out`-параметр** — параметр, присваиваемый вызываемой функцией.

Для связанной практики используйте репозиторные [лабораторную работу про bool](../../../labs/1_basic/06_bool.md) и [лабораторную работу про управление потоком](../../../labs/1_basic/07_flow_control.md).

**Охват:** во вступлении названы `if`, `while` и `for`, но разбираемая часть урока развивает логические выражения, `if/else`, `while`, `break`, `continue`, `do ... while` и повторный ввод. Синтаксис `for` не разбирается. Функции, переменные и ввод из консоли — вспомогательные инструменты, а не предметы полного повторения. Первая ветка разбора использует логические значения раньше их подробного объяснения; завершение бесконечного цикла также вводится только после самого цикла.

Примеры кода ниже — упрощённые реконструкции состояний видео по меткам времени, с английскими сообщениями и описательными именами. Просмотренные исходники лабораторных работ приведены как **связанные примеры**, а не как точные сохранённые состояния игры.

## Выбираем загаданное число и читаем первую догадку

[00:00:26](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=26s) Начнём с выбора загаданного числа. `Random` — генератор чисел, а `Next()` — вызов функции, получающий неотрицательное целое число. Остаток от деления на 100 ограничивает результат диапазоном от 0 до 99 включительно:

```csharp
var random = new Random();
int r = random.Next() % 100;
```

Здесь `%` — оператор остатка. Число 100 является делителем; остатком не может быть само 100.

[00:00:45](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=45s) Измените выражение генерации на `random.Next(100)`. Аргумент `100` попадает в параметр `maxValue` функции — исключающую верхнюю границу. Это тоже даёт число от 0 до 99:

```csharp
int r = random.Next(100);
```

[00:00:55](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=55s) Далее читаем текст из консоли и выполняем разбор. Разбор преобразует текстовое представление в целое число. `TryParse` даёт два результата: его логическое возвращаемое значение сообщает, удалось ли преобразование, а параметр `out` получает само целое число.

```csharp
string? input = Console.ReadLine();
if (!int.TryParse(input, out int num))
{
    Console.WriteLine("Not a number.");
    return;
}
```

Объявление `out int num` вводит выходную переменную. `!` отрицает признак успеха, поэтому эта ветка обрабатывает неудачу. `return` выходит из содержащей функции. В [00:01:02](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=62s) это намеренно лишь первое знакомство с `bool` и `if`; их механика объясняется после того, как игра сможет выполнить одно сравнение.

## Сравниваем один раз и выделяем функцию сравнения

[00:01:10](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=70s) Первая ветка проверяет равенство: если введённое число `num` равно загаданному числу `r`, печатаем успех. В [00:01:23](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=83s) добавляем упорядоченные сравнения: догадка меньше загаданного числа требует следующей догадки побольше, догадка больше — поменьше.

```csharp
if (num == r)
{
    Console.WriteLine("Correct!");
}
else if (num < r)
{
    Console.WriteLine("Guess higher.");
}
else if (num > r)
{
    Console.WriteLine("Guess lower.");
}
```

`==` — оператор равенства, а `<` и `>` — операторы сравнения. Каждый сравнивает два значения и даёт логическое значение. Конструкция `else if` будет разобрана позже; пока она выражает три исхода игры.

[00:01:33](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=93s) Выделим этот блок сравнения в отдельную функцию, чтобы рассмотреть его отдельно. Функция объединяет вызываемый код; параметры получают значения, переданные вызывающим кодом. Структурное изменение выглядит так:

```csharp
CompareGuess(num, r);

static void CompareGuess(int num, int r)
{
    if (num == r)
    {
        Console.WriteLine("Correct!");
    }
    else if (num < r)
    {
        Console.WriteLine("Guess higher.");
    }
    else if (num > r)
    {
        Console.WriteLine("Guess lower.");
    }
}
```

[00:01:41](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=101s) Записанный прогон ждёт число из консоли, а затем сообщает, нужно ли загадать больше или меньше. Он всё ещё обрабатывает только одну догадку. В [00:01:54](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=114s) урок приостанавливает разработку, чтобы проанализировать `if` до добавления бесконечного цикла.

## if читает логическое выражение

[00:02:05](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=125s) Условие `if` решает, выполнится ли присоединённый к нему оператор. В текущем примере такой оператор — блок, код в фигурных скобках:

```csharp
if (num == r)
{
    Console.WriteLine("Correct!");
}
```

[00:02:16](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=136s) Вычисление сначала получает значения левого выражения `num` и правого выражения `r`, а затем проверяет, равны ли они.

[00:02:33](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=153s) Не смешивайте присваивание и сравнение. Одиночный `=` записывает значение в переменную; двойной `==` спрашивает, совпадают ли два значения. В [00:02:42](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=162s) равенство названо операцией сравнения значений:

```csharp
num = r;            // присваивание: сохранить значение r в num
bool same = num == r; // сравнение: вычислить логическое значение
```

[00:02:49](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=169s) Операнды оператора — выражения. Чтение переменной — простое выражение, но с любой стороны может участвовать и вычисление. В [00:03:05](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=185s) само сравнение распознано как выражение, поэтому его результат можно использовать в других местах. В [00:03:10](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=190s) этот результат равен `true` для равных значений и `false` для разных.

[00:03:35](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=215s) Сохраним результат, вместо того чтобы помещать сравнение прямо в условие. В [00:03:41](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=221s) чтение переменной даёт условие:

```csharp
bool guessed = num == r;
if (guessed)
{
    Console.WriteLine("Correct!");
}
```

Сохранённое значение фиксирует результат того сравнения на момент его выполнения. Чтение `guessed` использует это сохранённое решение; оно не перевыполняет `num == r`.

[00:03:53](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=233s) Точнее говоря, `if` потребляет логическое выражение, а не особую категорию «синтаксиса условий». В [00:04:01](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=241s) обобщающее правило таково: выражение вычисляет `true` или `false` — сравнение, чтение логической переменной и вызов, возвращающий логическое значение, могут все давать это значение.

[00:04:10](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=250s) Равенство и неравенство входят в число операторов, используемых для построения логических выражений. Логическое выражение вычисляет истинностное значение, что подчёркивается в [00:04:33](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=273s). В [00:04:36](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=276s) назван его тип в C#: `bool`, от *boolean*.

[00:04:48](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=288s) Проследим присваивание от его операндов к результату. 1. В [00:04:56](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=296s) читаем текущие значения переменных: `a` даёт 5, `b` даёт 6.

## Комбинируем проверки операторами с сокращённым вычислением

[00:05:56](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=356s) Каждое сравнение — логическое выражение, поэтому его результат можно объединить с другим логическим выражением. Следующий пример одновременно спрашивает, различаются ли `a` и `b`, и равно ли `a` семи.

[00:06:18](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=378s) Логическое И, записываемое `&&`, требует истинности обеих проверок. Это та же операция, что и в [связанных сохранённых примерах И](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/06_bool.md):

```csharp
int a = 5;
int b = 6;
bool c = (a != b) && (a == 7);
```

1. В [00:06:35](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=395s) сначала вычисляем левый операнд: `5 != 6` — это `true`.
2. В [00:06:46](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=406s) рассмотрим альтернативу: если бы левый операнд был ложным, И уже дало бы ложь и правый операнд не вычислялся бы.
3. Здесь левый операнд истинен, поэтому в [00:07:00](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=420s) вычисляем правый операнд: `5 == 7` ложно.
4. В [00:07:14](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=434s) `true && false` даёт ложь. Для истинного результата И оба операнда должны быть истинными.

[00:07:25](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=445s) Логическое ИЛИ, записываемое `||`, тоже сначала вычисляет левую часть. Замените оператор:

```csharp
bool c = (a != b) || (a == 7);
```

В [00:07:31](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=451s) истинный левый операнд сразу даёт ИЛИ истину; правый операнд пропускается. В [00:07:42](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=462s) ложный левый операнд требует правой проверки. Если и она ложна, весь результат ложен.

[00:07:54](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=474s) Это и есть сокращённое, или ленивое, вычисление: второй операнд вычисляется только тогда, когда первый не может решить исход. В [00:08:05](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=485s) подчёркивается практическое следствие: побочный эффект в пропущенном операнде никогда не происходит.

| Оператор | Результат левой части | Вычисляется ли правый операнд? |
| --- | --- | --- |
| `&&` | `false` | Нет; результат уже ложен |
| `&&` | `true` | Да |
| `||` | `true` | Нет; результат уже истинен |
| `||` | `false` | Да |

## Делаем пропущенное вычисление заметным

[00:08:21](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=501s) Заменим правое сравнение функцией, которая сначала печатает, а затем выполняет проверку. Это делает вычисление наблюдаемым. Вызов функции выполняет её тело; возвращаемое значение становится значением операнда.

```csharp
static bool IsSeven(int number)
{
    Console.WriteLine("Check called.");
    return number == 7;
}
```

[00:08:37](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=517s) Используем этот вызов как второй операнд и напечатаем `c` после. Это тот же приём демонстрации, что и в [связанных сохранённых примерах ленивого вычисления](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/06_bool.md):

```csharp
int a = 5;
int b = 6;
bool c = (a != b) && IsSeven(a);
Console.WriteLine(c);
```

[00:08:47](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=527s) В записанном прогоне с И сообщение функции появляется, потому что левое сравнение истинно. В [00:08:57](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=537s) причина в том, что оператору всё ещё нужно значение правого операнда. В [00:09:05](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=545s) выполнение входит в функцию, печатает сообщение и возвращает ложь, потому что 5 не равно 7. В [00:09:22](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=562s) вывод подтверждает ложный результат, сохранённый в `c`:

```text
Check called.
False
```

[00:09:27](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=567s) Теперь заменим И на ИЛИ:

```csharp
bool c = (a != b) || IsSeven(a);
Console.WriteLine(c);
```

Левое сравнение уже истинно, поэтому записанный прогон с ИЛИ печатает только `True`. В [00:09:47](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=587s) главное здесь: пропуск правого выражения пропускает сам вызов. Функция не выполняется, поэтому её печать не может появиться.

Что напечатал бы вариант с И, если бы `b` изменили на 5?

<details>
<summary>Ответ</summary>

Только <code>False</code>. Левое сравнение <code>5 != 5</code> ложно, поэтому И пропускает <code>IsSeven(a)</code> и его печать.

</details>

## Сравниваем логические значения напрямую

[00:09:55](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=595s) Равенство и неравенство могут сравнивать логические значения напрямую, так же как числа в этом уроке. Преобразование не требуется.

[00:10:02](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=602s) Оставим истинный результат из демонстрации ИЛИ в `c`, положим ложь в `d` и сравним их. [Связанный сохранённый пример сравнения логических значений](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/06_bool.md) использует ту же идею:

```csharp
bool c = true;
bool d = false;
bool equal = c == d;
Console.WriteLine(equal); // False
```

[00:10:19](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=619s) Истина и ложь — разные значения, поэтому равенство даёт ложь.

[00:10:38](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=638s) У равенства нет правила сокращённого вычисления. Ему нужны оба значения, чтобы решить, совпадают ли они. В реконструированном варианте вызов функции выполнился бы, даже если левый операнд уже истинен:

```csharp
bool equal = c == IsSeven(5);
```

Различие — между операторами: `&&` и `||` иногда могут решить исход по одному лишь левому значению; `==` и `!=` нуждаются в обоих операндах.

## Один оператор может быть целым блоком

[00:11:00](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=660s) `if` присоединяется к одному следующему оператору. Блок в фигурных скобках считается таким оператором, позволяя при этом разместить внутри несколько инструкций. [Связанные сохранённые примеры блоков](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/07_flow_control.md) показывают такое группирование:

```csharp
bool execute = false;
if (execute)
{
    Console.WriteLine("First");
    Console.WriteLine("Second");
}
Console.WriteLine("After");
```

[00:11:17](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=677s) Если логическое выражение истинно, выполнение входит в блок и выполняет его операторы. В [00:11:39](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=699s) ложное значение пропускает весь блок, но не код после него.

[00:11:54](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=714s) Печать после `if` показывает эту границу: она появляется независимо от условия. При ложном значении выводится только `After`; при истинном перед ней выводятся оба внутренних сообщения. Условие управляет только присоединённым блоком.

## Скобки определяют, какие операторы относятся к if

[00:12:13](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=733s) Фигурные скобки можно опустить, когда присоединённый оператор — одиночная инструкция. Эта инструкция сама может быть `if`, включая её зависимый оператор. В [00:12:19](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=739s) сравниваются вложенные формы со скобками и без них:

```csharp
// Реконструированная форма с одиночным оператором:
if (num >= r)
    if (num == r)
        Console.WriteLine("Equal");

// Эквивалентная форма с явными скобками:
if (num >= r)
{
    if (num == r)
    {
        Console.WriteLine("Equal");
    }
}
```

[00:12:37](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=757s) Без блока в скобках каждому `if` принадлежит только один оператор. В [00:12:54](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=774s) отступ подчёркивается как визуальное форматирование, а не как правило принадлежности. Второй оператор с таким же отступом всё равно находится вне `if`. Смотрите [связанный сохранённый пример без скобок](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/07_flow_control.md):

```csharp
int r = 50;
if (num == r)
    Console.WriteLine("First");
    Console.WriteLine("Second"); // выполняется всегда
```

[00:13:11](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=791s) Для демонстрации загаданное число задаётся фиксированным, а не генерируется заново, чтобы одно и то же сравнение можно было надёжно проверить. Это означает присваивание 50; ключевое слово `fixed` в C# здесь не вводится.

[00:13:15](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=795s) Записанные проверки показывают оба сообщения для 50, но только второе — для другого числа. В [00:13:31](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=811s) объясняется, что второй вывод не присоединён к `if`.

[00:13:28](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=808s) Рекомендация по изучению — сохранять скобки даже для одной инструкции. Они делают группировку явной и позволяют безопасно добавить ещё одну инструкцию:

```csharp
if (num == r)
{
    Console.WriteLine("First");
    Console.WriteLine("Second");
}
```

## Присоединяем else к ложной ветке

[00:13:43](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=823s) `else` задаёт альтернативный оператор для `if`. Как и `if`, он может содержать блок или одиночную инструкцию без скобок. В [00:13:57](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=837s) действует то же правило отступов: пробельные символы не решают, что принадлежит `else`.

[00:14:05](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=845s) `else` должен непосредственно следовать за связанным оператором `if`. Он выполняется, когда условие `if` ложно. [Связанные сохранённые примеры if-else](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/07_flow_control.md) иллюстрируют две ветки:

```csharp
int r = 50;
if (num == r)
{
    Console.WriteLine("Equal");
}
else
{
    Console.WriteLine("Different");
}
Console.WriteLine("After");
```

[00:14:23](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=863s) Форма с одиночной инструкцией тоже допускает `else`; предшествующая инструкция завершает `if`:

```csharp
if (num == r)
    Console.WriteLine("Equal");
else
    Console.WriteLine("Different");
```

[00:14:37](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=877s) В записанной проверке 50 идёт по ветке `if`, а другое число — по ветке `else`. В [00:14:41](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=881s) выполнение прослеживается на ложном случае: пропустить блок `if`, выполнить его `else`, затем продолжить со следующими операторами. Обе альтернативы не выполняются одновременно.

## Строим цепочку else if из вложенных операторов

[00:15:00](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=900s) Вложим ещё одну проверку в ветку неверной догадки. Вложенность означает размещение оператора внутри другого блока. Эта начальная структура может напечатать общее сообщение о неверной догадке, прежде чем решить, какая подсказка подходит:

```csharp
if (num == r)
{
    Console.WriteLine("Correct!");
}
else
{
    Console.WriteLine("Wrong guess.");
    if (num < r)
    {
        Console.WriteLine("Guess higher.");
    }
}
```

[00:15:33](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=933s) Если внешний `else` содержит только внутренний `if`, его скобки можно опустить, и по соглашению оба ключевых слова стоят в одной строке. В [00:15:55](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=955s) это объясняет `else if`: `if` — это тот единственный оператор, который присоединён к `else`. [Связанный сохранённый пример цепочки](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/07_flow_control.md) использует эту структуру:

```csharp
if (num == r)
{
    Console.WriteLine("Correct!");
}
else if (num < r)
{
    Console.WriteLine("Guess higher.");
}
else
{
    Console.WriteLine("Guess lower.");
}
```

[00:15:58](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=958s) Развернём её обратно в скобки, сохранив последнюю альтернативу: этот `else` принадлежит внутреннему `if`, поэтому должен остаться внутри внешнего блока `else`.

```csharp
if (num == r)
{
    Console.WriteLine("Correct!");
}
else
{
    if (num < r)
    {
        Console.WriteLine("Guess higher.");
    }
    else
    {
        Console.WriteLine("Guess lower.");
    }
}
```

[00:16:01](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=961s) Явная финальная проверка `num > r` для этих целых чисел не нужна. Если число не равно `r` и не меньше его, оно обязательно больше.

[00:16:23](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=983s) `if` вместе с присоединённым к нему `else` считается одним оператором. Поэтому вся эта внутренняя пара может быть присоединена к внешнему `else`. В [00:16:51](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1011s) удаление необязательных скобок сжимает ту же цепочку:

```csharp
if (num == r) Console.WriteLine("Correct!");
else if (num < r) Console.WriteLine("Guess higher.");
else Console.WriteLine("Guess lower.");
```

Финальный `else` относится к ближайшему доступному внутреннему `if`; внешний блок для цепочки не нужен. Это объясняет синтаксис, хотя скобки остаются рекомендуемым способом показать содержимое каждой ветки.

[00:17:05](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1025s) Записанный прогон по-прежнему запускается один раз и выдаёт подсказку «больше/меньше». Правильный выбор ветки ещё не создал повторения.

## Повторяем ввод и сравнение

[00:17:07](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1027s) Чтобы спрашивать до успешной догадки, сначала определим повторяющуюся часть: чтение числа и сравнение его с загаданным. В [00:17:09](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1029s) предлагается бесконечный цикл с явно добавленным внутри выходом.

1. Выбор загаданного числа остаётся вне повторяющегося тела, чтобы оно не менялось на протяжении всей игры.
2. Ввод и сравнение помещаются внутрь тела.
3. В [00:17:17](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1037s) определяем, что верная догадка — событие, которое должно выйти из цикла.

[00:17:22](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1042s) Цикл `while` вычисляет своё логическое условие перед каждой итерацией. Итерация — один проход по телу. Литеральное `true` всегда разрешает ещё один проход:

```csharp
int r = new Random().Next(100);
while (true)
{
    int num = ReadNumber();
    CompareGuess(num, r);
}
```

Это промежуточное структурное состояние; вспомогательная функция ввода будет дополнена позже. В [00:17:30](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1050s) завершение намеренно отложено, поэтому эта версия не останавливается даже после верной догадки.

[00:17:33](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1053s) Цикл тоже присоединяется к одному оператору. Блок объединяет несколько инструкций; скобки можно опустить для одиночного оператора, используя то же правило, что и для `if`.

[00:18:04](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1084s) Завершение тела возвращает к условию цикла, а не сразу к оператору после цикла. Пока условие истинно, тело повторяется.

## Используем break и continue в цикле угадывания

[00:18:20](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1100s) `break` выходит из ближайшего объемлющего цикла. В [00:18:40](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1120s) уточняется его назначение: первый оператор после этого цикла, а не другой оператор внутри его тела.

[00:18:55](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1135s) `continue` завершает только текущую итерацию. В `while` он переходит к проверке условия перед следующим проходом. Для `while (true)` это сразу разрешает ещё один проход. Это ранний переход управления, отличный от `return`, который выходит из функции. Смотрите [связанные сохранённые примеры break и continue](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/07_flow_control.md) и [справочник по операторам перехода в C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/statements/jump-statements).

[00:19:06](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1146s) Поставим неуспешные случаи первыми, а успешное действие последним:

```csharp
while (true)
{
    int num = ReadNumber();

    if (num > r)
    {
        Console.WriteLine("Guess lower.");
        continue;
    }
    if (num < r)
    {
        Console.WriteLine("Guess higher.");
        continue;
    }

    Console.WriteLine("Correct!");
    break;
}
Console.WriteLine("Game finished.");
```

[00:19:35](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1175s) Проверки «больше» и «меньше» определяют направление подсказки. В [00:19:40](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1180s) совпадение со случаем «меньше» исключает и равенство, и «больше»; ему нужна только своя подсказка.

[00:19:52](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1192s) Каждый `continue` не даёт оставшимся проверкам и сообщению об успехе выполниться при неверной догадке. В [00:20:06](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1206s) равенство не нужно проверять явно: целое число, которое не меньше и не больше `r`, обязательно равно ему.

[00:20:15](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1215s) Проследим три пути:

1. Высокая догадка печатает «Guess lower», затем `continue` пропускает остаток тела.
2. Низкая догадка печатает «Guess higher», затем `continue` пропускает остаток.
3. Догадка, равная загаданному числу, доходит до успеха и `break`; выполнение продолжается после цикла.

[00:20:38](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1238s) Условие цикла перевычисляется для каждого прохода, включая следующий проход, запрошенный `continue`. Здесь оно случайно оказывается константой истиной.

Если добавить внутренний цикл, из какого цикла выйдет находящийся внутри него `break`?

<details>
<summary>Ответ</summary>

Из ближайшего объемлющего цикла — из внутреннего. Выполнение продолжилось бы после этого внутреннего цикла, всё ещё находясь внутри внешнего цикла, если именно там расположен следующий оператор.

</details>

## Переносим проверку выхода в условие цикла

[00:20:41](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1241s) Исследуем другой вариант. Перенесём объявление числа за пределы цикла и уберём `break`. Объявление вводит переменную; объявление снаружи делает её имя доступным условию вне тела.

```csharp
int num;
while (true)
{
    num = ReadNumber();
    if (num > r)
    {
        Console.WriteLine("Guess lower.");
        continue;
    }
    if (num < r)
    {
        Console.WriteLine("Guess higher.");
        continue;
    }
    Console.WriteLine("Correct!");
    // break удалён
}
```

[00:20:54](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1254s) Без выхода верная догадка достигает конца тела и вызывает новый запрос. Один успех не останавливает бесконечный цикл.

[00:21:08](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1268s) Альтернатива — условие цикла, означающее «число ещё не угадано». Перенесём печать успеха после цикла:

```csharp
// Промежуточная попытка: не компилируется.
int num;
while (num != r)
{
    num = ReadNumber();
    if (num > r)
    {
        Console.WriteLine("Guess lower.");
    }
    else if (num < r)
    {
        Console.WriteLine("Guess higher.");
    }
}
Console.WriteLine("Correct!");
```

[00:21:34](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1294s) Предполагаемое поведение — спрашивать снова, пока догадка неверна, и перестать спрашивать, когда она верна. В [00:21:37](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1297s) проверка описана как перенесённая изнутри тела в выражение, вычисляемое перед каждым проходом. В [00:21:44](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1304s) цикл останавливает ложь.

[00:21:59](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1319s) Поэтому проверка выхода из тела и проверка продолжения цикла используют противоположные истинностные значения: выходим при `num == r`; продолжаем цикл при `num != r`.

[00:22:08](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1328s) Эта версия обнажает определённое присваивание: компилятор отклоняет чтение неинициализированной локальной переменной `num` в первой проверке условия. Объявление локальной переменной не присваивает ей пригодного значения.

[00:22:22](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1342s) Телу нужно выполниться хотя бы один раз, чтобы получить ввод до того, как любая проверка выхода прочитает этот ввод. Именно это требование и подталкивает к переносу проверки в конец.

## Пробуем do while и сравниваем варианты

[00:22:32](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1352s) Цикл `do ... while` вычисляет своё условие после тела. Замените начальный `while` на `do`, поставьте `while (condition)` после закрывающей скобки и добавьте требуемую точку с запятой:

```csharp
int num;
do
{
    num = ReadNumber();
    if (num > r)
    {
        Console.WriteLine("Guess lower.");
    }
    else if (num < r)
    {
        Console.WriteLine("Guess higher.");
    }
}
while (num != r);
Console.WriteLine("Correct!");
```

Первый проход присваивает `num` до того, как условие прочитает его. Последующие проходы происходят только пока условие истинно. В этой форме цикла `continue`, если его использовать, перешёл бы к условию внизу перед следующим проходом; он не обошёл бы эту проверку.

[00:22:46](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1366s) Сохранение `while` с проверкой сверху потребовало бы инициализации сентинелом: искусственного начального значения, выбранного так, чтобы оно не означало реальный ввод. Урок считает это хуже, чем выразить настоящее требование — ввод должен произойти первым.

[00:23:02](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1382s) Сравним область видимости — область, где имя переменной можно использовать. Эта форма `do ... while` обязана объявлять проверяемую переменную вне тела, чтобы условие могло получить к ней доступ. В [00:23:14](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1394s) это противопоставляется варианту `while (true)` с `break`, где догадку можно объявить внутри тела рядом с её использованиями. Это свойство данной переделки, а не правило, требующее в каждом цикле do-while выносить все переменные наружу.

[00:23:22](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1402s) Выход в этом варианте также менее заметен. В [00:23:31](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1411s) у логики сравнения две роли: внутренние ветки решают, печатать ли подсказки, а условие цикла отдельно решает, нужна ли ещё одна догадка. Когда ни одна ветка подсказки не применяется, внутри тела ничего не печатается; успех обрабатывается после цикла.

[00:23:43](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1423s) При `break` достижение конца неуспешных проверок естественно означало успех и выход. Вариант с условием переформулирует ту же логику в обратном виде — в условии продолжения. Даже если используется сохранённый логический флаг, его всё равно нужно обновлять в теле и читать в условии.

[00:24:05](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1445s) Для этого примера преподаватель рекомендует `while (true)` с явным `break` при достижении успеха. Это сохраняет догадку локальной и помещает причину выхода рядом с самим выходом. Это рекомендация по стилю, проиллюстрированная игрой; урок всё же объясняет и корректный вариант с условием, и вариант с do-while.

## Неудачный разбор — это не догадка из нуля

[00:24:17](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1457s) Возникает оставшаяся проблема с вводом: когда вспомогательная функция возвращает ноль после неудачного преобразования, вызывающий код считает этот ноль настоящей догадкой. Этот промежуточный вариант функции показывает изъян:

```csharp
static int ReadNumber()
{
    string? input = Console.ReadLine();
    if (!int.TryParse(input, out int num))
    {
        Console.WriteLine("Not a number.");
        return 0;
    }
    return num;
}
```

[00:24:28](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1468s) Сохраним различие между неудачей разбора и значением выходного параметра. Для используемой здесь перегрузки `int.TryParse(string, out int)` при неудаче возвращается `false`, а в `out`-переменную записывается ноль; предыдущее значение этой переменной **не** сохраняется. Это подтверждает [официальный контракт параметров TryParse](https://learn.microsoft.com/en-us/dotnet/api/system.int32.tryparse?view=net-10.0#system-int32-tryparse(system-string-system-int32@)).

И ноль неудачного разбора, и явный `return 0` на пути ошибки нельзя принимать за успешный ввод пользователя. Ноль входит в диапазон загаданного числа, поэтому игра не может использовать его одного как сигнал о неудаче. Именно логическое значение успеха различает успешное преобразование и неудачу.

Что произойдёт, если загаданное число равно нулю, а эта функция получит `hello`?

<details>
<summary>Ответ</summary>

Функция сообщает об ошибке разбора, но возвращает ноль. Вызывающий код, сравнивающий только возвращённое целое число, может ошибочно объявить догадку верной. Повтор запроса внутри функции не даёт некорректному тексту превратиться в догадку.

</details>

## Повторяем ввод внутри собственной функции

[00:24:44](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1484s) Определим повторяющуюся единицу операции ввода: чтение новой строки, попытка преобразования и обработка неудачи либо возврат числа. Обернём всю эту операцию в цикл. Повторение только разбора привело бы к повторным попыткам с тем же некорректным текстом.

[00:25:02](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1502s) При неудаче разбора напечатаем ошибку и воспользуемся `continue` вместо возврата нуля:

```csharp
static int ReadNumber()
{
    while (true)
    {
        Console.Write("Enter a number: ");
        string? input = Console.ReadLine();
        if (!int.TryParse(input, out int num))
        {
            Console.WriteLine("Not a number. Try again.");
            continue;
        }
        return num;
    }
}
```

1. Читаем свежий текст из консоли.
2. Выполняем разбор. Логическое возвращаемое значение сообщает об успехе; переменная `out` хранит числовой результат.
3. При неудаче сообщаем о проблеме и начинаем итерацию заново.
4. При успехе возвращаем целое число в игру угадывания.

[00:25:11](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1511s) Здесь `continue` возвращает к проверке `while (true)`, а затем к первому оператору тела. Он пропускает последующий `return num` и не означает «выполнить следующую строку».

[00:25:24](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1524s) Успешному разбору не нужен `break`. `return` выходит из всей функции и тем самым тоже останавливает её цикл. [Связанный сохранённый пример return внутри while](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/07_flow_control.md) демонстрирует тот же переход управления:

```csharp
// Успешный путь внутри цикла ReadNumber:
return num; // выходит из функции, а не только из цикла
```

[00:25:35](https://www.youtube.com/watch?v=mj9E9BhOAhU&t=1535s) Готовая структура продолжает запрашивать ввод, пока не будет введено корректное целое число. Вместе с циклом угадывания это разделяет два повторения: функция повторяет запрос для некорректного текста, а игра — для корректных, но неверных догадок.

Урок проверяет преобразование в целое число. Дополнительные правила игры, такие как отклонение целочисленных догадок вне диапазона 0–99 и обработка конца потока ввода из консоли, выходят за рамки показанной реализации.
