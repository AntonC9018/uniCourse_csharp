# Разбор того, как работают функции

[00:00:00](https://www.youtube.com/watch?v=L62Og-Y4poE&t=0s) Функция объединяет инструкции под одним именем. Этот разбор идёт по тому, что происходит при вызове этого имени: аргументы становятся локальными значениями параметров, выполняется тело, а управление возвращается вызывающему коду. Затем локальные функции связываются с методами класса и объясняется, как метод экземпляра получает свой объект.

Термины, используемые на протяжении урока:

- **Функция, объявление, тело и инструкция:** функция — это именованная работа; её объявление определяет эту работу; её тело — блок в фигурных скобках; инструкция — действие, выполняемое программой.
- **Вызов, вызывающий код, место вызова и поток управления:** вызов запускает выполнение функции; вызывающий код — это код, который вызывает функцию; место вызова — его расположение; поток управления — порядок выполнения инструкций.
- **Тип возвращаемого значения, `void`, `int` и `return`:** тип возвращаемого значения описывает результат вызова; `void` означает отсутствие результата; `int` — используемый здесь целочисленный тип; `return` завершает вызов и, для функции с возвращаемым значением, передаёт его результат.
- **Параметр, аргумент и локальная переменная:** параметр — именованный вход, объявленный в объявлении; аргумент — выражение, переданное при вызове; локальная переменная принадлежит конкретному блоку или конкретному вызову функции.
- **Объявление, инициализация и присваивание переменной:** объявление вводит переменную, инициализация задаёт её начальное значение, а присваивание записывает в неё значение.
- **Выражение, операнд, оператор и вычисление выражения:** выражение вычисляет значение; операнд — это вход оператора, такого как `+` или `*`; вычисление выполняет те действия, которые нужны, чтобы получить значение.
- **Абстракция:** имя и интерфейс позволяют вызывающему коду использовать операцию, не изучая её реализацию.
- **Область видимости и затенение:** область видимости — это область, где имя можно использовать; затенение происходит, когда внутреннее имя скрывает внешнее.
- **Позиционные и именованные аргументы:** позиционные аргументы связываются по позиции параметра; именованные используют `parameterName: expression`, чтобы указать целевой параметр.
- **Локальная функция, захват и определённое присваивание:** локальная функция объявляется внутри объемлющего исполняемого кода; захват даёт ей доступ к объемлющей переменной; определённое присваивание означает, что компилятор может доказать, что переменная имеет значение до её чтения.
- **`static`, вход по значению, доступ по ссылке и понижение компилятором:** `static` запрещает локальной функции захватывать объемлющие локальные переменные или состояние экземпляра; обычные параметры получают значения; доступ по ссылке обращается к уже существующей переменной; понижение — это преобразование компилятором удобного синтаксиса исходного кода в реализацию.
- **Класс, член, метод, поле и модификатор доступа:** класс описывает тип; член принадлежит этому типу; метод — это функция, объявленная как член; поле хранит данные; модификатор доступа, например `public`, определяет, где член может использоваться.
- **Статический класс, статический метод и статическое поле:** у статического класса нет экземпляров; у статического метода нет получателя-экземпляра; статическое поле принадлежит типу, а не отдельному объекту.
- **Верхнеуровневые операторы, точка входа, `Program`, `Main` и `args`:** верхнеуровневые операторы — это исполняемый код, написанный вне явного метода; точка входа запускает программу; `Program` и `Main` выражают общепринятые имена содержащего класса и входного метода; `args` представляет аргументы командной строки.
- **Объект, экземпляр, получатель, скрытый параметр и `this`:** объект — это экземпляр типа; получатель — объект, на котором вызывается метод; метод экземпляра концептуально получает этот объект как скрытый параметр; `this` обозначает текущий получатель.
- **Синтаксис примеров:** круглые скобки ограничивают список параметров или аргументов, фигурные — тела, точка с запятой завершает оператор, а точка выбирает член. `Console.WriteLine` печатает строку; текст в кавычках — строковый литерал; `new` создаёт объект.

Это материалы для практики, а не снимки демонстрации.

## Объединяем инструкции под одним именем

[00:00:14](https://www.youtube.com/watch?v=L62Og-Y4poE&t=14s) Начнём с двух независимых инструкций:

```csharp
Console.WriteLine("Hello World");
Console.WriteLine("Hello You");
```

**Инструкция** выполняет действие. Каждый вызов `Console.WriteLine` печатает заключённую в кавычки строку на отдельной строке. **Функция** позволяет ссылаться на эти два действия вместе, чтобы вызывающий код мог запросить всю операцию по имени.

[00:00:24](https://www.youtube.com/watch?v=L62Og-Y4poE&t=24s) Перенесём их в **объявление** функции, которое определяет операцию:

```csharp
static void Greet()
{
    Console.WriteLine("Hello World");
    Console.WriteLine("Hello You");
}
```

Читайте объявление в порядке построения:

1. Пока отложите модификатор `static` в сторону.
2. Напишите **тип возвращаемого значения** — `void`. Эта функция только выполняет команды; она не даёт значения результата для выражения.
3. Напишите имя, здесь — `Greet`.
4. [00:00:34](https://www.youtube.com/watch?v=L62Og-Y4poE&t=34s) Добавьте круглые скобки для **списка параметров**. Список пуст, потому что эта операция не требует входов.
5. Поместите инструкции внутрь фигурных скобок. Этот блок — **тело** функции.

Вывод в консоль — это эффект функции, но он не означает, что функция возвращает значение. Именно поэтому `void` здесь уместно.

## Вызываем функцию и возвращаемся к вызывающему коду

[00:00:41](https://www.youtube.com/watch?v=L62Og-Y4poE&t=41s) Запуск состояния, содержащего только объявление, не даёт никакого приветствия. Определение работы не выполняет её тело.

[00:00:55](https://www.youtube.com/watch?v=L62Og-Y4poE&t=55s) Добавьте **вызов**, написав имя функции, затем круглые скобки и точку с запятой:

```csharp
Greet();

static void Greet()
{
    Console.WriteLine("Hello World");
    Console.WriteLine("Hello You");
}
```

Скобки должны присутствовать, даже если аргументы не передаются. Код, содержащий `Greet();`, — это **вызывающий** код, а эта строка — **место вызова**.

[00:01:04](https://www.youtube.com/watch?v=L62Og-Y4poE&t=64s) **Поток управления**, то есть порядок выполнения, выглядит так:

1. Достичь вызова и войти в функцию с этим именем.
2. Выполнить её первую инструкцию, затем вторую.
3. [00:01:12](https://www.youtube.com/watch?v=L62Og-Y4poE&t=72s) Вернуться к вызывающему коду и продолжить сразу после вызова.

[00:01:20](https://www.youtube.com/watch?v=L62Og-Y4poE&t=80s) Теперь добавим второй вызов. Это важное промежуточное состояние: объявление по-прежнему одно, но запросов на его выполнение уже два.

```csharp
Greet();
Greet();
// Тот же Greet ниже.
```

[00:01:27](https://www.youtube.com/watch?v=L62Og-Y4poE&t=87s) Трассировка этих вызовов даёт:

```text
Hello World
Hello You
Hello World
Hello You
```

[00:01:32](https://www.youtube.com/watch?v=L62Og-Y4poE&t=92s) Как только после последнего вызова в вызывающем коде не осталось инструкций, программа завершается. Объявление не вызывает повторного выполнения тела только потому, что встречается в файле позже.

[00:01:40](https://www.youtube.com/watch?v=L62Og-Y4poE&t=100s) Объявление определяет отдельную вызываемую сущность; встреча её текста не является запросом выполнить её инструкции. Точнее, C# действительно относит объявление локальной функции к операторам-объявлениям, но не выполняет объявленное тело в этом месте. [Спецификация операторов C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/statements#1364-local-function-declarations).

[00:01:53](https://www.youtube.com/watch?v=L62Og-Y4poE&t=113s) Функция типа `void` может завершаться без явного `return;`. Достижение её закрывающей фигурной скобки возвращает управление вызывающему коду, как если бы в конце был подставлен `return;`. Здесь **return** означает выход из текущего вызова; возвращать значение нечего.

<details>
<summary>Не приведёт ли перенос объявления выше двух вызовов к тому, что приветствия напечатаются трижды?</summary>

Нет. Тело выполняют только два вызова. Его текстовое положение не добавляет ещё одного вызова.

</details>

## Добавляем параметры и возвращаемое значение

[00:02:19](https://www.youtube.com/watch?v=L62Og-Y4poE&t=139s) Функция может одновременно принимать входы и возвращать значение. Заменим пример без входов и типа `void` на целочисленное вычисление:

```csharp
int sum = Compute(1, 2);

static int Compute(int a, int b)
{
    int red = a + b;
    return red;
}
```

[00:02:23](https://www.youtube.com/watch?v=L62Og-Y4poE&t=143s) **Параметр** — это именованный вход, записанный в скобках объявления. Здесь параметры — `int a` и `int b`, их разделяет запятая. Для каждого вызова каждый параметр выступает как свежая **локальная переменная**, принадлежащая этому вызову.

[00:02:33](https://www.youtube.com/watch?v=L62Og-Y4poE&t=153s) **Аргумент** — это выражение, переданное в месте вызова. В `Compute(1, 2)` аргументы равны 1 и 2. Эти значения инициализируют локальные переменные параметров: `a` получает 1, а `b` — 2.

[00:02:44](https://www.youtube.com/watch?v=L62Og-Y4poE&t=164s) **Тип возвращаемого значения** теперь — `int`, целочисленный тип. Поэтому вызов может входить в **выражение**, вычисление, дающее значение. Выражение `Compute(1, 2)` даёт то целое число, которое возвращает функция. **Оператор return** `return red;` передаёт это значение и завершает текущий вызов.

## Прослеживаем один вызов от объявления до присваивания

[00:02:49](https://www.youtube.com/watch?v=L62Og-Y4poE&t=169s) Одиночная строка `int sum = Compute(1, 2);` объединяет три смысловых действия: объявление переменной, вычисление выражения и присваивание его результата. Следующее разбиение делает эти действия видимыми; это объясняющее преобразование исходного кода, а не утверждение о точных машинных инструкциях:

```csharp
int sum;                // Объявление: значение ещё не присвоено.
sum = Compute(1, 2);    // Вычисляем вызов, затем присваиваем его результат.

static int Compute(int a, int b)
{
    int red = a + b;
    return red;
}
```

[00:03:06](https://www.youtube.com/watch?v=L62Og-Y4poE&t=186s) **Объявление** переменной вводит место для хранения значения. Без инициализатора локальная переменная изначально не присвоена; «пусто» — это учебная модель, а не отдельное целое значение и не автоматический ноль. C# требует **определённого присваивания**, прежде чем локальную переменную можно прочитать. [Правила локальных переменных C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/statements#1362-local-variable-declarations).

[00:03:09](https://www.youtube.com/watch?v=L62Og-Y4poE&t=189s) **Вычисление выражения** вычисляет значение справа. Эти аргументы уже являются известными константами; в дальнейших примерах перед вызовом функции потребуется больше работы.

Проследите весь вызов:

1. [00:03:26](https://www.youtube.com/watch?v=L62Og-Y4poE&t=206s) Подготовьте значения аргументов 1 и 2. Создайте локальные переменные параметров `a` и `b`, инициализированные копиями этих значений.
2. [00:03:33](https://www.youtube.com/watch?v=L62Og-Y4poE&t=213s) Войдите в первую инструкцию `Compute`.
3. [00:03:37](https://www.youtube.com/watch?v=L62Og-Y4poE&t=217s) Объявите локальную переменную `red` и вычислите `a + b`.
4. [00:03:44](https://www.youtube.com/watch?v=L62Og-Y4poE&t=224s) Идентификаторы `a` и `b` ссылаются на переменные-параметры этого вызова, поэтому сложение использует 1 и 2.
5. [00:03:52](https://www.youtube.com/watch?v=L62Og-Y4poE&t=232s) Замените сложение его результатом, 3, и запишите 3 в `red`. Это **инициализация** `red`.
6. [00:04:02](https://www.youtube.com/watch?v=L62Og-Y4poE&t=242s) Выполните `return red;`. Вычисление `red` читает хранящееся там значение, 3; возврат этого значения делает его результатом данного вызова.
7. [00:04:27](https://www.youtube.com/watch?v=L62Og-Y4poE&t=267s) Вызывающий код теперь может продолжить работу с результатом выражения вызова. Концептуально его правая часть превратилась в обычное значение 3.
8. [00:04:47](https://www.youtube.com/watch?v=L62Og-Y4poE&t=287s) Запишите это значение в `sum`. Эта финальная запись — **присваивание**; теперь в `sum` содержится 3.

Сама локальная переменная `red` не передаётся вызывающему коду. Возвращается её текущее значение. Если бы тело изменило `red` до выполнения `return red;`, вернулось бы значение на тот момент.

<details>
<summary>Почему сохранение суммы в red не мешает вызову дать 3?</summary>

Сложение инициализирует red значением 3, а затем return читает текущее значение red и использует его как результат вызова. Выражение в return может читать переменную; повторять исходную арифметику не обязательно.

</details>

## Комбинируем результаты вызовов в большем выражении

[00:05:05](https://www.youtube.com/watch?v=L62Og-Y4poE&t=305s) Изменим вызывающий код так, чтобы он складывал результаты двух вызовов:

```csharp
int sum = Compute(1, 2) + Compute(2, 3);

static int Compute(int a, int b)
{
    int red = a + b;
    return red;
}
```

**Оператор** вроде `+` нуждается в значениях своих **операндов**, то есть выражений по обе стороны. Поэтому каждый вызов должен дать своё значение, прежде чем внешнее сложение сможет завершиться.

1. Вычислите первый вызов: он возвращает 3.
2. Вычислите второй вызов, используя его собственные локальные переменные параметров: он возвращает 5.
3. [00:05:21](https://www.youtube.com/watch?v=L62Og-Y4poE&t=321s) Вычислите `3 + 5`, получив 8.
4. Присвойте итоговое значение 8 переменной `sum`.

[00:05:35](https://www.youtube.com/watch?v=L62Og-Y4poE&t=335s) Для этих константных аргументов и этого тела присваивание `sum` значения всего выражения даёт тот же конечный результат, что и присваивание 8 напрямую. Это не означает, что замена произвольных вызовов константами сохраняет всё поведение программы.

[00:05:40](https://www.youtube.com/watch?v=L62Og-Y4poE&t=340s) Функции становятся полезными, когда значение не зафиксировано заранее: оно может прийти из ввода пользователя, ответа сети или файла. [00:05:52](https://www.youtube.com/watch?v=L62Og-Y4poE&t=352s) Их тела могут делать что-то большее, чем простое сложение. Имя предоставляет **абстракцию**: вызывающий код запрашивает операцию через её интерфейс, не видя реализации. Содержательное имя помогает читателю понять этот запрос.

В последующей демонстрации эта операция называется `SumOperation`; в следующем примере используется это имя, а простое сложение в теле сохраняется, чтобы шаги вычисления оставались на виду.

## Вычисляем аргументы до входа в функцию

[00:06:04](https://www.youtube.com/watch?v=L62Og-Y4poE&t=364s) Большое выражение вычисляется всё так же: через получение значений содержащихся в нём меньших выражений. Замена константы переменной или арифметическим аргументом добавляет работы до вызова, но не меняет смысла вызова.

[00:06:30](https://www.youtube.com/watch?v=L62Og-Y4poE&t=390s) Эта упрощённая реконструкция сохраняет последовательность и итоговые значения записи:

```csharp
int a = 9;
int sum = SumOperation(1, a * 2 + 10) + SumOperation(3, a);

static int SumOperation(int a, int b)
{
    int red = a + b;
    return red;
}
```

**Аргумент** — это выражение в скобках вызова. Его значение должно быть получено до начала работы тела функции. [00:06:41](https://www.youtube.com/watch?v=L62Og-Y4poE&t=401s) Для первого вызова 1 уже является значением. Второй аргумент требует больше вычислений.

[00:06:49](https://www.youtube.com/watch?v=L62Og-Y4poE&t=409s) Выражение-переменная вроде `a` даёт значение, хранящееся в этой переменной. Обычный целочисленный параметр не получает ни имя переменной, ни невычисленный текст исходного кода.

[00:06:57](https://www.youtube.com/watch?v=L62Og-Y4poE&t=417s) Аргументом может быть и сложное выражение. Выражение вроде `a * 10` корректно; в разбираемом здесь состоянии используется `a * 2 + 10`. [00:07:04](https://www.youtube.com/watch?v=L62Og-Y4poE&t=424s) В обоих случаях вычисление сначала сводит выражение к одному значению, которое инициализирует соответствующую локальную переменную параметра.

Проследите разбираемое состояние по порядку:

1. [00:07:21](https://www.youtube.com/watch?v=L62Og-Y4poE&t=441s) Второй аргумент требует умножения и сложения. Чтение `a` у вызывающего кода даёт 9.
2. [00:07:35](https://www.youtube.com/watch?v=L62Og-Y4poE&t=455s) Вычислите `9 * 2` и получите 18, затем `18 + 10` и получите 28.
3. Вызовите `SumOperation(1, 28)`. Её собственные локальные переменные параметров получат 1 и 28; тело вернёт 29.
4. [00:07:51](https://www.youtube.com/watch?v=L62Og-Y4poE&t=471s) Вычислите аргументы второго вызова: 3 и `a` вызывающего кода, значение которого всё ещё равно 9. `SumOperation(3, 9)` возвращает 12.
5. Вычислите внешнее сложение `29 + 12`, получив 41. Запишите 41 в `sum`.

Эта процедура — **вычисление выражения**. Держите её уровни раздельно: 28 — вычисленный аргумент, 29 — результат первого вызова, 41 — результат всего выражения.

<details>
<summary>Получает ли функция выражение a * 2 + 10 или число 28?</summary>

Она получает 28 во второй параметр. Вызывающий код вычисляет выражение-аргумент до начала работы тела.

</details>

## Разделяем области видимости и именуем аргументы

[00:08:11](https://www.youtube.com/watch?v=L62Og-Y4poE&t=491s) **Область видимости**, её также называют зоной видимости, определяет, где имя можно использовать. `a` вызывающего кода и параметр с именем `a` — это разные переменные. Одинаковое написание не делает их одним и тем же местом хранения.

В этой сокращённой версии предыдущего состояния вызов передаёт параметру значение, а не разделяет целочисленную переменную вызывающего кода:

```csharp
int a = 9;
int result = SumOperation(1, a);

static int SumOperation(int a, int b)
{
    return a + b;
}
```

`a` вызывающего кода передаёт 9 второму параметру, `b`. Внутри тела имя `a` означает первый параметр, значение которого равно 1.

[00:08:24](https://www.youtube.com/watch?v=L62Og-Y4poE&t=504s) **Позиционные аргументы** связываются по позиции в объявленном списке параметров. **Именованные аргументы** указывают цель именем параметра и двоеточием:

```csharp
SumOperation(1, 9);        // Позиционные: a = 1, b = 9.
SumOperation(a: 1, b: 9);  // Именованные: то же связывание.
SumOperation(b: 9, a: 1);  // Именованные: то же связывание, порядок в исходнике обратный.
```

[00:08:38](https://www.youtube.com/watch?v=L62Og-Y4poE&t=518s) Именование аргументов избавляет от необходимости воспроизводить порядок параметров в месте вызова. [00:08:52](https://www.youtube.com/watch?v=L62Og-Y4poE&t=532s) Явное имя управляет связыванием: запись `b: 9` по-прежнему передаёт 9 в `b`, второй объявленный параметр. Первый записанный аргумент не становится параметром `a` только из-за того, что он записан первым.

Формулировки записи «первый» и «второй» следует читать с учётом этого различия. Порядок связывания и порядок вычисления — разные вещи: выражения-аргументы вычисляются в порядке записи, а имена определяют их целевые параметры. [Правила именованных аргументов Microsoft](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/named-and-optional-arguments).

## Делаем локальные зависимости явными с помощью static

[00:09:01](https://www.youtube.com/watch?v=L62Og-Y4poE&t=541s) Пока что объявление — это **локальная функция**, функция, вложенная в объемлющий исполняемый код. **Статическая локальная функция** не может **захватывать**, то есть напрямую использовать, локальные переменные объемлющего блока или состояние экземпляра. Её обычные локальные входы должны передаваться явно.

```csharp
int outside = 9;
int sum = Add(outside, 1);

static int Add(int a, int b)
{
    return a + b;
}
```

В вызове наглядно видно, что передаётся значение `outside`. Попытка прочитать `outside` напрямую внутри этой статической локальной функции отклоняется. Значит, `static` помогает держать зависимости от объемлющих локальных переменных видимыми в списке аргументов, а не прячет их. [Правила статических локальных функций](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/local-functions).

[00:09:13](https://www.youtube.com/watch?v=L62Og-Y4poE&t=553s) Удаление `static` разрешает доступ к объемлющим локальным переменным, но компилятор всё равно должен убедиться, что захваченная переменная присвоена до вызова, который её читает. Например, это объясняющее промежуточное состояние некорректно:

```csharp
int sum;
sum = ReadSum();       // Некорректно: ReadSum прочитал бы неприсвоенную sum.

int ReadSum()
{
    return sum;
}
```

Проблема — это ошибка **определённого присваивания**, обнаруживаемая во время компиляции, а не разрешение прочитать неинициализированную локальную переменную.

[00:09:27](https://www.youtube.com/watch?v=L62Og-Y4poE&t=567s) Инициализируйте объемлющую переменную до первого вызова, который её читает:

```csharp
int sum = 0;
sum = ReadSum();       // Корректно: захватываемая sum имеет значение.

int ReadSum()
{
    return sum;
}
```

Теперь захват допустим: `ReadSum` читает уже существующую `sum`. Определённое присваивание касается того, доступно ли для чтения значение, а объявление функции по-прежнему может встречаться позже в файле.

<details>
<summary>Почему более раннее объявление ReadSum не исправляет первый пример?</summary>

Объявление не инициализирует sum. До вызова, который читает sum, значение должно быть присвоено sum.

</details>

## Снимаем затенение разными именами

[00:09:42](https://www.youtube.com/watch?v=L62Og-Y4poE&t=582s) Параметр локальной функции может иметь то же имя, что и объемлющая локальная переменная, оставаясь при этом отдельной сущностью. **Затенение** означает, что при разрешении идентификатора приоритет у внутреннего имени:

```csharp
int a = 9;
int result = SumOperation(1, 2);  // Результат: 3.

int SumOperation(int a, int b)
{
    return a + b;                // Читает параметры 1 и 2.
}
```

[00:09:50](https://www.youtube.com/watch?v=L62Og-Y4poE&t=590s) Внутри этого тела простое имя `a` ссылается на параметр, поэтому оно не может выбрать внешнюю `a`. Внешняя переменная по-прежнему существует — она скрыта этим именем.

[00:10:02](https://www.youtube.com/watch?v=L62Og-Y4poE&t=602s) В записи сообщение редактора описывается как «a — это локальная переменная с таким же именем». Сохраняйте различие между сокрытием имени и настоящей ошибкой компилятора: начиная с C# 8 параметр локальной функции законно может затенять объемлющую локальную переменную. Описания редактором сущности с тем же именем недостаточно, чтобы утверждать, что этот корректный пример не компилируется. [Правила затенения в локальных функциях](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/local-functions).

[00:10:08](https://www.youtube.com/watch?v=L62Og-Y4poE&t=608s) Поиск имён выбирает параметр. [00:10:23](https://www.youtube.com/watch?v=L62Og-Y4poE&t=623s) Дайте одной из переменных отдельное имя, например `a1`, когда нужно различать оба значения:

```csharp
int a = 9;
int result = SumOperation(1, 2);  // Эта версия возвращает 12.

int SumOperation(int a1, int b)
{
    return a1 + b + a;           // Параметр a1, параметр b, захваченная внешняя a.
}
```

Этот объясняющий вариант делает различие явным: 1 + 2 + 9 равно 12. Одного переименования недостаточно, чтобы добавить зависимость; использование внешней `a` здесь намеренно.

[00:10:32](https://www.youtube.com/watch?v=L62Og-Y4poE&t=632s) Если функции нужны только значения её параметров, оставьте чистое сложение в теле и верните `static`. Это предотвращает случайный захват:

```csharp
static int SumOperation(int a1, int b)
{
    return a1 + b;
}
```

## Понимаем захват как доступ к общей переменной

[00:10:44](https://www.youtube.com/watch?v=L62Og-Y4poE&t=644s) Уберите первый параметр и вместо этого читайте внешнюю переменную. Результат функции теперь зависит от окружающего состояния, хотя это состояние отсутствует в её явном списке аргументов:

```csharp
int a = 9;
int result = SumOperation(2); // 11.

int SumOperation(int b)
{
    return a + b;
}
```

Здесь **захват** — это доступ к объемлющей переменной `a`, а не создание постороннего параметра со скопированным целым числом.

[00:10:56](https://www.youtube.com/watch?v=L62Og-Y4poE&t=656s) В записи **понижение компилятором** объясняется с помощью дополнительного параметра-ссылки. Понижение — это преобразование реализации, выполняемое компилятором. Ниже приведён концептуальный эквивалент, а не точный сгенерированный C# и не обязательная правка исходного кода:

```csharp
int a = 9;
int result = SumOperationLowered(ref a, 2);

static int SumOperationLowered(ref int capturedA, int b)
{
    return capturedA + b;
}
```

В этой модели `ref` даёт **доступ по ссылке** к уже существующей переменной. Обычный целочисленный параметр получает значение, а модель со ссылкой может добраться до памяти вызывающего кода.

[00:11:07](https://www.youtube.com/watch?v=L62Og-Y4poE&t=667s) Общая переменная важна потому, что захватывающая функция может присваивать ей значение. Копирование её значения в независимое целое число потеряло бы это обновление. Чтобы показать разницу, расширим исходный пример с захватом:

```csharp
int a = 9;
Increase();
Console.WriteLine(a); // 10.

void Increase()
{
    a = a + 1;
}
```

[00:11:20](https://www.youtube.com/watch?v=L62Og-Y4poE&t=680s) Вы продолжаете писать исходный вызов локальной функции; доступ к захвату обеспечивает компилятор. [00:11:32](https://www.youtube.com/watch?v=L62Og-Y4poE&t=692s) Концептуально он может поместить тело во вспомогательный метод с дополнительным доступом к захваченному состоянию, вместо того чтобы вспомогательный метод волшебным образом доставал бы объемлющий блок исходного кода. Не гарантируется, что для каждой переменной будет сгенерирован буквальный параметр `ref` или что на уровне исходного кода появится статическая локальная функция. Существенное наблюдаемое поведение — общий доступ к захваченной переменной. [Объяснение реализации захвата от Microsoft](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/local-functions).

В записи прямо отмечена неопределённость возможных оптимизаций с копированием. Они не нужны для рассуждения о результатах программы, а точная раскладка генерируемой памяти выходит за рамки этого разбора.

## Переносим функцию в класс

[00:11:45](https://www.youtube.com/watch?v=L62Og-Y4poE&t=705s) Функция, объявленная как **член** класса, называется **методом**. Член принадлежит типу, а не является локальным для объемлющего исполняемого блока.

[00:11:57](https://www.youtube.com/watch?v=L62Og-Y4poE&t=717s) Перенесём функцию сложения в статический класс и дадим методу модификатор доступа `public`:

```csharp
int sum = Functions.SumOperation(1, 2);

static class Functions
{
    public static int SumOperation(int a, int b)
    {
        return a + b;
    }
}
```

Проследите изменения:

1. Поместите объявление внутрь тела класса.
2. Сохраните `static`: у **статического класса** нет экземпляров, и он может содержать только статические методы.
3. Добавьте `public` — **модификатор доступа**, позволяющий использовать метод за пределами этого класса. Метод класса без модификатора доступа по умолчанию является закрытым; здесь выбран `public`, а это не единственный уровень доступа, поддерживаемый C#.
4. [00:12:08](https://www.youtube.com/watch?v=L62Og-Y4poE&t=728s) Обновите вызывающий код до `Functions.SumOperation(1, 2)`. Имя класса, точка и имя метода определяют операцию.

[00:12:14](https://www.youtube.com/watch?v=L62Og-Y4poE&t=734s) У **статического метода** нет объекта-получателя, и его часто вольно называют функцией. [00:12:20](https://www.youtube.com/watch?v=L62Og-Y4poE&t=740s) Он всё же может читать **статические поля**, то есть данные, принадлежащие типу, поэтому `static` не означает, что результат зависит только от явных аргументов. Для этого примера это цель проектирования.

[00:12:34](https://www.youtube.com/watch?v=L62Og-Y4poE&t=754s) Предпочитайте параметры статическим переменным, когда передаёте информацию в операцию. Параметры делают поток данных видимым там, где написан вызов, вместо того чтобы заставлять читателя искать общее состояние.

## Узнаём точку входа за верхнеуровневым кодом

[00:12:43](https://www.youtube.com/watch?v=L62Og-Y4poE&t=763s) Исполняемые строки вне явно написанного метода — это **верхнеуровневые операторы**. Компилятор предоставляет содержащий их тип `Program` и статическую **точку входа**, метод, с которого начинается выполнение. В записи это показано на знакомой модели `Main`.

Для простого вызова выше эквивалентную структуру, написанную вручную, можно изобразить так; это учебная модель, а не точное сгенерированное имя метода и не его доступность:

```csharp
class Program
{
    public static void Main(string[] args)
    {
        int sum = Functions.SumOperation(1, 2);
    }
}
// Класс Functions из предыдущего раздела предоставляет SumOperation.
```

[00:12:59](https://www.youtube.com/watch?v=L62Og-Y4poE&t=779s) `Main` по соглашению обозначает явно написанный входной метод, а `string[] args` представляет массив строк командной строки. При использовании верхнеуровневых операторов писать эту обёртку не обязательно. Урок откладывает смысл целочисленного результата точки входа и не разбирает обработку аргументов командной строки.

[00:13:08](https://www.youtube.com/watch?v=L62Og-Y4poE&t=788s) Сгенерированный класс `Program` нестатический, а его входной метод — статический. Нестатический класс может содержать статические методы; создавать экземпляр `Program` для выполнения точки входа не требуется.

Точность важна: сгенерированный входной метод не обязан буквально называться `Main` или быть объявленным `public`. Его сигнатура зависит от верхнеуровневого кода. Для синхронных примеров здесь без возвращаемого значения точки входа модель — это входной метод типа `void`; целочисленный return на верхнем уровне меняет тип результата на `int`. Целочисленная обёртка в записи поэтому является иллюстрацией, а не универсальным выводом компилятора. [Правила верхнеуровневой точки входа Microsoft](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/program-structure/top-level-statements).

## Даём методу экземпляра его объект

[00:13:21](https://www.youtube.com/watch?v=L62Og-Y4poE&t=801s) **Метод экземпляра** выполняется для конкретного объекта. В этом разборе на основе классов методы экземпляра требуют нестатического класса; статические классы не могут их содержать. [00:13:25](https://www.youtube.com/watch?v=L62Og-Y4poE&t=805s) Статические методы тоже могут объявляться в нестатических классах.

[00:13:31](https://www.youtube.com/watch?v=L62Og-Y4poE&t=811s) В отличие от статического метода, метод экземпляра может читать поля своего получателя. **Поле** — это данные, хранящиеся в объекте; **получатель** — конкретный объект, на котором вызывается метод. Думайте о получателе как о дополнительном **скрытом параметре**: вызывающий код передаёт его, не перечисляя среди явных аргументов.

[00:13:49](https://www.youtube.com/watch?v=L62Og-Y4poE&t=829s) Создайте объект, задайте его поле, затем вызовите его метод экземпляра. Эта короткая реконструкция использует `Animal` с полем `H`:

```csharp
Animal animal = new Animal();
animal.H = 7;
int result = animal.AddToH(2); // 9.

class Animal
{
    public int H;

    public int AddToH(int amount)
    {
        return H + amount;
    }
}
```

1. `new Animal()` создаёт **объект**, экземпляр типа `Animal`.
2. Сохраните его ссылку в `animal`.
3. Присвойте 7 полю `H` этого объекта.
4. [00:14:07](https://www.youtube.com/watch?v=L62Og-Y4poE&t=847s) Напишите `animal.AddToH(2)`: выражение-получатель, точка, имя метода и явные аргументы.
5. Получатель концептуально передаётся как скрытый объектный параметр. Явный аргумент 2 инициализирует `amount`; чтение `H` у этого получателя даёт 7, поэтому результат равен 9.

[00:13:39](https://www.youtube.com/watch?v=L62Og-Y4poE&t=819s) Скрытый параметр представляет ссылку на объект, а не копию всего `Animal`. Поэтому разные вызовы могут получать разные объекты, хотя выполняют одно и то же тело метода.

## Используем выражения-получатели и this

[00:14:23](https://www.youtube.com/watch?v=L62Og-Y4poE&t=863s) Получателем не обязательно должно быть голое имя переменной. Это может быть любое выражение, дающее подходящую ссылку на объект. [00:14:31](https://www.youtube.com/watch?v=L62Og-Y4poE&t=871s) Только что созданный объект можно использовать сразу:

```csharp
int result = new Animal().AddToH(2);
```

Здесь используется то же объявление `Animal`, что и в предыдущем состоянии. [00:14:40](https://www.youtube.com/watch?v=L62Og-Y4poE&t=880s) Создание объекта внутри вызова и отсутствие ссылки на него после вызова законны. Для этого упрощённого класса целочисленное поле `H` у только что созданного объекта изначально равно 0, поэтому это выражение возвращает 2; явно неинициализированная локальная целочисленная переменная, о которой шла речь раньше, подчиняется другим правилам.

[00:14:46](https://www.youtube.com/watch?v=L62Og-Y4poE&t=886s) Внутри метода экземпляра обращение к полю без уточнения, например `H`, читает поле, принадлежащее получателю именно этого вызова. Это не значит произвольное поле какого-то другого `Animal`.

[00:15:00](https://www.youtube.com/watch?v=L62Og-Y4poE&t=900s) Скрытый получатель доступен под ключевым словом **`this`**, означающим текущий объект. Сделаем эту связь явной, изменив тело:

```csharp
public int AddToH(int amount)
{
    return this.H + amount;
}
```

Здесь `H` и `this.H` выбирают одно и то же поле текущего получателя. Точка выбирает поле у этого объекта.

[00:15:14](https://www.youtube.com/watch?v=L62Og-Y4poE&t=914s) На верхнем уровне вызывающего кода используйте то выражение-объект, которое у вас действительно есть, например `animal.H`; там нет текущего экземпляра, который можно назвать через `this`. Внутри метода `this.H` относится к объекту, переданному для данного вызова. Это не означает навсегда переменную вызывающего кода с именем `animal`.

<details>
<summary>Если у двух объектов Animal разные значения H, какое прочитает AddToH?</summary>

Он читает H у получателя вызова. Для `first.AddToH(2)` это `first`, для `second.AddToH(2)` — `second`. Одно и то же тело выполняется с разным скрытым получателем.

</details>
