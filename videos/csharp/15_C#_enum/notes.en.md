# Purpose and vocabulary

[00:00:00](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=0s) Build a reliable representation of a bomb's discrete choices, moving from text to numbers, named constants, and finally separate enum types. In the assignment, one player reads a manual while another inspects the bomb and follows instructions to decide which wire to cut. [00:00:18](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=18s) The bomb has one of three portraits—Lenin, George Washington, or Hitler—together with a wire color, a toggle state, and a dial value. This lesson develops the representation of portraits and lamp colors; it does not implement the complete defusal game.

The terms used along the way are:

- **Variable and assignment:** a variable stores a current value; assignment evaluates an expression and stores its result. A later assignment replaces the earlier value.
- **Type, string, and integer:** a type describes a value's permitted uses. A `string` represents text; `int` represents a whole number in a fixed range.
- **Equality and condition:** `==` compares values and produces `true` or `false`; an `if` condition chooses whether a block executes.
- **Compile time and runtime:** compile time is when source is checked and translated; runtime is when the program executes. A compile error prevents the build, a runtime failure occurs during execution, and a logic error can produce wrong behavior without either.
- **Function, argument, parameter, and signature:** a function performs an operation. An argument is the value supplied by the caller; a parameter is the function's local name for that input. The signature describes the function's name and parameter types; its declaration also states the return type.
- **Expression, evaluation, and return:** an expression produces a value. Evaluation computes it, and `return` ends a function call and supplies its result.
- **Block and scope:** braces `{ }` group statements into a block; scope determines where a declared name can be used.
- **Constant and magic number:** a constant is a named value fixed at compile time. A magic number is a numeric literal whose application meaning is hidden.
- **Switch, case, and default:** a `switch` statement selects a branch for one value. A `case` labels a matching branch; `default` handles values without a matching case.
- **Enumeration, member, and underlying value:** an enumeration (`enum`) is a distinct value type with named constants called members. Each member has an underlying numeric value; the default underlying type is `int`.
- **Abstraction and type contract:** abstraction lets readers work with meaningful names while hiding representation details. A type contract tells callers which category of value a function accepts.
- **Cast:** explicit conversion written as `(TargetType)expression`; converting a number to an enum does not check whether a member has that number.
- **Assertion, diagnostic, and exception:** an assertion checks an assumption during development. `Debug.Assert` and `Debug.Fail` report diagnostics; an exception interrupts normal execution and can terminate the program when unhandled.
- **Array and Count sentinel:** an array stores a fixed number of entries. A sentinel is a special marker; a final `Count` member can mark the number of real choices under a consecutive, zero-based numbering convention.

It communicates the intended named choices, but it does not prove that every possible `Portrait` value has a declared name. That limitation explains the next two demonstrations.

# Keep the default branch

[00:14:33](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=873s) The switch still needs its **default** branch, which handles inputs without a matching case.

[00:14:47](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=887s) Add another enum member without updating the conversion. [00:15:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=903s) The new member is now a legal argument to a function taking `Portrait`, but the function has no branch for it.

Reconstructed [extension-with-missing-case state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=887s); `AdditionalPortrait` is a descriptive placeholder for the added choice:

```csharp
enum Portrait
{
    Lenin = 0,
    GeorgeWashington = 1,
    Hitler = 2,
    AdditionalPortrait = 3
}

// The earlier switch still has only three named cases.
Console.WriteLine(PortraitToString(Portrait.AdditionalPortrait));
```

[00:15:09](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=909s) The unhandled value reaches the diagnostic fallback. In the demonstrated development environment this exposes the missing case, directing attention to the conversion function. With the video's debug-diagnostic-plus-empty-return form, the outcome is diagnostic-dependent and can become an empty label when `DEBUG` is absent. With the exception alternative, the missing case interrupts execution in every build.

Extending an enum and extending each exhaustive operation on it are separate changes. The type allows the new argument; it does not automatically write the missing behavior.

[00:16:10](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=970s) A member name is an internal identifier, not necessarily suitable text for the player. # Understand numeric storage and runtime types

[00:17:20](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1040s) A member such as `Portrait.Hitler` is a constant with the numeric backing value 2. Its value can be embedded in compiled code; a variable of this enum stores the numeric payload rather than the text `"Hitler"`.

Reconstructed [numeric-comparison video state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1040s):

```csharp
Portrait portrait = Portrait.Hitler;
if (portrait == Portrait.Hitler)
{
    Console.WriteLine("Matched");
}
```

[00:17:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1052s) The recording describes the enum as a compile-time concept and the stored value as a number. Keep the numeric-storage insight, but correct the claim that the enum type disappears at runtime: .NET retains enum type information and member names. Enum storage and numeric operations do not require storing strings.

[00:17:40](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1060s) That retained information also explains name-based formatting. [00:17:44](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1064s) Printing the enum and printing an explicit integer conversion can produce different representations of the same numeric payload. The name is not exclusively chosen by the compiler; runtime enum formatting can resolve it. See the [System.Enum type reference](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/enum#the-systemenum-type-and-enum-constraint) and [Enum.ToString](https://learn.microsoft.com/en-us/dotnet/api/system.enum.tostring).

[00:17:55](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1075s) The “no string conversion” explanation belongs to the equality check, not to producing printed text. Comparing two `Portrait` values compares their numeric values. [00:18:22](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1102s) Meaningful member names make these numbers self-documenting.

[00:18:23](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1103s) A constant contributes its fixed numeric value to that comparison. [00:18:24](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1104s) When both values are 2, equality is true and the guarded block runs. No comparison of the strings `"Hitler"` occurs.

# Cast without assuming validation

[00:18:27](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1107s) A **cast** explicitly converts an expression to a target type. Numbers can be cast to an enum even when no member declares that value.

Reconstructed [direct-cast state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1110s):

```csharp
Portrait portrait = (Portrait)2;
Console.WriteLine(portrait == Portrait.Hitler);  // True
```

[00:18:30](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1110s) Here the literal 2 produces the same enum value as `Portrait.Hitler`. [00:18:33](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1113s) The cast can act directly on a literal or another expression; no intermediate integer variable is required.

[00:18:35](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1115s) This conversion performs no **membership validation**, meaning it does not check the member list. It converts the numeric value to the enum type. [00:18:37](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1117s) A number absent from that list can still be stored.

Reconstructed [unnamed-value state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1172s):

```csharp
Portrait portrait = (Portrait)123;
Console.WriteLine(portrait == Portrait.Hitler);  // False
Console.WriteLine(PortraitToString(portrait));   // Reaches default
```

[00:19:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1172s) The cast produces no compile-time complaint merely because 123 is unnamed. [00:19:40](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1180s) In the recorded run, the assignment succeeds and failure appears later when the value reaches the programmed check/failure path. Equality itself does not crash: it produces a Boolean result. A diagnostic or exception in the surrounding logic is the source of failure.

[00:19:41](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1181s) A `Portrait` value can use any value representable by its underlying `int`; the named members are not a closed, automatically validated set. [00:19:45](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1185s) This is why numeric casting bypasses the assumption that only known portraits arrive.

[00:19:45](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1185s) The reverse cast extracts the underlying integer:

Reconstructed [reverse-conversion state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1185s):

```csharp
int code = (int)Portrait.Hitler;
Console.WriteLine(code);          // 2
```

The [enum conversion reference](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/enum#conversions) confirms both conversion directions and unnamed values.

<details>
<summary>Does a parameter of type Portrait make the default branch unnecessary?</summary>

No. A caller can supply an unnamed value through an explicit cast. A later named member can also lack a matching branch. The type prevents accidental category mixing, but does not validate completeness.

</details>

# Evaluate arithmetic through integer conversions

[00:19:51](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1191s) Cast enum values to `int` to expose their numeric values, then perform ordinary integer arithmetic. **Evaluation** still means computing each expression before using its result.

Reconstructed [multiplication demonstration](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1191s):

```csharp
int hitlerCode = (int)Portrait.Hitler;
Console.WriteLine(hitlerCode);    // 2

int product = (int)Portrait.Lenin * (int)Portrait.GeorgeWashington;
Console.WriteLine(product);       // 0
```

[00:20:01](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1201s) Predict the output by following the subexpressions, not by reading the names as text:

1. [00:20:09](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1209s) Multiplication needs the values of both operand expressions. In C#, these operand expressions are evaluated left to right.
2. [00:20:57](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1257s) `Portrait.Lenin` has underlying value 0.
3. [00:21:05](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1265s) Casting it to `int` yields 0.
4. [00:21:11](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1271s) `Portrait.GeorgeWashington` has underlying value 1, so its cast yields 1.
5. [00:21:12](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1272s) Multiply the computed operands: 0 × 1 = 0.

[00:20:55](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1255s) The recorded result is zero, as this evaluation predicts.

[00:21:21](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1281s) The numeric backing value of `Portrait.Hitler` is 2, but do not generalize that to an implicit conversion of every enum expression to `int`. Ordinary numeric extraction here uses `(int)`. [00:21:23](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1283s) A computed integer result can then be cast back to `Portrait` if an enum-typed result is needed.

Reconstructed [integer-result conversion](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1283s):

```csharp
int product = (int)Portrait.Lenin * (int)Portrait.GeorgeWashington;
Portrait result = (Portrait)product;    // Underlying value 0
```

[00:21:29](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1289s) A broader modular-arithmetic example is deliberately skipped. The lesson requires the integer-conversion technique, not an implementation of cycling through values.

[00:21:37](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1297s) The takeaway is numeric representation. [00:21:56](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1316s) The statement that “every integer operation works on enums” needs a qualification: arbitrary integer operations can be performed after conversion, but enum expressions do not directly support all integer operators. For example, multiplication of two enum operands requires converting them first. The [enum operations specification](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/enums#206-enum-values-and-operations) lists the operators supported directly.

<details>
<summary>Does casting the product back to Portrait verify that the result is a declared portrait?</summary>

No. The cast only converts the number. Here 0 happens to correspond to Lenin; a different calculation could produce an unnamed value.

</details>

# Let omitted values follow the previous member

[00:22:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1323s) Members can omit their numeric initializers. Each omitted member receives the immediately preceding member's value plus one.

Reconstructed [omitted-value state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1323s):

```csharp
enum Color
{
    Blue = 0,
    White,       // 1
    Red          // 2
}
```

[00:22:10](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1330s) This recreates the explicit 0, 1, 2 sequence. [00:22:17](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1337s) Setting only Blue to 0 is enough to give White and Red values 1 and 2. [00:22:22](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1342s) If the first member also omits its initializer, it defaults to zero.

[00:22:24](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1344s) An explicit initializer starts a new sequence. The transcript's compressed wording about assigning 5 and getting 6 must not be read as changing the explicitly assigned member: the member written `= 5` is 5; the next omitted member is 6.

Reconstructed [explicit-jump demonstration](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1344s):

```csharp
enum Color
{
    Blue,        // 0
    White = 5,   // 5
    Red          // 6
}
```

[00:22:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1352s) Red receives 6 because its immediately preceding member has value 5. The rule is previous member plus one, not the number of members and not a rule that overrides an explicit assignment. See the [enum member specification](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/enums#204-enum-members).

# Use a Count sentinel to size an array

[00:22:40](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1360s) Restore the consecutive zero-based sequence, then append a final omitted member named `Count`. This is a **sentinel**, a marker rather than an actual lamp color.

Reconstructed [three-color Count state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1360s):

```csharp
enum Color
{
    Blue = 0,
    White,       // 1
    Red,         // 2
    Count        // 3
}
```

[00:22:51](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1371s) In the demonstrated result, Count evaluates to 3. [00:23:01](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1381s) That matches the three real colors preceding it.

[00:23:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1383s) Count is derived from the declaration's numeric sequence rather than a separately typed size. [00:23:09](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1389s) Insert another real color before the sentinel and it becomes 4.

Reconstructed [added-color state](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1389s):

```csharp
enum Color
{
    Blue = 0,
    White,
    Red,
    Yellow,      // 3
    Count        // 4
}
```

[00:23:19](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1399s) Count works because each omitted value depends on its predecessor. [00:23:21](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1401s) It does not inspect an array, reflect over members, or automatically count declarations. The value equals the number of real choices only because they start at zero, are consecutive, and precede the sentinel. Gaps, duplicate backing values, a nonzero start, or moving Count can break that equality. Count is itself a declared enum member, so application code must still distinguish it from a usable color.

[00:23:31](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1411s) Replace the hardcoded array size with the sentinel's numeric value. An **array** has a fixed number of entries when created. The desired size here is one entry per real color.

Reconstructed [array-sizing change](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1411s):

```csharp
// Before: a literal must be maintained separately.
int[] entries = new int[3];

// After: use the zero-based consecutive color convention.
int[] entriesByColor = new int[(int)Color.Count];
```

[00:23:38](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1418s) With this convention, adding Yellow requires one new declaration line; the consuming allocation does not need its own size edit. [00:23:55](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1435s) This pattern is useful when an array needs one entry for each enum choice. [00:24:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1443s) Passing the Count value as the array length creates exactly that many entries: three before Yellow is inserted, four afterward. The `(int)` cast makes the size an integer. In `new int[length]`, `new` creates an integer array and the square brackets specify its length; `int[]` is the variable's array type.

<details>
<summary>If White is explicitly assigned 5, can Count still be trusted as the number of colors?</summary>

No. Omitted values continue from 5, so the sentinel follows the numeric sequence rather than counting names. Restore consecutive zero-based values before using this sizing convention.

</details>
