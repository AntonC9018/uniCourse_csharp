# Named-argument binding: the recording's "first/second parameter" wording is about written order, not binding

- Ledger TP-048 (transcript 531959–541150ms) states that the call-site order decides binding, "so a value written first becomes the first parameter even if it is listed second in the signature". The transcript at t=534s says the same in Russian ("это теперь передастся как первый параметр").
- That is imprecise C#: with named syntax the explicit name controls the target. `SumOperation(b: 9, a: 1)` supplies 9 to `b` (the second declared parameter), not to `a`. Established during `english_authoring` (run 292, codex session `01a11ac4-93c7-7f23-8b39-147262d45d5f`) and confirmed by `factual_verification` (run 295, session `ses_ee52f49d6ffet9R7k0ozsh3F0N`), which compiled all three call forms — positional, in-order named, reversed named — and got 10 each time.
- The note handles this at 00:08:52 by stating the correction explicitly and separating two concepts the recording blurs: argument expressions are evaluated in written order, while names determine target parameters.
