# Field masks

A field mask turns a choice of fields into data. This lesson starts with a client and a printer, makes printing configurable, reuses masks to describe differences between clients, and finally stores the flags in one integer. Follow the changes in that order: the bit operations solve a maintenance problem established by the earlier boolean version.

The terms used along the way are:

- **Domain model**: a type representing an entity from the task, with fields describing that entity. An **enum** gives names to numeric values, such as client groups or field identifiers.
- **`sealed` and `required`**: `sealed` prevents inheritance; `required` requires member initialization when constructing an object. Initialization and non-null validation are separate concerns.
- **Static utility class and local function**: a static class groups operations without instances; a local function is declared inside another function.
- **Field mask and flag**: a mask contains one yes/no choice per field; a flag is one such choice. It selects membership, not ordering.
- **Serialization**: representing data in a form that can be saved and read back, for example in a configuration file.
- **`struct`, value type, and `record struct`**: a struct is a value type, normally copied on assignment or argument passing; a record struct also supplies value equality, including `==`.
- **Heap allocation and boxing**: heap allocation creates managed object storage; boxing wraps a value type as an object. Using a small mask value avoids a separate mask-object allocation in the demonstrated calls, but does not guarantee that every struct always lives on the stack.
- **Default value, nullable value, and optional parameter**: a mask's default value has false flags; a nullable mask can instead have no value; an optional parameter has a declared fallback when its argument is omitted.
- **Null-coalescing operator `??` and discard `_`**: `??` supplies a fallback for an absent value; a discard indicates that a result is intentionally unused.
- **Collection expression, switch, and nameof**: square brackets can construct the group array; a switch selects a case with a default branch for unmatched values; nameof obtains an identifier's name.
- **Configuration function and mask roles**: a configuration function transforms selection data; a build mask selects comparisons, a check mask selects required results, and a deletion mask selects flags to clear.
- **Named argument**: `parameterName: value` identifies the parameter explicitly instead of relying on argument position.
- **Difference mask, or diff**: one flag per field recording whether two objects differ. **Any** asks whether at least one selected flag is set; **all** asks whether every selected flag is set.
- **Field index**: a numeric identifier for one field, allowing common logic to iterate over fields.
- **Contract**: restrictions on inputs and promises about outputs. **Assertion** means a development diagnostic; an **exception** reports a failure that can be caught. `Debug` calls depend on the `DEBUG` compilation symbol.
- **Getter, setter, property, and backing field**: a getter reads a value, a setter writes it, a property exposes those operations with field-like syntax, and a backing field stores the actual state.
- **`with` expression and reference passing**: `with` produces a modified copy; reference passing lets a function update the caller's storage directly.
- **Iterator and generic**: an iterator supplies a sequence of values; a generic parameterizes code by a type. Both are mentioned as broader applications, not developed here.
- **Bit mask and bitwise operations**: one integer stores flags in bit positions. `<<` shifts, `|` combines set bits, `&` keeps common bits, and `~` complements bits.
- **Expression-bodied accessor**: `=>` gives a getter or setter a compact single-expression body.
- **Encapsulation and source generator**: encapsulation hides representation behind meaningful operations; a source generator can produce repetitive source code during compilation.

## One boolean for each field

[00:05:04](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=304s) A **field mask** initially means one boolean flag for each client field. True selects that field; false skips it. The mask separates the decision from the printer's implementation.

Related [committed boolean mask and conditional printer](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); simplified sample:

```csharp
record struct ClientFieldMask
{
    public bool FirstName;
    public bool LastName;
    public bool BelongsToGroups;
}

static void Print(Client c, ClientFieldMask m)
{
    if (m.FirstName) Console.WriteLine(c.FirstName);
    if (m.LastName) Console.WriteLine(c.LastName);
    if (m.BelongsToGroups)
        foreach (var group in c.BelongsToGroups)
            Console.WriteLine(group);
}
```

1. [00:05:18](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=318s) Add a second parameter for the mask, so the caller supplies the selection.
2. [00:05:23](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=323s) Guard each field's output with its corresponding flag. The printer retains its fixed name, surname, groups order.
3. [00:05:59](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=359s) Once callers use the aggregate operation, separate per-field print functions are no longer needed as the caller's selection mechanism. The saved example still retains them as implementation helpers; that is compatible with delegating selection to the mask.

A `record struct` is a value type with generated value equality. The lesson reaches the reason for that choice while working through defaults next.

## Configure a mask before printing

[00:08:56](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=536s) Selection is now ordinary data that another function can transform. A **configuration function** takes a starting mask and returns the modified value. [00:09:23](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=563s) Its decisions can be arbitrary: it may consult user input, other settings, or remove a field the caller requested. [00:09:33](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=573s) The mask still controls only field selection; it does not prescribe how the decision was reached.

static ClientFieldMask ConfigureFilter(ClientFieldMask mask)
{
    if (mask.BelongsToGroups)
        mask.FirstName = false;

```

## Subtract forbidden fields

[00:10:18](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=618s) A useful next operation takes one mask, supplied by the user or by default, and removes every field named by another mask. The second mask may come from any configuration source. [00:10:43](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=643s) Call the two roles “to print” and “not to print”: the first requests fields, and the second forbids them.

[00:11:02](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=662s) The narrated example leaves only the surname. The reason is that the surviving field is requested and **not forbidden**. A field requested and forbidden cannot survive; that wording matters when reading the explanation. [00:11:16](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=676s) The forbidding mask overrides the printing mask for its selected fields. [00:11:37](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=697s) If it names a field the first mask never selected, clearing that flag simply does nothing. This no-op behavior is the chosen design.

Related [committed Without implementation](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); simplified truth table for one field:

[00:11:47](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=707s) Keeping two masks separately does not itself combine them. Write a **Without** function taking the original mask and the mask to remove. [00:11:50](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=710s) It returns the first mask with matching selected fields cleared. The primitive implementation checks every flag:

```csharp
static ClientFieldMask Without(ClientFieldMask mask, ClientFieldMask toDelete)
{
    if (toDelete.FirstName) mask.FirstName = false;
    if (toDelete.LastName) mask.LastName = false;
    if (toDelete.BelongsToGroups) mask.BelongsToGroups = false;
    return mask;
}
```

[00:12:08](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=728s) This is easy to understand, but [00:12:17](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=737s) it duplicates the field list already present in the mask type. [00:12:28](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=748s) A new field requires another branch; forgetting that branch leaves the new flag uncleared and creates a bug. [00:12:45](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=765s) The goal is to move field knowledge into shared access operations so combination functions do not hand-maintain that list.

[00:12:55](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=775s) A **named argument** uses the parameter name and a colon. The names associate arguments with parameters even when their order is swapped.     FirstName = true, LastName = true, BelongsToGroups = true

## Compute and reuse a difference mask

[00:14:24](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=864s) A mask can describe comparison results as well as requested operations. A **difference mask** uses true to mean “these objects differ in this field.” Initially the discussion includes a build mask selecting which fields the comparison should inspect.

[00:14:45](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=885s) Start the result with all flags false. For each inspected field, set its result flag only if the corresponding values differ. [00:15:11](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=911s) This operation is conventionally called **diff**, the name used in the example. [00:15:27](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=927s) A masked diff checks only fields named by its input selection; it is not necessarily a comparison of every field.

Related [committed Diff and comparison helper](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); reconstructed selected-field version, with the intended difference polarity:

```csharp
static ClientFieldMask Diff(Client a, Client b, ClientFieldMask selected)
{
    ClientFieldMask result = new();
    if (selected.FirstName && a.FirstName != b.FirstName)
        result.FirstName = true;
    if (selected.LastName && a.LastName != b.LastName)
        result.LastName = true;
    if (selected.BelongsToGroups &&
        !a.BelongsToGroups.SequenceEqual(b.BelongsToGroups))
        result.BelongsToGroups = true;
    return result;
}
```

[00:15:37](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=937s) In the demo, remove the selection checks and retain the value comparisons. This reduces the number of conditions and yields a complete stored diff that can be filtered afterwards. These are two designs: selection during computation skips irrelevant comparisons; selection after computation reuses already calculated results.

[00:15:56](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=956s) Once the diff is stored, asking whether first name matches means inspecting its flag, rather than comparing the strings again. [00:16:16](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=976s) String inequality compares the string's character sequence, so accents or other diacritics make otherwise similar names different. [00:16:35](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=995s) Ignoring them requires explicit comparison rules; ordinary inequality does not silently normalize them.

[00:16:41](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1001s) Centralize such rules in the comparison implementation. [00:16:51](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1011s) An unrelated inline inequality would still follow the ordinary rule, so all call sites needing the custom rule must reuse the same comparison. [00:17:05](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1025s) Extracting that comparison avoids duplication.

Related [committed FirstNameEquals helper and its Diff call](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); a corrected simplified helper and caller:

```csharp
static bool FirstNameEquals(Client a, Client b) =>
    a.FirstName == b.FirstName; // Add any intended normalization here.

static ClientFieldMask Diff(Client a, Client b)
{
    ClientFieldMask result = new();
    result.FirstName = !FirstNameEquals(a, b);
    result.LastName = a.LastName != b.LastName;
    result.BelongsToGroups =
        !a.BelongsToGroups.SequenceEqual(b.BelongsToGroups);
    return result;
}
```

The inspected snapshots call `FirstNameEquals` without negation when setting the first-name diff flag. That marks equality as a difference and contradicts the intended diff contract; the sample above fixes that polarity. The committed helper uses `SequenceEqual`, which still performs an ordinary sequence comparison and implements no diacritic-insensitive rule.

## Enforce the field index contract

[00:23:42](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1422s) A **contract** states which inputs are allowed and what outputs are promised. Types express part of it: this getter accepts a field identifier and returns a boolean. [00:23:57](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1437s) But an enum does not guarantee a named member. ## Replace repeated checks with loops

[00:28:07](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1687s) Rework call sites through indexed access. [00:28:09](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1689s) Replace handwritten per-field checks with a loop over every usable field. Shared combination functions no longer need an extra branch for each new field; field definitions and indexed mappings still need to be kept consistent.

1. [00:28:16](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1696s) Start at `ClientField.FirstField`. Naming the first-field marker avoids scattering the starting member through loops.
2. [00:28:32](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1712s) Stop at `ClientField.Count`. A separate last-field marker is unnecessary in this contiguous, zero-based design.
3. [00:28:54](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1734s) While the index is below the count, it identifies a usable field. Read its flag with the getter.
4. [00:29:04](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1744s) Perform the required check or write using that index instead of a hardcoded field name.

Related [committed indexed AreSet and Without loops](https://github.com/AntonC9018/uniCourse_csharp/blob/80eddb6786130b733401932cadfb35f5c939d8f4/examples/field_masks/Program.cs); corrected simplified all-flags loop:

```csharp
static bool AreSet(ClientFieldMask mask, ClientFieldMask required)
{
    for (var field = ClientField.FirstField; field < ClientField.Count; field++)
        if (Get(required, field) && !Get(mask, field))
            return false;
    return true;
}
```

The indexed snapshot returns false when `Get(mask, i)` is true inside a required-field branch. Its missing negation reverses the intended check; the sample uses `!Get(mask, field)`. The prior boolean helper and later bitwise helper both express the all-required-flags contract.

[00:29:33](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1773s) The deletion operation uses the same enumeration, but its updated mask must reach the caller. Because a struct parameter is copied, return the new value or pass storage by reference. ## Properties hide a different representation

[00:31:09](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1869s) The goal is now to store all boolean flags as bits of one number while preserving convenient access. **Getters** read logical flags; **setters** write them. A **property** exposes the two operations with field-like syntax while a **backing field** holds the actual representation.

[00:31:21](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1881s) In Java one would typically write methods such as `getFirstName` and `setFirstName`. [00:31:34](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1894s) C# combines get and set accessors under one property name. Its setter receives the assigned value through the implicit `value` parameter. [00:31:34](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1894s) That value is a bool here because the property is a boolean flag.

Related [committed FirstName property and integer backing field](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); simplified property shape:

internal int _value;

public bool FirstName
{

    set => Set(ClientField.FirstName, value);
}
```

[00:31:44](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1904s) Assigning `mask.FirstName = true` invokes the setter implicitly; [00:31:54](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1914s) reading the property invokes its getter. [00:32:01](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1921s) The accessor bodies still determine what actually happens.

[00:32:12](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1932s) Store flags in `_value` as a **bit mask**: a set bit means true and a cleared bit means false. [00:32:21](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1941s) Successive positions represent successive fields. [00:32:28](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1948s) Each field's index supplies its bit position, so indexed operations can address every flag. ## Set and clear one bit

[00:32:43](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1963s) Use the field index as its bit position. [00:32:49](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1969s) Other assignments of indices are possible, but a consistent one-to-one mapping avoids collisions between flags. [00:32:58](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1978s) The setter chooses a set-bit branch for true and a clear-bit branch for false.

Related [committed indexed Set implementation](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); simplified setter:

```csharp
public void Set(ClientField field, bool value)
{
    int bit = 1 << (int)field;
    if (value)
        _value |= bit;
    else
        _value &= ~bit;
}
```

[00:33:02](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1982s) **Left shift** (`<<`) moves the single 1 to the desired position. **Bitwise OR** (`|`) sets that bit and leaves every other bit unchanged; `|=` assigns the combined value back. [00:33:09](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1989s) For false, use the same one-bit value to clear only the target position.

[00:33:59](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2039s) [00:34:02](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2042s) Clearing uses **bitwise AND** (`&`) with the **complement** (`~`) of the one-bit mask. The complement has zero at the target and ones everywhere else, so all non-target bits survive.

[00:34:09](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2049s) Work through a value written as `101`. [00:34:23](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2063s) Build `v` by shifting 1 to the flag position, then complement it. [00:34:25](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2065s) The video's four-bit diagram shows `0111` as a complement; that corresponds to a one-bit mask `1000`, with the selected bit drawn on the left. It is not the complement of position-zero `0001`. Use a consistent bit convention for a concrete calculation.

Related [committed bit-setting and bit-clearing logic](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); low four bits shown, first name at the committed position 0:

```text
value:       0101
v = 1 << 0: 0001
~v:          1110
value & ~v:  0100
```

[00:34:33](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2073s) AND retains a 1 only where both operands have 1. [00:34:50](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2090s) If either operand has zero, the result bit is zero. Thus the target becomes zero while each other position copies the original value. The diagrams show only a few bits; actual integer complement also flips the other bits of the integer.

[00:34:57](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2097s) Because this logic sits behind a property, callers can assign the property. [00:35:05](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2105s) [00:35:21](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2121s) Writing `FirstName = true` invokes the property's set accessor with `value` equal to true, so the true branch runs. [00:35:32](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2132s) This is syntax sugar for invoking the accessor, not an independent storage operation. The recording's Java-style “SetFirstName” wording describes the equivalent operation; the committed C# property delegates to the indexed `Set` method.

<details>
<summary>Predict: does clearing first name also clear groups?</summary>

No. With first name at bit 0 and groups at bit 2, 0101 becomes 0100. The complement has a 1 at bit 2, so the group flag is preserved.

</details>

## Read one bit

[00:35:40](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2140s) The **getter** needs the same one-bit mask as the setter. [00:35:45](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2145s) AND the backing value with that mask, discarding every position except the selected flag.

Related [committed indexed Get implementation](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); simplified getter:

```csharp
public bool Get(ClientField field)
{
    int bit = 1 << (int)field;
    return (_value & bit) != 0;
}
```

[00:35:54](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2154s) If the flag is absent, the AND result is zero. [00:36:03](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2163s) If present, the result is the nonzero one-bit value. The getter turns that numeric result into a boolean.

[00:36:09](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2169s) With a value `101` and first name at position 0, the selected result is 1. [00:36:21](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2181s) Mask zeroes force result zeroes, and the one permitted position copies the value's bit:

```text
value:       0101
bit:         0001
value & bit: 0001  -> true

value:       0100
bit:         0001
value & bit: 0000  -> false
```

[00:36:30](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2190s) A nonzero result means the original flag was set; zero means it was not. [00:36:36](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2196s) The reason is that a zero in the value at the selected position cannot become one through AND. [00:36:42](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2202s) One expression covers both cases, so the getter works for every valid mask configuration.

## Share the bit logic between properties

[00:36:46](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2206s) Every flag needs the same read/write bit operations; only its field index changes. Duplicating those operations in each property would recreate the maintenance problem.

1. [00:37:01](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2221s) Extract indexed helpers for setting and reading bits.
2. [00:37:10](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2230s) Give the setter a field identifier and an assigned boolean.
3. [00:37:20](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2240s) Pass the named field to reuse the manipulation logic.
4. [00:37:28](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2248s) Reduce each property's setter to a single helper call.
5. [00:37:30](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2250s) Use an **expression-bodied accessor**, written with `=>`, when one expression suffices. Getters support the same form.

Related [committed indexed helpers and three property wrappers](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); simplified property wrappers:

```csharp
public bool FirstName
{
    get => Get(ClientField.FirstName);
    set => Set(ClientField.FirstName, value);
}
public bool LastName
{
    get => Get(ClientField.LastName);
    set => Set(ClientField.LastName, value);
}
public bool BelongsToGroups
{
    get => Get(ClientField.BelongToGroups);
    set => Set(ClientField.BelongToGroups, value);

```

[00:37:41](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2261s) The getter/helper can also be expressed compactly. [00:37:46](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2266s) [00:37:50](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2270s) Read from the current backing field, which remains mutable through the setters; the compact syntax does not freeze the value. [00:37:54](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2274s) The getter receives only the field identifier, because reading needs no assigned boolean.

[00:38:03](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2283s) The property wrappers still repeat the field-to-index names. A **source generator** could generate this repetitive API during compilation. The lesson leaves that advanced technique out of scope; it is not a proof that no other API design could avoid named wrappers. [00:38:17](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2297s) For now the wrappers remain handwritten, while their shared bit logic is written only once.

## Expose indexed access on the mask

[00:38:24](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2304s) All flags now reside in one integer. [00:38:26](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2306s) Setting one flag does not depend on another property's setter; the indexed helper can stand on its own. [00:38:32](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2312s) Make the setter public, alongside indexed reading, so both internal code and callers can work with a field identifier.

var mask = new ClientFieldMask();

## Replace mask subtraction with one operation

[00:39:13](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2353s) With all flags packed into an integer, subtraction no longer needs a loop. [00:39:20](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2360s) AND the original mask with the inverse of the deletion mask. [00:39:33](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2373s) Remove the indexed loop: one bitwise expression performs the same clearing operation.

Related [final committed Without implementation](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); simplified version:

```csharp
static ClientFieldMask Without(ClientFieldMask mask, ClientFieldMask toDelete)
{
    mask._value &= ~toDelete._value;
    return mask;
}
```

The operation still returns the changed mask because its parameter is a copied value. Its external meaning remains “keep requested fields except those named for deletion.”

[00:39:41](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2381s) First example: request first name and last name, then delete first name and groups. In the following diagrams columns run first name, last name, groups from left to right to make the selection roles easy to read. These are logical field columns, not the conventional high-to-low display of the stored integer.

```text

~delete:    0 1 0
result:     0 1 0

[00:40:02](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2402s) The final group position also becomes zero; it was never requested, so deletion there changes nothing. Only surname survives.

[00:40:07](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2407s) Second example: request everything and delete only first name. [00:40:13](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2413s) Copy every other position unchanged:

[00:40:21](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2421s) Put the raw bitwise work inside the named method. ## Test every required flag at once

[00:40:59](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2459s) The final optimization is the all-flags predicate. Take the common bits between the actual mask and the required mask. [00:41:08](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2468s) If those bits differ from the required mask, at least one requirement is missing. [00:41:19](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2479s) If they equal it, every required flag is present.

Related [final committed AreSet implementation](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); simplified predicate:

```csharp
static bool AreSet(ClientFieldMask mask, ClientFieldMask required) =>
    (mask._value & required._value) == required._value;
```

[00:41:26](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2486s) The worked diagram requires two positions and ignores the others. As in the video/source diagram, these are displayed flag columns:

```text
actual:      1 1 0 1
required:    1 1 0 0
common:      1 1 0 0  -> equals required, true

actual:      1 0 0 1
required:    1 1 0 0
common:      1 0 0 0  -> differs from required, false
```

[00:41:39](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2499s) The third and fourth positions are zeroed by the required mask, even if the actual mask has a flag there. Only required positions contribute. [00:41:46](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2506s) When every required position was one, each copies a one and the result exactly matches the requirement.

[00:41:53](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2513s) If even one required position was zero, that zero survives into the common mask and equality fails. [00:42:01](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2521s) That equality is the complete decision rule: “all required flags are set.” It is not an “any” test.

<details>
<summary>Why compare the common bits with required rather than with the actual mask?</summary>

The actual mask may contain additional flags that the caller explicitly ignores. The required mask contains exactly the obligations to satisfy. Equality with it proves that none of those obligations is missing.

</details>

The lesson ends with configurable selection, reusable difference results, and named operations over a compact representation. Alternative domain layouts, reference-return syntax, iterators, a generalized generic field container, source generation, and document parsing remain outside the implemented example.
