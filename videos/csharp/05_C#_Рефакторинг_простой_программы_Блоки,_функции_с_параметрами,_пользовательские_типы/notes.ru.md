# Рефакторинг расстояния по сетке с помощью областей видимости, вызовов и типов позиции

[00:00:00](https://www.youtube.com/watch?v=z51K0UhriOk&t=0s) Этот урок начинается с четырёх переменных координат и превращает повторяющуюся арифметику расстояния по сетке в переиспользуемую операцию. Каждое изменение отвечает на конкретную проблему: отрицательные разности, сталкивающиеся временные имена, дублирующиеся инструкции и слишком легко перепутываемые координатные аргументы. Финальное сравнение спрашивает, почему изменение поля через параметр функции ведёт себя по-разному для структуры и для класса.

Используемый по ходу словарь:

- **Координата и ось:** X и Y описывают положение вдоль двух направлений; пара записывается как (X, Y). **Расстояние по сетке** считает шаги по горизонтали и вертикали по клеткам. **Модуль**, записываемый как `Math.Abs`, сохраняет величину числа без его знака.
- **Переменная, тип и `int`:** переменная даёт имя месту хранения значения; её тип говорит, какое именно значение она хранит. Здесь `int` хранит целочисленные координаты и расстояния. **Объявление** вводит переменную, **инициализация** задаёт ей начальное значение, а **присваивание** копирует значение справа в хранилище слева. **Скаляр** — это одно простое значение, например целое число. **Определённое присваивание** — это требование C#, согласно которому локальной переменной должно быть присвоено значение до её чтения.
- **Выражение и значение:** выражение — это код, вычисляемый в значение; значение — конкретный результат, который можно сохранить. **Промежуточный результат** — это значение, получаемое по пути к окончательному ответу.
- **Блок, область видимости и локальная переменная:** фигурные скобки задают границы блока; область видимости определяет, где можно использовать имя. Локальная переменная принадлежит объемлющему её блоку или функции. Её **время жизни** описывает, когда эта переменная существует в модели выполнения урока.
- **Рефакторинг и дублирование:** рефакторинг меняет организацию программы, сохраняя её задуманное поведение. Дублирование означает поддержание нескольких копий одной и той же операции.
- **Функция, вызов, сигнатура, параметр и аргумент:** функция объединяет инструкции; вызов выполняет их. Её сигнатура описывает имя и типизированные входные данные. Параметр — это входная переменная функции; аргумент — это выражение, переданное при вызове. **Вызывающая** сторона делает вызов, а **вызываемая** функция его выполняет.
- **Тип возврата, возвращаемое значение, `return` и `void`:** тип возврата объявляет вид результата; возвращаемое значение — это сам результат. `return` передаёт его и завершает текущее выполнение функции. `void` объявляет, что функция не возвращает значение. **Статическая локальная функция** не может захватывать окружающие локальные переменные.
- **Стек, кадр вызова, куча и адрес:** на рисунке временное рабочее хранилище названо стеком; кадр представляет параметры и локальные переменные одного вызова. Динамическое хранение объектов — это куча. Адрес идентифицирует место хранения. Коробки — это учебная модель, а не обещание точной раскладки в памяти машины.
- **Пользовательский тип, `Position`, структура, тип значения и поле:** пользовательский тип даёт имя полезной форме данных. `Position` группирует X и Y. Структура — это тип значения, значение которого содержит его поля; поле — именованная часть этого значения. `public` позволяет коду вне типа обращаться к полю. **Инициализатор объекта** задаёт именованные поля при создании значения, а **оператор точки** выбирает поле.
- **Передача по значению, копия и побочный эффект:** обычные вызовы копируют значение аргумента в хранилище параметра. Побочный эффект — это изменение вне приватных рабочих данных функции.
- **`ref`, псевдоним и `out`:** явная передача переменной с помощью `ref` делает параметр ещё одним способом доступа к хранилищу вызывающей стороны. `out` — это отдельный режим выходного параметра; он не вводится трассировкой возвращаемого значения в этом уроке.
- **Класс, ссылочный тип, объект и ссылка:** экземпляр класса — это объект в динамическом хранилище. Переменная ссылочного типа хранит ссылку на этот объект. Копирование ссылки позволяет двум переменным обращаться к одному объекту.

[Лабораторная по улучшению программы](../../../labs/1_basic/13_improvement_techniques.md) позже объединяет группировку данных и выделение функций с массивами и циклами; эти последние техники выходят за рамки данной записи.

## Координаты превращаются в счётчик шагов по сетке

[00:00:00](https://www.youtube.com/watch?v=z51K0UhriOk&t=0s) **Координата** — это одна составляющая положения: на исходном эскизе у игрока X = 5 и Y = 6, а у врага X = 3 и Y = 2. Переменная даёт имя месту хранения каждого числа, а `int` — используемый здесь тип для целых чисел. Начальное [состояние кода в видео](https://www.youtube.com/watch?v=z51K0UhriOk&t=0s) можно представить так:

```csharp
int xPlayer = 5;
int yPlayer = 6;
int xEnemy = 3;
int yEnemy = 2;
```

[00:00:25](https://www.youtube.com/watch?v=z51K0UhriOk&t=25s) Задача — посчитать, сколько клеток сетки должен пройти враг, чтобы добраться до игрока. Это **расстояние по сетке** считает ходы вдоль осей X и Y, а не по прямой через плоскость.

[00:00:30](https://www.youtube.com/watch?v=z51K0UhriOk&t=30s) В нарисованном примере добраться до игрока — это два хода вверх и один вправо. [00:00:46](https://www.youtube.com/watch?v=z51K0UhriOk&t=46s) Каждый ход даёт одну клетку, поэтому итог равен горизонтальному счёту плюс вертикальный: 1 + 2 = 3. Порядок этих ходов не меняет сумму.

[00:01:01](https://www.youtube.com/watch?v=z51K0UhriOk&t=61s) Читайте пары координат: сначала X, затем Y. На рисунке используются игрок (3, 1) и враг (2, 3). Это новый иллюстративный набор координат, а не начальные значения (5, 6)/(3, 2). Соглашение о порядке координат важно, когда решаем, какие значения вычитать.

## Отбрасываем направление с помощью модуля

[00:01:23](https://www.youtube.com/watch?v=z51K0UhriOk&t=83s) Обычное вычитание несёт информацию о направлении. Для нарисованного примера X врага минус X игрока даёт 2 − 3 = −1. Обратный порядок вычитания даёт +1; число горизонтальных шагов всё равно равно одному.

[00:01:37](https://www.youtube.com/watch?v=z51K0UhriOk&t=97s) Расстояние не должно меняться, когда игрок переходит с одной стороны от врага на другую. Знак сообщает нам направление, которое для этого вопроса не нужно. **Модуль** отбрасывает этот знак: и −1, и +1 имеют величину 1.

[00:01:58](https://www.youtube.com/watch?v=z51K0UhriOk&t=118s) [Состояние с модулем в видео](https://www.youtube.com/watch?v=z51K0UhriOk&t=118s) вводит `Math.Abs`. В этом упрощённом фрагменте оба порядка вычитания дают одинаковое расстояние:

```csharp
int xDistance = Math.Abs(xEnemy - xPlayer);
int sameDistance = Math.Abs(xPlayer - xEnemy);
```

[00:02:22](https://www.youtube.com/watch?v=z51K0UhriOk&t=142s) Применим ту же логику к Y: враг может быть выше или ниже игрока. Возьмите модуль разности по каждой оси, затем сложите два неотрицательных результата. Формула: |enemyX − playerX| + |enemyY − playerY|. Она измеряет шаги по осям в показанном здесь примере.

## Разделяем результаты по осям и запускаем первый тест

[00:02:41](https://www.youtube.com/watch?v=z51K0UhriOk&t=161s) Сохраняйте вклад каждой оси отдельно, чтобы вычисление можно было проследить. [00:02:45](https://www.youtube.com/watch?v=z51K0UhriOk&t=165s) **Объявление** вводит именованную переменную; **инициализация** сохраняет её первое значение. Новая переменная расстояния по X хранит промежуточный результат, который можно прочитать снова при вычислении итога.

[00:02:50](https://www.youtube.com/watch?v=z51K0UhriOk&t=170s) Затем пример задаёт игрока как (1, 1), а врага как (2, 3). Правки координат и [состояние с разделённым вычислением](https://www.youtube.com/watch?v=z51K0UhriOk&t=170s) резюмированы этой реконструкцией:

```csharp
int xPlayer = 1;
int yPlayer = 1;
int xEnemy = 2;
int yEnemy = 3;

int x_dist = Math.Abs(xEnemy - xPlayer);
int y_dist = Math.Abs(yEnemy - yPlayer);
int z = x_dist + y_dist;
Console.WriteLine(z);
```

[00:03:11](https://www.youtube.com/watch?v=z51K0UhriOk&t=191s) Предскажите вывод перед запуском: горизонтальное расстояние 1, вертикальное 2, итог 3. Произнесённое вслух «1, 2, 3» считает шаги и вклады; программа печатает единственный итог `3`, а не три координатных значения. Первый запуск — это база, с которой сравниваются последующие структурные изменения.

## Вычисляем выражение до сохранения его значения

После этого она намечает временное хранилище для промежуточного вычисления. Эти коробки объясняют, какие значения нужны, а не требуют, чтобы каждая нарисованная коробка была отдельным физическим размещением.

[00:04:00](https://www.youtube.com/watch?v=z51K0UhriOk&t=240s) **Выражение** — это фрагмент кода, у которого есть значение. **Значение** — это конкретный результат, который можно записать в хранилище. Правая часть присваивания расстояния является выражением, а не записанной куском алгебры.

[Состояние вычисления выражения](https://www.youtube.com/watch?v=z51K0UhriOk&t=263s) фиксируется так:

## Второе измерение обнаруживает дублирование

[00:06:46](https://www.youtube.com/watch?v=z51K0UhriOk&t=406s) Когда враг один, арифметика встречается один раз. Второй объект, например дерево, создаёт ещё одно измерение. Первая попытка — скопировать рабочее вычисление и подставить другие координатные входные данные.

[00:06:53](https://www.youtube.com/watch?v=z51K0UhriOk&t=413s) В [состоянии с дублированным кодом](https://www.youtube.com/watch?v=z51K0UhriOk&t=413s) вставленной версии нужны другие временные имена, например `x3`. Эта сокращённая реконструкция предполагает, что переменные координат уже существуют; вторая пара позже исправляется:

```csharp
int x_dist = Math.Abs(xEnemy - xPlayer);
int y_dist = Math.Abs(yEnemy - yPlayer);
int distanceToEnemy = x_dist + y_dist;

int x3 = Math.Abs(xTree - xPlayer);
int y3 = Math.Abs(yTree - yPlayer);
int distanceToTree = x3 + y3;
```

[00:07:09](https://www.youtube.com/watch?v=z51K0UhriOk&t=429s) Сейчас обе копии существуют в одной **области видимости** — регионе, в котором можно использовать их имена переменных. Объявление одного и того же локального имени там дважды завершается ошибкой. Переименование снимает это немедленное столкновение, но оставляет две реализации арифметики, которые нужно поддерживать.

## Используем соседние блоки для переиспользования временных имён

[00:07:18](https://www.youtube.com/watch?v=z51K0UhriOk&t=438s) **Блок** — это группа инструкций, заключённая в фигурные скобки. Его локальные имена принадлежат области видимости этого блока. Поместите копии в отдельные соседние блоки, чтобы обе могли использовать `x_dist` и `y_dist`.

[00:07:52](https://www.youtube.com/watch?v=z51K0UhriOk&t=472s) Фигурные скобки задают границы региона, в котором можно использовать временные переменные каждой копии.

[00:07:55](https://www.youtube.com/watch?v=z51K0UhriOk&t=475s) Теперь обход памяти оставляет некоторые окружающие координатные локальные переменные вне рисунка стека, чтобы освободить место под переменные блоков. ## Следуем за временем жизни блока, не предполагая точных адресов

## Сохраняем результат во внешней области видимости

[00:09:58](https://www.youtube.com/watch?v=z51K0UhriOk&t=598s) Попытка напечатать `x_dist` после его блока не удаётся, потому что имя находится вне его области видимости. Его прежняя нарисованная коробка не делает его снова доступным.

[00:10:16](https://www.youtube.com/watch?v=z51K0UhriOk&t=616s) Чтобы сохранить ответ, объявите результат во внешней области видимости и **присваивайте** ему значение внутри блока. Присваивание копирует значение выражения справа в переменную слева. [Правка внешнего результата](https://www.youtube.com/watch?v=z51K0UhriOk&t=616s) принимает вид:

```csharp

{
    int x_dist = Math.Abs(xEnemy - xPlayer);
    int y_dist = Math.Abs(yEnemy - yPlayer);
    dist = x_dist + y_dist;
}
Console.WriteLine(dist);
```

[00:10:34](https://www.youtube.com/watch?v=z51K0UhriOk&t=634s) `int dist;` — это объявление без инициализатора. Оно не даёт пригодного начального значения. Присваивание внутри блока сообщает это значение; C# требует, чтобы локальной переменной было определённо присвоено значение до её чтения.

[00:10:44](https://www.youtube.com/watch?v=z51K0UhriOk&t=644s) Блок вычисляет свою временную переменную по Y и присваивает сумму, 3, переменной `dist`. Закрытие блока заканчивает доступ к его временным переменным, но оставляет `dist` доступной, поскольку её объявление принадлежит внешней области видимости. [00:10:59](https://www.youtube.com/watch?v=z51K0UhriOk&t=659s) Входные координаты тоже остаются доступными снаружи; скрыты только внутренние рабочие значения.

[00:11:05](https://www.youtube.com/watch?v=z51K0UhriOk&t=665s) Вынесите результаты, нужные последующему коду, за пределы их локальных вычислительных блоков. [00:11:17](https://www.youtube.com/watch?v=z51K0UhriOk&t=677s) Переименуйте безликие результаты так, чтобы было видно, какое измерение хранит каждый, например `distanceToEnemy` и соответствующее имя для расстояния до дерева. В идентификаторе C# используйте корректное написание вроде camelCase; описательная фраза «distance-to-enemy» сама по себе идентификатором не является.

[00:11:30](https://www.youtube.com/watch?v=z51K0UhriOk&t=690s) Запуск после этой перестройки сохраняет прежнее поведение. Это **рефакторинг**: изменение структуры с сохранением сути вычисления.

<details>
<summary>Почему внешний результат можно напечатать, а две временные переменные по осям — нет?</summary>

## Описываем функцию с входными данными и результатом

[00:13:02](https://www.youtube.com/watch?v=z51K0UhriOk&t=782s) **Функция** объединяет одну последовательность инструкций. **Вызов** выполняет её с выбранными входными данными: игрок и враг, игрок и дерево или дерево и враг. **Параметр** — это типизированная входная переменная в функции; **аргумент** — это выражение, переданное в месте вызова. Разные аргументы позволяют одной и той же реализации измерять разные пары.

[00:13:19](https://www.youtube.com/watch?v=z51K0UhriOk&t=799s) Функция может также давать **возвращаемое значение** — результат, который она передаёт обратно. Вызов, дающий значение, является выражением. [00:13:33](https://www.youtube.com/watch?v=z51K0UhriOk&t=813s) Присваивание значения этого вызова переменной заменяет прежнее встроенное вычисление.

```csharp

```

3. [00:14:24](https://www.youtube.com/watch?v=z51K0UhriOk&t=864s) **Тип возврата** указывает вид производимого результата. [00:14:39](https://www.youtube.com/watch?v=z51K0UhriOk&t=879s) Выберите `int`, потому что расстояние в клетках — целое число.
4. [00:14:51](https://www.youtube.com/watch?v=z51K0UhriOk&t=891s) Напишите имя функции, затем скобки со списком её параметров. Это имя и типизированный список описывают **сигнатуру** функции, её вызываемый интерфейс.
5. [00:15:03](https://www.youtube.com/watch?v=z51K0UhriOk&t=903s) Задайте четыре параметра: сначала X и Y первого объекта, затем X и Y второго объекта. [00:15:18](https://www.youtube.com/watch?v=z51K0UhriOk&t=918s) Это все четыре координатных входных данных, от которых зависит вычисление.

## Прослеживаем второй вызов и проверяем оба вывода

[00:21:19](https://www.youtube.com/watch?v=z51K0UhriOk&t=1279s) Начните следующее объявление результата с ещё не присвоенной локальной переменной в трассировке. [00:21:42](https://www.youtube.com/watch?v=z51K0UhriOk&t=1302s) Вычислите локальное расстояние и передайте его значение в целевую переменную вызывающей стороны. <details>
<summary>Разделяют ли два вызова свои переменные-параметры потому, что они вызывают одну и ту же функцию?</summary>

У каждого вызова свои параметры и рабочие локальные переменные. Имена прежнего вызова недоступны после его возврата. Хранилище может быть переиспользовано, но второй вызов всё равно получает свежие значения аргументов и вычисляет свежий результат.

## Делаем позицию единым типизированным значением

[00:22:49](https://www.youtube.com/watch?v=z51K0UhriOk&t=1369s) Четыре аргумента одного типа приглашают тихую ошибку. Компилятор принимает любые четыре целых числа, даже если вызывающая сторона сначала передаст все значения X, смешает сущности или перепутает координату. [Проблема порядка аргументов](https://www.youtube.com/watch?v=z51K0UhriOk&t=1369s) проиллюстрирована так:

```csharp
// Задуманный порядок:
Distance(xEnemy, yEnemy, xPlayer, yPlayer);
// Корректный по типам, но, возможно, неверный порядок:
Distance(xEnemy, xPlayer, yEnemy, yPlayer);
```

[00:23:22](https://www.youtube.com/watch?v=z51K0UhriOk&t=1402s) Сгруппируйте X и Y каждой сущности в одно значение. Тогда функция может запрашивать две позиции вместо четырёх никак не связанных чисел. [00:23:24](https://www.youtube.com/watch?v=z51K0UhriOk&t=1404s) **Пользовательский тип** — это именованная форма для данных, нужных программе; `Position` будет представлять эту пару координат. Модификатор `public` делает её поля доступными из окружающего кода примера.

[00:23:45](https://www.youtube.com/watch?v=z51K0UhriOk&t=1425s) Объявите его как **структуру**, то есть тип значения. **Тип значения** хранит содержимое значения прямо в собственном хранилище; для этой позиции содержимым являются две координаты. В модели локальных переменных они не требуют отдельно адресуемого объекта в куче. Это описание представления значения, а не универсальное утверждение, что структуры никогда не могут оказаться внутри кучной памяти.

[Состояние определения типа](https://www.youtube.com/watch?v=z51K0UhriOk&t=1425s) упрощено до:

```csharp
struct Position
{
    public int X;
    public int Y;
}
```

[00:24:08](https://www.youtube.com/watch?v=z51K0UhriOk&t=1448s) Используйте `Position` везде, где программе нужна вся пара, вместо представления этой пары двумя независимыми переменными `int`. [00:24:25](https://www.youtube.com/watch?v=z51K0UhriOk&t=1465s) В текущей однофайловой программе с верхнеуровневыми операторами поместите объявление типа после исполняемых операторов и локальных функций. Запись оставляет его в конце файла. Это текущее расположение файла; оно не требует, чтобы каждая структура в каждом проекте объявлялась последней, и не запрещает другие исходные файлы.

## Создаём Position и именуем его поля

[00:24:40](https://www.youtube.com/watch?v=z51K0UhriOk&t=1480s) Создайте переменную с помощью нового типа. **Инициализатор объекта** — это заключённый в фигурные скобки список присваиваний именованным полям, прикреплённый к созданию; он делает связку X/Y видимой.

[Состояние создания позиции](https://www.youtube.com/watch?v=z51K0UhriOk&t=1480s) вводит такую форму:

Читайте объявление по порядку: `Position` задаёт тип переменной, `position` — её имя, а `new Position` создаёт значение этого типа. Инициализатор присваивает X значение 2, а Y — значение 3; его запятая разделяет присваивания полей. Всё значение целиком инициализирует переменную. Разбор меняет метки сущностей и значения, иллюстрируя эту форму; при прослеживании известного теста расстояния используйте более позднюю пару (1, 1)/(2, 3).

[00:25:02](https://www.youtube.com/watch?v=z51K0UhriOk&t=1502s) Переменная `Position` рисуется как один более крупный блок хранилища, содержащий две меньшие целочисленные ячейки. Группировка не убирает ни одну координату и не превращает пару в одно целое число.

[00:25:27](https://www.youtube.com/watch?v=z51K0UhriOk&t=1527s) Эти именованные части — **поля**. Имя переменной обращается ко всему значению позиции; имя каждого поля выбирает одну его часть. Здесь `player.X` означает поле X, принадлежащее именно этой переменной `player`, а не отдельной глобальной переменной с именем X.

## Предсказываем, что может затронуть изменение параметра-структуры

[00:32:29](https://www.youtube.com/watch?v=z51K0UhriOk&t=1949s) **Побочный эффект** — это изменение, наблюдаемое вне приватных рабочих данных функции. Предскажите, изменит ли присваивание `a.X = 5` внутри функции переменную врага у вызывающей стороны.

[Состояние изменения параметра-структуры](https://www.youtube.com/watch?v=z51K0UhriOk&t=1949s) можно свести к:

```csharp
Position enemy = new Position { X = 2, Y = 3 };
Change(enemy);
Console.WriteLine(enemy.X); // 2

static void Change(Position a)
{
    a.X = 5;
}
```

1. [00:32:33](https://www.youtube.com/watch?v=z51K0UhriOk&t=1953s) Создайте свежее хранилище параметра для `a` и скопируйте в него X и Y вызывающей стороны.
2. [00:32:39](https://www.youtube.com/watch?v=z51K0UhriOk&t=1959s) Для функции с двумя позициями таким же образом отдельно создайте и инициализируйте `b`.
3. [00:32:42](https://www.youtube.com/watch?v=z51K0UhriOk&t=1962s) Запись в `a.X` нацелена на поле X в этом локальном значении параметра.
4. [00:32:52](https://www.youtube.com/watch?v=z51K0UhriOk&t=1972s) Перезапись его содержимого не объединяет его хранилище с хранилищем вызывающей стороны; параметр остаётся копией.
5. [00:33:03](https://www.youtube.com/watch?v=z51K0UhriOk&t=1983s) Ни изменение `a`, ни изменение `b` не меняют исходные позиции вызывающей стороны.
6. [00:33:16](https://www.youtube.com/watch?v=z51K0UhriOk&t=1996s) При обычной передаче эта запись в поле не оказывает внешнего воздействия на те позиции. [00:33:21](https://www.youtube.com/watch?v=z51K0UhriOk&t=2001s) **Передача по значению** означает, что каждый вызов копирует значение аргумента в свой параметр.

Тип возврата `void` во фрагменте означает, что демонстрационная функция не возвращает значения. Прежняя `Distance` по-прежнему может возвращать число, вычисленное по своим скопированным позициям; возврат результата и изменение данных вызывающей стороны — разные механизмы.

<details>
<summary>Если изменение a.X внутри Distance меняет возвращённый ею ответ, должна ли меняться и enemy.X у вызывающей стороны?</summary>

Нет. Функция может вычислить другой результат по своей приватной копии и вернуть это число, оставив исходную позицию вызывающей стороны нетронутой. Вызывающая сторона получает результат только через явный возврат и присваивание.

</details>

## Используем ref, чтобы получить псевдоним переменной вызывающей стороны

[00:33:27](https://www.youtube.com/watch?v=z51K0UhriOk&t=2007s) Следующая возможность — краткий предварительный обзор. Она преподносится как идея, которая, скорее всего, не потребуется в текущей лабораторной работе.

[00:33:33](https://www.youtube.com/watch?v=z51K0UhriOk&t=2013s) **`ref`** меняет способ передачи переменной: вместо обычной копии значения параметр становится **псевдонимом** — ещё одним способом доступа к хранилищу вызывающей стороны. [00:33:37](https://www.youtube.com/watch?v=z51K0UhriOk&t=2017s) Напишите `ref` и в объявлении параметра, и в вызове.

[Демонстрация явного ref](https://www.youtube.com/watch?v=z51K0UhriOk&t=2013s) упрощена до:

```csharp
Position enemy = new Position { X = 2, Y = 3 };
Change(ref enemy);
Console.WriteLine(enemy.X); // 5

static void Change(ref Position a)
{
    a.X = 5;
}
```

[00:33:57](https://www.youtube.com/watch?v=z51K0UhriOk&t=2037s) Теперь запись затрагивает исходную переменную. Именно это внешнее воздействие служит причиной выбрать такой режим параметров.

[00:34:08](https://www.youtube.com/watch?v=z51K0UhriOk&t=2048s) Рисунок изображает псевдоним с помощью **адреса** ячейки вызывающей стороны, используя в качестве примера число вроде 64. Адрес идентифицирует место хранения; здесь он помогает объяснить, до какой переменной доходит запись. Это учебная картинка псевдонима в управляемой памяти, похожая на указатель, а не требование писать небезопасный код с указателями.

[00:34:15](https://www.youtube.com/watch?v=z51K0UhriOk&t=2055s) Значение X/Y больше не копируется в отдельный параметр-позицию, как раньше. Оба имени дают доступ к одному месту хранения. [00:34:29](https://www.youtube.com/watch?v=z51K0UhriOk&t=2069s) При вызове `ref enemy` запрашивает доступ к хранилищу этой переменной, а не только к её текущему значению координаты.

[00:34:34](https://www.youtube.com/watch?v=z51K0UhriOk&t=2074s) Это остаётся продвинутым предварительным обзором, а не ожидаемой техникой для текущих упражнений. Урок переходит к классам, которые вводят другую причину, по которой записи в поля могут быть разделяемыми.

## Меняем представление, выбирая класс

[00:34:40](https://www.youtube.com/watch?v=z51K0UhriOk&t=2080s) Замените объявление позиции как структуры объявлением класса. Большая часть синтаксиса записи инициализации, доступа к полям и вызова может остаться прежней, но её смысл в отношении хранилища меняется.

[00:35:06](https://www.youtube.com/watch?v=z51K0UhriOk&t=2106s) **Класс** определяет объекты **ссылочного типа**. Его экземпляры используют динамическое, то есть **кучное**, хранилище. **Ссылка** — это значение, через которое другая переменная может добраться до объекта. [00:35:15](https://www.youtube.com/watch?v=z51K0UhriOk&t=2115s) Переменная этого класса содержит такую ссылку, а не два координатных поля напрямую.

[Состояние представления классом](https://www.youtube.com/watch?v=z51K0UhriOk&t=2106s) показано ниже. Это заменяет прежнее определение структуры; два объявления не подразумеваются как сосуществующие:

```csharp

Position tree = new Position();

class Position
{
    public int X = 1;
    public int Y = 1;
}
```

[00:35:21](https://www.youtube.com/watch?v=z51K0UhriOk&t=2121s) Ячейка временной памяти для `enemy` хранит ссылку на объект. [00:35:30](https://www.youtube.com/watch?v=z51K0UhriOk&t=2130s) Поэтому она не хранит X и Y напрямую, как это делала прежняя ячейка структуры.

1. [00:35:41](https://www.youtube.com/watch?v=z51K0UhriOk&t=2141s) Создайте объект врага с его собственными полями X и Y. В этой демонстрации класса инициализаторы полей задают оба поля равными 1.
2. [00:35:59](https://www.youtube.com/watch?v=z51K0UhriOk&t=2159s) Сохраните ссылку на местоположение этого объекта в переменной врага.

Ссылки занимают рабочие ячейки вызывающей стороны; три отдельно созданных объекта хранят сами поля в динамическом хранилище. Выбор класса меняет это представление даже там, где исходные выражения всё ещё выглядят знакомыми.

## Копируем ссылку и пишем в общий объект

[00:36:45](https://www.youtube.com/watch?v=z51K0UhriOk&t=2205s) При повторном входе в функцию в модели временного стека создаются её рабочие локальные переменные и хранилище параметров. [00:36:52](https://www.youtube.com/watch?v=z51K0UhriOk&t=2212s) Поскольку `Position` теперь класс, обычная ячейка параметра хранит ссылку, а не копию полей X/Y объекта.

[Трассировка изменения параметра-класса](https://www.youtube.com/watch?v=z51K0UhriOk&t=2212s) представлена обычным вызовом без модификатора `ref`:

```csharp

Change(enemy);
Console.WriteLine(enemy.X); // 7

static void Change(Position a)
{
    a.X = 7;
}
```

1. Скопируйте значение ссылки из переменной вызывающей стороны в параметр `a`.
2. [00:37:11](https://www.youtube.com/watch?v=z51K0UhriOk&t=2231s) Пройдите по этой ссылке к объекту в динамическом хранилище.
3. [00:37:32](https://www.youtube.com/watch?v=z51K0UhriOk&t=2252s) Выберите поле X объекта через `a.X`. Обращение к полю достигает поля объекта, а не приватного целочисленного поля, встроенного в ячейку параметра `a`. Такое использование ссылки не является новым неявным параметром `ref`.
4. [00:37:41](https://www.youtube.com/watch?v=z51K0UhriOk&t=2261s) Запишите 7 в это поле. Иллюстративный адрес 64 на схеме идентифицирует общий объект; это не гарантированный машинный адрес.
5. [00:37:58](https://www.youtube.com/watch?v=z51K0UhriOk&t=2278s) Копировалась только ссылка, поэтому переменная врага и `a` обе достигают объекта, у которого изменилось X.
6. [00:38:11](https://www.youtube.com/watch?v=z51K0UhriOk&t=2291s) Чтение X через ссылку вызывающей стороны сразу замечает эту запись. Завершение хранилища параметров функции не отменяет уже сделанного изменения объекта.

Это **побочный эффект**, изменение вне приватных локальных данных вызываемой функции. Он возникает потому, что скопированная ссылка достигает общего хранилища объекта. Он не требует делать псевдонимом саму ссылочную переменную вызывающей стороны через `ref`.

## Сравниваем одну и ту же запись в поле для двух типов

[00:38:22](https://www.youtube.com/watch?v=z51K0UhriOk&t=2302s) Сравните класс с прежним типом значения, оставив выражение записи в поле неизменным. [Сравнение представлений](https://www.youtube.com/watch?v=z51K0UhriOk&t=2302s) сосредоточено на:

```csharp
static void Change(Position a)
{
    a.X = 7;
}
```

- Если `Position` объявлен как структура, а параметр обычный, `a` содержит скопированные поля. Запись затрагивает значение позиции вызываемой функции.
- Если `Position` объявлен как класс, а параметр обычный, `a` содержит скопированную ссылку. Запись затрагивает объект, до которого дотягивается и вызывающая сторона.

[00:38:51](https://www.youtube.com/watch?v=z51K0UhriOk&t=2331s) Один и тот же синтаксис с точкой не рассказывает всей истории о хранилище. Сначала определите тип, затем то, что содержит переменная, затем то, что копирует вызов, и наконец то, куда попадает запись. Такое рассуждение облегчает понимание последующих абстракций языка.

<details>
<summary>Почему обычная передача класса всё ещё является передачей по значению, хотя вызывающая сторона видит изменённое X?</summary>

Копируется значение, и это значение — ссылка. Ссылочная переменная вызывающей стороны и параметр различны, но обе ссылаются на один объект. Запись в поле меняет этот объект; это не доказывает, что переменная вызывающей стороны была передана через ref.

</details>

## Точно формулируем, что копирует передача по значению

[00:39:06](https://www.youtube.com/watch?v=z51K0UhriOk&t=2346s) Сформулируйте итоговое правило точно: обычные аргументы C# передаются **по значению**. Что копируется, зависит от того, что содержит переменная-аргумент.

[Заключительное различение копий](https://www.youtube.com/watch?v=z51K0UhriOk&t=2346s) резюмируется так:

```text
struct Position argument -> copy of its X/Y value
class Position argument  -> copy of its object reference
explicit ref argument    -> alias to the caller's variable
```

[00:39:16](https://www.youtube.com/watch?v=z51K0UhriOk&t=2356s) Позиция-тип значения хранит значение координаты напрямую; позиция-ссылочный тип хранит ссылку на объект. Обычные вызовы копируют соответствующие значения. Фраза «всегда по значению» в заключительном объяснении касается именно этих обычных вызовов; явно продемонстрированный режим `ref` — другой режим. Более ранняя передача возвращаемого значения не вводила `out`, ещё один отличный режим параметров.

Так одно правило объясняет оба примера, не смешивая скопированную ссылку на объект с псевдонимом на переменную вызывающей стороны.

## Область видимости и дальнейшая практика

[00:28:10](https://www.youtube.com/watch?v=z51K0UhriOk&t=1690s) Урок намеренно показывает промежуточную версию, которая группирует поля позиции, всё ещё передавая отдельные целочисленные координаты. Затем он группирует параметры. Это два различных улучшения.

[00:33:27](https://www.youtube.com/watch?v=z51K0UhriOk&t=2007s) Демонстрация `ref` — это предварительный обзор и, скорее всего, не нужна для текущих лабораторных. [00:34:34](https://www.youtube.com/watch?v=z51K0UhriOk&t=2074s) Вместо этого курс движется к классам. [00:34:40](https://www.youtube.com/watch?v=z51K0UhriOk&t=2080s) Здесь классы служат для противопоставления хранения значения и хранения объекта по ссылке, а не для разработки полного объектно-ориентированного проектирования.

Вычисление считает шаги по горизонтали и вертикали в показанной сетке. Запись не реализует полноценную игру, поиск пути с учётом препятствий, диагональное перемещение, массивы или цикл по сущностям. Её коробки памяти объясняют область видимости, копирование аргументов, возврат и изменение общего объекта. Точная раскладка, оптимизации компилятора и полное изложение управления памятью остаются за рамками этой модели. Проходы про возвращаемое значение не учат выходным параметрам и разбору ввода из консоли.

Для необязательной практики сверх этой записи используйте [лабораторную по функциям](../../../labs/1_basic/05_functions.md), чтобы рассуждать о локальных переменных, вызовах, типах возврата и вложенных выражениях. Её упражнение на рекурсию заходит дальше этого урока. [Лабораторная по улучшению программы](../../../labs/1_basic/13_improvement_techniques.md) применяет сгруппированные данные и выделенные функции к библиотеке книг вместе с массивами и циклами, здесь не преподаваемыми.

Просмотренный [связанный пример из репозитория на коммите d5af1fb](https://github.com/AntonC9018/uniCourse_csharp/blob/d5af1fb372be56a453e3b139990013c28e50198c/examples/property_dict/Subclassing.cs) тоже принимает две сгруппированные позиции. Его релевантный фрагмент, сокращённый из этого зафиксированного файла, имеет вид:

```csharp
static float Distance(Position a, Position b)
{
    var diff = new Position(a.X - b.X, a.Y - b.Y);
    var dist = (float)Math.Sqrt(
        diff.X * diff.X + diff.Y * diff.Y);
    return dist;
}

record struct Position(float X, float Y);
```

Это связанный код, а не точная или финальная версия программы из видео. Здесь используется record struct с координатами с плавающей точкой и евклидово расстояние, то есть метрика прямой. Синтаксис record, арифметика с плавающей точкой и формула с квадратным корнем в этой записи не преподаются. При восстановлении примера с сеткой сохраняйте целочисленную сумму модулей разностей из видео.
