# Ввод с консоли, out-параметры и валидация

## Цель и термины

[00:00:00](https://www.youtube.com/watch?v=SSTFFX5heuY&t=0s) Цель — превратить текст, введённый в консоли, в пригодные для использования числа, не перезапуская программу после каждой опечатки. Построение идёт от блокирующего чтения к преобразованию, к out-параметру, к циклу с повтором, к переиспользуемой функции ввода и, наконец, к валидации нескольких значений вместе.

Для этого построения нужен следующий словарь терминов:

- **Ввод и вывод в консоль:** текст, получаемый из консоли или отправляемый в неё. **Семейство методов Console** включает такие функции, как **Console.ReadLine**, читающая строку; **Console.Write**, печатающая без добавления перевода строки; и **Console.WriteLine**, печатающая и добавляющая перевод строки.
- **Последовательное выполнение и блокировка:** инструкции обычно выполняются одна за другой, сверху вниз. Блокирующая инструкция ждёт события, прежде чем сможет выполниться следующая.
- **string, int и bool:** string — это текст, int хранит целое число, а bool — true или false. Ввод цифр сам по себе не превращает string в int.
- **Nullable-ввод, null и перенаправленный ввод:** nullable-строка, записываемая как **string?**, может содержать текст или null, то есть отсутствие строкового значения. Перенаправленный ввод поступает из источника вроде файла, а не из живой консоли. **Конец ввода** означает, что в источнике больше нет строк.
- **Оператор подавления null:** постфиксный **!** говорит анализу nullability в компиляторе считать выражение отличным от null. Он подавляет предупреждение, но не подставляет недостающее значение.
- **Конкатенация и арифметика:** конкатенация соединяет строки; арифметика выполняет числовые операции. Смысл **+** зависит от типов операндов.
- **Разбор, int.Parse и исключения:** разбор (parsing) преобразует текстовое представление в значение. int.Parse возвращает целое число для подходящего числового текста. Исключение — это сигнал об ошибке времени выполнения; необработанное исключение останавливает эту демонстрационную программу.
- **Параметр, аргумент и out-параметр:** параметр — именованный входной или выходной слот в объявлении функции; аргумент — то, что передаёт вызывающий код. out-параметр позволяет функции инициализировать переменную, принадлежащую вызывающему коду.
- **Локальная переменная, стек, адрес, ссылка и инициализация:** локальная переменная принадлежит блоку или функции. Стек — учебная модель временного хранилища вызовов. Адрес идентифицирует место хранения; ссылка даёт доступ к этому месту. Инициализация записывает первое пригодное значение переменной.
- **Выражение вызова и возвращаемое значение:** вызов функции сам по себе может давать значение. **return** завершает функцию и может передать это значение вызывающему коду. Функция **void** не имеет возвращаемого значения; **static** вспомогательная функция вызывается без экземпляра объекта.
- **int.TryParse, inline-объявление out и флаг успеха:** TryParse пытается выполнить преобразование, записывает целое число через out и возвращает bool, показывающий успех. Inline-объявление out создаёт эту выходную переменную прямо на месте вызова. Флаг — это переменная, фиксирующая состояние «да или нет».
- **Область видимости и время жизни:** область видимости определяет, где имя можно использовать; время жизни — как долго нужно его хранилище. Перенос кода в блок или функцию меняет то, какие переменные он может видеть.
- **Цикл и итерация:** цикл повторяет тело; итерация — один проход по нему. **while** проверяет условие до тела; **do-while** — после тела. **while (true)** — бесконечный цикл, пока его явно не покинут.
- **Операторы условия:** префиксный **!** означает логическое отрицание bool, а **||** — «или». Условие — это выражение, истинный или ложный результат которого управляет веткой или циклом.
- **Ветвление, метка, goto, continue и break:** ветвь **if** выполняется, когда её условие истинно. Метка задаёт точку перехода для goto. continue пропускает остаток текущей итерации; break выходит из цикла.
- **Выделение функции и абстракция:** выделение переносит повторяющуюся логику в функцию. Получившаяся абстракция даёт вызывающему коду именованную операцию, скрывая шаги её реализации.
- **Класс, объект, поле, метод и new:** класс описывает объекты; объект хранит значения в полях; метод — функция, связанная с типом или объектом. Выражение new создаёт объект.
- **Валидация и правила допустимости:** валидация проверяет, корректны ли значения и допустимы ли они для программы. Возможность разбора — одно требование; выполнение правил вроде «B должно быть не меньше 2A» — другое.
- **Отладка:** изучение хода выполнения и промежуточных значений, чтобы понять, почему поведение отличается от задуманного.

Связанная [лабораторная работа про ввод с консоли](../../../labs/1_basic/08_input.md) даёт практику по разбору, out-параметрам и повторному вводу. Код её упражнения — учебная справка, а не сохранённая последовательность правок из записи.

[00:02:24](https://www.youtube.com/watch?v=SSTFFX5heuY&t=144s) У чтения есть результат: **nullable-строка**, записываемая как string?. [00:02:35](https://www.youtube.com/watch?v=SSTFFX5heuY&t=155s) Такая возможность существует, потому что ввод не обязан приходить из живой консоли. [00:02:50](https://www.youtube.com/watch?v=SSTFFX5heuY&t=170s) При **перенаправленном вводе** строки предоставляет файл. Когда в нём больше нет строк, ReadLine может вернуть null, а не пустую строку. [00:03:06](https://www.youtube.com/watch?v=SSTFFX5heuY&t=186s) Для демонстрации предполагается, что интерактивный пользователь введёт строку. [00:03:30](https://www.youtube.com/watch?v=SSTFFX5heuY&t=210s) **Оператор подавления null** — это восклицательный знак после выражения. ## out-параметр пишет в переменную вызывающего кода

[00:07:21](https://www.youtube.com/watch?v=SSTFFX5heuY&t=441s) Прежде чем заменить Parse, познакомимся с **out-параметрами**. Out-параметр даёт вызываемой функции доступ к переменной вызывающего кода, которую она обязана инициализировать. [00:07:23](https://www.youtube.com/watch?v=SSTFFX5heuY&t=443s) Именно этот механизм позволит преобразованию отдельно сообщать число и успех.

[00:07:29](https://www.youtube.com/watch?v=SSTFFX5heuY&t=449s) Небольшая демонстрация оставляет в целом числе вызывающего кода значение 5. Переменная вызывающего кода сначала обсуждается как p, а позже как a; имена не создают связи. Упрощённая версия этого состояния из видео:

```csharp
int p;
OutExample(out p);
Console.WriteLine(p);

static void OutExample(out int output)
{
    output = 5;
}
```

Здесь void означает, что вызов не даёт отдельного возвращаемого значения. Static-вспомогательная функция вызывается без создания объекта. Модификатор out встречается и в объявлении параметра функции, и в аргументе на месте вызова.

## TryParse отделяет успех от числа

[00:12:58](https://www.youtube.com/watch?v=SSTFFX5heuY&t=778s) **int.TryParse** пытается разобрать строку. Он записывает целое число в свой out-аргумент и возвращает bool, сообщающий, удался ли разбор. Упрощённое демонстрационное состояние из видео:

```csharp
string text = "1234";

Console.WriteLine(b);
Console.WriteLine(a);
```

Роли параметров важны: text — вход, a получает число, b получает признак успеха. Изменение имён не меняет их ролей.

- [00:13:15](https://www.youtube.com/watch?v=SSTFFX5heuY&t=795s) При 1234 значение b равно true, а a равно 1234.

[00:13:52](https://www.youtube.com/watch?v=SSTFFX5heuY&t=832s) **Inline-объявление out** объявляет переменную на месте вызова и сразу передаёт её ссылку. Следующее изменение синтаксиса:

```csharp

```

int в out int value объявляет value прямо там. Напротив, out value ссылается на уже объявленную переменную.

## Строим цикл с повтором

[00:20:28](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1228s) Успешный разбор нуля или отрицательного значения тоже должен запускать ещё одну итерацию.

Предложенное сжатое состояние из видео можно проиллюстрировать так; это отвергаемый альтернативный вариант, а не окончательная форма вспомогательной функции:

```csharp
int value;
do
{
    Console.Write("Enter a positive integer: ");

while (!int.TryParse(Console.ReadLine()!, out value) || value <= 0);
```

Здесь || означает «или»: повторять при неудачном разборе или неприемлемом разобранном значении. Чтение происходит до того, как его результат может быть разобран, но в одно условие втиснуто сразу несколько операций.

[00:20:42](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1242s) Настоятельное исправление — перестать сжимать операции в одну строку. ## Валидируем значения вместе

[00:21:16](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1276s) Переходим от чтения одного пригодного числа к **валидации**: решению, корректны ли значения и допустимы ли они по правилам программы.

[00:21:21](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1281s) Теперь класс хранит A и B в полях. **Класс** описывает данные, **объект** — экземпляр, содержащий эти данные, а **поле** хранит одно из значений. Чтение положительных целых в эти поля всё ещё не доказывает, что объект удовлетворяет всем правилам.

[00:21:26](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1286s) «Валидный» означает корректный и допустимый. [00:21:37](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1297s) Конкретное правило — B >= 2 * A: B должно быть не меньше двух A. [00:21:40](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1300s) Поместите проверку в метод валидации — функцию, связанную с объектом.

[00:21:45](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1305s) Возвращайте false при B < 2 * A. [00:21:50](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1310s) Иначе возвращайте true. Это начальное состояние валидации из видео эквивалентно:

```csharp
class Values
{
    public int A;
    public int B;

    public bool Validate()
    {
        if (B < 2 * A)
            return false;

        return true;
    }
}
```

Две ветви покрывают правило: равенство валидно, а всё, что меньше двух A, — нет.

[00:21:53](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1313s) Расширим пример до C и потребуем C > A + B. Один метод может проверять несколько правил. Проверка должна описывать **нарушение**, поэтому [00:22:25](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1345s) условие исправляется на C <= A + B перед возвратом false. Соответствующее промежуточное состояние из видео:

```csharp
// Inside Values, after adding a public int C field:
public bool Validate()
{
    if (B < 2 * A)
        return false;

    if (C <= A + B)
        return false;

    return true;
}
```

[00:22:03](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1323s) Задуманная схема — валидировать сразу после чтения значений, сохранять результат bool и запрашивать данные заново, когда результат равен false.

## Повторяем ввод для невалидных объектов

[00:22:28](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1348s) Обернём весь шаг ввода в цикл. Невалидные данные повторяют ввод; валидные завершают цикл. С уже имеющейся вспомогательной функцией InputInt упрощённое состояние ввода объекта из видео:

```csharp
Values data = new Values();
while (true)
{
    data.A = InputInt("A");
    data.B = InputInt("B");
    data.C = InputInt("C");

    bool isValid = data.Validate();
    if (isValid)
        break;
}
```

Выражение new создаёт объект. Обращение через точку записывает его поля или вызывает его метод. Переменная isValid вызывающего кода — это **флаг**, bool, фиксирующий, удовлетворяет ли весь объект правилам.

[00:23:02](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1382s) В зафиксированном запуске ввод повторяется, пока не будут введены валидные данные. Результат валидации напрямую определяет, остановится ли цикл.

[00:23:18](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1398s) Первый недостаток — слабая обратная связь: пользователю не сообщают, почему объект не прошёл валидацию. [00:23:26](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1406s) Другое наблюдение: проверки правил можно рассматривать независимо, а не сливать в одно сложное условие.

[00:23:36](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1416s) В принципе некоторые проверки можно перенести в процедуру чтения и выполнять по мере поступления нужных значений. Урок намеренно этого не делает. Демонстрируемая форма остаётся такой: сначала ввод, затем валидация объекта.

## Объясняем первое нарушенное правило

[00:24:07](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1447s) Улучшим обратную связь, печатая точное правило, которое не выполнено. [00:24:17](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1457s) Вместо того чтобы просто вернуть false, объявите нарушенное правило перед возвратом. Упрощённое промежуточное состояние валидации из видео:

```csharp
public bool Validate()
{
    if (B < 2 * A)
    {
        Console.WriteLine("B must be at least twice A.");
        return false;
    }

    if (C <= A + B)
    {
        Console.WriteLine("C must be greater than A + B.");
        return false;
    }

    return true;
}
```

[00:24:22](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1462s) Когда нарушены оба правила, эта версия печатает только первую ошибку. [00:24:34](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1474s) Первый return завершает функцию валидации; оставшееся правило при этом вызове не проверяется. Окружающий цикл ввода может продолжаться, но текущий вызов валидации завершён.

<details>
<summary>Предсказание: если поменять две проверки местами, эта версия сообщит обо всех ошибках?</summary>

Нет. Это изменит только то, какая ошибка появится первой. Первое нарушенное правило всё равно завершит функцию до проверки второго правила.

</details>

## Сообщаем обо всех нарушенных правилах

[00:24:39](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1479s) Чтобы сообщать о каждом нарушенном правиле, перестанем возвращать управление из ветвей отказа. Вместо этого используйте **флаг isValid** — bool, который помнит, не провалилась ли какая-нибудь проверка.

[00:24:44](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1484s) Каждая ветвь устанавливает флаг, позволяя функции продолжаться. [00:24:50](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1490s) Флаг возвращается только после выполнения всех проверок. Рабочая форма этого итогового состояния валидации из видео:

```csharp
public bool Validate()
{
    bool isValid = true;

    if (B < 2 * A)
    {
        Console.WriteLine("B must be at least twice A.");
        isValid = false;
    }

    if (C <= A + B)
    {
        Console.WriteLine("C must be greater than A + B.");
        isValid = false;
    }

    return isValid;
}
```

Начальное значение должно быть true: объект остаётся валидным, пока правило не нарушено. Начав с isValid = false и присваивая false только в этих ветвях, мы отвергали бы любой объект, в том числе удовлетворяющий всем правилам. Именно такая инициализация требуется объяснению и итоговому результату для валидного ввода; false принадлежит ветвям отказа.

[00:25:02](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1502s) Попадание даже в одну ветвь отказа делает итоговый ответ равным false. Более позднее выполненное правило не возвращает true. [00:25:06](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1506s) Каждое нарушенное условие печатает своё сообщение, потому что выполнение продолжается к оставшимся проверкам.

Следуйте процедуре:

1. В начале каждого вызова предполагайте валидность.
2. Проверьте одно правило и напечатайте сообщение, если оно нарушено.
3. Зафиксируйте false для этого нарушения, затем продолжайте проверки.
4. Повторите для каждого правила.
5. Один раз верните накопленный вердикт.

Вызывающий код по-прежнему получает один bool. Пользователь видит несколько напечатанных ошибок, но вызывающий код не получил список этих ошибок как данные.

## Итоговые проверки и их границы

[00:25:26](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1526s) Достаточно одного нарушенного правила допустимости, чтобы весь объект стал невалидным. Метод всё же проверяет каждое правило отдельно, чтобы можно было объявить каждое нарушение. Итоговые проверки из видео используют два правила, B >= 2 * A и C > A + B; оба должны выполняться, чтобы объект в целом был валиден.

Зафиксированные проверки и их смысл:

| Проверка в видео | A, B, C | B >= 2 * A | C > A + B | Результат |
| --- | --- | --- | --- | --- |
| [00:25:32](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1532s) | 2, 3, 1 | False: 3 < 4 | False: 1 <= 5 | Два сообщения об ошибке; валидация false |
| [00:25:39](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1539s) | 2, 5, 4 | True: 5 >= 4 | False: 4 <= 7 | Одно сообщение об ошибке; валидация всё равно false |
| [00:25:45](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1545s) | Значения, удовлетворяющие обоим правилам | True | True | Сообщений об ошибках нет; валидация true |

Два сообщения в первом запуске означают два **нарушения**, а не два выполненных пункта. Выполненное правило во втором запуске не отменяет отказа другого правила. Запуск с валидным вводом проходит без объявления нарушений; этот метод валидации возвращает bool и не выбрасывает исключение.

Для компактной реконструкции итогового поведения из видео соединим этот метод с таким вызывающим кодом:

```csharp
bool isValid = data.Validate();
if (isValid)
    break; // inside the surrounding input loop
```

[00:25:52](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1552s) Когда валидация возвращает true, вызывающий код достигает break и покидает цикл ввода. Этот break — успешный выход, а не завершение из-за нарушенного правила. В более ранней версии return false завершал метод валидации досрочно; в итоговой версии ветви отказа продолжают проверки.

[00:26:00](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1560s) Этот подход подходит вызывающему коду, которому нужен только ответ «да или нет» о допустимости, тогда как пользователь получает напечатанное объяснение. [00:26:03](https://www.youtube.com/watch?v=SSTFFX5heuY&t=1563s) Если вызывающий код должен знать, какие именно правила не выполнены, нужны более продвинутые техники отчётности, и они намеренно отложены.

<details>
<summary>Самобъяснение: почему A = 2, B = 5, C = 4 остаётся невалидным?</summary>

B удовлетворяет первому правилу, но C должно превышать A + B, то есть 7. C = 4 нарушает это второе правило. Любое одно невыполненное правило делает результат валидации всего объекта равным false.

</details>
