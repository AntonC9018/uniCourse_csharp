# Организация игры: статические методы и методы экземпляра

[00:00:04](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=4s) Этот урок продолжает боевую программу из предыдущего видео. Его первая цель — разделить единственный исходный файл на несколько файлов; более широкая цель — показать, относятся ли данные и поведение к типу, к одному объекту или к конкретной игре. Следуйте за изменениями по порядку: перенести объявления, ввести статический контейнер утилит, попробовать и отвергнуть глобальный счётчик, добавить фабрики, превратить операции в методы экземпляра, вынести операцию в метод расширения и, наконец, объяснить код верхнего уровня и локальные функции.

Термины, которые понадобятся на этом пути:

- **Исходный файл, проект, компилятор и диагностика:** исходный файл содержит текст на C#; проект группирует файлы, компилируемые вместе; компилятор переводит этот текст и проверяет его правила; диагностика сообщает об ошибке или предупреждении.
- **Операторы верхнего уровня и точка входа:** операторы верхнего уровня — это исполняемые инструкции, написанные вне явного метода. Точка входа — место, где начинается выполнение программы.
- **Тип, класс, структура, объект, экземпляр и ссылка:** тип описывает значения и операции над ними. Класс описывает объекты ссылочного типа; структура описывает экземпляры типа значений. Объект — это экземпляр типа, а ссылка указывает на конкретный объект.
- **Поле, метод и член:** поле хранит данные; метод — это функция, объявленная в типе; «член» — общее имя для обоих понятий. «Функция-член» означает метод.
- **Статический класс, статический член и член экземпляра:** статический класс — это контейнер уровня типа, который нельзя инстанцировать. Статический член принадлежит типу; член экземпляра принадлежит конкретному экземпляру или действует на него.
- **Квалификация, точка и `public`:** квалификация указывает владельца члена; точка в `Owner.Member` выбирает этот член; `public` разрешает доступ к нему из другого кода.
- **Параметр, аргумент, сигнатура, получатель и `this`:** параметр объявляет вход функции; аргумент передаёт его при вызове; сигнатура определяет метод и типы объявленных параметров. Получатель — это объект, на котором вызывается метод экземпляра; `this` ссылается на текущий объект. «Скрытый первый параметр» — это модель получателя в рамках урока, а не дополнительный параметр, записываемый в C#.
- **Состояние, характеристики, глобальное состояние, изменяемое и неизменяемое:** состояние — текущие данные игры; характеристики (stats) — значения здоровья и атаки. Глобальное состояние разделяется за пределами конкретного объекта игры. Изменяемые данные могут меняться; неизменяемые данные не меняются после инициализации.
- **Фабрика, инициализация, инициализатор объекта и `new`:** фабрика создаёт и возвращает готовый к использованию объект. Инициализация задаёт начальные значения; инициализатор объекта задаёт значения полей при создании; `new` создаёт экземпляр.
- **Счётчик, инкремент, целое число и константа:** счётчик считает количество событий; инкремент прибавляет единицу; `int` хранит целое число. Константа — это фиксированное значение, а не изменяющееся состояние игры.
- **Логическое значение, выражение, вычисление, присваивание, условие и `return`:** `bool` хранит `true` или `false`; выражение вычисляет значение; вычисление получает этот результат; присваивание сохраняет его; условие проверяет логическое значение; `return` возвращает результат и завершает текущую функцию. `void` означает, что результат не возвращается.
- **Список и игровой цикл:** `List<Enemy>` — расширяемая коллекция объектов врагов; игровой цикл повторяет бои до выполнения условия остановки. Это уже существующие части программы, а не новые алгоритмы работы с коллекциями.
- **Сериализация:** преобразование состояния в представление, которое можно сохранить или передать, а затем восстановить.
- **Метод расширения:** статический метод, у которого первый параметр помечен `this`, что позволяет вызывать его в объектном стиле, оставляя объявление в отдельном статическом классе.
- **Область видимости, локальная функция, захват и затенение:** область видимости — это место, где можно использовать имя; локальная функция объявлена внутри другой функции; захват позволяет ей использовать данные объемлющих локальных переменных; затенение — это коллизия имён, при которой одно объявление скрывает другое.
- **Аргументы командной строки, паттерн «строитель» и инкапсуляция:** аргументы командной строки — входные данные, передаваемые при запуске программы; «строитель» (builder) собирает или настраивает что-то последовательными операциями; инкапсуляция управляет тем, как обращаются к данным объекта. Эти темы лишь названы, чтобы отметить будущий материал курса.

[Лабораторная по статическому классу](../../../labs/1_basic/15_static_class.md) предлагает перенести существующие функции в класс `Functions` в новом файле. [Лабораторная по методам экземпляра](../../../labs/1_basic/16_method.md) применяет превращение в методы с получателем к абстракции библиотеки. Это связанные упражнения, а не зафиксированные копии боевой программы.

В проверенной рабочей копии не нашлось точного зафиксированного исходного файла боевой программы. Все примеры ниже — упрощённая реконструкция состояния из связанного видео, а не точная зафиксированная программа. Неизменяемый транскрипт является подтверждающим материалом для записи, а не коммитом с исходным кодом боевой программы.

## Разделяем программу на исходные файлы

[00:00:04](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=4s) Изначально у игры есть один **исходный файл** — `Program.cs`. [00:00:09](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=9s) В этом **проекте** исходные файлы, лежащие рядом с файлом проекта или во вложенных папках, подхватываются автоматически. Это описание поведения включения по умолчанию в показанном проекте, а не гарантия для любого изменённого проекта.

[00:00:33](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=33s) **Операторы верхнего уровня** — это инструкции, написанные прямо в главном исходном файле, вне явно объявленного метода. Они выполняются из сгенерированной **точки входа** при запуске программы. Имя файла `Program.cs` — соглашение; важен именно его код верхнего уровня.

[Связанный неизменяемый транскрипт](https://github.com/AntonC9018/uniCourse_csharp/blob/4814706ae2fafbc797829239a33afc2eeefa29e8/videos/csharp/09_C%23_Применения_static,_instance_методы,_this,_extension_методы/internal/transcript.md) фиксирует исходную конструкцию. Это сокращённое начальное состояние объединяет исполняемую инструкцию с объявлением класса:

```csharp
// Program.cs — before splitting
Console.WriteLine("Game starts");

class Stats
{
    public int Health;
    public int Attack;
}
```

[00:00:45](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=45s) Если добавить ещё одну исполняемую верхнеуровневую инструкцию во второй файл, компилятор выдаст ошибку: в проекте только в одном файле могут быть операторы верхнего уровня. **Диагностика** — это сообщение компилятора о такой недопустимой структуре; второй файл полезен, но не может предоставить ещё одну верхнеуровневую точку входа.

[00:01:13](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=73s) Вместо этого переносите **объявления типов**, например классы:

1. [00:01:20](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=80s) Вырежьте объявления классов из `Program.cs`.
2. Вставьте их в новый `Logic.cs` в том же проекте.
3. [00:01:38](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=98s) Продолжайте обращаться к этим типам из главного файла. Переход к определению теперь ведёт к объявлению в другом файле.

**Класс** определяет поля и операции своих объектов; **поле** хранит данные. Разделённое состояние из видео можно представить так:

```csharp
// Program.cs
Stats player = new Stats { Health = 10, Attack = 1 };

// Logic.cs
class Stats
{
    public int Health;
    public int Attack;
}
```

[00:01:20](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=80s) Здесь не нужно добавлять никакой связки между файлами: перенесённые типы остаются доступны по тем же правилам именования и видимости. «Всё доступно» в записи означает именно эти объявления. Верхнеуровневая локальная переменная вроде `player` не становится глобальной переменной, доступной из произвольных методов другого файла.

## Переносим функции в статический класс

[00:01:56](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=116s) Функцию нельзя просто перенести в другой обычный файл как свободную функцию в стиле C/C++. Функции, написанные рядом с операторами верхнего уровня, являются локальными для сгенерированного тела точки входа, а не глобально объявленными функциями.

[00:02:10](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=130s) Именам нужен контейнер. [00:02:26](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=146s) Здесь рассматриваются объявления, которые являются **типами**, в частности классами и структурами; это не исчерпывающий перечень всех объявлений C#. [00:02:36](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=156s) Поместите перенесённые функции внутрь класса. [00:02:38](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=158s) **Статический класс** удобен как контейнер для операций, которым не нужен объект-контейнер.

Следуйте этой реконструкции изменения:

1. Перенесите функцию из файла верхнего уровня в `Logic`.
2. Пометьте класс и его методы как `static`.
3. [00:02:46](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=166s) Измените внешние вызовы так, чтобы они содержали имя класса.
4. [00:03:01](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=181s) Используйте точку для выбора метода внутри этого класса.

```csharp
// Program.cs — changed call
Logic.TakeDamage(player, 2);

// Logic.cs — moved operation
static class Logic
{
    public static void TakeDamage(Stats target, int amount)
    {
        target.Health -= amount;
    }
}
```

**Квалификация** называет владельца: `Logic.TakeDamage` выбирает метод из типа `Logic`. `public` делает метод доступным вызывающим; `void` говорит, что значение не возвращается; `target` и `amount` — объявленные **параметры**, а `player` и `2` — переданные **аргументы**. Присваивание с вычитанием изменяет здоровье на переданное значение.

[00:02:54](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=174s) Более подробный смысл префикса с именем класса пока отложен. На этом этапе просто используйте форму вызова и увидьте, что операция по-прежнему явно получает свои данные.

[00:03:18](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=198s) Попытка добавить обычное, нестатическое поле в этот статический класс приводит к ошибке компилятора. Точное правило: статический класс не может содержать полей **экземпляра**; статические поля разрешены, как показывает следующая демонстрация. [00:03:33](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=213s) Попытка создать объект `Logic` тоже не работает: статический класс нельзя инстанцировать. Соответствующие отвергнутые эксперименты из состояния видео:

```csharp
// Invalid experiments:
static class Logic
{
    public int Count; // instance field in a static class
}
// new Logic();        // a static class cannot be instantiated
```

Эти ограничения описаны в [справочнике Microsoft по статическим классам](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/static-classes-and-static-class-members).

[00:04:05](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=245s) Функция, объявленная в классе, называется **методом**; это статические методы. [00:04:14](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=254s) Более глубокий смысл `static` ненадолго откладывается, а затем раскрывается через поля и объекты.

## Имена членов класса

[00:04:20](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=260s) **Статический метод** принадлежит типу. Метод без `static` — это **метод экземпляра**, связанный с объектом, на котором он вызывается. Этот набросок состояния из видео показывает разницу в объявлениях до изменения реализации урона:

```csharp
class Stats
{
    public int Health;                   // instance field
    public static int SharedCount;       // static field
    public static void Utility() { }      // static method
    public void ActOnThisObject() { }     // instance method
}
```

[00:04:35](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=275s) **Член** — это общее слово здесь для поля или метода. [00:04:48](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=288s) «Функция-член» — другое название метода. В C# есть и другие категории членов, но именно поля и методы упорядочивает этот урок.

## Пробуем общий статический счётчик

[00:05:01](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=301s) **Изменяемое глобальное состояние** — это данные, которые несвязанные операции могут читать и менять. Урок не советует использовать статические поля для изменяющихся игровых данных, потому что это делает зависимости трудно заметными.

[00:05:12](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=312s) Нестатическое поле принадлежит объекту. [00:05:21](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=321s) Однако статический класс всё же может содержать **статическое поле**: оно принадлежит типу, а не какому-либо объекту. Это исправляет прежнее сокращённое объяснение «не может иметь полей».

[00:05:31](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=331s) Временно добавьте счётчик в класс утилит и увеличивайте его при добавлении врага. **Счётчик** считает, сколько событий произошло; `++` **увеличивает** его на единицу. Реконструированное промежуточное состояние:

```csharp
static class Logic
{
    public static int AddedEnemies;

    public static void AddEnemy(GameState state, Enemy enemy)
    {
        state.Enemies.Add(enemy);
        AddedEnemies++;
    }
}
```

[00:05:43](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=343s) Счётчик принадлежит `Logic` в целом. [00:05:54](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=354s) В этом обычном, необобщённом примере есть одно общее хранимое значение, а не своё на каждую игру или врага. Оно ведёт себя как глобальная переменная на всём протяжении запуска.

[00:06:05](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=365s) Внутри объявляющего класса достаточно написать `AddedEnemies`, чтобы назвать поле. [00:06:22](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=382s) `Logic.AddedEnemies` ссылается на то же поле. [00:06:32](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=392s) За пределами этого класса квалифицируйте его именем типа, например при выводе из главного кода:

```csharp
// Inside Logic:
AddedEnemies++;
// Equivalent qualification, shown separately:
Logic.AddedEnemies++;

// Outside Logic:
Console.WriteLine(Logic.AddedEnemies);
```

Два приведённых выше инкремента показывают альтернативные варианты записи; писать оба означало бы увеличить счётчик дважды.

[00:06:39](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=399s) Поскольку в этом примере поле публичное, другой код программы может обращаться к нему через `Logic.AddedEnemies`. Само по себе `static` не делает поле публичным. [00:06:48](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=408s) Вот в чём проблема такого подхода: любая функция может незаметно зависеть от счётчика или менять его.

[00:07:05](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=425s) Предпочтительнее делать нужные данные явными через параметры. Технически функция может получить значение из статического поля, но прямой доступ к глобальному состоянию не обязывает вызывающий код раскрывать эту зависимость. Формулировка урока про «невозможность» — это предупреждение о скрытых зависимостях, а не запрет языка на передачу данных.

## Переносим счётчик в состояние игры

[00:07:14](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=434s) **Состояние игры** — это данные, описывающие одну запущенную игру. Существующий `GameState` группирует эти данные так, что одна переменная определяет текущий контекст игры.

[00:07:44](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=464s) Объект делает явными и зависимость, и местонахождение данных. ## Используем статические методы как фабрики

[00:09:30](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=570s) **Статический метод** привязан к типу, поэтому статический класс утилит — удобное место для функций, работающих со входами без поведения экземпляра. [00:09:37](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=577s) Статический метод можно разместить и в обычном классе. [00:09:49](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=589s) Класс любого из этих видов может вызвать публичный статический метод другого класса.

[00:10:02](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=602s) Внешний вызов остаётся `ClassName.MethodName(...)`: метод принадлежит классу, а экземпляр этого класса для его вызова не нужен. Подход со статическим классом — это организационное предпочтение для кода утилит, а не ограничение на круг возможных вызывающих.

[00:10:16](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=616s) Особенно полезная статическая операция — **фабрика**: функция, которая создаёт и возвращает инициализированный объект. [00:10:28](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=628s) Например, фабрика на `Stats` может возвращать объект `Stats`. [00:10:33](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=633s) Она может заранее инициализировать поля, чтобы каждому вызывающему не приходилось повторять присваивания.

Эта реконструкция состояния из видео показывает мотивацию и выделенную фабрику вместе:

```csharp
// Repeated construction before introducing the factory:
Stats ordinary = new Stats { Attack = 1, Health = 10 };

// Factory placed in the type it produces:
class Stats
{
    public int Attack;
    public int Health;

    public static Stats CreateDefault()
    {
        return new Stats { Attack = 1, Health = 10 };
    }
}

// Changed call:
Stats ordinary = Stats.CreateDefault();
```

Первое и последнее объявления — альтернативные этапы, а не два объявления для вставки в одну область видимости. `new` создаёт объект; **инициализатор объекта** задаёт значения его полей; `return` отдаёт эту ссылку вызывающему. **Инициализация** устанавливает начальное состояние. Фабрика статична потому, что для этого вызова нет уже созданного целевого объекта.

[00:10:56](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=656s) Фабрики часто привязывают к типу, который они производят. Давайте им имена, раскрывающие суть создания; имена вроде `CreateDefault` или `CreateDefaultStats` делают шаг создания читаемым.

[00:11:41](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=701s) Показанные значения по умолчанию — **атака 1 и здоровье 10**. Без этих присваиваний обычные целочисленные поля получают нуль; фабрика задаёт полезные игровые значения по умолчанию, а не делает видимыми поля, которых иначе не было бы.

[00:12:00](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=720s) Добавьте вторую фабрику для усиленных характеристик: **атака 5 и здоровье 10**. Упрощённое продолжение этого состояния из видео:

```csharp
// Inside Stats:
public static Stats CreateStrong()
{
    return new Stats { Attack = 5, Health = 10 };
}
```

[00:12:10](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=730s) Фабрике не обязательно жить в `Stats`; она может находиться в другом месте игровой логики, если её имя явно указывает на результат. [00:12:17](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=737s) Вызывайте фабрику по умолчанию для каждого обычного врага, чтобы все получали нужные значения. [00:12:40](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=760s) В записи экспериментируют с именем с префиксом `Create`, например `CreateDef`; переименование объявления и соответствующих вызовов сохраняет поведение.

```csharp

Stats strongStats = Stats.CreateStrong();
```

Каждый вызов создаёт свой собственный объект характеристик. [00:12:55](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=775s) Эта операция «создать и инициализировать» и есть паттерн **фабричной функции**. Урок демонстрирует паттерн, а не правило «каждый объект должен создаваться через фабрику».

## Разделяем данные типа и данные объекта

[00:13:05](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=785s) Обычный класс вроде `Enemy` тоже может содержать статическое поле. Чтение или увеличение его из главной программы по-прежнему использует имя типа. [00:13:19](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=799s) Все экземпляры врага разделяют это единственное значение; создание новых врагов не создаёт новых копий статического поля.

Промежуточную идею из состояния видео можно упростить:

```csharp

{
    public static int Count;
}

// In the main code:

Console.WriteLine(Enemy.Count);
```

[00:13:26](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=806s) Привязывайте изменяющиеся данные к тому, что они описывают: к игре, к команде или к конкретному врагу. Помещение счётчика в `Enemy` не решает проблему глобального владения, если поле остаётся статическим.

[00:13:45](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=825s) Уберите `static`, чтобы поле принадлежало экземпляру. **Ссылка** указывает на один объект, и у каждого **экземпляра** своя копия этого поля:

```

Это демонстрирует раздельное хранение; фактический счётчик всех добавленных врагов, как было установлено ранее, по-прежнему принадлежит `GameState`.

[00:14:05](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=845s) Поэтому класс может сочетать члены, привязанные к типу, и члены, привязанные к объектам. То же различие касается методов: операция уровня типа статична; операция уровня объекта имеет получателя.

## Превращаем обработку урона в метод экземпляра

Здесь **сигнатура** объявляет вход с объектом и вход с величиной урона. Вызов передаёт ссылку на характеристики цели и значение атаки.

[00:14:42](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=882s) Превратите операцию в **метод экземпляра**, то есть метод, действующий на конкретный объект:

2. Уберите `static`.
3. Уберите явно объявленный параметр `Stats target`.
4. [00:15:00](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=900s) Замените `target` в теле на `this` — текущий объект.
5. [00:15:15](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=915s) Измените вызов так, чтобы он начинался с объекта, а не с типа.

Изменённое состояние из видео:

```

[00:15:31](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=931s) Объект перед точкой — это **получатель**. Представление о нём как о «скрытом первом параметре» объясняет, откуда метод берёт свой объект, но это не параметр, который вы объявляете или передаёте в скобках. Контекст экземпляра предоставляет компилятор.

[00:15:53](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=953s) Вызывающему нужна ссылка на нужный объект. [00:15:59](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=959s) В новом вызове получателем является `enemyStats`. [00:16:14](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=974s) Компилятор находит метод по типу получателя, здесь — `Stats`. Он не превращается в объект, и в сигнатуру не нужно добавлять никакого параметра-смещения.

## Читаем поля экземпляра через this

[00:18:19](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1099s) Внутри метода экземпляра **`this`** означает объект, получающий вызов. Префикс часто можно опустить, когда неквалифицированное имя поля однозначно.

[00:18:32](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1112s) Сравните с прежним правилом для статических полей: внутри объявляющего класса квалификатор типа можно было опустить. Здесь необязательный квалификатор — это квалификатор **экземпляра** `this`, а не имя класса. [00:18:52](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1132s) К полю можно обращаться напрямую; запись `Stats.Attack` ошибочно пыталась бы обратиться к полю экземпляра через тип.

Сокращённые эквивалентные тела из этого объяснения состояния видео:

```csharp
// With an explicit receiver:
public void ReduceDamage()
{
    this.Attack--;
}

// Alternative spelling, when no local name hides Attack:
public void ReduceDamage()
{
    Attack--;
}
```

Выберите одно объявление. В этом примере оба изменяют поле получающего объекта. Если имя поля скрыто параметром или локальной переменной, квалификация помогает их различить.

[00:18:59](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1139s) **Экземпляр** — это объект данного типа, поэтому такие методы и называются методами экземпляра. Используемый в объяснении русский термин — «экземпляр», то есть объект. [00:19:21](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1161s) В записи остаётся нестатическая версия: её вызов задаёт цель через получателя, а её тело изменяет данные этой цели.

## Возвращаем и сохраняем признак смерти

[00:19:55](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1195s) Пауза для практики: напишите функцию, которая принимает характеристики и возвращает, меньше ли здоровье нуля или равно нулю. **Логический** результат — это либо `true`, либо `false`. Начальную статическую форму упражнения можно реконструировать так:

```csharp
public static bool IsDead(Stats target)
{
    return target.Health <= 0;
}
```

[00:20:01](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1201s) Сохраните ответ в переменной типа `bool`, а затем проверьте переменную. Это отделяет вычисление от его использования и даёт результату читаемое имя вместо того, чтобы вкладывать весь вызов в условие.

[00:20:09](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1209s) Превратите решение в метод экземпляра: уберите `static` и явный вход с характеристиками. [00:20:13](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1213s) Сохраните тип возврата `bool`; превращение в метод экземпляра не меняет то, что операция может вернуть.

```csharp
// Inside Stats:
public bool IsDead()
{
    return Health <= 0;
}

// At the call site:
bool playerIsDead = playerStats.IsDead();
if (playerIsDead)
{
    Console.WriteLine("The game is over");
}
```

[00:20:37](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1237s) Вызов — это просто объект, точка и имя метода. ## Выносим поведение в метод расширения

[00:22:01](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1321s) Следующая демонстрация спрашивает, может ли операция жить в другом месте, оставляя тип данных сосредоточенным на своих данных. [00:22:05](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1325s) Код метода можно перенести в отдельный файл, но перенос в другой класс меняет то, кто его объявляет. Обычный метод экземпляра по-прежнему должен быть объявлен в своём типе; внешняя форма, которая будет показана дальше, — это **метод расширения**.

[00:22:15](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1335s) Когда `IsDead` оказывается за пределами `Stats` и внутри класса утилит, он уже не может оставаться обычным методом экземпляра `Stats`. Это не значит, что вызовы в объектном стиле никогда не могут вызывать методы экземпляра — предыдущие примеры делают ровно это. Это значит, что метод, объявленный в другом контейнере, не является членом экземпляра типа получателя.

Следуйте промежуточной реконструкции:

1. Удалите показанное объявление `IsDead` из `Stats`.
2. [00:22:26](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1346s) Поместите статический метод в `Logic`, явно принимающий объект характеристик.
3. [00:22:38](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1358s) Сначала вызовите его как обычный статический метод.

```csharp
static class Logic
{
    public static bool IsDead(Stats target)
    {
        return target.Health <= 0;
    }
}

// Intermediate call:
bool playerIsDead = Logic.IsDead(playerStats);
```

У статического метода нет автоматического `this`, но он может читать данные экземпляра через объект, переданный параметром. Нужный вход здесь — это объект характеристик, а не какие-то «статические значения» внутри него.

[00:22:38](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1358s) Сам по себе перенос в другой класс не делает `playerStats.IsDead()` допустимым. [00:22:50](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1370s) Пометьте первый параметр словом `this`, чтобы разрешить такую форму вызова:

```csharp
static class Logic
{
    public static bool IsDead(this Stats target)
    {
        return target.Health <= 0;
    }
}

// Extension syntax:
bool playerIsDead = playerStats.IsDead();

// Equivalent explicit static call, shown separately:
bool sameAnswer = Logic.IsDead(playerStats);
```

Здесь **`this` у первого параметра** помечает метод расширения. Метод остаётся статическим; вызов в объектном стиле передаёт получателя как свой первый объявленный аргумент. Сам тип не получил нового обычного члена экземпляра. Удаление исходного метода экземпляра нужно, чтобы этот существующий член не перекрыл расширение.

[00:23:11](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1391s) Метод должен находиться внутри статического класса — этого требует синтаксис, изучаемый здесь. Перенос в нестатический класс даёт зафиксированную диагностику: методы расширения должны быть определены в статическом классе. Этот урок использует традиционный синтаксис с первым параметром; [справочник Microsoft по методам расширения](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/extension-methods) подтверждает, что это статические методы, вызываемые в синтаксисе экземпляра.

[00:23:41](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1421s) Такой стиль часто встречается в конфигурационном коде, в том числе в коде, использующем **паттерн «строитель»**, который собирает результат последовательными операциями настройки. [00:23:51](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1431s) Сам паттерн отложен; здесь строитель не реализуется.

[00:23:59](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1439s) Почему выбрать метод расширения, а не метод экземпляра? Этот вопрос проектирования явно отложен до изучения **инкапсуляции** — контроля над доступом к внутренностям объекта. Понимание текущего преобразования не требует решения этой более поздней задачи проектирования.

<details>
<summary>Стал ли IsDead методом экземпляра Stats после переноса в Logic?</summary>

Нет. Это статический метод в Logic. Пометка его первого параметра словом this разрешает вызов в стиле получателя и передаёт объект Stats в этот параметр.

</details>

## Разбираем сгенерированную точку входа

[00:24:11](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1451s) Вернёмся к специальному главному файлу. **Операторы верхнего уровня** — удобный синтаксис исходного кода: компилятор предоставляет окружающую структуру программы и точку входа.

[00:24:23](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1463s) В записи набрасывается класс `Program` со статическим `Main`, принимающим массив аргументов командной строки. Показанная форма — `public static int Main(string[] args)`. Относитесь к ней как к объясняющему эквиваленту в явном виде, а не как к точному имени, уровню доступа или типу возврата, гарантированным для генерируемого компилятором кода. Форма сгенерированной точки входа зависит от того, что делает программа верхнего уровня.

Эта сокращённая модель состояния из видео помещает исполняемые операторы и локальные функции внутрь метода:

```csharp
// Explicit explanatory equivalent, not exact compiler output:
class Program
{
    public static int Main(string[] args)
    {
        GameState state = new GameState();
        IncrementCounter(state);
        return 0;

        static void IncrementCounter(GameState gameState)
        {
            gameState.AddedEnemies++;
        }
    }
}
```

**Точка входа** — это метод, в котором начинается выполнение. **Аргументы командной строки** — входные данные времени запуска; `string[] args` — параметр, представляющий массив строк. [00:24:45](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1485s) Подробности их использования отложены.

[00:24:53](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1493s) Различайте порядок исходного кода и это концептуальное преобразование: в файле с операторами верхнего уровня исполняемый верхнеуровневый код должен предшествовать объявлениям пространств имён или типов. Определённые пользователем типы остаются объявлениями типов; компилятор не переносит каждое объявление в тело точки входа. Сгенерированная структура не обещает определённого текстового порядка «выше» или «ниже» типов. Правила точки входа и порядка исходного кода описаны в [справочнике Microsoft по операторам верхнего уровня](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/program-structure/top-level-statements).

[00:25:06](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1506s) Типы также могут объявляться внутри других типов. В записи прямо выражена неуверенность насчёт того, использует ли компилятор здесь такую схему; это не доказательство, что ваши собственные типы автоматически вкладываются друг в друга. [00:25:22](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1522s) Другие добавляемые компилятором детали, упомянутые в конце наброска, отложены на потом.

[00:25:28](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1528s) Статические функции, ранее написанные после основного исполняемого кода и до объявлений пользовательских типов, являются **локальными функциями** в теле точки входа. Они автоматически не становятся публичными служебными методами `Program`. Приведённая выше реконструкция показывает их локальное размещение и объясняет, почему перенос в явный класс утилит меняет их видимость.

## Делаем зависимости локальных функций явными

[00:25:41](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1541s) **Локальная функция** объявлена внутри другой функции. Её можно объявить даже после `return`: само объявление не является исполняемой инструкцией, поэтому оно не выполняется в этой точке и не мешает `return` завершить функцию.

Этот упрощённый пример из состояния видео показывает вызов до объявления, а объявление — после `return`:

```csharp
static int Main(string[] args)
{
    GameState state = new GameState();
    IncrementCounter(state);
    return 0;

    static void IncrementCounter(GameState gameState)
    {
        gameState.AddedEnemies++;
    }
}
```

[00:25:52](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1552s) Её **область видимости**, то есть область, где доступно её имя, находится внутри содержащей функции. [00:26:00](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1560s) Код за пределами `Main` не может просто вызвать эту локальную `IncrementCounter`; она не является членом класса, видимым для других методов.

[00:26:13](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1573s) Если локальная функция опустит `static`, она сможет обращаться к локальным переменным и параметрам объемлющей области. **Захват** — это использование этих внешних данных вместо требования явного входа. Это не значит, что компилятор жадно захватывает каждую локальную переменную независимо от того, используется она или нет.

[00:26:31](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1591s) В записи показана диагностика, связанная с именем, уже видимым из `Main`. Важная опасность — изменение источника имени: удаление явного параметра может привести к тому, что тело начнёт ссылаться на локальную переменную внешней области. **Затенение** — это скрытие одного имени другим; коллизии зависят от участвующих объявлений и областей видимости, поэтому показанная диагностика не является правилом о том, что любое совпадение имён всегда даёт одну и ту же ошибку.

Проблему захвата и альтернативу с явным входом можно реконструировать вместе:

```csharp
// Non-static local function in Main:
GameState state = new GameState();
IncrementCounter();

void IncrementCounter()
{
    state.AddedEnemies++; // uses the enclosing local
}

// Alternative static local function and call:
IncrementCounterExplicit(state);

static void IncrementCounterExplicit(GameState gameState)
{
    gameState.AddedEnemies++; // uses its declared input
}
```

[00:26:51](https://www.youtube.com/watch?v=UVLUbfcCcG0&t=1611s) Рекомендация курса — писать статические локальные функции, когда операция должна зависеть только от явных входов. Тогда случайная ссылка на локальную переменную внешней области отвергается, а не молча связывает функцию с этой переменной. `static` не обязателен для каждой локальной функции в C#; это защита, рекомендуемая для таких вспомогательных функций. [Справочник Microsoft по локальным функциям](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/local-functions) объясняет локальную область видимости, объявления после `return` и ограничение на захват для статических локальных функций.

Урок заканчивается с сохранением всех этих границ: подробная механика префикса с именем класса отложена, смысл `static` сначала откладывается, а затем объясняется, особые применения статических полей остаются более поздним материалом, логическая проверка смерти — практической задачей, проектирование методов расширения ждёт инкапсуляции, паттерн «строитель» лишь назван, а работа с командной строкой и дальнейшие детали генерируемого компилятором кода остаются за пределами демонстрации.

<details>
<summary>Почему объявление вспомогательной функции статическим помогает при появлении второго состояния игры?</summary>

Вспомогательная функция не может молча продолжать использовать локальную переменную состояния внешней области. Требуемый `GameState` нужно передать явно, и тогда в месте вызова видна предполагаемая игра.

</details>
