# Маски полей

Маска полей превращает набор выборов по полям в данные. Урок начинается с клиента и принтера, делает печать настраиваемой, затем использует маски повторно, чтобы описать различия между клиентами, и в конце хранит все флаги в одном целом числе. Следуйте изменениям именно в таком порядке: побитовые операции решают задачу сопровождения, поставленную более ранней булевой версией.

Используемые по ходу термины:

- **Предметная модель:** тип, представляющий сущность из задачи, с полями, описывающими эту сущность. **Перечисление (enum)** даёт имена числовым значениям, например группам клиентов или идентификаторам полей.
- **`sealed` и `required`:** `sealed` запрещает наследование; `required` требует инициализации членов при создании объекта. Инициализация и проверка на `null` — разные задачи.
- **Статический вспомогательный класс и локальная функция:** статический класс группирует операции без экземпляров; локальная функция объявляется внутри другой функции.
- **Маска полей и флаг:** маска содержит по одному выбору да/нет на каждое поле; флаг — один такой выбор. Он задаёт принадлежность, а не порядок.
- **Сериализация:** представление данных в форме, которую можно сохранить и затем прочитать, например в файле конфигурации.
- **`struct`, тип значения и `record struct`:** struct — тип значения, обычно копируемый при присваивании или передаче аргумента; record struct дополнительно даёт равенство по значению, включая `==`.
- **Выделение в куче и упаковка:** выделение в куче создаёт управляемое хранилище объекта; упаковка оборачивает тип значения в объект. Небольшое значение маски позволяет в показанных вызовах избежать отдельного выделения объекта-маски, но не гарантирует, что любой struct всегда живёт в стеке.
- **Значение по умолчанию, nullable-значение и необязательный параметр:** значение по умолчанию маски содержит флаги `false`; nullable-маска может вместо этого не иметь значения; необязательный параметр имеет объявленный запасной вариант, когда его аргумент опущен.
- **Оператор объединения с `null` (`??`) и символ пропуска `_`:** `??` подставляет запасное значение при отсутствии значения; символ пропуска означает, что результат намеренно не используется.
- **Коллекционное выражение, `switch` и `nameof`:** квадратные скобки могут создавать массив групп; `switch` выбирает ветвь с ветвью по умолчанию для несовпавших значений; `nameof` получает имя идентификатора.
- **Функция конфигурации и роли масок:** функция конфигурации преобразует данные выбора; маска сравнения выбирает, что сравнивать, маска проверки выбирает требуемый результат, а маска удаления выбирает флаги, которые нужно сбросить.
- **Именованный аргумент:** `parameterName: value` явно указывает параметр, не полагаясь на позицию аргумента.
- **Маска различий, или diff:** по одному флагу на поле, фиксирующему, различаются ли два объекта. **Any** спрашивает, установлен ли хотя бы один выбранный флаг; **all** — установлены ли все выбранные флаги.
- **Индекс поля:** числовой идентификатор одного поля, позволяющий общей логике перебирать поля.
- **Контракт:** ограничения на вход и обещания для выхода. **Утверждение (assertion)** — диагностика для этапа разработки; **исключение** сообщает о сбое, который можно перехватить. Вызовы `Debug` зависят от символа компиляции `DEBUG`.
- **Геттер, сеттер, свойство и резервное поле:** геттер читает значение, сеттер записывает его, свойство предоставляет эти операции синтаксисом, похожим на поля, а резервное поле хранит реальное состояние.
- **Выражение `with` и передача по ссылке:** `with` создаёт изменённую копию; передача по ссылке позволяет функции напрямую обновлять хранилище вызывающего кода.
- **Итератор и обобщённый код:** итератор предоставляет последовательность значений; обобщение параметризует код типом. Оба упомянуты как более широкие применения, здесь они не разрабатываются.
- **Битовая маска и побитовые операции:** одно целое число хранит флаги в позициях битов. `<<` сдвигает, `|` объединяет установленные биты, `&` оставляет общие, `~` инвертирует.
- **Аксессор с телом-выражением:** `=>` даёт геттеру или сеттеру компактное тело из одного выражения.
- **Инкапсуляция и генератор исходного кода:** инкапсуляция скрывает представление за осмысленными операциями; генератор исходного кода может порождать повторяющийся код во время компиляции.

[Лабораторная по маскам полей](../../../labs/2_design/01_field_mask.md) даёт практику. Её расширения — база данных, REST API, копирование, слияние и юнит-тесты — являются упражнениями; не все эти реализации преподаются в этой записи.

Ссылки на код ниже — неизменяемые снимки. Короткие примеры упрощены ради окружающего объяснения. Ранние состояния живой правки, не оформленные отдельным коммитом, помечены как реконструкции из видео со ссылкой на соответствующий сохранённый исходник; исправления к сохранённому примеру отмечены явно.

## По одному булеву значению на поле

[00:05:04](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=304s) **Маска полей** изначально означает по одному булеву флагу на каждое поле клиента. `true` выбирает поле, `false` пропускает его. Маска отделяет решение от реализации принтера.

Связанный [сохранённая булева маска и условный принтер](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); упрощённый пример:

```csharp
record struct ClientFieldMask
{
    public bool FirstName;
    public bool LastName;
    public bool BelongsToGroups;
}

static void Print(Client c, ClientFieldMask m)
{
    if (m.FirstName) Console.WriteLine(c.FirstName);
    if (m.LastName) Console.WriteLine(c.LastName);
    if (m.BelongsToGroups)
        foreach (var group in c.BelongsToGroups)
            Console.WriteLine(group);
}
```

1. [00:05:18](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=318s) Добавьте второй параметр для маски, чтобы выбор задавал вызывающий код.
2. [00:05:23](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=323s) Оберните вывод каждого поля в проверку соответствующего флага. Принтер сохраняет фиксированный порядок: имя, фамилия, группы.
3. [00:05:59](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=359s) Когда вызывающий код использует агрегированную операцию, отдельные функции печати по полям больше не нужны как механизм выбора вызывающего кода. Сохранённый пример всё же держит их как вспомогательные реализации; это совместимо с делегированием выбора маске.

`record struct` — это тип значения с генерируемым равенством по значению. Урок приходит к причине такого выбора, разбирая дальше значения по умолчанию.

## Опущенные маски и явно пустые маски

[00:06:13](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=373s) Сделайте маску необязательной, чтобы существующий вызывающий код по-прежнему мог запросить весь вывод, опустив её. **Необязательный параметр** имеет значение по умолчанию в своём объявлении. [00:06:21](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=381s) Знак вопроса означает **nullable-тип значения**, а не необязательность сам по себе; `= null` делает параметр необязательным. **Оператор объединения с `null`** `??` выбирает запасное значение только тогда, когда nullable-значение отсутствует.

Связанный [сохранённый nullable-параметр Print и запасной вариант для всех полей](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); реконструированный эквивалент запасного варианта:

```csharp
static void Print(Client c, ClientFieldMask? mask = null)
{
    ClientFieldMask m = mask ?? new ClientFieldMask
    {
        FirstName = true,
        LastName = true,
        BelongsToGroups = true
    };
    // Печатать только поля, флаги которых в m равны true.
}
```

[00:06:35](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=395s) Попробуйте явно построенную маску с включёнными именем и фамилией. [00:06:52](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=412s) Не упомянутые булевы поля имеют **значение по умолчанию** `false`, поэтому группы остаются отключёнными. [00:07:05](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=425s) Запуск показывает только выбранные имена. Это явная частичная маска; опускание аргумента — другой случай. [00:07:21](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=441s) Если аргумент опущен, используется запасной вариант и печатается всё.

Связанный [сохранённый способ представления маски](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); упрощённый эксперимент на месте вызова:

```csharp
var names = new ClientFieldMask { FirstName = true, LastName = true };
Functions.Print(client, names);                  // Только имена.
Functions.Print(client);                         // Все поля.
Functions.Print(client, new ClientFieldMask());  // Ни одного поля.
_ = names;                                       // Результат намеренно не используется.
```

[00:07:11](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=431s) **Символ пропуска** `_` сигнализирует о намеренном неиспользовании. В записанной среде диагностика о неиспользуемой переменной считается ошибкой сборки, блокирующей сборку; это политика проекта и инструментов, а не смысл пропуска на уровне выполнения. Символ пропуска не меняет то, какие поля печатаются.

[00:07:32](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=452s) **struct** — это тип значения: обычная передача маски не требует отдельного выделенного в куче объекта-маски. Именно по причине выделения его предпочитают построению класса-маски для каждого вызова. Не следует делать более сильное утверждение, что struct никогда не попадает в кучу: его могут упаковать (обернуть в объект) или хранить внутри объектов в куче. [Справка по struct](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/struct) объясняет копирование по значению.

static ClientFieldMask Without(ClientFieldMask mask, ClientFieldMask toDelete)
{

}

## Вычислите маску различий и используйте её повторно

[00:14:24](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=864s) Маска может описывать не только запрошенные операции, но и результаты сравнения. **Маска различий** использует `true` в значении «эти объекты различаются в этом поле». Сначала обсуждается маска сравнения, выбирающая, какие поля сравнение должно просматривать.

[00:14:45](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=885s) Начните результат со всех флагов `false`. Для каждого просмотренного поля устанавливайте его флаг результата только если соответствующие значения различаются. [00:15:11](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=911s) Эту операцию обычно называют **diff** — именно это имя используется в примере. [00:15:27](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=927s) Маскированный diff проверяет только поля, названные его входным выбором; это не обязательно сравнение всех полей.

Связанный [сохранённый код Diff и вспомогательной операции сравнения](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); реконструированная версия с выбором полей и с предполагаемой полярностью различий:

```csharp
static ClientFieldMask Diff(Client a, Client b, ClientFieldMask selected)
{
    ClientFieldMask result = new();
    if (selected.FirstName && a.FirstName != b.FirstName)
        result.FirstName = true;
    if (selected.LastName && a.LastName != b.LastName)
        result.LastName = true;
    if (selected.BelongsToGroups &&
        !a.BelongsToGroups.SequenceEqual(b.BelongsToGroups))
        result.BelongsToGroups = true;
    return result;
}
```

[00:15:37](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=937s) В демонстрации уберите проверки выбора и оставьте сравнения значений. Это уменьшает число условий и даёт полный сохранённый diff, который потом можно фильтровать. Это два дизайна: выбор во время вычисления пропускает нерелевантные сравнения; выбор после вычисления повторно использует уже рассчитанные результаты.

[00:15:56](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=956s) Когда diff сохранён, вопрос о совпадении имени решается проверкой его флага, а не повторным сравнением строк. [00:16:16](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=976s) Неравенство строк сравнивает последовательность символов, поэтому акценты или другие диакритики делают похожие имена различными. [00:16:35](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=995s) Их игнорирование требует явных правил сравнения; обычное неравенство не нормализует их молча.

[00:16:41](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1001s) Централизуйте такие правила в реализации сравнения. [00:16:51](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1011s) Несвязанное встроенное неравенство по-прежнему следовало бы обычному правилу, поэтому все места вызовов, которым нужно особое правило, должны использовать одно и то же сравнение. [00:17:05](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1025s) Вынесение этого сравнения устраняет дублирование.

Связанный [сохранённый код FirstNameEquals и его вызов из Diff](https://github.com/AntonC9018/uniCourse_csharp/blob/ef4630d291e20ffbcf93018cba43a53971d327a2/examples/field_masks/Program.cs); исправленная упрощённая вспомогательная функция и вызывающий код:

```csharp
static bool FirstNameEquals(Client a, Client b) =>
    a.FirstName == b.FirstName; // Добавьте сюда нужную нормализацию.

static ClientFieldMask Diff(Client a, Client b)
{
    ClientFieldMask result = new();
    result.FirstName = !FirstNameEquals(a, b);
    result.LastName = a.LastName != b.LastName;
    result.BelongsToGroups =
        !a.BelongsToGroups.SequenceEqual(b.BelongsToGroups);
    return result;
}
```

В просмотренных снимках `FirstNameEquals` вызывается без отрицания при установке флага различия по имени. Это помечает равенство как различие и противоречит предполагаемому контракту diff; приведённый выше пример исправляет эту полярность. Сохранённая вспомогательная функция использует `SequenceEqual`, который всё же выполняет обычное сравнение последовательностей и не реализует никакого правила, нечувствительного к диакритикам.

[00:17:16](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1036s) Вспомогательная функция с именем `CompareFirstName(a, b)` или сохранённая `FirstNameEquals(a, b)` убирает встроенное сравнение с места проверки. [00:17:24](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1044s) Место вызова превращается в короткую делегированную проверку. [00:17:37](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1057s) Подход с большой маской собирает всё различие сразу. [00:17:39](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1059s) Вызывающий код может игнорировать выбранные поля и [00:18:03](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=1083s) повторно использовать сохранённые результаты по имени и фамилии, не пересчитывая сравнения.

Связанный [сохранённое индексированное отображение Set](https://github.com/AntonC9018/uniCourse_csharp/blob/80eddb6786130b733401932cadfb35f5c939d8f4/examples/field_masks/Program.cs); реконструкция более ранней изменяющей версии:

```csharp
static void Set(ref ClientFieldMask mask, ClientField field, bool value)
{
    switch (field)
    {
        case ClientField.FirstName: mask.FirstName = value; break;
        case ClientField.LastName: mask.LastName = value; break;
        case ClientField.BelongToGroups: mask.BelongsToGroups = value; break;
        default: throw new ArgumentException("Invalid value", nameof(field));
    }
}
```

Здесь **передача по ссылке** (`ref`) позволяет операции обновлять хранилище вызывающего кода; присваивание обычному параметру-типу значения изменило бы только его копию. Возврат маски — это API преобразования значения, отличный от возврата булева флага.

static bool AreSet(ClientFieldMask mask, ClientFieldMask required)

## Проверьте все обязательные флаги сразу

[00:40:59](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2459s) Финальная оптимизация — предикат «все флаги». Возьмите общие биты фактической маски и обязательной маски. [00:41:08](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2468s) Если эти биты отличаются от обязательной маски, то как минимум одно требование не выполнено. [00:41:19](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2479s) Если они равны ей, то присутствуют все обязательные флаги.

Связанный [финальная сохранённая реализация AreSet](https://github.com/AntonC9018/uniCourse_csharp/blob/6b312db7c3e158e27048d8921f426054c4a1b2b0/examples/field_masks/Program.cs); упрощённый предикат:

```csharp
static bool AreSet(ClientFieldMask mask, ClientFieldMask required) =>
    (mask._value & required._value) == required._value;
```

[00:41:26](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2486s) Разобранная схема требует двух позиций и игнорирует остальные. Как и на схеме в видео и исходнике, это столбцы флагов:

```text
actual:      1 1 0 1
required:    1 1 0 0
common:      1 1 0 0  -> equals required, true

actual:      1 0 0 1
required:    1 1 0 0
common:      1 0 0 0  -> differs from required, false
```

[00:41:39](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2499s) Третья и четвёртая позиции обнуляются обязательной маской, даже если в фактической маске там стоит флаг. Вклад дают только обязательные позиции. [00:41:46](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2506s) Когда каждая обязательная позиция была единицей, каждая копирует единицу, и результат в точности совпадает с требованием.

[00:41:53](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2513s) Если хотя бы одна обязательная позиция была нулём, этот ноль сохраняется в общей маске и равенство не выполняется. [00:42:01](https://www.youtube.com/watch?v=BmdWiUEgwNw&t=2521s) Это равенство и есть полное правило решения: «все обязательные флаги установлены». Это не проверка «any».

<details>
<summary>Почему сравнивать общие биты с обязательной маской, а не с фактической?</summary>

Фактическая маска может содержать дополнительные флаги, которые вызывающий код явно игнорирует. Обязательная маска содержит ровно те требования, которые нужно выполнить. Равенство с ней доказывает, что ни одно из этих требований не пропущено.

</details>

Урок заканчивается настраиваемым выбором, переиспользуемыми результатами сравнения и именованными операциями над компактным представлением. Альтернативные предметные раскладки, синтаксис возврата по ссылке, итераторы, обобщённый контейнер полей, генерация исходного кода и разбор документов остаются за пределами реализованного примера.

// Побитовый этап: выбрать индексированный бит и проверить его.
return (_value & (1 << (int)field)) != 0;
