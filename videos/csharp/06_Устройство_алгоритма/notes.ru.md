# Из чего состоит алгоритм

[00:00:00](https://www.youtube.com/watch?v=C6plSGSYuyc&t=0s) Существенная задача по программированию обычно требует нескольких согласованных действий. Это занятие выстраивает способ находить эти действия, описывать используемые ими данные и превращать описание в инструкции. Главный пример — поиск средней длины строк в файле. Умножение даёт небольшой стартовый пример, а суммирование списка — подробный строительный блок.

Словарь ниже — это анонс. Каждая идея разбирается заново, когда в этом возникает необходимость:

- **Задача и алгоритм:** задача задаёт результат, который нужно получить; алгоритм описывает, как получить его из заданных данных. В этом занятии программа, решающая задачу, описывается через входные данные, выходные данные и реализацию.
- **Вход и выход:** вход — данные, передаваемые задаче; выход — производимый ею результат. **Представление** — конкретная форма, в которой несут эти данные.
- **Интерфейс и реализация:** интерфейс описывает взаимодействие с алгоритмом, прежде всего его вход и выход. Реализация содержит шаги, которые выполняют работу, и их временное хранилище.
- **Декомпозиция и подалгоритм:** декомпозиция разбивает задачу на меньшие задачи. Подалгоритм — алгоритм, используемый для выполнения одной из этих меньших задач. **Примитивная операция** — операция, уже доступная на используемом уровне детализации.
- **Высокий уровень, низкий уровень и абстракция:** описание высокого уровня называет существующие операции по тому, что они делают; описание низкого уровня расписывает их меньшие шаги. Абстракция позволяет полезному имени обозначать поведение, не раскрывая его внутренних шагов.
- **Файл, строка (string), символ, строка текста и перевод строки:** файл хранит содержимое; строка представляет текст как последовательность символов. Символ — отдельный элемент текста в модели занятия. Строка текста — часть содержимого, отделённая от следующей части переходом строки.
- **Длина и среднее:** длина — количество элементов в последовательности или символов в строке. Среднее здесь — среднее арифметическое: сумма значений, делённая на их количество.
- **Массив, элемент и индекс:** массив моделируется как последовательные ячейки памяти со значениями, называемыми элементами. Индекс определяет элемент по его смещению от начала; первый индекс равен нулю.
- **Обход и границы:** обход посещает элементы коллекции. Границы задают, какие индексы допустимы.
- **Переменная и рабочая память:** переменная — именованная ячейка, значение которой может меняться. Рабочая память — временное хранилище, которое алгоритм использует во время выполнения.
- **Цикл и накопленная сумма:** цикл повторяет шаги. Накопленная сумма, она же аккумулятор, хранит накопленное к текущему моменту итоговое значение.
- **Ассоциативность, нейтральный элемент и свёртка:** ассоциативность допускает перегруппировку сложений без изменения математического результата. Ноль — нейтральный элемент для сложения, потому что прибавление нуля ничего не меняет. Свёртка слева направо многократно объединяет текущий результат со следующим элементом.
- **Присваивание и управляющие конструкции:** присваивание записывает значение в переменную. Составное присваивание вроде `+=` объединяет вычисление с записью результата обратно. Поток управления определяет, какая инструкция выполняется следующей; переход передаёт выполнение именованной метке, а цикл for упаковывает повторяющееся выполнение.
- **Функция, параметр и тип возвращаемого значения:** функция упаковывает инструкции под именем. Параметр принимает входные данные для вызова; тип возвращаемого значения описывает вид возвращаемого результата. Тип описывает, какое значение хранит ячейка или какой результат получается.
- **Буфер и срез:** буфер хранит порцию данных, пока она обрабатывается. Срез — выбранная часть последовательности.
- **Дополнительный словарь для практики:** проверка контракта подтверждает обязательное условие; утверждение проверяет ожидаемое условие, а исключение сообщает об ошибке. Они упоминаются только в дополнительных материалах.
- **Объект, адрес и ссылка:** объект объединяет связанные данные. Адрес указывает, где объект находится в памяти; ссылка позволяет программе добраться до этого объекта через отдельно переданное значение.

Репозиторий содержит [лабораторную «Алгоритмы»](../../../labs/1_basic/11_algorithms.md), которая указывает на эту запись. [Лабораторная с реализацией на C#](../../../labs/1_basic/12_algorithms_code.md) — это более позднее практическое задание, а не реализация, выполненная в этом видео.

## Первый алгоритм: умножение двух чисел

[00:05:51](https://www.youtube.com/watch?v=C6plSGSYuyc&t=351s) Дайте двум входам имена `A` и `B`, чтобы инструкции могли однозначно на них ссылаться.

[00:06:04](https://www.youtube.com/watch?v=C6plSGSYuyc&t=364s) [Записанные шаги умножения](https://www.youtube.com/watch?v=C6plSGSYuyc&t=364s) имеют следующий упрощённый вид:

```text
input: A, B
1. Read A.
2. Read B.
3. Multiply the two values.
output: the product from step 3
```

1. Взять значение по имени A.
2. Взять значение по имени B.
3. Перемножить их и использовать результат как выход.

[00:06:21](https://www.youtube.com/watch?v=C6plSGSYuyc&t=381s) **Декомпозиция** означает разбиение задачи на меньшие действия. Здесь достаточно одного уровня: умножение — уже **примитивная операция**, действие, доступное напрямую на этом уровне. Для более крупной проблемы понадобится несколько уровней декомпозиции.

## Декомпозиция задачи о средней длине строк

[00:06:54](https://www.youtube.com/watch?v=C6plSGSYuyc&t=414s) Декомпозиция продолжается разбиением каждого трудного шага на меньшие. В итоге действие становится таким же привычным, как умножение чисел, чтение значения или перенос значения в другую ячейку.

## Анализ требования о среднем

[00:07:57](https://www.youtube.com/watch?v=C6plSGSYuyc&t=477s) Вернёмся к задаче с файлом и спросим, что именно требует «средняя длина строк».

```

[00:09:07](https://www.youtube.com/watch?v=C6plSGSYuyc&t=547s) Деление завершает формулу, но операция «сумма» всё ещё скрывает работу.

## Получение строк из файла

[00:10:17](https://www.youtube.com/watch?v=C6plSGSYuyc&t=617s) Другая ветвь состоит в получении строк и их измерении. [00:10:30](https://www.youtube.com/watch?v=C6plSGSYuyc&t=630s) **Строка текста** — это часть текста файла, отделённая от следующей части **переводом строки**, то есть переходом на новую строку.

[00:10:40](https://www.youtube.com/watch?v=C6plSGSYuyc&t=640s) Это определение даёт информацию, необходимую для извлечения строк: найти переходы в содержимом.

## Массивы и индексы

[00:13:14](https://www.youtube.com/watch?v=C6plSGSYuyc&t=794s) Чтобы посетить каждое значение, сначала решим, как они представлены. **Массив** моделируется как область памяти, в которой значения хранятся подряд. Каждое хранимое значение — **элемент**.

[00:13:31](https://www.youtube.com/watch?v=C6plSGSYuyc&t=811s) На этой картинке на каждое значение приходится одна ячейка. [00:13:53](https://www.youtube.com/watch?v=C6plSGSYuyc&t=833s) Ещё один фрагмент памяти хранит длину: сколько значений имеется. ```text
values:   [ a ][ b ][ c ][ d ]       length: 4
indices:    0    1    2    3
```

[00:14:10](https://www.youtube.com/watch?v=C6plSGSYuyc&t=850s) **Индекс** — это позиция, отсчитанная от начала массива. Он говорит нам, сколько элементов пропустить, прежде чем прочитать нужный элемент. Буква вроде `i` может обозначать текущий индекс.

[00:14:23](https://www.youtube.com/watch?v=C6plSGSYuyc&t=863s) У первого элемента индекс ноль: пропустить нечего и прочитать значение в начале. [00:14:32](https://www.youtube.com/watch?v=C6plSGSYuyc&t=872s) Индекс три означает пропустить элементы с индексами ноль, один и два, а затем прочитать четвёртый элемент. Индекс определяет нашу текущую позицию.

[00:14:58](https://www.youtube.com/watch?v=C6plSGSYuyc&t=898s) Переход к следующему элементу означает увеличение индекса на единицу. Индекс один пропускает один элемент; индекс два — два.

[00:15:30](https://www.youtube.com/watch?v=C6plSGSYuyc&t=930s) **Границы** — допустимые индексы. Для непустого массива из N элементов они идут от нуля до N минус один. Перед последним элементом находятся N минус один элементов — это объясняет вычитание.

[00:15:47](https://www.youtube.com/watch?v=C6plSGSYuyc&t=947s) В записи отступы у первой и последней ячеек слегка подправлены, чтобы конец списка было легче различить. Это дополнение сделано для читаемости; оно не добавляет элемент и не меняет индекс. [Объяснение последнего индекса](https://www.youtube.com/watch?v=C6plSGSYuyc&t=960s) можно изобразить так:

```text
          [ a ][ b ][ c ][ d ][ e ][ f ][ g ][ h ]
offset:     0    1    2    3    4    5    6    7   | end
```

[00:15:57](https://www.youtube.com/watch?v=C6plSGSYuyc&t=957s) Смещение первой ячейки равно нулю; смещение последней — количество минус один. [00:16:00](https://www.youtube.com/watch?v=C6plSGSYuyc&t=960s) Значит, восемь элементов заканчиваются индексом семь. Это та граница, которую будет использовать обход.

<details>
<summary>В массиве восемь значений. Должен ли обход читать индекс восемь?</summary>

Нет. Его индексы идут от нуля до семи. Индекс восемь — позиция за последним значением, поэтому алгоритм должен остановиться, не пытаясь его прочитать.
</details>

## Обход как подалгоритм

[00:16:19](https://www.youtube.com/watch?v=C6plSGSYuyc&t=979s) **Обход** означает посещение элементов коллекции. Рассматривайте его как собственный подалгоритм, чтобы его поведение можно было разобрать отдельно от того, что происходит с каждым значением.

[00:16:34](https://www.youtube.com/watch?v=C6plSGSYuyc&t=994s) Чтобы посетить значения по порядку, нужно посетить их индексы по порядку и прочитать элемент по каждому из них. Для этого требуется текущий индекс, меняющийся по мере выполнения.

[00:16:40](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1000s) Четыре правила задают этот текущий индекс:

1. Трактовать индекс как количество пропущенных позиций элементов от начала.
2. Начинать с нуля.
3. Увеличивать его на единицу после обработки элемента.
4. Останавливаться, когда он превысил последний допустимый индекс.

[00:16:47](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1007s) Начало с нуля и шаг в единицу позволяют посетить элементы, не оставляя пропусков. [00:17:16](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1036s) Как только индекс больше N минус один, все доступные индексы посещены.

[00:17:32](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1052s) Это сравнение даёт правило остановки; отдельный счётчик итераций не нужен. [00:17:48](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1068s) Индекс служит сразу двум целям: он находит следующее значение и сообщает, как далеко продвинулся обход.

## Запись обхода в виде шагов

[00:18:01](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1081s) Теперь превратим эти правила в **инструкции**, конкретные действия, которые программа будет выполнять.

[00:18:17](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1097s) Индекс должен сохраняться от одной инструкции к следующей, хотя и меняется. **Переменная** предоставляет такое хранилище: это именованная ячейка памяти, в которую можно записать значение.

[00:18:28](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1108s) Создайте ячейку и инициализируйте её нулём. Это делает первую попытку посещения начинающейся с начала массива. [Записанная разработка обхода](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1108s) имеет следующий упрощённый промежуточный вид. Операция накопленной суммы на этом этапе всё ещё заглушка:

```text
create currentIndex
currentIndex = 0
check:
    if currentIndex > length - 1, finish
    value = element at currentIndex
    add value to the current sum       // storage for this comes next
    currentIndex = currentIndex + 1
    go back to check
```

[00:19:03](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1143s) Проверка конца должна стоять перед первым чтением. У пустого массива нет допустимых индексов, поэтому при текущем индексе ноль он уже завершён.

[00:19:12](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1152s) Завершение на этой проверке предотвращает чтение за границами. [00:19:26](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1166s) Если индекс допустим, забираем элемент, пропустив столько позиций, сколько хранится в ячейке индекса: сначала ноль, затем один, затем два и так далее.

[00:19:37](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1177s) После прибавления забранного значения к накопленной сумме переходим к следующему элементу. [00:19:44](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1184s) Инкремент индекса — прибавление к нему единицы — и выполняет этот переход.

[00:19:55](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1195s) После увеличения снова проверяем границы. Если индекс теперь оказался вне массива, останавливаемся до следующего чтения.

[00:20:02](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1202s) **Цикл** повторяет одни и те же действия, пока не выполнено условие остановки. Полная процедура обхода поэтому выглядит так:

1. Создать и инициализировать переменную текущего индекса.
2. Проверить, допустим ли её индекс; если нет — завершить.
3. Забрать элемент по этому индексу и выполнить над ним нужную операцию.
4. Увеличить индекс на единицу.
5. Вернуться к проверке и повторить.

Действия чтения, прибавления и увеличения — это повторяемая работа. Один проход по ним обрабатывает только одно значение; возврат к проверке превращает их в обход всего массива.

## Прибавление каждого элемента к текущей сумме

[00:20:23](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1223s) Обсуждение шестого шага возвращает к отложенной инструкции: прибавлять каждый элемент к текущей сумме. Обход теперь предоставляет элементы, но самой сумме нужны начальное значение и хранилище.

[00:20:41](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1241s) Для пустого списка сумма определена как ноль. Инициализация результата только после чтения первого элемента оставила бы этот случай без ответа.

[00:20:50](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1250s) Обсуждение указывает на **ассоциативность**: в математическом сложении перегруппировка сложений не меняет результат. Например, объединение первых двух значений и затем объединение этого результата с третьим даёт ту же сумму, что и группировка последних двух первыми. Роль нуля точнее в том, что это **нейтральный элемент** для сложения: прибавление нуля ничего не добавляет. Ассоциативность объясняет перегруппировку; нейтральный элемент даёт базовое значение для пустого случая.

[00:20:54](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1254s) Процесс объединения слева направо в занятии называется **свёрткой**: объединить результат со следующим элементом, затем использовать этот новый результат в следующем объединении.

[00:21:12](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1272s) Замена начального объединения на базовую сумму плюс первый элемент превращает длинное суммирование в однотипные действия. [00:21:22](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1282s) Начинаем с нуля, прибавляем первое значение, прибавляем второе к результату и продолжаем до третьего, четвёртого и пятого. [Записанные рассуждения о базовой сумме](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1282s) можно записать так:

```text
base sum: 0
running sum after first element: 0 + first
running sum after second:       (0 + first) + second
continue by adding each next element to the preceding result
```

[00:21:36](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1296s) Уже разработанный обход говорит нам, как добраться до каждого элемента. Дополнительное требование — запоминать накопленное значение между посещениями.

[00:21:52](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1312s) **Накопленная сумма**, или аккумулятор, — выделенная переменная, хранящая это накопленное значение. [00:21:56](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1316s) Заводим для неё новую ячейку, изначально содержащую базовую сумму.

[00:22:08](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1328s) На первом проходе прибавляем первый элемент к нулю и записываем результат обратно в ячейку суммы. На каждом последующем проходе читаем текущий итог, прибавляем следующий элемент и перезаписываем ячейку новым итогом.

[00:22:21](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1341s) В числовом примере первое значение даёт пять, а следующая пятёрка — десять. Сохранённая транскрипция затем называет следующим значение девять, давая девятнадцать на [00:23:02](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1382s). На этом шаге используйте девять: десять плюс четыре дали бы четырнадцать, а не девятнадцать.

[00:23:10](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1390s) Нарисованные промежуточные результаты — это последовательные узлы процесса сложения. Прибавление трёх к девятнадцати даёт двадцать два; прибавление восьми — тридцать. [Записанный пример накопления](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1390s) здесь суммирован так:

```text
elements:       5, 5, 9, 3, 8
running sums:   0 -> 5 -> 10 -> 19 -> 22 -> 30
```

[00:23:22](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1402s) Ячейка суммы последовательно хранит каждый из этих промежуточных результатов. Когда обход достигает последнего узла, её значение — полный итог.

[00:23:39](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1419s) Объединим накопление с обходом: при каждом посещении прибавляем значение элемента к этой ячейке.

[00:24:00](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1440s) Изменение прежнего псевдокода невелико, но существенно: добавляем перед циклом шаг, который создаёт ячейку суммы и записывает в неё ноль. [Записанное добавление аккумулятора](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1444s) даёт следующую упрощённую полную процедуру суммирования:

```text
create currentSum and write 0 into it
create currentIndex and write 0 into it
check:
    if currentIndex > length - 1, answer with currentSum
    currentSum = currentSum + element at currentIndex
    currentIndex = currentIndex + 1
    go back to check
```

1. Инициализировать сумму нулём.
2. Инициализировать текущий индекс нулём.
3. Если индекс прошёл последнюю допустимую позицию, выдать сохранённую сумму.
4. Иначе прибавить текущий элемент к сумме и сохранить результат.
5. Увеличить индекс и повторить с проверки границ.

[00:24:21](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1461s) Завершающий шаг теперь явно указывает ответ: он находится в ячейке текущей суммы. [00:24:45](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1485s) После того как все элементы внесли свой вклад по одному разу, эта ячейка хранит значение последнего узла. Если бы элементов не было, она всё равно содержала бы базовую сумму, ноль.

Алгоритм инициализирует сумму и индекс нулём, затем проваливает первую проверку границ, потому что допустимых индексов нет. Он не читает ни одного элемента и возвращает уже инициализированную сумму, ноль.

## От записанных шагов к коду

[00:24:54](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1494s) Достаточно конкретное описание алгоритма имеет прямой эквивалент в коде. Создайте переменную для текущей суммы и присвойте ей базовое значение.

[00:25:05](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1505s) Затем создайте переменную текущего индекса и инициализируйте её нулём. [00:25:18](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1518s) Проверка равенства индекса длине обнаруживает первую позицию за массивом. Это эквивалентно проходу N минус один, потому что обход начинается с нуля и продвигается на одну позицию за раз.

[00:25:33](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1533s) Прибавляем элемент по текущему индексу к сумме, увеличиваем индекс и возвращаемся к проверке. [Записанный перевод в код](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1515s) подсказывает следующую упрощённую реконструкцию на C#. Это поясняющий пример, а не точная транскрипция экрана и не заявленный снимок репозитория; предполагается, что передан массив с именем values:

```csharp
int sum = 0;
int i = 0;

CheckIndex:
if (i == values.Length)
    goto Finished;

sum += values[i];
i += 1;
goto CheckIndex;

Finished:
; // Leave sum unchanged; it holds the answer.
```

**Тип** описывает вид хранимого значения: `int` здесь используется для небольшого примера с целыми числами. Присваивание вроде `i = 0` записывает значение в переменную. `values.Length` читает сохранённое количество элементов; `values[i]` читает элемент, заданный индексом. Составное присваивание `sum += values[i]` означает «прибавить этот элемент к текущей сумме и записать результат обратно». Аналогично, `i += 1` заменяет старый индекс следующим. Точка с запятой завершает каждую обычную инструкцию. Именованные метки с двоеточием обозначают места перехода; `goto` передаёт выполнение одной из них. Инструкция `if` выполняет проверку конца до любого обращения к массиву. Финальная одиночная точка с запятой — пустая инструкция, чтобы у завершающей метки было допустимое назначение.

[00:25:58](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1558s) **Цикл for** упаковывает инициализацию, условие продолжения и обновление в одну конструкцию цикла. Он заменяет ручной переход назад, сохраняя тот же обход. [Записанное уточнение циклом](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1558s) соответствует следующей упрощённой версии:

```csharp
int sum = 0;
for (int i = 0; i < values.Length; i += 1)
{
    sum += values[i];
}
```

Внутри скобок первая часть инициализирует индекс, вторая разрешает ещё одну итерацию, только пока индекс допустим, а третья продвигает его после тела цикла. Точки с запятой разделяют эти три части. Фигурные скобки группируют повторяемые инструкции. Условие продолжения сформулировано положительно — «индекс меньше длины»; когда оно перестаёт выполняться, выполнение покидает цикл.

[00:26:03](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1563s) Этот перевод работает, потому что проза уже задаёт хранилище, инициализацию, проверку, операцию и обновление. Синтаксис языка даёт прямой способ выразить каждое действие.

[00:26:08](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1568s) **Функция** упаковывает эти инструкции под именем, чтобы другой алгоритм мог их вызвать. Её **параметр** описывает переданный вход, а **тип возвращаемого значения** — результат. [Записанное обсуждение интерфейса функции](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1568s) приводит к следующей упрощённой полной функции:

```csharp
int Sum(int[] values)
{
    int sum = 0;
    for (int i = 0; i < values.Length; i += 1)
    {
        sum += values[i];
    }
    return sum;
}
```

Здесь `Sum` называет поведение, `int[] values` объявляет массив целых чисел на входе, а начальное `int` описывает результат. `return sum` выдаёт значение, оставшееся в аккумуляторе. Наименование поведения и объявление его входа и выхода дают вызываемому алгоритму **интерфейс**.

[00:26:14](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1574s) Тот же шаг проектирования интерфейса применим к подалгоритму усреднения: дать ему имя, указать получаемые значения и указать вид возвращаемого результата. Его реализация может использовать только что завершённую операцию суммирования.

[00:26:23](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1583s) Оставшаяся операция усреднения делит сумму на количество. [Записанное вычисление среднего](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1583s) проиллюстрировано математически, а не выбором числовых типов C#:

```text
Average(values):
    total = Sum(values)
    count = length of values
    return total / count
```

[00:26:31](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1591s) Количество уже хранится вместе с массивом. На этом уровне оставшиеся примитивные действия — чтение суммы, чтение длины и деление. [00:26:38](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1598s) Частное — это и есть ответ, чем завершается подзадача усреднения.

Эти примеры объясняют переход от шагов к коду; это не сообщения о сборке или выполнении. Нулевой результат для пустой суммы был выведен рассуждением, а не показан записанным тестовым запуском. Запись не определяет политику для пустого входа при усреднении: нулевая сумма сама по себе не задаёт деление на нулевое количество.

## Более сложный подалгоритм, разобранный вручную

[00:26:41](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1601s) Извлечение строк — намеренно самая трудная часть декомпозиции. Обсуждение намечает, как сделать это вручную, не дописывая функцию разбиения файла.

[00:26:45](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1605s) **Срез** — часть последовательности между выбранными позициями. Чтобы извлекать последовательные строки из строки содержимого:

1. Запомнить позицию, где начинается текущая строка.
2. Просматривать по одному символу, пока не встретится перевод строки.
3. Взять срез от запомненной позиции до этой границы как строку.
4. Сохранить позицию для следующей строки.
5. Продолжать просмотр до следующей границы и повторить.

[00:27:01](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1621s) Каждое действие в этой схеме само по себе можно разбить на базовые шаги, как обход и накопление. [00:27:17](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1637s) Принципы индексации и обычные рассуждения о требуемом результате делают такой перевод возможным; никакой новой загадки не стоит между записанной процедурой и кодом.

[00:27:37](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1657s) Эта подробная работа полезна, когда операцию нужно построить. Когда доступна функция, уже суммирующая значения, используйте её и оставьте эту часть файлового алгоритма на высоком уровне. Полный код просмотра и его политики по границам здесь не разрабатываются.

## Высокий уровень, низкий уровень и абстракция

[00:27:55](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1675s) Описание **высокого уровня** использует существующий алгоритм по выполняемому им действию. Описание **низкого уровня** раскрывает это действие в его примитивные шаги. Они могут описывать одно и то же поведение с разной степенью детализации.

[00:28:02](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1682s) Подробная процедура суммирования — низкий уровень по отношению к «сложить этот список»: она задаёт переменные, их начальные значения, доступ к элементам, накопление и обновление индекса.

[00:28:10](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1690s) На высоком уровне достаточно знать, что алгоритм суммирования существует и какой ответ он даёт. Вызывающей стороне не нужно заново обдумывать, как он выделяет временные ячейки или обходит список.

[00:28:55](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1735s) **Абстракция** — это использование такой операции через её имя и смысл, оставляя внутреннее устройство вне текущего описания. [00:29:11](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1751s) Полезное имя описывает то, что произойдёт на том уровне, где планируется большая задача.

<details>
<summary>Почему «сложить длины» может быть полным шагом в одном описании, хотя само суммирование потребовало многих шагов для построения?</summary>

Когда алгоритм суммирования существует и его интерфейс известен, больший алгоритм может вызвать его как одну подзадачу. Его реализация по-прежнему выполняет подробную работу. Абстракция меняет то, сколько этой работы вызывающей стороне нужно описывать.
</details>

## Изображение алгоритма как ячеек памяти

[00:29:15](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1755s) Декомпозиция алгоритма означает задание не только его шагов, но и его интерфейса.

[00:29:30](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1770s) **Интерфейс** состоит из входа и выхода. [00:29:38](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1778s) **Реализация** состоит из конкретных инструкций и **рабочей памяти**: временных ячеек вроде меняющегося индекса и накопленной суммы.

[00:29:47](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1787s) На схеме памяти различают три области: ячейки входа, ячейки выхода и временное пространство, используемое во время работы алгоритма. [Записанная модель памяти](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1803s) суммирована так:

```text
input                  working memory              output
[ a ] [ b ]            [ temporary sum ]            [ answer ]
```

[00:30:14](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1814s) Входные данные поставляются извне. Алгоритм не выбирает их содержимое; он работает с полученными данными.

[00:30:19](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1819s) Для сложения двух чисел ячейки входа хранят значения a и b. Временная ячейка может хранить их сумму, которая затем выдаётся как ответ. Результат примера — одиннадцать. Это различает внешне заданные значения, промежуточное хранилище и выход, не требуя физической раскладки памяти для конкретной среды выполнения.

## Передача списка на практике

[00:30:42](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1842s) Схема ячеек объясняет, из чего состоит алгоритм. Остаётся практический вопрос: как к нему доставляется целый список?

[00:30:45](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1845s) Обычно мы не записываем каждый элемент в отдельную позицию входа, а затем не передаём рядом никакую несвязанную длину.

[00:30:56](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1856s) Вместо этого **объект** представляет список и объединяет его элементы с его длиной. Объект находится по **адресу**, то есть в позиции памяти. Передаваемая ячейка может хранить значение, ведущее к этому объекту, — **ссылку** в этой пояснительной модели. [Записанное обсуждение передачи списка](https://www.youtube.com/watch?v=C6plSGSYuyc&t=1862s) можно изобразить так:

```text
passed input cell                 list object's storage
[ address/reference ] ---------> [ elements ... | length ]

returned data can likewise be treated as separate memory
before the result is written to its destination
```

Элементы, длина и память для возвращаемых данных остаются отдельными частями концептуальной картины. Передача значения, идентифицирующего список, позволяет функции использовать коллекцию как один вход. Это объяснение потока данных, а не спецификация точной раскладки объекта.

**Дальнейшая практика, не преподаваемая в этом видео:** [лабораторная с реализацией на C#](../../../labs/1_basic/12_algorithms_code.md) просит написать функцию алгоритма, которая работает только со своими параметрами и ничего не печатает. Массивы, включая массив вывода, создаются главной функцией и передаются внутрь; алгоритм записывает свой ответ в массив вывода, а печатает только главная функция. В практических вариантах используются и циклы while, и циклы for. Эти требования переносят текущую запись в упражнение по реализации.

Та же лабораторная предлагает необязательные **проверки контракта** — проверки того, что массивы имеют допустимые длины, с помощью утверждения или исключения. Утверждение проверяет ожидаемое условие; исключение сообщает об ошибке через механизм ошибок языка. Эти приёмы относятся к более позднему материалу. Дополнительная практика включает подсчёт значений выше порога, поиск одного или двух наибольших значений, генерацию простых чисел и вычисление чисел Фибоначчи. Ничто из этого не требуется для понимания декомпозиции в этом видео.
