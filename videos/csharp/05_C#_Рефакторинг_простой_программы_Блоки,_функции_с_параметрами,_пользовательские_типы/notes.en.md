# Refactoring grid distance through scope, calls, and position types

[00:00:00](https://www.youtube.com/watch?v=z51K0UhriOk&t=0s) This lesson begins with four coordinate variables and turns repeated grid-distance arithmetic into a reusable operation. Each change answers a concrete problem: negative differences, colliding temporary names, duplicated instructions, and coordinate arguments that are too easy to mix up. The final comparison asks why changing a field through a function parameter behaves differently for a struct and a class.

The vocabulary used along the way is:

- **Coordinate and axis:** X and Y describe a position along two directions; write a pair as (X, Y). **Grid distance** counts horizontal and vertical cell steps. **Absolute value**, written with `Math.Abs`, keeps a number's magnitude without its sign.
- **Variable, type, and `int`:** a variable names storage for a value; its type says what kind of value it holds. Here `int` holds whole-number coordinates and distances. **Declaration** introduces a variable, **initialization** gives it its initial value, and **assignment** copies a right-hand value into left-hand storage. A **scalar** is one simple value such as an integer. **Definite assignment** is C#'s requirement that a local has been given a value before it is read.
- **Expression and value:** an expression is code that evaluates to a value; a value is the concrete result that can be stored. An **intermediate result** is a value produced on the way to the final answer.
- **Block, scope, and local variable:** braces delimit a block; scope determines where a name can be used. A local variable belongs to an enclosing block or function. Its **lifetime** describes when that variable exists in the lesson's execution model.
- **Refactoring and duplication:** refactoring changes the program's organization while preserving its intended behavior. Duplication means maintaining several copies of the same operation.
- **Function, call, signature, parameter, and argument:** a function packages instructions; a call runs them. Its signature describes its name and typed inputs. A parameter is the function's input variable; an argument is the expression supplied at a call. The **caller** makes the call and the **callee** runs it.
- **Return type, return value, `return`, and `void`:** the return type declares the kind of result; the return value is that result. `return` supplies it and ends the current function execution. `void` declares that a function returns no value. A **static local function** cannot capture the surrounding local variables.
- **Stack, call frame, heap, and address:** the drawing calls temporary working storage the stack; a frame represents the parameters and locals for one call. Dynamic object storage is the heap. An address identifies a storage location. The boxes are a teaching model, not a promise of exact machine layout.
- **User-defined type, `Position`, struct, value type, and field:** a user-defined type gives a useful shape a name. `Position` groups X and Y. A struct is a value type whose value contains its fields; a field is a named part of that value. `public` lets code outside the type access a field. An **object initializer** sets named fields when creating a value, and the **dot operator** selects a field.
- **Pass by value, copy, and side effect:** ordinary calls copy the argument value into parameter storage. A side effect is a change outside the function's private working data.
- **`ref`, alias, and `out`:** explicitly passing a variable with `ref` makes the parameter another way to access the caller's storage. `out` is a separate output-parameter mode; it is not introduced by the return-value trace in this lesson.
- **Class, reference type, object, and reference:** a class instance is an object in dynamic storage. A reference-type variable holds a reference to that object. Copying the reference lets two variables reach one object.


1. Trace the first local cell, called `dist` or an X-distance temporary in the walkthrough: reading the X inputs gives |2 − 1| = 1.
2. [00:18:32](https://www.youtube.com/watch?v=z51K0UhriOk&t=1112s) Store 1, then compute and store the Y contribution |3 − 1| = 2 in its fresh local cell.
3. [00:18:43](https://www.youtube.com/watch?v=z51K0UhriOk&t=1123s) Add the two contributions. The diagram reserves another box for the sum, even where it has no meaningful written name.
4. [00:18:52](https://www.youtube.com/watch?v=z51K0UhriOk&t=1132s) Continue strictly from the first instruction to the last. This identifies which values were created for this call before it ends.

An **intermediate result** is a value used to obtain a later result. The sum and subtraction boxes visualize such values. Compiled execution need not give every intermediate expression its own permanent named variable.

## Return a value and resume the caller

[00:19:06](https://www.youtube.com/watch?v=z51K0UhriOk&t=1146s) Returning performs two related actions: it produces the call's value and stops the callee's execution. [00:19:33](https://www.youtube.com/watch?v=z51K0UhriOk&t=1173s) Control goes back to the caller, just as with a parameterless call, and proceeds after the call has completed.

The [return-transfer state](https://www.youtube.com/watch?v=z51K0UhriOk&t=1187s) can be read as this pair of fragments from the caller and callee:

```csharp

    Distance(xEnemy, yEnemy, xPlayer, yPlayer);
Console.WriteLine(distanceToEnemy);

// At the end of Distance:

```

1. [00:19:47](https://www.youtube.com/watch?v=z51K0UhriOk&t=1187s) Recall **assignment**: copy the value of the right-hand expression into the left-hand variable.
2. [00:19:59](https://www.youtube.com/watch?v=z51K0UhriOk&t=1199s) Evaluate the expression after `return`. Reading `dist` gives 3.
3. [00:20:08](https://www.youtube.com/watch?v=z51K0UhriOk&t=1208s) The call expression at the caller therefore has value 3; its assignment stores that value in `distanceToEnemy`.
4. [00:20:25](https://www.youtube.com/watch?v=z51K0UhriOk&t=1225s) Think of the entire call being replaced by its returned number for this assignment. It is the value that transfers, not the callee's variable.
5. [00:20:44](https://www.youtube.com/watch?v=z51K0UhriOk&t=1244s) Resume the caller's next instruction after the call-containing statement. Do not continue through the function definition as if it were another inline block.
6. [00:20:52](https://www.youtube.com/watch?v=z51K0UhriOk&t=1252s) The callee's parameters and locals cease to be available when that call ends. [00:21:03](https://www.youtube.com/watch?v=z51K0UhriOk&t=1263s) Its temporary frame no longer provides names the caller can access.
7. [00:21:07](https://www.youtube.com/watch?v=z51K0UhriOk&t=1267s) The caller's pre-existing coordinate variables remain accessible; their scope did not end when the callee returned.
8. [00:21:14](https://www.youtube.com/watch?v=z51K0UhriOk&t=1274s) Print the number retained in the caller's result variable.

## Make a position a single typed value

[00:22:49](https://www.youtube.com/watch?v=z51K0UhriOk&t=1369s) Four arguments of the same type invite a quiet mistake. The compiler accepts any four integers, even if the caller supplies all X values first, mixes entities, or swaps a coordinate. The [argument-order problem](https://www.youtube.com/watch?v=z51K0UhriOk&t=1369s) is illustrated by:

```csharp
// Intended order:
Distance(xEnemy, yEnemy, xPlayer, yPlayer);
// A type-correct but potentially wrong order:
Distance(xEnemy, xPlayer, yEnemy, yPlayer);
```

[00:23:22](https://www.youtube.com/watch?v=z51K0UhriOk&t=1402s) Group each entity's X and Y into one value. The function can then ask for two positions rather than four unrelated-looking numbers. [00:23:24](https://www.youtube.com/watch?v=z51K0UhriOk&t=1404s) A **user-defined type** is a named shape for data the program needs; `Position` will represent that coordinate pair. The `public` modifier makes its fields accessible from the surrounding example code.

[00:23:45](https://www.youtube.com/watch?v=z51K0UhriOk&t=1425s) Declare it as a **struct**, a value type. A **value type** holds the value's contents directly in its own storage; for this position, the contents are the two coordinates. In the local-variable model they do not require a separately referenced heap object. This describes the value's representation, not a universal claim that structs can never occur within heap storage.

The [type-definition state](https://www.youtube.com/watch?v=z51K0UhriOk&t=1425s) is simplified to:

```csharp
struct Position
{
    public int X;
    public int Y;
}
```

[00:24:08](https://www.youtube.com/watch?v=z51K0UhriOk&t=1448s) Use `Position` wherever the program needs the whole pair, instead of representing that pair with two independent `int` variables. [00:24:25](https://www.youtube.com/watch?v=z51K0UhriOk&t=1465s) In the current single-file, top-level program, place the type declaration after the executable statements and local functions. The recording keeps it at the end of the file. This is the current file arrangement; it does not require every struct in every project to be declared last or forbid other source files.

## Construct a Position and name its fields

[00:24:40](https://www.youtube.com/watch?v=z51K0UhriOk&t=1480s) Construct a variable using the new type. An **object initializer** is the brace-enclosed list of named field assignments attached to creation; it makes the X/Y pairing visible.

The [position-construction state](https://www.youtube.com/watch?v=z51K0UhriOk&t=1480s) introduces the form:

```csharp

```

Read the declaration in order: `Position` gives the variable's type, `position` is its name, and `new Position` creates a value of that type. The initializer assigns 2 to X and 3 to Y; its comma separates the field assignments. The whole value initializes the variable. The walkthrough changes entity labels and values while illustrating this form; use the later (1, 1)/(2, 3) pair when tracing the known distance test.

[00:25:02](https://www.youtube.com/watch?v=z51K0UhriOk&t=1502s) A `Position` variable is drawn as one larger storage block containing two smaller integer cells. Grouping does not remove either coordinate or turn the pair into one integer.

[00:25:27](https://www.youtube.com/watch?v=z51K0UhriOk&t=1527s) Those named parts are **fields**. The variable name reaches the entire position value; each field name selects one part of it. [00:25:55](https://www.youtube.com/watch?v=z51K0UhriOk&t=1555s) The **dot operator** joins those names. In the [field-access state](https://www.youtube.com/watch?v=z51K0UhriOk&t=1555s):


Here `player.X` means the X field belonging to this particular `player` variable, not a separate global variable named X.

## Read and change fields in independent positions

[00:26:15](https://www.youtube.com/watch?v=z51K0UhriOk&t=1575s) Reading a field can initialize another variable. [00:26:43](https://www.youtube.com/watch?v=z51K0UhriOk&t=1603s) Struct fields can be overwritten after creation. `player.Y = 7` changes the field inside the player's own block. It does not change the earlier copy in `savedY`.

[00:27:01](https://www.youtube.com/watch?v=z51K0UhriOk&t=1621s) Use the same type again to create a separate enemy position. The [two-position state](https://www.youtube.com/watch?v=z51K0UhriOk&t=1621s) can be reduced to:


[00:27:15](https://www.youtube.com/watch?v=z51K0UhriOk&t=1635s) The teaching drawing now has two coordinate cells per position: four integer field cells in all. [00:27:32](https://www.youtube.com/watch?v=z51K0UhriOk&t=1652s) The player's block and enemy's block occupy separate locations, so changing one does not change the other.

[00:27:45](https://www.youtube.com/watch?v=z51K0UhriOk&t=1665s) Grouping X and Y makes each position one complete block. [00:27:50](https://www.youtube.com/watch?v=z51K0UhriOk&t=1670s) Within the drawing, its sub-cells can be named with composite field accesses: `player.X`, `player.Y`, `enemy.X`, and `enemy.Y`. ## Change the interface after grouping the data

[00:28:10](https://www.youtube.com/watch?v=z51K0UhriOk&t=1690s) Pause at the intermediate state: only the stored fields have been grouped. The function still takes separate integer arguments. The [field-only intermediate state](https://www.youtube.com/watch?v=z51K0UhriOk&t=1690s) uses:

```csharp

    Distance(enemy.X, enemy.Y, player.X, player.Y);
```

[00:28:14](https://www.youtube.com/watch?v=z51K0UhriOk&t=1694s) Now group the parameters too. Replace the four integer parameters with two parameters of type `Position`. [00:28:18](https://www.youtube.com/watch?v=z51K0UhriOk&t=1698s) Each is one typed value containing X and Y, rather than one scalar coordinate.

The [grouped-signature edit](https://www.youtube.com/watch?v=z51K0UhriOk&t=1694s) leads to this simplified implementation and call:

```csharp
static int Distance(Position a, Position b)
{
    int x_dist = Math.Abs(a.X - b.X);
    int y_dist = Math.Abs(a.Y - b.Y);

int distance = Distance(enemy, player);
```

[00:28:24](https://www.youtube.com/watch?v=z51K0UhriOk&t=1704s) The caller passes each complete position as an argument. The field accesses move into the function. There can still be mistakes in creating a position, but this signature removes the four-integer ordering trap.

## Let the parameter type determine its storage

[00:29:29](https://www.youtube.com/watch?v=z51K0UhriOk&t=1769s) A **parameter** is storage local to a call, so passing an argument requires space for that parameter's value. [00:29:34](https://www.youtube.com/watch?v=z51K0UhriOk&t=1774s) One `Position` parameter needs both integer fields. Being one parameter does not mean occupying one integer-sized box.

The [parameter-layout trace](https://www.youtube.com/watch?v=z51K0UhriOk&t=1769s) is summarized schematically beside the call:

```text
Distance(enemy, player)
a: [ a.X | a.Y ]     b: [ b.X | b.Y ]
int result: [ one integer value ]
```

1. [00:29:41](https://www.youtube.com/watch?v=z51K0UhriOk&t=1781s) Draw one enclosing block for `a`, containing two sub-cells.
2. [00:29:46](https://www.youtube.com/watch?v=z51K0UhriOk&t=1786s) Name them `a.X` and `a.Y`; do the same for `b`.
3. [00:29:52](https://www.youtube.com/watch?v=z51K0UhriOk&t=1792s) Contrast an `int` variable or parameter, drawn as one cell. Parameter-list syntax does not determine the size; the declared type does.
4. [00:29:59](https://www.youtube.com/watch?v=z51K0UhriOk&t=1799s) A position contains X and Y, so draw the X field first and the Y field second.
5. [00:30:06](https://www.youtube.com/watch?v=z51K0UhriOk&t=1806s) The enemy position used in the trace contains X = 2 and Y = 3.
6. [00:30:13](https://www.youtube.com/watch?v=z51K0UhriOk&t=1813s) The player's coordinates supply values of 1. A scalar `int` cell annotated 1 remains a single cell. Do not interpret that annotation as a claim that the complete `Position` parameter `b` became an integer.

[00:30:33](https://www.youtube.com/watch?v=z51K0UhriOk&t=1833s) Position parameters have two field boxes because their type is `Position`; changing that type to `int` would change what value could be stored.
8. [00:30:45](https://www.youtube.com/watch?v=z51K0UhriOk&t=1845s) The caller's result cell is initially drawn without its answer, before the position parameter cells are filled.

This is a distinction between types and their values. Neither the integer 1 inside a field nor the number of arguments changes the declared type of its enclosing position.

## Calculate through fields and keep the returned sum

[00:31:37](https://www.youtube.com/watch?v=z51K0UhriOk&t=1897s) The function can now compute by reading fields from its parameter copies. The [grouped-distance calculation](https://www.youtube.com/watch?v=z51K0UhriOk&t=1897s) follows this fragment:

```csharp
int x_dist = Math.Abs(a.X - b.X); // |2 - 1| = 1
int y_dist = Math.Abs(a.Y - b.Y); // |3 - 1| = 2
int dist = x_dist + y_dist;     // 1 + 2 = 3
return dist;
```

1. Create the X-distance temporary and evaluate the field subtraction.
2. [00:31:43](https://www.youtube.com/watch?v=z51K0UhriOk&t=1903s) With X values 2 and 1, the contribution is 1.
3. [00:31:51](https://www.youtube.com/watch?v=z51K0UhriOk&t=1911s) With Y values 3 and 1, the contribution is 2. The intended arithmetic is 3 − 1; a garbled caption suggesting 3 − 3 cannot explain the traced result 2.
4. [00:32:03](https://www.youtube.com/watch?v=z51K0UhriOk&t=1923s) Add the contributions into the sum variable, obtaining 3.
5. [00:32:10](https://www.youtube.com/watch?v=z51K0UhriOk&t=1930s) Return 3 and store it in the caller's result. The temporary parameter and local cells stop being accessible.
6. [00:32:14](https://www.youtube.com/watch?v=z51K0UhriOk&t=1934s) The caller's result variable retains that returned distance. [00:32:19](https://www.youtube.com/watch?v=z51K0UhriOk&t=1939s) No callee field or local needs to remain available for the answer to survive.
7. [00:32:20](https://www.youtube.com/watch?v=z51K0UhriOk&t=1940s) Resume execution after the function call and use the retained result.

Grouping inputs changes how the call communicates positions, while preserving the same arithmetic and the known answer.

## Use ref to alias the caller's variable

[00:34:08](https://www.youtube.com/watch?v=z51K0UhriOk&t=2048s) The drawing represents the alias with the **address** of the caller's cell, using a number such as 64 as an example. ## Copy a reference and write to the shared object

[00:36:45](https://www.youtube.com/watch?v=z51K0UhriOk&t=2205s) Entering the function again creates its working locals and parameter storage in the temporary stack model. [00:36:52](https://www.youtube.com/watch?v=z51K0UhriOk&t=2212s) Because `Position` is now a class, an ordinary parameter cell holds a reference, not a copy of the object's X/Y fields.

The [class-parameter mutation trace](https://www.youtube.com/watch?v=z51K0UhriOk&t=2212s) is represented by an ordinary call with no `ref` modifier:

```csharp
Position enemy = new Position();
Change(enemy);
Console.WriteLine(enemy.X); // 7

static void Change(Position a)
{
    a.X = 7;
}
```

1. Copy the reference value from the caller's variable into the parameter `a`.
2. [00:37:11](https://www.youtube.com/watch?v=z51K0UhriOk&t=2231s) Follow that reference to the object in dynamic storage.
3. [00:37:32](https://www.youtube.com/watch?v=z51K0UhriOk&t=2252s) Select the object's X field with `a.X`. The field access reaches the object's field, rather than a private integer field embedded in `a`'s parameter cell. This use of a reference is not a new implicit `ref` parameter.
4. [00:37:41](https://www.youtube.com/watch?v=z51K0UhriOk&t=2261s) Write 7 into that field. The diagram's illustrative address 64 identifies the shared object; it is not a guaranteed machine address.
5. [00:37:58](https://www.youtube.com/watch?v=z51K0UhriOk&t=2278s) Only the reference was copied, so the enemy variable and `a` both reach the object whose X has changed.
6. [00:38:11](https://www.youtube.com/watch?v=z51K0UhriOk&t=2291s) Reading X through the caller's reference observes that write immediately. Ending the function's parameter storage does not reverse a change already made to the object.

This is a **side effect**, a change outside the callee's private local data. It occurs because the copied reference reaches shared object storage. It does not require aliasing the caller's reference variable itself with `ref`.

## Compare the same field write across the two types

[00:38:22](https://www.youtube.com/watch?v=z51K0UhriOk&t=2302s) Compare the class with the earlier value type while leaving the field-write expression unchanged. The [representation comparison](https://www.youtube.com/watch?v=z51K0UhriOk&t=2302s) centers on:

```csharp
static void Change(Position a)
{
    a.X = 7;
}
```

- With `Position` declared as a struct and an ordinary parameter, `a` contains copied fields. The write affects the callee's position value.
- With `Position` declared as a class and an ordinary parameter, `a` contains a copied reference. The write affects the object also reached by the caller.

[00:38:51](https://www.youtube.com/watch?v=z51K0UhriOk&t=2331s) The same dot syntax does not tell the whole storage story. First identify the type, then what the variable contains, then what the call copies, and finally where the write lands. This reasoning makes later language abstractions easier to follow.

<details>
<summary>Why is ordinary class passing still pass by value when the caller sees the changed X?</summary>

The copied value is a reference. The caller's reference variable and the parameter are separate, but both reference the same object. Writing a field changes that object; it does not prove that the caller's variable was passed with ref.

</details>

## State precisely what pass by value copies

[00:39:06](https://www.youtube.com/watch?v=z51K0UhriOk&t=2346s) State the concluding rule precisely: ordinary C# arguments are passed **by value**. What is copied depends on what the argument variable contains.

The [closing copy distinction](https://www.youtube.com/watch?v=z51K0UhriOk&t=2346s) is summarized as:

```text
struct Position argument -> copy of its X/Y value
class Position argument  -> copy of its object reference
explicit ref argument    -> alias to the caller's variable
```

[00:39:16](https://www.youtube.com/watch?v=z51K0UhriOk&t=2356s) A value-type position holds the coordinate value directly; a reference-type position holds the link to an object. Ordinary calls copy those respective values. The phrase “always by value” in the closing explanation concerns these ordinary calls; the explicitly demonstrated `ref` mode is a different mode. The earlier return transfer did not introduce `out`, another distinct parameter mode.

This lets one rule explain both examples without confusing a copied object reference with an alias to the caller's variable.

```csharp
static float Distance(Position a, Position b)
{
```
