# From fixed statements to configurable pipelines

[00:00:00](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=0s) The purpose of this lesson is to turn an ordinary sequence of C# statements into a program whose actions can be stored, reordered, inspected, and supplied by a caller. A dog changes owner, receives a new name, and gets printed. Following that small example through successive refactorings explains why each additional object is useful.

Here is the vocabulary used along the way:

- **Design pattern:** a reusable arrangement of components for a class of problems. **Creational patterns** organize object creation; **structural patterns** organize object composition; **behavioral patterns** organize execution. **Composition** means combining objects, including keeping one object inside another.
- **Pipeline:** an ordered sequence of operations. Later, a `Pipeline` object stores those operations and runs them. **Chain of Responsibility** is the related pattern named in the opening; this lesson's runner visits every configured step.
- **Context:** the shared data available during a run. The dog and ownership history belong to this context. The instruction list and each step's settings have separate roles.
- **Refactoring:** reorganizing code while preserving intended behavior. **Abstraction** lets callers refer to work by a name; **encapsulation** puts the concrete actions into one implementation behind that name.
- **Local function and capture:** a function declared in an enclosing function or entry-point scope can use local variables from that scope. **Top-level statements** provide an entry-point body without writing an explicit `Main`.
- **Dependency:** data or another object an operation needs. An **adapter** presents the interface a caller expects and forwards to existing logic with the arguments that logic requires.
- **Interface and polymorphism:** an interface is a common contract; polymorphism allows different implementations to be used through it. **Dispatch** selects the implementation at run time. The C# keyword `virtual` separately permits overriding a class method.
- **Step object:** an object representing an action to perform later. **Construction-time configuration** is data stored when creating it, such as a chosen owner or name. A **factory method** builds and returns a configured object.
- **Introspection:** examining a pipeline's steps and the descriptions they expose. A **type test** checks an object's type. A **lambda** is a short function; here it serves as a **predicate**, a condition returning true or false.
- **Decorator or wrapper:** an object that holds a compatible step, preserves its contract, and adds behavior around its action.
- **Model and collection syntax:** `sealed` prevents class inheritance; `required` requires initialization of a member. An **object initializer** supplies members after `new`. `List<T>` is a growable collection; **target-typed new** infers the constructed type from the declaration. A **collection expression**, such as `[]`, supplies collection contents. An **array** has a fixed length; a **zero-based index** numbers the first element 0.
- **Nullability and initialization:** `null` means no referenced object; `Owner?` expresses that absence is allowed. A **constructor** initializes an object. A **readonly field** can be assigned at declaration or in its constructor, and cannot later be reassigned by a caller. Property accessors `get`, `set`, and `init` control reading, writing, and initialization.
- **Control and output syntax:** `foreach` visits collection elements; `while` repeats; `switch/case` selects a command branch; `break` leaves that branch; `return` returns a result or leaves the entry point. `static` associates a member with its type, `public` exposes it, and `void` means no returned value. **String interpolation** inserts values into text; **null coalescing** (`??`) supplies a fallback for null.

## Introduce a decorator dependency

[00:26:43](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1603s) Representing individual steps as objects also makes it possible to attach extra work around one chosen action. [00:26:51](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1611s) A **decorator**, or wrapper, contains an already compatible step, implements the same contract, and adds behavior while delegating the original work. The recording proposes a step that prints an inner action's description and executes it.

[00:27:02](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1622s) The inner `IPipelineStep` is a **dependency**: the wrapper needs it in order to function, so it must be supplied when the wrapper is constructed. This is **composition**, combining objects by keeping one inside another.

[00:27:34](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1654s) A constructor or a writable field could receive that dependency. The design choice is to prevent callers from replacing it afterward. [00:27:37](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1657s) The recording considers a public required, getter-only member as a way to allow initialization once. That wording needs a syntax correction: a required property needs an accessible `set` or `init` accessor; a genuinely getter-only required property cannot be initialized by the caller. [Required-property rules](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/required) establish this constraint.

The [final saved decorator](https://github.com/AntonC9018/uniCourse_csharp/blob/df46c75bc2516786091ed07ebc48fe9c47b461c7/examples/pipeline/Program.cs) uses a constructor and a public readonly field instead. This excerpt shows its dependency storage; the next section supplies the methods:

```csharp
// Members of PrintStep_AndExecute_PipelineStep:
public readonly IPipelineStep Step;

public PrintStep_AndExecute_PipelineStep(IPipelineStep step)
{
    Step = step;
}
```

A **constructor** initializes the object as it is created. A **readonly field** permits assignment at declaration or in that constructor, while preventing later replacement by a caller. The saved field is public, so callers can read it. Keeping the reference fixed does not freeze the inner object's contents.

A property's `get` accessor reads it; `set` allows assignment; `init` allows assignment during initialization. A constructor-initialized getter-only property is another way to expose a read-only reference. A `required` property with `get; init;` permits object-initializer configuration; it should not be described as a getter-only member or a universal “exactly one assignment” guarantee.
