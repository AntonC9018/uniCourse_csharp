# Назначение и словарь

[00:00:00](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=0s) Построим надёжное представление дискретных вариантов бомбы, двигаясь от текста к числам, именованным константам и, наконец, отдельным типам-перечислениям. В задании один игрок читает инструкцию, а другой осматривает бомбу и решает, какой провод перерезать. [00:00:18](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=18s) У бомбы есть один из трёх портретов — Ленин, Джордж Вашингтон или Гитлер, — а также цвет лампочки, состояние тумблера и значение регулятора. Этот урок строит представление портретов и цветов лампочек; полная реализация игры по обезвреживанию здесь не приводится.

Используемые по ходу термины:

- **Переменная и присваивание:** переменная хранит текущее значение; присваивание вычисляет выражение и сохраняет его результат. Последующее присваивание заменяет предыдущее значение.
- **Тип, строка и целое число:** тип описывает допустимые способы использования значения. `string` представляет текст; `int` представляет целое число в фиксированном диапазоне.
- **Равенство и условие:** `==` сравнивает значения и даёт `true` или `false`; условие `if` определяет, выполнится ли блок.
- **Время компиляции и время выполнения:** время компиляции — когда исходный код проверяется и транслируется; время выполнения — когда программа работает. Ошибка компиляции мешает сборке, сбой во время выполнения происходит при работе программы, а логическая ошибка может дать неверное поведение без той и другой.
- **Функция, аргумент, параметр и сигнатура:** функция выполняет операцию. Аргумент — значение, переданное вызывающим кодом; параметр — локальное имя функции для этого входа. Сигнатура описывает имя функции и типы параметров; в её объявлении также указывается тип возвращаемого значения.
- **Выражение, вычисление и возврат:** выражение производит значение. Вычисление получает это значение, а `return` завершает вызов функции и передаёт его результат.
- **Блок и область видимости:** фигурные скобки `{ }` группируют инструкции в блок; область видимости определяет, где можно использовать объявленное имя.
- **Константа и магическое число:** константа — именованное значение, фиксированное на этапе компиляции. Магическое число — числовой литерал, смысл которого в программе скрыт.
- **Switch, case и default:** инструкция `switch` выбирает ветку для одного значения. `case` помечает подходящую ветку; `default` обрабатывает значения без подходящего `case`.
- **Перечисление, элемент и базовое значение:** перечисление (`enum`) — отдельный тип значений с именованными константами, которые называются элементами. У каждого элемента есть базовое числовое значение; базовый тип по умолчанию — `int`.
- **Абстракция и контракт типа:** абстракция позволяет работать с осмысленными именами, скрывая детали представления. Контракт типа сообщает вызывающему коду, какую категорию значений принимает функция.
- **Приведение типа:** явное преобразование, записываемое как `(TargetType)expression`; преобразование числа в перечисление не проверяет, есть ли элемент с таким числом.
- **Проверка, диагностика и исключение:** проверка (`Assert`) контролирует предположение во время разработки. `Debug.Assert` и `Debug.Fail` сообщают диагностику; исключение прерывает обычный ход выполнения и при отсутствии обработки может завершить программу.
- **Массив и сентинел Count:** массив хранит фиксированное число элементов. Сентинел — специальная метка; последний элемент `Count` может обозначать число настоящих вариантов при соглашении о последовательной нумерации с нуля.

Лабораторная работа про [перечисления](../../../labs/1_basic/09_enum.md) даёт отдельное упражнение со светофором. Весь код ниже — короткая реконструкция состояний из связанного видео, с исправлениями там, где это необходимо. Ни в одном просмотренном зафиксированном исходнике нет именно этих состояний программы-бомбы, поэтому примеры не выдаются за построчно точный код коммитов.

# Начнём со строки

[00:00:28](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=28s) Начнём с самого простого представления: **строки** — текстового значения, хранящего имя показанного портрета. **Переменная** хранит текущее значение. Игра задумывает, чтобы эта переменная одновременно содержала ровно одно из трёх имён; сам тип `string` допускает любой текст и не требует этого ограничения.

Реконструкция [начального состояния из видео](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=28s):

```csharp
string portrait = "Ленин";
Console.WriteLine(portrait);
```

[00:00:47](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=47s) Если текущее значение равно `"Ленин"`, именно это значение определяет показанный портрет. Повторное присваивание переменной другого имени меняет текущий портрет; второго портрета одновременно не появляется.

[00:00:57](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=57s) Чтобы проверить, какой портрет загружен, повторите ожидаемое имя в сравнении на **равенство**. Условие даёт логический результат, и блок выполняется, только когда результат истинен.

Реконструкция [состояния с проверкой строки](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=57s):

```csharp
{
    Console.WriteLine("Lenin is displayed");
}
```

Так работает, но каждая проверка зависит от того, чтобы один и тот же текст был набран безошибочно.

# Следуйте порядку выполнения

[00:01:11](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=71s) Инструкции выполняются в порядке написания. Печать переменной до повторного присваивания выводит прежнее значение. **Присваивание** заменяет текущее значение; последующие инструкции видят замену.

Реконструкция [демонстрации порядка выполнения](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=71s):

```csharp
string portrait = "Ленин";
Console.WriteLine(portrait);       // Печатает Ленин
portrait = "Гитлер";
if (portrait == "Ленин")
{
    Console.WriteLine("Matched");
}
```

[00:01:22](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=82s) Проверка после более позднего присваивания не выполняется: в этот момент переменная содержит `"Гитлер"`, а не `"Ленин"`. Условие читает текущее значение, а не историю переменной.

[00:01:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=92s) Перенесите проверку перед повторным присваиванием — и она выполнится, потому что текущее значение всё ещё ожидаемое. Запись показывает выполнение блока после такого переноса.

Реконструкция [состояния с перенесённой проверкой](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=92s):

```csharp
string portrait = "Ленин";
if (portrait == "Ленин")
{
    Console.WriteLine("Matched");
}
portrait = "Гитлер";
```

<details>
<summary>Изменит ли перенос только инструкции печати то значение, которое увидит условие?</summary>

Нет. Условие зависит от того, какое присваивание стоит перед ним. Перенос печати меняет то, что выводится в этом месте, но не меняет саму переменную.

</details>

# Почему строки — ненадёжные идентификаторы

[00:01:36](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=96s) Равенство строк требует совпадения текста: одинаковой длины и одинаковых символов в соответствующих позициях. Запись объясняет это как проверку символов по порядку. Это полезная модель требуемого результата, а не обещание точной реализации в среде выполнения.

Реконструкция [демонстрации опечатки](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=108s):

```csharp
string portrait = "Гитлер";
if (portrait == "Гитлре")          // Ожидаемое имя с опечаткой
{
    Console.WriteLine("Matched");
}
```

[00:01:48](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=108s) Опечатка в ожидаемом имени делает условие ложным, поэтому блок не выполняется. [00:02:02](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=122s) Добавление символов тоже не помогает: общего префикса мало, а лишние символы меняют длину.

[00:02:14](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=134s) **Ошибка компиляции** — проблема в исходном коде, обнаруженная до выполнения. Портрет с опечаткой в кавычках всё равно остаётся корректной строкой, поэтому компилятор не может распознать ошибку программиста. [00:02:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=152s) Это также не обязательно сбой во время выполнения. Программа может работать без аварии и молча выбрать неверную ветку: это **логическая ошибка**.

[00:02:36](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=156s) Урок мотивирует переход к числам и объёмом работы, нужным для сравнения строк: строки могут требовать проверки длины и сравнения по содержимому, тогда как сравнение целых чисел не требует обхода текста. Не воспринимайте «намного больше операций» как измеренный результат для каждого сравнения: быстрые пути и ранние несовпадения могут сокращать работу при сравнении строк.

[00:03:02](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=182s) Читаемая печать — главная причина, по которой этому примеру нужен текст. [00:03:19](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=199s) Мы хотим, чтобы игрок видел имя, но внутреннему принятию решений это имя как идентификатор не требуется. [00:03:36](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=216s) Если оставить идентификатор строкой, риск незаметной опечатки сохраняется и в присваиваниях, и в повторяющихся проверках. Разделив идентичность и отображаемый текст, мы получим читаемый вывод, не используя текст повсюду.

[00:04:21](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=261s) Печать теперь обнажает представление: `2` не сообщает игроку, что показан Гитлер. # Построим функцию из числа в текст

[00:04:34](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=274s) **Функция** может сопоставить числовую идентичность с текстом, нужным для вывода. [00:04:50](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=290s) Сделаем ветвление по входному значению: 0 соответствует Ленину, 1 — Вашингтону, 2 — Гитлеру.

[00:05:08](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=308s) Одно слово вроде `Hitler` — это идентификатор, а не строковый литерал. Без объявления, придающего ему смысл, оно не может дать нужный текст; записанное отдельно как инструкция, оно также не выражает преобразование. Результат должен быть выражением, занимающим позицию аргумента печати.

[00:05:15](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=315s) Введём функцию с входом типа `int` и результатом типа `string`. В расшифровке это пользовательское преобразование называется функцией «int to string». Здесь оно названо `PortraitToString`, чтобы отличать его от встроенного `portrait.ToString()` без параметров, который для целого числа дал бы `"2"`, а не подпись портрета.

Реконструкция [состояния с функцией преобразования](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=315s) с временной заглушкой, которую мы скоро рассмотрим:

```csharp
static string PortraitToString(int p)
{
    if (p == 0) { return "Ленин"; }
    if (p == 1) { return "Джордж Вашингтон"; }
    if (p == 2) { return "Гитлер"; }
    return "";
}
```

[00:05:25](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=325s) **Параметр** `p` — локальное имя входа функции. Ему необязательно совпадать с именем переменной `portrait` у вызывающего кода. **Аргумент** — это значение, переданное в месте вызова.

[00:05:36](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=336s) Заменим сырое число в месте печати вызовом преобразования:

Реконструкция [изменённого места печати](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=336s):

```csharp
int portrait = 2;
Console.WriteLine(PortraitToString(portrait));
```

[00:05:46](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=346s) Эквивалентный двухшаговый вариант сначала сохраняет преобразованный текст, а затем печатает его:

Реконструкция [двухшагового варианта](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=346s):

```csharp
string portraitText = PortraitToString(portrait);
Console.WriteLine(portraitText);
```

Обе формы выражают одну и ту же зависимость: сначала вычислить подпись, затем её напечатать.

# Вычислим вызов и вернём результат

[00:05:53](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=353s) **Выражение** — код, производящий значение, а **вычисление** получает это значение во время выполнения. После того как целочисленный аргумент вычислен, вызов преобразования является выражением типа `string`.

Используем [двухшаговое состояние из видео](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=353s):

```csharp
string portraitText = PortraitToString(portrait);
```

Проследим вызов по порядку:

1. [00:05:53](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=353s) Прочитать аргумент `portrait`, в котором сейчас хранится 2.
2. [00:06:04](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=364s) Войти в функцию: её параметр получает это значение.
3. [00:06:16](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=376s) Вычислить выражение справа до завершения присваивания.
4. [00:06:37](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=397s) Найти ветку для 2 и получить соответствующую строку.
5. [00:06:52](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=412s) Вызов даёт `"Гитлер"`; это вычисление выражения во время выполнения, а не компилятор правит исходный код.
6. Сохранить результат в `portraitText`. Строковая переменная хранит ссылку на полученную строку; присваивание не обязательно создаёт новый объект строки.

[00:07:00](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=420s) Инструкция **return** определяет результат, передаваемый вызывающему коду, и завершает данный вызов функции.

Реконструкция [ветки с return](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=420s):

```csharp
if (p == 2)
{
    return "Гитлер";
}
```

[00:07:13](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=433s) Запись добавляет фигурные скобки, чтобы ветка стала **блоком** — группой инструкций. Сохраните этот ясный стиль, но утверждение, что самому `return` эти скобки всегда обязательны, слишком широкое: `if (p == 2) return "Гитлер";` — допустимый код на C#. Обычной функции с телом в виде блока по-прежнему нужны внешние скобки. [Справочник по инструкциям выбора C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/statements/selection-statements) различает одиночные инструкции и блоки.

[00:07:21](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=441s) После выполнения `return` последующие инструкции этой функции не выполняются. Именно поэтому три последовательные проверки `if` могут заменить цепочку `if/else if`, когда каждая успешная ветка делает возврат. См. [справку по инструкции return](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/statements/jump-statements#the-return-statement).

# Сделаем неожиданные значения заметными

[00:07:28](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=448s) Что, если `p` равно 5? Функция, возвращающая строку, не может дойти до конца, не создав строку или не выбрав путь без нормального возврата. Компилятор видит, что три условия не покрывают все возможные целые числа.

[00:07:44](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=464s) Заглушка вида `return "";` выполняет требование о возврате, но может скрыть ошибку программиста. [00:07:49](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=469s) Урок предпочитает немедленный заметный отказ во время разработки молчаливому возврату бессмысленного вывода.

Реконструкция [состояния с диагностикой для разработки](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=482s):

```csharp
static string PortraitToString(int p)
{
    if (p == 0) { return "Ленин"; }
    if (p == 1) { return "Джордж Вашингтон"; }
    if (p == 2) { return "Гитлер"; }

    System.Diagnostics.Debug.Fail("Unknown portrait");
    return "";
}
```

[00:08:02](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=482s) `Debug.Fail` — это **диагностика**, сообщение о нарушенном предположении. Компилятор не считает её гарантированным завершением, поэтому возвращать значение в этой форме по-прежнему необходимо. [00:08:14](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=494s) В задуманной готовой программе эта ветка недостижима; попадание в неё во время разработки означает, что нужно исправить представление или вызывающий код.

[00:08:28](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=508s) Предположение функции в том, что вход — одно из допустимых значений портрета. [00:08:42](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=522s) Игра определяет три портрета, поэтому четвёртое неизвестное значение в этой модели смысла не имеет. [00:08:54](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=534s) Его следует считать ошибкой, а не подставлять правдоподобную подпись. Это проверка предположения программиста, а не обычный выбор игрока между корректными портретами.

[00:09:16](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=556s) **Проверка** (`Assert`) контролирует предположение, например `Debug.Assert(false, "Unknown portrait")` на неожиданном пути. И проверки, и сообщения об отказе зависят от символа компиляции `DEBUG`. В сборках Release их обычно нет, и это не только следствие оптимизации. Безусловный `return "";` остаётся. Кроме того, эти диагностические вызовы не гарантируют аварии: поведение зависит от обработки диагностики. См. [Debug.Assert](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.debug.assert) и [Debug.Fail](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.debug.fail).

Для гарантированного прерывания обычного хода управления исправленная альтернатива [состоянию из видео с неожиданным значением](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=469s) использует **исключение**:

```csharp
throw new System.ArgumentOutOfRangeException(nameof(p));
```

Здесь `throw` возбуждает исключение, `new` создаёт его объект, а `nameof(p)` передаёт имя параметра строкой. Эта замена — уточнение ради корректности, а не утверждение, что в видео была именно такая строка. Необработанное исключение завершает программу; вызывающий код также может его перехватить. Это различие пригодится позже, когда отсутствующий элемент перечисления дойдёт до заглушки.

# Заменим повторяющиеся сравнения на switch

[00:10:39](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=639s) Предлагаются два улучшения: переписать повторяющиеся сравнения с помощью `switch` и выделить каждому семейству значений собственный тип. Сначала изменим ветвление.

[00:10:55](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=655s) **Инструкция switch** выбирает ветку по одному входному значению. Именно так устроены повторяющиеся проверки: сравнивается одно и то же `p` с разными константами. В видео используется инструкция switch с метками `case`, а не отдельная возможность C#, называемая switch-выражением.

Реконструкция [преобразования на switch](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=655s):

```csharp
static string PortraitToString(int p)
{
    switch (p)
    {
        case Lenin:
        {
            return "Ленин";
        }
        case GeorgeWashington:
        {
            return "Джордж Вашингтон";
        }
        case Hitler:
        {
            return "Гитлер";
        }
        default:
        {
            System.Diagnostics.Debug.Fail("Unknown portrait");
            return "";
        }
    }
}
```

[00:11:06](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=666s) Пишите фигурные скобки после каждой метки `case`, чтобы создать отдельный **блок**. [00:11:09](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=669s) Блок задаёт локальным переменным ясную **область видимости** — область, где можно использовать их имена. Без внутреннего блока локальная переменная, объявленная в секции switch, может иметь область видимости через весь блок switch, хотя правила определённости присваивания всё же ограничивают её использование. Скобки для каждого `case` избавляют от путаницы в коллизиях имён и видимости.

[00:11:33](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=693s) Этот switch выражает то же ветвление, что и прежние проверки. Возврат выходит из функции, поэтому эти случаи не нуждаются в `break`. Случаи, которые продолжают работу после switch, обычно заканчивались бы `break`.

[00:11:51](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=711s) Запись ненадолго откладывает более сложный синтаксис switch для форм, которые не просто возвращают значение в каждом `case`. [00:11:57](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=717s) Возврат результата из выбранного случая — обычный и полезный приём, на котором здесь сделан акцент. Заметка остаётся на показанной форме инструкции и не превращается в учебник по switch-выражениям.

# Сохраним ветку default

[00:14:33](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=873s) Конструкция switch по-прежнему нуждается в ветке **default**, обрабатывающей входы без подходящего `case`.

[00:14:47](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=887s) Добавьте ещё один элемент перечисления, не обновляя преобразование. [00:15:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=903s) Новый элемент теперь является допустимым аргументом функции, принимающей `Portrait`, но для него нет ветки.

Реконструкция [состояния с расширением и пропущенным случаем](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=887s); `AdditionalPortrait` — описательное имя-заглушка для добавленного варианта:

```csharp

{
    Lenin = 0,
    GeorgeWashington = 1,
    Hitler = 2,
```

Расширение перечисления и расширение каждой исчерпывающей операции над ним — разные изменения. Тип допускает новый аргумент, но сам по себе не пишет недостающее поведение.

# Поймём числовое хранение и типы во время выполнения

[00:17:20](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1040s) Элемент вроде `Portrait.Hitler` — константа с базовым числовым значением 2. Его значение может быть встроено в скомпилированный код; переменная этого перечисления хранит числовую нагрузку, а не текст `"Hitler"`.

Реконструкция [состояния из видео с числовым сравнением](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1040s):

```csharp
Portrait portrait = Portrait.Hitler;

{
    Console.WriteLine("Matched");
}
```

[00:17:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1052s) Запись описывает перечисление как понятие времени компиляции, а хранимое значение — как число. Сохраните это наблюдение о числовом хранении, но исправьте утверждение, что тип перечисления исчезает во время выполнения: .NET сохраняет сведения о типе перечисления и об именах его элементов. Хранение в перечислении и числовые операции не требуют хранения строк.

[00:17:40](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1060s) Сохранённые сведения объясняют и форматирование по именам. [00:17:44](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1064s) Печать перечисления и печать явного преобразования в целое число могут дать разные представления одной и той же числовой нагрузки. Имя выбирается не только компилятором; его может определить форматирование перечислений во время выполнения. См. [справку по типу System.Enum](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/enum#the-systemenum-type-and-enum-constraint) и [Enum.ToString](https://learn.microsoft.com/en-us/dotnet/api/system.enum.tostring).

[00:17:55](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1075s) Объяснение «без преобразования в строку» относится к проверке равенства, а не к получению печатного текста. Сравнение двух значений `Portrait` сравнивает их числовые значения. [00:18:22](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1102s) Осмысленные имена элементов делают эти числа самодокументируемыми.

[00:18:24](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1104s) Когда оба значения равны 2, равенство истинно, и защищённый блок выполняется. Никакого сравнения строк `"Hitler"` не происходит.

# Приведение без предположения о проверке

[00:18:27](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1107s) **Приведение типа** явно преобразует выражение к целевому типу. Число можно привести к перечислению, даже если ни один элемент не объявляет такое значение.

Реконструкция [состояния с прямым приведением](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1110s):

```csharp
Portrait portrait = (Portrait)2;
Console.WriteLine(portrait == Portrait.Hitler);  // True
```

[00:18:30](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1110s) Здесь литерал 2 даёт то же значение перечисления, что и `Portrait.Hitler`. [00:18:33](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1113s) Приведение может действовать прямо на литерал или другое выражение; промежуточная целочисленная переменная не нужна.

[00:18:35](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1115s) Это преобразование не выполняет **проверку принадлежности**, то есть не сверяется со списком элементов. Оно переводит числовое значение в тип перечисления. [00:18:37](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1117s) Число, отсутствующее в этом списке, всё равно может быть сохранено.

Реконструкция [состояния с безымянным значением](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1172s):

```csharp
Portrait portrait = (Portrait)123;
Console.WriteLine(portrait == Portrait.Hitler);  // False
Console.WriteLine(PortraitToString(portrait));   // Достигает default
```

[00:19:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1172s) Приведение не даёт жалобы на этапе компиляции только из-за того, что у 123 нет имени. [00:19:40](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1180s) В зафиксированном запуске присваивание проходит успешно, а отказ проявится позже, когда значение дойдёт до запрограммированной ветки проверки/отказа. Само равенство не приводит к аварии: оно даёт логический результат. Источником отказа служит диагностика или исключение в окружающей логике.

[00:19:41](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1181s) Значение типа `Portrait` может принимать любое значение, представимое его базовым `int`; именованные элементы не образуют закрытого, автоматически проверяемого множества. [00:19:45](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1185s) Именно поэтому числовое приведение обходит предположение, что приходят только известные портреты.

[00:19:45](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1185s) Обратное приведение извлекает базовое целое число:

Реконструкция [состояния с обратным преобразованием](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1185s):

```csharp
int code = (int)Portrait.Hitler;
Console.WriteLine(code);          // 2
```

[Справочник по преобразованиям перечислений](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/enum#conversions) подтверждает оба направления преобразования и безымянные значения.

<details>
<summary>Делает ли параметр типа Portrait ветку default избыточной?</summary>

Нет. Вызывающий код может передать безымянное значение через явное приведение. У более позднего именованного элемента тоже может не оказаться подходящей ветки. Тип предотвращает случайное смешение категорий, но не проверяет полноту.

</details>

# Вычисляем арифметику через преобразование в целые

[00:19:51](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1191s) Приводите значения перечисления к `int`, чтобы увидеть их числовую величину, а затем выполняйте обычную целочисленную арифметику. **Вычисление** по-прежнему означает получение значения каждого выражения до использования его результата.

Реконструкция [демонстрации умножения](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1191s):

```csharp
int hitlerCode = (int)Portrait.Hitler;
Console.WriteLine(hitlerCode);    // 2

int product = (int)Portrait.Lenin * (int)Portrait.GeorgeWashington;
Console.WriteLine(product);       // 0
```

[00:20:01](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1201s) Предскажите вывод, прослеживая подвыражения, а не читая имена как текст:

1. [00:20:09](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1209s) Для умножения нужны значения обоих операндов-выражений. В C# эти выражения-операнды вычисляются слева направо.
2. [00:20:57](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1257s) У `Portrait.Lenin` базовое значение 0.
3. [00:21:05](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1265s) Его приведение к `int` даёт 0.
4. [00:21:11](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1271s) У `Portrait.GeorgeWashington` базовое значение 1, поэтому приведение даёт 1.
5. [00:21:12](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1272s) Перемножим полученные операнды: 0 × 1 = 0.

[00:20:55](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1255s) Зафиксированный результат равен нулю, как и предсказывает это вычисление.

[00:21:21](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1281s) Базовое значение `Portrait.Hitler` равно 2, но не обобщайте это на неявное преобразование любого выражения перечисления в `int`. Обычное извлечение числа здесь выполняется через `(int)`. [00:21:23](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1283s) Затем вычисленный целочисленный результат можно обратно привести к `Portrait`, если нужен результат типа перечисления.

Реконструкция [преобразования целочисленного результата](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1283s):

```csharp
int product = (int)Portrait.Lenin * (int)Portrait.GeorgeWashington;
Portrait result = (Portrait)product;    // Базовое значение 0
```

[00:21:29](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1289s) Более широкий пример на модульной арифметике намеренно пропущен. Уроку требуется приём преобразования в целое число, а не реализация циклического перебора значений.

[00:21:37](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1297s) Главный вывод — числовое представление. [00:21:56](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1316s) Утверждению «любая целочисленная операция работает с перечислениями» нужна оговорка: произвольные целочисленные операции можно выполнять после преобразования, но выражения перечислений напрямую поддерживают не все целочисленные операторы. Например, умножение двух операндов-перечислений требует сначала преобразовать их. [Спецификация операций над перечислениями](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/enums#206-enum-values-and-operations) перечисляет операторы, поддерживаемые напрямую.

<details>
<summary>Подтверждает ли обратное приведение произведения к Portrait, что результат — объявленный портрет?</summary>

Нет. Приведение только преобразует число. Здесь 0 как раз соответствует Ленину; другой расчёт может дать безымянное значение.

</details>

# Пусть пропущенные значения продолжают предыдущий элемент

[00:22:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1323s) Элементы могут опускать числовые начальные значения. Каждый пропущенный элемент получает значение непосредственно предшествующего элемента плюс один.

Реконструкция [состояния с пропущенными значениями](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1323s):

```csharp
enum Color
{
    Blue = 0,
    White,       // 1
    Red          // 2
}
```

[00:22:10](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1330s) Это воспроизводит явную последовательность 0, 1, 2. [00:22:17](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1337s) Достаточно задать Blue равным 0, чтобы White и Red получили значения 1 и 2. [00:22:22](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1342s) Если и первый элемент опускает начальное значение, он получает ноль.

[00:22:24](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1344s) Явное начальное значение начинает новую последовательность. Сжатая формулировка расшифровки про присваивание 5 и получение 6 не должна читаться как изменение явно заданного элемента: элемент, записанный как `= 5`, равен 5; следующий пропущенный элемент равен 6.

Реконструкция [демонстрации явного скачка](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1344s):

```csharp
enum Color
{
    Blue,        // 0
    White = 5,   // 5
    Red          // 6
}
```

[00:22:32](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1352s) Red получает 6, потому что непосредственно предшествующий ему элемент равен 5. Правило — предыдущий элемент плюс один, а не число элементов и не правило, отменяющее явное присваивание. См. [спецификацию элементов перечисления](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/enums#204-enum-members).

# Используем элемент Count для размера массива

[00:22:40](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1360s) Восстановим последовательную нумерацию с нуля, а затем добавим последний пропущенный элемент с именем `Count`. Это **сентинел** — метка, а не настоящий цвет лампочки.

Реконструкция [состояния с Count для трёх цветов](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1360s):

```csharp
enum Color
{
    Blue = 0,
    White,       // 1
    Red,         // 2
    Count        // 3
}
```

[00:22:51](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1371s) В показанном результате Count вычисляется как 3. [00:23:01](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1381s) Это совпадает с тремя настоящими цветами, стоящими перед ним.

[00:23:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1383s) Count получается из числовой последовательности объявления, а не из отдельно набранного размера. [00:23:09](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1389s) Вставьте ещё один настоящий цвет перед сентинелом — и он станет равен 4.

Реконструкция [состояния с добавленным цветом](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1389s):

```csharp
enum Color
{
    Blue = 0,
    White,
    Red,
    Yellow,      // 3
    Count        // 4
}
```

[00:23:19](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1399s) Count работает потому, что каждое пропущенное значение зависит от предыдущего. [00:23:21](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1401s) Он не анализирует массив, не выполняет рефлексию по элементам и не подсчитывает объявления автоматически. Значение равно числу настоящих вариантов только потому, что они начинаются с нуля, идут подряд и предшествуют сентинелу. Пропуски, повторяющиеся базовые значения, ненулевое начало или перенос Count нарушают это равенство. Сам Count — объявленный элемент перечисления, поэтому код приложения всё равно обязан отличать его от используемого цвета.

[00:23:31](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1411s) Замените жёстко заданный размер массива числовым значением сентинела. **Массив** при создании имеет фиксированное число элементов. Здесь нужен размер по одному элементу на каждый настоящий цвет.

Реконструкция [изменения размера массива](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1411s):

```csharp
// До: литерал нужно поддерживать отдельно.
int[] entries = new int[3];

// После: используется соглашение о последовательных цветах с нуля.
int[] entriesByColor = new int[(int)Color.Count];
```

[00:23:38](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1418s) При таком соглашении для добавления Yellow нужна одна новая строка объявления; использующему её выделению памяти не требуется собственная правка размера. [00:23:55](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1435s) Этот приём полезен, когда массиву нужен один элемент на каждый вариант перечисления. [00:24:03](https://www.youtube.com/watch?v=LLfU1a7pTxg&t=1443s) Передача значения Count в качестве длины массива создаёт ровно столько элементов: три до вставки Yellow и четыре после неё. Приведение `(int)` делает размер целым числом. В `new int[length]` оператор `new` создаёт массив целых чисел, а квадратные скобки задают его длину; `int[]` — тип массива у переменной.

<details>
<summary>Можно ли доверять Count как числу цветов, если White явно задано равным 5?</summary>

Нет. Пропущенные значения продолжаются от 5, поэтому сентинел следует за числовой последовательностью, а не считает имена. Перед использованием этого соглашения о размере восстановите последовательные значения с нуля.

</details>
