# От исходных файлов к вызовам функций

[00:00:02](https://www.youtube.com/watch?v=jLWY_id6nXU&t=2s) Проследите за небольшой консольной программой на C# от её исходных файлов до скомпилированного результата, а затем проследите за выполнением по отдельным инструкциям и по именованным группам инструкций. Цель — объяснить и откуда берётся запускаемая программа, и почему её действия выполняются в определённом порядке.

[Лабораторная работа «Основы проекта»](../../../labs/1_basic/02_project.md) даёт связанные упражнения. [Лабораторная работа по Git](../../../labs/1_basic/03_git.md) отдельно рассматривает настройку репозитория; эта запись объясняет только то, почему сгенерированные папки следует игнорировать.

Словарь терминов, нужных для разбора:

- **Исходный файл и конфигурация проекта:** исходный файл содержит текст на C#, обычно в файле `.cs`; файл `.csproj` описывает, как собирать проект. **.NET SDK** предоставляет инструменты разработки, включая **компилятор**, который переводит этот исходный код в скомпилированный код программы.
- **Компиляция и сборка:** компиляция переводит код; сборка выполняет всю работу, необходимую для получения результата, включая подготовку и компиляцию. **Запуск** означает старт этого результата.
- **Инструкция верхнего уровня, класс и метод входа:** инструкция верхнего уровня — это исполняемый код, написанный прямо в основном исходном файле. Компилятор помещает её в сгенерированный класс, контейнер для членов программы, и в сгенерированный метод входа, через который начинается работа программы. Детали их реализации откладываются.
- **Инструкция (statement):** одно исполняемое действие в исходной программе. Курс использует слово «инструкция»; английский термин программирования — «statement». В примерах одна инструкция занимает отдельную строку, но инструкция и физическая строка текста — не всегда одно и то же.
- **Консоль и `Console.WriteLine`:** консоль — это терминальный интерфейс ввода-вывода; `Console.WriteLine` печатает значение и переводит строку.
- **DLL, библиотека, исполняемый файл и среда выполнения:** DLL — это скомпилированная сборка .NET; библиотека предоставляет переиспользуемый код другим программам; исполняемый файл — это результат сборки, который можно запустить. **Среда выполнения .NET** предоставляет окружение для выполнения скомпилированного кода .NET. Возможность запустить файл отдельно сама по себе не доказывает, что приложение было развёрнуто со своей средой выполнения.
- **`bin`, `obj` и артефакты сборки:** артефакты — это сгенерированные файлы. `bin` хранит результат сборки; `obj` хранит промежуточные данные сборки. **Кеш** хранит переиспользуемую работу. **Пакет** предоставляет переиспользуемое программное обеспечение; **зависимость** — это программное обеспечение, которое нужно проекту.
- **`Debug` и целевой фреймворк:** `Debug` — конфигурация сборки, используемая здесь; целевой фреймворк определяет версию .NET, на которую нацелен проект, и в записи показан как `net9.0`.
- **Полный путь и оператор вызова:** полный путь начинается с диска или корня файловой системы, поэтому терминал может найти файл независимо от текущей папки. Пример для PowerShell использует оператор вызова `&`, чтобы запустить исполняемый файл, имя которого задано в кавычках.
- **Репозиторий Git и `.gitignore`:** репозиторий хранит историю исходного кода. `.gitignore` перечисляет пути, которые Git должен исключать при рассмотрении неотслеживаемых файлов.
- **Последовательное выполнение и процессор:** процессор выполняет работу программы. Последовательное выполнение означает, что действия последовательности завершаются по одному, прежде чем начинается следующее.
- **`Thread.Sleep(1000)`:** вызов, приостанавливающий текущий поток — отслеживаемую последовательность выполнения — на 1 000 миллисекунд, то есть на одну секунду.
- **Функция (метод), определение и тело:** функция — это именованная последовательность инструкций. Её определение задаёт имя и тело, то есть инструкции между `{` и `}`. В записи используется также слово «метод».
- **`void`, скобки, фигурные скобки и точка с запятой:** `void` — ключевое слово перед именами функций в примерах, а не имя самой функции. Круглые скобки `()` встречаются в определениях и вызовах; фигурные скобки `{}` охватывают тело; точка с запятой `;` завершает показанные здесь инструкции. Подробный синтаксис объявлений и смысл `void` как типа возвращаемого значения откладываются.
- **Вызов, вызывающий код, возврат и вложенный вызов:** вызов запускает тело функции; вызывающий код — это код, который делает этот вызов. Возврат продолжает работу вызывающего кода после вызова. Вложенный вызов возникает, когда тело одной функции вызывает другую.

Примеры ниже — это сокращённые реконструкции записанных действий, а не утверждения о точных состояниях редактора в коммитах. Ссылки на видео обозначают эти состояния. Примеры из репозитория явно помечены как связанные, если они не относятся к записанному проекту.

[00:00:02](https://www.youtube.com/watch?v=jLWY_id6nXU&t=2s) **Исходный файл** — это текст, который читает компилятор. 3. [00:00:33](https://www.youtube.com/watch?v=jLWY_id6nXU&t=33s) Скомпилируйте и запустите снова. Программа по-прежнему работает.

Перенос меняет расположение, а не содержимое исходника:

```text
Before:                   After:
project/                  project/
  project.csproj            project.csproj
  Program.cs                nested/
                              Program.cs
```

[00:00:36](https://www.youtube.com/watch?v=jLWY_id6nXU&t=36s) Файлы `.cs` и в корне, и во вложенной папке находятся благодаря стандартному включению исходников проекта. Этот пример переносит единственный файл, а не создаёт две копии стартовых инструкций. Правило включения по умолчанию также не означает, что любая возможная конфигурация проекта обязана включать каждый файл: явная конфигурация может менять значения по умолчанию.

## Результат сборки и отдельные запуски

[00:00:45](https://www.youtube.com/watch?v=jLWY_id6nXU&t=45s) **Сборка** автоматически создаёт папку `bin`. Это место для скомпилированного результата, который может включать **DLL** — скомпилированную сборку, способную служить **библиотекой** кода для других программ, — и **исполняемый файл**, который используется для запуска программы. Вторая сгенерированная папка, `obj`, хранит промежуточные данные, а не тот результат, который обычно запускают.

[00:01:07](https://www.youtube.com/watch?v=jLWY_id6nXU&t=67s) **Компиляция** и **запуск** — разные действия, даже если одна команда запрашивает и то и другое:

```powershell
dotnet run
```

Проект собирается по необходимости, затем запускается полученная программа. Результат остаётся на диске; он не удаляется после завершения программы.

1. Найдите исполняемый файл в `bin`.
2. Скопируйте его **полный путь**, включая диск, папки и имя файла.
3. [00:01:20](https://www.youtube.com/watch?v=jLWY_id6nXU&t=80s) Введите этот путь в терминале.
4. [00:01:23](https://www.youtube.com/watch?v=jLWY_id6nXU&t=83s) Наблюдайте, как программа запустится снова.

Например, в PowerShell оператор вызова `&` запускает путь к исполняемому файлу, взятый в кавычки. Имя проекта и папки здесь — условные обозначения:


[00:01:28](https://www.youtube.com/watch?v=jLWY_id6nXU&t=88s) Это показывает, что скомпилированную программу можно запустить отдельно от команды разработки. **Среда выполнения .NET** по-прежнему предоставляет окружение, необходимое для исполнения её скомпилированного кода. «Работает сама по себе» здесь означает лишь, что повторная компиляция исходников не нужна; это не доказывает автономное развёртывание со встроенной средой выполнения.

[00:01:36](https://www.youtube.com/watch?v=jLWY_id6nXU&t=96s) Чтобы получить результат, не запуская его, используйте команду сборки:

```powershell

```

[00:01:46](https://www.youtube.com/watch?v=jLWY_id6nXU&t=106s) Результат — это итог компиляции/сборки, а не напечатанный программой вывод: `dotnet build` не запускает приложение. Это полезно, когда получение двоичного файла и его запуск — разные шаги.

[00:01:51](https://www.youtube.com/watch?v=jLWY_id6nXU&t=111s) Посмотрите в `bin/Debug/net9.0` записанного проекта. **Debug** — это конфигурация; папка **целевого фреймворка** называет версию .NET. Общая инструкция «посмотрите в bin/debug» — это сокращение для полного пути, чьи имена файлов зависят от проекта:

```text
bin/
  Debug/
    net9.0/
      project.exe
      project.dll
      ...
```

## Одноразовые артефакты сборки

[00:01:57](https://www.youtube.com/watch?v=jLWY_id6nXU&t=117s) **Артефакты сборки** — это файлы, создаваемые сборкой. Папка `obj` хранит промежуточные артефакты и кешированные данные сборки, включая сведения о **пакетах** и **зависимостях** — программном обеспечении, которое использует проект. Это отличается от запускаемого результата в `bin`; наличие в `obj` данных о пакетах не означает, что каждый установленный пакет хранится исключительно там.

[00:02:16](https://www.youtube.com/watch?v=jLWY_id6nXU&t=136s) **Кеш** можно воссоздать, потому что его входные данные по-прежнему существуют. В записи это свойство проверяется:

1. [00:02:19](https://www.youtube.com/watch?v=jLWY_id6nXU&t=139s) Удалите сгенерированные папки `bin` и `obj`.
2. [00:02:25](https://www.youtube.com/watch?v=jLWY_id6nXU&t=145s) Соберите проект заново из неизменённых исходников и конфигурации.
3. [00:02:28](https://www.youtube.com/watch?v=jLWY_id6nXU&t=148s) Наблюдайте, как сгенерированные папки и файлы появляются снова.

Шаг пересборки:

```powershell
dotnet build
```

Демонстрация восстанавливает те же нужные выходные и промежуточные файлы. Суть в воспроизводимости из одних и тех же входных данных, а не в гарантии, что временные метки или каждый байт каждого артефакта всегда должны совпадать. Сохраняйте исходный код и конфигурацию проекта — именно они делают возможным повторное получение файлов.

Минимальное правило урока показано в этом сокращённом фрагменте из изученного [файла игнорирования в репозитории](https://github.com/AntonC9018/uniCourse_csharp/blob/c70666b5a2c1f3be23798f9a90d2952249a938a4/.gitignore), который является **связанным примером из репозитория**, а не записанным файлом:


[00:02:53](https://www.youtube.com/watch?v=jLWY_id6nXU&t=173s) Игнорируйте обе папки, чтобы их сгенерированное содержимое не попадало в историю исходного кода. ## Стартовый код и границы урока

[00:02:58](https://www.youtube.com/watch?v=jLWY_id6nXU&t=178s) С этого момента сосредоточьтесь на **основном исходном файле**: файле, содержащем код, который выполняется при запуске программы. **Инструкция верхнего уровня** пишется прямо в этом файле, вне явно написанного класса или метода:

```csharp
Console.WriteLine("Hello world!");
```

[00:03:17](https://www.youtube.com/watch?v=jLWY_id6nXU&t=197s) Компилятор предоставляет **класс** — контейнер для членов программы — и **метод входа**, через который начинается выполнение. Их полная структура отложена на потом. Этот урок изучает видимую последовательность и функции, написанные в основном файле, а не сгенерированную реализацию.

[00:05:11](https://www.youtube.com/watch?v=jLWY_id6nXU&t=311s) Вторая граница появляется, когда в коде есть функции: подробный синтаксис объявления функций, особенно смысл `void`, сознательно отложен. Ближайшая задача — понять, как выполняется именованное тело при вызове.

## Инструкции выполняются в порядке исходника

[00:03:28](https://www.youtube.com/watch?v=jLWY_id6nXU&t=208s) **Инструкция** (в курсе — **инструкция**) выполняет действие. Здесь инструкции печати занимают отдельные строки. «Одна строка» — удобное описание этих примеров, а не общее правило грамматики: инструкция может занимать несколько строк.

[00:03:37](https://www.youtube.com/watch?v=jLWY_id6nXU&t=217s) Расширьте начальное приветствие несколькими действиями печати. **`Console.WriteLine`** передаёт значение и символ новой строки в **консоль** — терминальный интерфейс вывода. Эта сокращённая версия делает порядок исходника наглядным:

```csharp
Console.WriteLine("Hello world!");
Console.WriteLine(1);
Console.WriteLine(2);
Console.WriteLine(3);
```

[00:03:47](https://www.youtube.com/watch?v=jLWY_id6nXU&t=227s) Запуск программы выполняет инструкции в том порядке, в каком они написаны. [00:03:53](https://www.youtube.com/watch?v=jLWY_id6nXU&t=233s) Наблюдаемый вывод следует этому порядку:

```text
Hello world!
1
2
3
```

[00:04:01](https://www.youtube.com/watch?v=jLWY_id6nXU&t=241s) У каждой инструкции есть работа; в этом примере действие — печать. [00:04:16](https://www.youtube.com/watch?v=jLWY_id6nXU&t=256s) **Последовательное выполнение** означает, что текущее действие завершается, прежде чем выполнение перейдёт к следующему. **Процессор** выполняет работу программы; в этой простой последовательности выполнения более позднее действие печати не обгоняет более раннее.

[00:04:22](https://www.youtube.com/watch?v=jLWY_id6nXU&t=262s) Когда инструкция приветствия завершится, выполнение переходит к следующей инструкции, затем к следующей за ней. [00:04:36](https://www.youtube.com/watch?v=jLWY_id6nXU&t=276s) Если действие занимает много времени, последующие действия ждут его. Это описание касается последовательной программы из урока; это не утверждение обо всех параллельных программах.

<details>
<summary>Предскажите вывод, если инструкция, печатающая 3, окажется выше инструкции, печатающей 1.</summary>

После приветствия значения печатаются в новом порядке исходника: сначала 3, затем 1, затем 2. Инструкции не сортируют свои значения.
</details>

## Как сделать задержку заметной

[00:04:40](https://www.youtube.com/watch?v=jLWY_id6nXU&t=280s) Сделайте правило ожидания наблюдаемым, вставив задержку между действиями печати. **`Thread.Sleep(1000)`** приостанавливает текущий **поток** — отслеживаемую последовательность выполнения — на 1 000 миллисекунд, то есть на секунду. Сокращённая версия изменения:

```csharp
Console.WriteLine("Hello world!");
Thread.Sleep(1000);
Console.WriteLine(1);
Thread.Sleep(1000);
Console.WriteLine(2);
Thread.Sleep(1000);
Console.WriteLine(3);
```

[00:04:55](https://www.youtube.com/watch?v=jLWY_id6nXU&t=295s) Записанный запуск показывает вывод с интервалами в секунду. [00:04:57](https://www.youtube.com/watch?v=jLWY_id6nXU&t=297s) Пока вызов сна не завершён, следующая инструкция печати ещё не началась. [00:05:04](https://www.youtube.com/watch?v=jLWY_id6nXU&t=304s) Когда задержка заканчивается, этот вызов считается завершённым, и выполнение продолжается.

Порядок остаётся тем же; добавленные паузы показывают время, потраченное на ожидание. В последующих примерах задержки опущены, чтобы пути вызовов оставались читаемыми. То же правило «завершение до продолжения» действует, если задержки остаются в теле функции.

## Определение именованной последовательности

[00:05:11](https://www.youtube.com/watch?v=jLWY_id6nXU&t=311s) **Функция** (в записи — **метод**) даёт нескольким инструкциям имя. Её **определение** задаёт имя и её **тело**, то есть последовательность в фигурных скобках.

[00:05:18](https://www.youtube.com/watch?v=jLWY_id6nXU&t=318s) Причина ввести её именно сейчас практическая: сгруппировать действия так, чтобы одно имя могло затребовать их все. Не позволяйте синтаксису объявления отвлекать от этой модели выполнения. Записанная форма с изначально пустым телом выглядит так:

```csharp
void Example()
{
    // The grouped statements will go here.
}
```

[00:05:20](https://www.youtube.com/watch?v=jLWY_id6nXU&t=320s) **`void`** — ключевое слово перед именем в этом определении. Это не имя списка инструкций и само по себе не объявляет полноценную функцию. После `Example` идут **круглые скобки**; **фигурные скобки** охватывают тело. Подробный смысл `void` как типа возвращаемого значения выходит за рамки объяснения в уроке.

[00:05:37](https://www.youtube.com/watch?v=jLWY_id6nXU&t=337s) Дать списку имя `Example` позволяет позже запросить его инструкции. Такой запрос — это **вызов**, здесь он записан именем и круглыми скобками. **Точка с запятой** `;` завершает этот оператор вызова:

```csharp
Example();
```

Определение говорит, что содержится в последовательности. Вызов говорит, когда её выполнить.

## Вход в функцию и возврат

[00:05:46](https://www.youtube.com/watch?v=jLWY_id6nXU&t=346s) Перенесите три действия печати в тело `Example`. Обычные стартовые инструкции оставьте снаружи. [00:05:57](https://www.youtube.com/watch?v=jLWY_id6nXU&t=357s) Напечатайте `Anton`, вызовите список, затем снова напечатайте `Anton`. Эта сокращённая реконструкция сохраняет видимыми приветствие и три действия:

```csharp
Console.WriteLine("Hello world!");
Console.WriteLine("Anton");
Example();
Console.WriteLine("Anton");

void Example()
{
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
}
```

[00:06:14](https://www.youtube.com/watch?v=jLWY_id6nXU&t=374s) Запуск проходит через внешние действия печати, затем через сгруппированные действия, а затем через следующую внешнюю инструкцию. В этой реконструкции две печати `Anton` окружают вызов; перенос трёх числовых инструкций внутрь функции не помещает эти внешние печати в её тело.

[00:06:24](https://www.youtube.com/watch?v=jLWY_id6nXU&t=384s) **Вызов** временно передаёт выполнение внутрь функции. **Вызывающий код** — это код, делающий такой запрос. При вызове не переходите сразу к следующей внешней инструкции:

1. [00:06:42](https://www.youtube.com/watch?v=jLWY_id6nXU&t=402s) Войдите в первую инструкцию вызванного тела.
2. [00:06:47](https://www.youtube.com/watch?v=jLWY_id6nXU&t=407s) Выполните инструкции этого тела сверху вниз, как и стартовую последовательность.
3. [00:07:03](https://www.youtube.com/watch?v=jLWY_id6nXU&t=423s) После завершения его последней инструкции функция заканчивается.
4. [00:07:10](https://www.youtube.com/watch?v=jLWY_id6nXU&t=430s) **Вернитесь** к вызывающему коду и продолжите с инструкции после вызова.

Для этого сокращённого примера результат такой:

```text
Hello world!
Anton
1
2
3
Anton
```

Возврат «к вызову» описывает возобновление его продолжения. Это не означает автоматического повторного выполнения того же вызова. Вызов считается завершённым только после того, как закончится его тело.

## Повторное выполнение того же тела

[00:07:23](https://www.youtube.com/watch?v=jLWY_id6nXU&t=443s) Добавьте ещё один вызов после следующей внешней инструкции. Каждый вызов начинает то же тело с его первой инструкции; второй вызов не продолжает первый запуск с середины:

```csharp
Console.WriteLine("Anton");
Example();
Console.WriteLine("Anton");
Example();

void Example()
{
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
}
```

[00:07:31](https://www.youtube.com/watch?v=jLWY_id6nXU&t=451s) Разбор снова входит в тело и повторяет все три действия. Результат для этой сокращённой стартовой последовательности:

```text
Anton
1
2
3
Anton
1
2
3
```

[00:07:44](https://www.youtube.com/watch?v=jLWY_id6nXU&t=464s) Завершение последней инструкции тела возвращает управление коду, который сделал второй вызов. [00:07:49](https://www.youtube.com/watch?v=jLWY_id6nXU&t=469s) Если стартовых инструкций больше нет, программа завершается. Она не выполняет соседнее определение функции как ещё одно действие.

<details>
<summary>Означает ли возврат из первого вызова, что тело больше не может выполняться?</summary>

Нет. Более поздний вызов начинает новое выполнение того же тела с его начала. У каждого вызова своё продолжение в вызывающем коде.
</details>

## Определения и имена

[00:07:58](https://www.youtube.com/watch?v=jLWY_id6nXU&t=478s) **Определение** делает именованное тело доступным; это не инструкция, которая запускает тело только потому, что выполнение дошло до её записанного места. Вызовы определяют, происходят ли её действия и когда.

[00:08:09](https://www.youtube.com/watch?v=jLWY_id6nXU&t=489s) Переименуйте `Example` в `Hello` и обновите вызовы. Ключевое слово остаётся `void`; меняется имя функции. В этом сокращённом состоянии те же сгруппированные действия:

```csharp
Hello();

void Hello()
{
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
}
```

[00:08:21](https://www.youtube.com/watch?v=jLWY_id6nXU&t=501s) Для эквивалентной последовательности вызовов вывод не меняется, потому что инструкции внутри тела не изменились. `Hello` заменяет `Example`, а не `void`. Можно выбрать и другое допустимое имя при условии, что вызовы используют это имя.

[00:08:32](https://www.youtube.com/watch?v=jLWY_id6nXU&t=512s) Программа может определять несколько функций, каждая со своими инструкциями. Следующий эксперимент отделяет возможность определить тело от решения его вызвать.

## Неиспользуемые функции и явные вызовы

[00:08:43](https://www.youtube.com/watch?v=jLWY_id6nXU&t=523s) Добавьте ещё один именованный список, не вызывая его. Новое тело не влияет на стартовый вывод. В этом сокращённом примере лишнее тело печати существует, но основная последовательность его никогда не запрашивает:

```csharp
Hello();
Console.WriteLine("Anton");

void Hello()
{
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
}

void PrintAnton()
{
    Console.WriteLine("Anton");
}
```

[00:09:01](https://www.youtube.com/watch?v=jLWY_id6nXU&t=541s) В записи проверяется, что добавление неиспользуемого списка не добавляет его вывод: соответствующий вывод `Anton` наблюдается один раз, а не дважды. Диагностика редактора или сборки о неиспользуемой функции — это не то же самое, что вывод, полученный при выполнении её инструкций.

[00:09:14](https://www.youtube.com/watch?v=jLWY_id6nXU&t=554s) Чтобы использовать новую функцию, явно добавьте **вызов**. В сокращённом примере допишите этот оператор в конец стартовой последовательности, перед определениями:

```csharp
PrintAnton();
```

[00:09:35](https://www.youtube.com/watch?v=jLWY_id6nXU&t=575s) Теперь действия функции тоже выполняются. Сокращённый пример печатает три числа, затем `Anton` из внешней инструкции, затем `Anton` из добавленного вызова. Когда этот вызов завершается, выполнение возобновляется со следующей стартовой инструкции, если она есть. Определение тела сделало вызов возможным; добавление вызова вызвало выполнение.

<details>
<summary>Почему добавление только второго определения не добавляет вторую печать?</summary>

Определение предоставляет доступные инструкции. Оно не запрашивает их выполнение. Лишнее тело выполняется только тогда, когда его вызывает исполняемый код.
</details>

## Вызовы внутри тел функций

[00:09:39](https://www.youtube.com/watch?v=jLWY_id6nXU&t=579s) **Вложенный вызов** — это вызов, сделанный внутри тела другой функции. Для него нет особого правила: вызванное тело всё равно выполняется до конца, прежде чем вызывающий код сможет продолжить работу.

[00:09:52](https://www.youtube.com/watch?v=jLWY_id6nXU&t=592s) Разбор входит в `Hello`, выполняет его три действия, затем достигает вызова другого списка. Сокращённая реконструкция показывает это направление вложенности; имя второго списка и печатаемые значения здесь условны:

```csharp
Hello();

void Hello()
{
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
    Other();
}

void Other()
{
    Console.WriteLine("A");
    Console.WriteLine("B");
}
```

Следите за каждым переходом, а не просто читайте весь файл сверху вниз:

1. Стартовый вызов входит в `Hello`.
2. [00:09:58](https://www.youtube.com/watch?v=jLWY_id6nXU&t=598s) Его три инструкции печати завершаются по порядку.
3. [00:10:07](https://www.youtube.com/watch?v=jLWY_id6nXU&t=607s) Его последний вызов входит в `Other`, начиная с первой инструкции этого тела.
4. [00:10:10](https://www.youtube.com/watch?v=jLWY_id6nXU&t=610s) Две инструкции внутреннего тела завершаются.
5. [00:10:18](https://www.youtube.com/watch?v=jLWY_id6nXU&t=618s) Выполнение возвращается к месту вызова внутри `Hello`.
6. [00:10:25](https://www.youtube.com/watch?v=jLWY_id6nXU&t=625s) Поскольку это была последняя инструкция `Hello`, сама `Hello` тоже завершается.
7. [00:10:33](https://www.youtube.com/watch?v=jLWY_id6nXU&t=633s) Выполнение возвращается снова, на этот раз к стартовому вызову. Поскольку после него ничего нет, программа заканчивается.

Более короткое описание «функция вызывает `Hello`» работает так же: поменяйте местами, в каком теле находится вызов, и вызов сначала войдёт в `Hello`, напечатает его три действия по порядку и вернётся к этому вызывающему коду. Важны место вызова и его продолжение, а не то, какое имя внешнее.

Возврат происходит и тогда, когда следующей инструкции нет. Именно так завершение внутреннего тела позволяет завершиться объемлющему телу, а затем и стартовой последовательности. Финальный вложенный вызов — не повод пропускать вызывающий код.

## Прослеживание всего пути выполнения

[00:10:41](https://www.youtube.com/watch?v=jLWY_id6nXU&t=641s) Финальный разбор прослеживает ещё одну инструкцию и ещё один вызов после возврата. Чтобы показать и промежуточный возврат, и последующее завершение, эта сокращённая вариация добавляет продолжение в стартовый код:

```csharp
Hello();
Console.WriteLine("After the first call");
Hello();

void Hello()
{
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
    Other();
}

void Other()
{
    Console.WriteLine("A");
    Console.WriteLine("B");
}
```

На каждом уровне применяйте ту же процедуру:

1. [00:10:41](https://www.youtube.com/watch?v=jLWY_id6nXU&t=641s) После завершения вызова продолжайте со следующей инструкции в его вызывающем коде. Здесь печатается сообщение между двумя вызовами.
2. [00:11:01](https://www.youtube.com/watch?v=jLWY_id6nXU&t=661s) При вызове функции входите в первую инструкцию именованного тела. Второй стартовый вызов начинает `Hello` заново.
3. [00:11:08](https://www.youtube.com/watch?v=jLWY_id6nXU&t=668s) Выполните инструкции этого тела по порядку, завершая каждую до начала следующей; вложенный вызов подчиняется тому же правилу.
4. [00:11:16](https://www.youtube.com/watch?v=jLWY_id6nXU&t=676s) Когда последняя инструкция тела завершается, возвращайтесь к месту вызова. Если последней инструкцией был другой вызов, его завершение позволяет объемлющему телу тоже закончиться.
5. [00:11:25](https://www.youtube.com/watch?v=jLWY_id6nXU&t=685s) Тело, существующее только как определение, не даёт никаких действий, если его не вызвали где-то на исполняемом пути.

<details>
<summary>Предскажите, сколько раз печатается A, и объясните, почему определения не добавляют лишних запусков.</summary>

A печатается дважды. Каждый стартовый вызов входит в `Hello`; каждое выполнение `Hello` один раз вызывает `Other`. `Other` печатает A и B и возвращается в `Hello`, а та — в стартовую последовательность. Два определения лишь делают свои тела доступными.
</details>

[00:11:16](https://www.youtube.com/watch?v=jLWY_id6nXU&t=676s) «Вернуться к строке с вызовом» и «продолжить после вызова» описывают две части одного и того же события: управление возвращается этому вызывающему коду, вызов теперь завершён, и следующая инструкция может начаться. При последнем стартовом вызове следующей инструкции нет, поэтому происходит завершение программы.
