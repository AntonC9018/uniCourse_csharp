# Files created during compilation; statements and program execution

[00:00:02](https://www.youtube.com/watch?v=jLWY_id6nXU&t=2s) This lesson answers three questions about the project created in the previous video: which files the compiler reads, which folders the build produces, and how the program actually runs line by line. The walkthrough ends with functions, so a group of statements can be given a name and run on demand.

Related lesson: [Understanding the basic project](../../../labs/1_basic/02_project.md), whose lab tasks repeat these exercises.

Terms introduced up front:

- **Source file:** a text file with program code. In C# a source file has the `.cs` extension, for example `Program.cs`.
- **Compiler:** the tool that translates source code into a form the machine can run.
- **Compile:** that translation step, done by the `dotnet build` and `dotnet run` commands.
- **Build:** everything the project does to turn sources into runnable output.
- **Library (DLL):** compiled output meant to be used by another program.
- **Executable:** compiled output meant to be launched on its own.
- **`bin` folder:** created by the build; holds the compiled output.
- **`obj` folder:** created by the build; caches intermediate compilation data.
- **Cache:** data stored so a later build can reuse it instead of recomputing.
- **`.gitignore`:** a file listing paths git must not track.
- **Statement:** the English word for one line of code; the course calls it an **instruction**.
- **Function (method):** a named list of statements that performs one unit of work.
- **`void`:** the keyword placed before a function name in the recording; its full meaning is postponed.
- **Call:** writing a function's name in code so its statements run.
- **Processor:** the part of the machine that executes instructions one after another.
- **`Thread.Sleep(1000)`:** a statement that pauses execution for one second.

## Statements: one line, one action

[00:03:27](https://www.youtube.com/watch?v=jLWY_id6nXU&t=207s) Each line of code is called an instruction here. The English word for that is **statement**, which refers to a single line, so the statements of the program are the lines that execute on start.

[00:03:37](https://www.youtube.com/watch?v=jLWY_id6nXU&t=217s) The program at this moment has three instructions, one after another:

```csharp
Console.WriteLine("Hello world!");
Console.WriteLine(1);
Console.WriteLine(2);
Console.WriteLine(3);
```

[00:03:53](https://www.youtube.com/watch?v=jLWY_id6nXU&t=233s) Running it prints the first line's output, then the second's, then the third's: the first instruction ran, the second ran, the third ran. The term **instruction** (statement) is the one used throughout the course.

[00:04:08](https://www.youtube.com/watch?v=jLWY_id6nXU&t=248s) Each instruction is responsible for some action — printing a line is that action — and each statement therefore names code that executes on program start.

## Statements run top to bottom

[00:03:47](https://www.youtube.com/watch?v=jLWY_id6nXU&t=227s) When the program starts, its statements execute one after another in the order they were written.

[00:04:14](https://www.youtube.com/watch?v=jLWY_id6nXU&t=254s) That order is top to bottom: the processor executes these instructions one after another from the first line down.

[00:04:22](https://www.youtube.com/watch?v=jLWY_id6nXU&t=262s) The processor finishes one instruction completely before beginning the next. The `Console.WriteLine` that prints `Hello world!` completes, its output reaches the screen, and only then does the processor start the following instruction, which prints the numbers in their source order.

[00:04:36](https://www.youtube.com/watch?v=jLWY_id6nXU&t=276s) This is why the output appears in source order. It also means a slow instruction delays everything after it: an instruction that runs long keeps the processor busy until it finishes.

<details>
<summary>Predict: if the <code>Console.WriteLine(3)</code> line were moved above <code>Console.WriteLine(1)</code>, what would the console print?</summary>

The numbers would print as `3` then `1`, because statements run in the order they are written, from top to bottom. Order in the file is the only thing that decides output order.
</details>

## Proving the order with Thread.Sleep

[00:04:40](https://www.youtube.com/watch?v=jLWY_id6nXU&t=280s) The rule can be checked rather than assumed. A pause of one second is added between the instructions:

```csharp
Console.WriteLine("Hello world!");
Thread.Sleep(1000);
Console.WriteLine(1);
Thread.Sleep(1000);
Console.WriteLine(2);
Thread.Sleep(1000);
Console.WriteLine(3);
```

[00:04:52](https://www.youtube.com/watch?v=jLWY_id6nXU&t=292s) Running it prints the lines one second apart, which is the visible proof of the one-at-a-time order.

[00:04:57](https://www.youtube.com/watch?v=jLWY_id6nXU&t=297s) `Thread.Sleep(1000)` stops the program for one second. Once the second has passed, the instruction counts as done and the processor continues with the next one.

## A function groups several statements

[00:05:11](https://www.youtube.com/watch?v=jLWY_id6nXU&t=311s) A function is a list of several instructions that performs a named unit of work.

[00:05:20](https://www.youtube.com/watch?v=jLWY_id6nXU&t=320s) The exact syntax is deliberately left vague at this point — in particular, what `void` before the name means is not explained yet, so nothing is said about it here.

[00:05:23](https://www.youtube.com/watch?v=jLWY_id6nXU&t=323s) What the recording does fix is the shape: `void` followed by a name declares a list of instructions, also called a function, and the instructions themselves are written between the curly braces:

```csharp
void Example()
{
    // the instructions of the function go here
}
```

[00:05:39](https://www.youtube.com/watch?v=jLWY_id6nXU&t=339s) Giving the list a name is the point: using the name lets all the instructions inside the list be executed later.

## Moving statements into Hello and calling it

[00:05:46](https://www.youtube.com/watch?v=jLWY_id6nXU&t=346s) Three statements are moved into the list, `Console.WriteLine("Anton")` is added, and the list is named `Hello`:

```csharp
void Hello()
{
    Console.WriteLine("Hello world!");
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
    Console.WriteLine("Anton");
}
```

[00:05:57](https://www.youtube.com/watch?v=jLWY_id6nXU&t=357s) Then the statements are executed — by referring to the name — and `Console.WriteLine("Anton")` is printed again afterwards.

[00:06:11](https://www.youtube.com/watch?v=jLWY_id6nXU&t=371s) Inside the call, execution walked the body in order: the first line printed, `Anton` printed, then the next line, and so on. A function's body is just a sequence of statements.

[00:06:24](https://www.youtube.com/watch?v=jLWY_id6nXU&t=384s) Writing the name in the code is a **call**, and this is where it changes execution. When the program reaches a call, execution does not continue on the next line: it jumps to the first instruction inside the function.

[00:06:47](https://www.youtube.com/watch?v=jLWY_id6nXU&t=407s) The statements inside the function execute exactly like the program's own top-to-bottom statement sequence:

```text
main:   print "Hello world!" → call Hello → print "Anton"
Hello:  print "Hello world!" → print 1 → print 2 → print 3 → print "Anton"
```

[00:07:03](https://www.youtube.com/watch?v=jLWY_id6nXU&t=423s) Once the statements inside `Hello` run out, the function is finished. The program jumps back to the line where the function was called and continues with the next statement after it — here, the statement printing `Anton` again.

<details>
<summary>Why does <code>Anton</code> print twice?</summary>

Once from inside `Hello`, where it is one of the function's statements. Then again from the main program, because execution returns to the line after the call and that line prints `Anton` too.
</details>

## Calling the same function again

[00:07:21](https://www.youtube.com/watch?v=jLWY_id6nXU&t=441s) Calling the same function a second time makes execution jump once more to its first instruction and run the body from the top, repeating everything the body contains.

[00:07:44](https://www.youtube.com/watch?v=jLWY_id6nXU&t=464s) When the last instruction of a function has run, the function is finished and the program jumps back to its caller.

[00:07:49](https://www.youtube.com/watch?v=jLWY_id6nXU&t=469s) After that jump back, no statements remain — nothing is left to run — so the program terminates.

## A definition is not a statement

[00:07:55](https://www.youtube.com/watch?v=jLWY_id6nXU&t=475s) The block that defines the function is not itself an instruction. It simply exists in the program; nothing executes it as code where it is written.

[00:08:09](https://www.youtube.com/watch?v=jLWY_id6nXU&t=489s) The name can be anything: the same list could be called `Hello` instead of the name used in the recording, and it would behave identically, because only the name changes while the instructions stay the same.

[00:08:12](https://www.youtube.com/watch?v=jLWY_id6nXU&t=492s) The list now carries the name `Hello`, and it works the same way as before:

[00:11:20](https://www.youtube.com/watch?v=jLWY_id6nXU&t=680s) A function does nothing on its own just by existing; it must be called somewhere in the program to be used.

## An unused function never runs

[00:08:43](https://www.youtube.com/watch?v=jLWY_id6nXU&t=523s) Suppose a second list is defined but never used in the main program. It has no effect on execution, and its output is never printed on start — the program shows `Anton` once, not twice.

[00:09:14](https://www.youtube.com/watch?v=jLWY_id6nXU&t=554s) To make such a function actually run, it must be called in the code. And after its instructions finish, execution continues from the first statement following the call.

## A function that calls another function

[00:09:41](https://www.youtube.com/watch?v=jLWY_id6nXU&t=581s) A function body may itself contain a call to another function. Reaching that call sends execution into the named function instead of along the current list.

[00:09:48](https://www.youtube.com/watch?v=jLWY_id6nXU&t=588s) The trace shows what happens: the program reaches the call and jumps to the first instruction of `Hello`; the three instructions of `Hello` print in order; then execution returns to the statement that made the call.

```csharp
void Hello()
{
    Console.WriteLine(1);
    Console.WriteLine(2);
    Console.WriteLine(3);
}

void Outer()
{
    Console.WriteLine("start");
    Hello();              // nested call: jumps into Hello
    Console.WriteLine("end");
}
```

[00:10:18](https://www.youtube.com/watch?v=jLWY_id6nXU&t=618s) Because the call was the last instruction in that list, finishing it ends the list — and the program itself.

[00:10:22](https://www.youtube.com/watch?v=jLWY_id6nXU&t=622s) Even so, the trace shows execution returning to the place where that instruction list was last used, before the program ends.

## The rule for calls and returns

[00:10:41](https://www.youtube.com/watch?v=jLWY_id6nXU&t=641s) Summarized from the final trace:

1. [00:10:43](https://www.youtube.com/watch?v=jLWY_id6nXU&t=643s) After the statement that calls a function finishes, control returns to the code and execution continues with the following statement.
2. [00:10:48](https://www.youtube.com/watch?v=jLWY_id6nXU&t=648s) When execution reaches a call to a function, it jumps to the first statement inside that function.
3. [00:10:53](https://www.youtube.com/watch?v=jLWY_id6nXU&t=653s) Inside the called function, statements execute in order from top to bottom, one statement after another.
4. [00:11:01](https://www.youtube.com/watch?v=jLWY_id6nXU&t=661s) When the last statement of a function is reached, the function finishes and execution returns to the line with its call.
5. [00:11:12](https://www.youtube.com/watch?v=jLWY_id6nXU&t=672s) If that call was itself the last statement of the enclosing list, the enclosing list finishes too, and the process walks back out until nothing remains to run.
