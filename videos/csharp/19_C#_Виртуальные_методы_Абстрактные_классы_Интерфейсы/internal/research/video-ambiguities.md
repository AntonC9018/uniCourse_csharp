# Video ambiguities the note deliberately hedges (82vaxb6o_rg)

All items below were established during english_authoring (run 333, session 01a11afa-f8ad-7bc1-bbd8-845ef58b2980), which opened the cited Microsoft Learn sources as evidence; transcript moments locate the ambiguity, not the proof.

- Overload choice precedes dispatch: for statically typed calls such as animal.Speak("hello") (~00:32:29/00:32:57, TP-165–TP-169 region), overload selection happens at compile time first, then virtual dispatch picks the override of the selected signature — not a runtime scan across same-named overloads. Source opened: C# language specification, Expressions (overload resolution).
- Static type of `this` is fixed: inside Bird.Speak the static type of `this` is Bird, the declaring class (~00:15:18–00:15:31, TP-074/TP-075); the runtime object may be Bird or a descendant. Source opened: C# specification, this-access.
- Vtable numbers are labels: code addresses 100/200/300/400/500 and the slot tables (TP-014, TP-022, TP-085) illustrate the lesson's dispatch model; they are not measured process addresses and do not specify .NET memory layout, instruction selection, or optimization behavior.
- "Static call" / "dynamic (late) binding" are the video's dispatch terms (~00:08:25, ~00:09:18, TP-039/TP-042): a nonvirtual target fixed by the expression's static type vs. an override selected from the receiver's runtime type. Neither requires C#'s `dynamic` keyword nor turns an instance method into a `static` method. Source opened: C# specification, Expressions (static and dynamic binding).
- Hiding vs. overriding: the initial Bird.Speak is a separate hidden member (explicit `new` in the note); omitting `new` does not create an override, and removing `override` while keeping a same-named body restores hiding — a base-typed virtual call then keeps the inherited implementation (~00:11:04–00:11:19, ~00:35:52). Sources opened: `virtual` and `override` references.
- `sealed override`, not `sealed virtual`: freezing one operation uses `sealed override` (~00:29:03); an interface membership alone never justifies `override` on the implementing method (~00:35:52). Source opened: `sealed` reference.
- Interface "no fields" means no per-object instance state (~00:34:11, TP interface section); modern interfaces can still declare default bodies and static members, which the lesson explicitly defers. Sources opened: `interface` reference, explicit-interface-implementation guide.
- Explicit implementation is per-interface: two interfaces with identical Speak signatures cannot be satisfied by two same-signature public methods (compile error ~00:44:19); `void ISpeak.Speak()` / `void ISpeak1.Speak()` are reached only through the corresponding interface reference (~00:45:06–00:45:30). Source opened: explicit-interface-implementation guide.
- `readonly` nuance for the AdditionAction singleton (~00:52:34): readonly fixes the shared reference against ordinary later reassignment; it also permits assignment in declaration/constructor context and does not make a mutable shared object immutable. Source opened: `readonly` reference.
- Delegate comparison is simplified (~00:47:14): the lesson's single-function-address picture omits that delegates can target instance methods and combine invocation entries; the retained distinction is that a class/interface action contract can expose several named operations through one reference while a simple delegate offers one callable signature. Source opened: delegate guide.
- Transcript wording traps flagged by the author and hedged in the note: "overloaded" at ~00:42:46 means overridden (virtual Speak path through ISpeak); the ~00:36:36 "FlapWings.FlapWings()" phrasing is an interface-variable declaration plus call, not a constructor; the ~00:40:31 "continue from an address" wording is the machine call/return resuming the caller, not a C# return value of an address.
