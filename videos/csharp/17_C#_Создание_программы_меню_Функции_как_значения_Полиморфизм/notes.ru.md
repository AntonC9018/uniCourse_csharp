# Построение меню, которое можно развивать

[00:00:00](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=0s) Построим консольное меню, в котором пользователь выбирает одну из трёх небольших операций. Разбираемый пример растёт в три этапа: нумерованные действия, переставляемые пункты, хранящиеся как данные, и пункты, которые хранят сами функции. Цель — сохранять устойчивый поток выполнения программы, меняя то, что предлагает меню.

Используемый по ходу словарь:

- **Функция или метод**: именованный фрагмент исполняемого кода. **Параметр** передаёт ей входные данные; **возвращаемое значение** — её результат. **Статические** методы не требуют экземпляра содержащего их класса; **void** означает отсутствие возвращаемого значения.
- **Enum (перечисление)**: тип с именованными константами, представляющими варианты выбора. **Член перечисления** называет один вариант; **приведение типов** явно преобразует значение в другой тип.
- **Диспетчеризация**: выбор реализации по значению действия и её вызов. **switch** выбирает ветку по этому значению; **Debug.Fail** сообщает о неожиданной ситуации средствам отладки.
- **Разбор (parsing)**: интерпретация текста как значения, например целого числа. **TryParse** сообщает об успехе или неудаче; **out-параметр** получает результат. **Валидация** проверяет, допустимо ли успешно разобранное значение.
- **Цикл ввода**: повторяет запрос, пока не поступит приемлемый ввод. **continue** начинает следующую итерацию; **break** прерывает цикл. **Вспомогательная функция (helper)** выделяет повторяющуюся задачу в переиспользуемую функцию.
- **Список или массив**, собирательно — **коллекция**: упорядоченная группа элементов. **Индекс** — позиция, считающаяся с нуля. **Count** списка или **Length** массива даёт количество элементов.
- **Класс, объект, поле и свойство**: класс определяет вид объекта, объект — один его экземпляр, поле хранит часть данных объекта, а свойство предоставляет значение через член. Здесь объект **Option** объединяет метку, описание и действие.
- **Пространство имён и директива using**: пространство имён группирует имена типов; директива using позволяет коду ссылаться на эти типы без повторения префикса пространства имён.
- **Аннотации и ссылки на nullable-типы**: null означает отсутствующую ссылку. Знак вопроса в string? допускает отсутствие строкового значения. Оператор подавления предупреждений о nullable (null-forgiving operator) ! отключает такое предупреждение, не меняя значение. Параметр ref даёт функции доступ к переданному состоянию по ссылке.
- **nameof**: оператор времени компиляции, превращающий имя символа в текст. **==** сравнивает строки по их содержимому. **Рефлексия** исследует метаданные программы во время выполнения; она упомянута, но не реализована.
- **Рефакторинг**: изменение организации кода с сохранением его предполагаемого поведения. **Регистрация** заполняет коллекцию меню. **Конфигурация** определяет, какие пункты существуют. Передача этой конфигурации в меню отделяет содержимое от потока управления и снижает **связанность** — зависимости между частями.
- **public и private**: модификаторы доступа, определяющие, где член можно назвать. **Инкапсуляция** прячет детали реализации за небольшим публичным интерфейсом.
- **Компилятор**, **IL**, **байт-код** и **DLL**: компилятор переводит исходный код в промежуточный язык, более низкоуровневое представление инструкций; байт-код кодирует такие инструкции численно. Скомпилированная DLL .NET (Dynamic Link Library) содержит IL и метаданные. **dotnet build** собирает проект; **dotnet run** при необходимости собирает его и запускает.
- **Среда выполнения**, **JIT**, **машинный код**, **архитектура CPU** и **адрес**: среда выполнения исполняет программы .NET; её JIT-компилятор (just-in-time) переводит IL в инструкции для конкретного процессора. Архитектура CPU определяет набор инструкций и их кодирование. Адрес указывает на расположение в памяти процесса. **SharpLab** показывает вывод компилятора, включая IL и читаемые листинги ассемблера.
- **Локальная функция**, **захват**, **понижение (lowering)** и **искажение имён (name mangling)**: локальная функция объявляется внутри другой функции; захват даёт ей доступ к окружающим переменным. Понижение переписывает конструкции исходного кода в порождённые методы и состояние. Искажение имён даёт порождённым членам различные внутренние имена.
- **Делегат** и **Action**: делегат — типизированный вызываемый объект, ссылающийся на метод и, при необходимости, на состояние цели. Встроенный тип Action не принимает аргументов и ничего не возвращает. **Преобразование группы методов** превращает имя метода, использованное как значение, в совместимый делегат. **Затенение (shadowing)** отдаёт предпочтение более близкому объявлению перед другим именем. **Кэширование** повторно использует ранее созданный объект.
- **Полиморфизм**: один вызов может выполнять разные реализации, выбранные во время выполнения. Урок демонстрирует это через делегат, хранящийся в переменной.

О более ранней практике по вводу и перечислениям см. в репозитории [лабораторную по консольному вводу](../../../labs/1_basic/08_input.md) и [лабораторную по перечислениям](../../../labs/1_basic/09_enum.md). Это предварительные упражнения, а не сохранённые версии этого меню.

## Выделение переиспользуемого ввода целого числа

[00:03:44](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=224s) Сначала реализуем Addition. Оно запрашивает число, читает текст из консоли и пытается интерпретировать этот текст как int. **Разбор** — это и есть преобразование текста в типизированное значение; **int.TryParse** возвращает признак успеха и записывает целое число через свой **out-параметр**.

[00:03:53](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=233s) Первоначальный цикл ввода повторяет попытку при неудачном разборе. [00:04:04](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=244s) Объявите результат вне цикла, чтобы он остался в области действия после него, и прерывайте цикл, как только разбор удался. В этом упрощённом состоянии из видео continue перезапускает цикл, а break выходит из него:

```csharp
int a;
while (true)
{
    Console.Write("Enter A: ");
    if (!int.TryParse(Console.ReadLine(), out a))
        continue;
    break;
}
// a is available here
```

**Область действия:** [00:03:56](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=236s) эта схема повторных попыток преподавалась раньше; [00:04:51](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=291s) отдельный урок по вводу даёт подробное объяснение. Здесь причина вернуться к ней — повторное использование.

[00:04:12](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=252s) Та же логика нужна и для A, и для B. Выделим **вспомогательную функцию** — функцию, выполняющую повторяющуюся задачу. ReadIntIn принимает отображаемое имя переменной в виде строкового **параметра**. [00:04:27](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=267s) Она печатает этот параметр, а не захардкоженную A, и возвращает успешно разобранный результат:

```csharp
static int ReadIntIn(string variableName)
{
    int result;
    while (true)
    {
        Console.Write("Enter " + variableName + ": ");
        if (!int.TryParse(Console.ReadLine(), out result))
            continue;
        break;
    }
    return result;
}
```

Тип возврата int говорит, что функция выдаёт целочисленный результат. Оператор return передаёт это значение вызывающему коду.

[00:04:40](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=280s) Замените оба дублирующихся блока ввода вызовами вспомогательной функции. [00:04:56](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=296s) Тогда Addition может сосредоточиться на сложении a и b и печати ответа:

## Завершение действий приветствия и случайного числа

[00:05:03](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=303s) Greeting — **статический** метод, поэтому для его вызова не нужен экземпляр содержащего его класса. Его тип возврата **void** означает, что возвращаемого значения нет: вся работа — это взаимодействие с консолью. Пустые скобки задают, что аргументов он не принимает.

```csharp
static void Greeting()
{
    Console.Write("Enter your name: ");
    string? name = Console.ReadLine();
    Console.WriteLine("Hello, " + name);
}
```

В этом сокращённом состоянии из видео используется **аннотация nullable** — знак ? в string?, — разрешающая null, то есть отсутствующую ссылку, возвращаемую, когда нет введённой строки. Обычные введённые имена являются строками.

[00:05:17](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=317s) Для генерации случайного числа нужен объект, который производит случайные значения. [00:05:33](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=333s) Random.Shared — статическое **свойство**, член, предоставляющий значение, дающее доступ к общему генератору. Вызовите его метод Next, чтобы получить целое число:

```csharp
static void RandomNumber()
{

```

Свойство предоставляет генератор; Next выполняет генерацию. Теперь все три функции действия помещаются в ветви диспетчеризации.

```csharp
static Action ReadAction()
{
    while (true)
    {
        Console.WriteLine("0: Addition, 1: Greeting, 2: RandomNumber");

        {
            Console.WriteLine("Invalid option");
            continue;

        return (Action)number;

}
```

Условие || означает, что для отклонения номера достаточно нарушения любой из границ.

[00:15:15](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=915s) Извлечём сохранённое действие напрямую, убрав приведение индекса к перечислению. Получившееся сокращённое состояние из видео:

```csharp
static Action ReadAction(List<Option> options)
{
    while (true)
    {
        for (int i = 0; i < options.Count; i++)
            Console.WriteLine(i + " or " + options[i].Name
                              + ": " + options[i].Description + ".");

        string? input = Console.ReadLine();
        foreach (Option option in options)
            if (option.Name == input)
                return option.Action;

        if (!int.TryParse(input, out int index))
        {
            Console.WriteLine("Invalid option");
            continue;
        }
        if (index < 0 || index >= options.Count)
        {
            Console.WriteLine("Invalid option");
            continue;
        }
        return options[index].Action;
    }
}
```

foreach обходит каждый объект коллекции. return немедленно завершает функцию чтения; саму операцию он не выполняет.

[00:15:17](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=917s) После перестановки сложение находится на позиции один, а не ноль. Индекс 1 извлекает пункт Addition, хотя его значение в перечислении по-прежнему равно 0. Именно поэтому приведение индекса к перечислению больше неуместно.

Совпадение по имени возвращает управление раньше, поэтому путь числового разбора пропускается. Выбранное действие выполняется только после завершения выбора.

## Понимание адресов функций

[00:25:00](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1500s) В работающем **процессе**, то есть экземпляре исполняемой программы, у скомпилированных функций в памяти находятся исполняемые инструкции. **Адрес** указывает на расположение там. ```csharp

## Разделение кода локальной функции и захваченного состояния

[00:26:48](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1608s) **Локальная функция** объявляется внутри другой функции. Она может **захватывать** окружающие переменные, то есть использовать их через сгенерированный компилятором доступ к их состоянию. Важное различие — между её исполняемым кодом и состоянием, принадлежащим конкретному вызову окружающей функции.

[00:26:56](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1616s) **Понижение (lowering)** переписывает конструкции исходного кода в порождённые методы и состояние. В показанном случае прямого вызова компилятор может передавать захваченные локальные переменные через порождённую структуру по ссылке. Схематическая реконструкция, а не точный вывод компилятора:

```csharp
struct CapturedValues
{
    public int a;
    public int b;
}

static void GeneratedSamOperations(ref CapturedValues values)
{
    Console.WriteLine(values.a + values.b);
}
```

Здесь ref означает, что порождённый метод обращается к переданному состоянию по ссылке, что позволяет ему ссылаться на те же захваченные переменные, а не на независимые копии.

[00:27:11](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1631s) Порождённая реализация скрыта от обычного внешнего исходного кода. [00:27:21](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1641s) **Искажение имён** даёт порождённое внутреннее имя, чтобы две локальные функции с одинаковым исходным именем в разных объемлющих методах не конфликтовали.

[00:27:37](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1657s) Повторный вызов объемлющей функции не требует заново написанной копии исполняемого кода локальной функции. [00:27:49](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1669s) Вместо этого её вызов получает соответствующее захваченное состояние или обращается к нему. [00:28:00](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1680s) Порождённые вызовы в конечном счёте достигают исполняемого кода; [00:28:09](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1689s) расположения кода позволяют ссылаться на функции косвенно.

Описание в видео «становится статической» соответствует показанному там преобразованию, а не каждой локальной функции. В зависимости от захватов и преобразования в делегат понижение может использовать другое порождённое состояние и методы экземпляра. Состояние для каждого вызова может различаться, даже когда реализация метода переиспользуется. Уроку не требуется изучать все стратегии понижения.

## Использование встроенного делегата Action

[00:28:39](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1719s) Удалите объявленное локально перечисление Action. [00:28:44](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1724s) Это объявление **затеняло** имя Action из стандартной библиотеки: оно брало верх при поиске имён в коде. [00:29:03](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1743s) После удаления Action разрешается во встроенный тип делегата.

[00:29:09](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1749s) **Делегат** — это типизированный вызываемый объект. Объявление встроенного Action концептуально выглядит так:

```csharp
// Standard-library type, shown for explanation; do not redeclare it.
public delegate void Action();
```

[00:29:10](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1750s) **void** означает, что указанная функция ничего не возвращает. Пустой список параметров () означает, что аргументов нет. Это разные свойства; void не значит «нет параметров».

Тип поля теперь ссылается на значение-функцию, а не на идентификатор перечисления. Реконструированное изменение:

```csharp
class Option
{
    public string Name = "";
    public string Description = "";
    public Action Action = null!;
}
```

Заполнитель null! использует оператор подавления предупреждений о nullable **!** для этого сокращённого примера на основе полей; значение всё равно null. Каждый зарегистрированный пункт должен присвоить настоящий делегат, прежде чем его можно будет выбрать и вызвать.

[00:29:28](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1768s) Вызов Action передаёт выполнение указанному методу и возвращает управление вызывающему коду, когда тот завершится. Адресная модель объясняет этот переход, а C# управляет вызываемым объектом:

```csharp
static void ExecuteAction(Action action)
{
    action();
}
```

Тип параметра задаёт, какая сигнатура функции допустима. Никакого switch больше нет: он не переводит значение перечисления в функцию.

## Регистрация приватных методов как делегатов

[00:29:43](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1783s) Вынесем реализации действий в MenuOptions. [00:29:57](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1797s) Сделаем их **приватными**, видимыми по имени только из их собственного класса, поскольку внешний код меню теперь вызывает сохранённый делегат.

[00:30:05](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1805s) Заменим каждое присваивание значения перечисления самим методом. Это **преобразование группы методов**: имя метода, использованное как значение, превращается в делегат с совместимой сигнатурой. Получившееся сокращённое состояние из видео:

```csharp
static class MenuOptions
{
    public static void AddOptions(List<Option> options)
    {
        options.Add(new Option {
            Name = nameof(Addition),
            Description = "Add two integers",
            Action = Addition
        });
        // Greeting and RandomNumber are registered in the same way.
    }

    private static void Addition()
    {
        int a = ReadIntIn("A");
        int b = ReadIntIn("B");
        Console.WriteLine(a + b);
    }

    // ReadIntIn and the other private operations live here too.
}
```

Обратите внимание: у Action = Addition нет скобок. Оно сохраняет ссылку на вызываемый объект. Addition() выполнил бы метод немедленно, и его результат void нельзя было бы присвоить полю.

[00:30:11](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1811s) Объект делегата ссылается на целевой метод и, где это применимо, на целевой объект. [00:30:20](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1820s) Здесь цели — статические методы, поэтому экземпляр MenuOptions не нужен. Поле хранит ссылку на объект делегата, а не число из перечисления и не открытый сырой адрес.

[00:30:26](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1826s) В записи обсуждается повторное использование объектов делегатов для статических методов. [00:30:50](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1850s) **Кэширование** означает сохранение и повторное использование уже созданного объекта. Современные компиляторы C# могут кэшировать преобразования статических групп методов, избегая повторных выделений в месте преобразования. Это оптимизация, а не гарантия для всего языка ровно одного объекта делегата на метод в пределах всей программы. Разные места преобразования и другие формы создания могут давать разные объекты.

## Разделение меток и вызываемых действий

[00:31:10](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1870s) Метка по-прежнему может использовать **nameof**, оператор времени компиляции, дающий имя:

```csharp
Name = nameof(Greeting),
Action = Greeting
```

[00:31:16](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1876s) nameof — не функция времени выполнения, принимающая делегат. Его макроподобная роль в этом объяснении — подстановка во время компиляции: метка становится "Greeting", а поле действия получает ссылку на вызываемый объект.

[00:31:29](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1889s) Даже статический метод, который ничего не делает, можно зарегистрировать, если его сигнатура соответствует Action. [00:31:36](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1896s) Имя в меню вообще не обязано совпадать с именем метода. В этой реконструированной альтернативе это самостоятельная метка, обращённая к пользователю:

```csharp
options.Add(new Option {
    Name = "Do nothing",
    Description = "Return immediately",
    Action = DoesNothing
});

```

Метка управляет сопоставлением ввода и отображением. Делегат управляет выполнением. Изменение только метки не меняет вызываемый метод.

## Вызов выбранного действия через полиморфизм

[00:31:42](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1902s) Функция чтения по-прежнему ищет имена и проверяет индексы точно так же. Она возвращает поле действия пункта; изменились только представление этого поля и шаг вызова.

[00:31:49](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1909s) Запустите версию с делегатами. Появляются те же пункты меню, и выбор первого приводит к указанной операции. Сам Action не принимает аргументов; такая операция, как Addition, по-прежнему может запрашивать ввод и вызывать свои собственные вспомогательные функции с аргументами.

[00:31:55](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1915s) Main сохраняет ту же последовательность. [00:32:02](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1922s) Выбранное значение теперь хранит ссылку на вызываемый объект, а не число, ожидающее перевода.
