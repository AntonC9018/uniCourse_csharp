В ходе этой конструкции используются следующие термины:

- **Алгоритм, интерфейс и реализация:** алгоритм — это последовательность действий для получения результата. Его интерфейс описывает входные данные и выход; реализация выполняет эти действия.
- **Список, массив, элемент и непрерывное размещение:** список — это упорядоченная последовательность. Массив — конкретное представление с последовательным размещением элементов; элемент — одно хранимое значение. Непрерывность означает соседство без промежутков между ячейками элементов.
- **Ячейка памяти, адрес, индекс и индексация:** ячейка — это хранилище одного значения на рисунках урока. Адрес определяет местоположение. Индекс отсчитывает смещения элементов от начала; индексация выбирает элемент по этому смещению.
- **Тип и целое число:** тип описывает допустимые значения. `int` хранит целые числа; `int[]` описывает массив целых чисел.
- **Объект, ссылка, разыменование и куча:** объект — это выделенный массив вместе со своими элементами и длиной. Ссылка определяет этот объект; разыменование переходит по ней к объекту. Куча — это область динамической памяти, используемая для таких объектов в модели урока.
- **Длина, буфер, свойство и представление среза:** длина считает ячейки массива. Буфер — это хранилище, выделенное под эти ячейки. Свойство — именованное значение, доступное через объект, как `a.Length`. Представление среза описывает часть существующего хранилища; изменение его протяжённости не меняет размер исходного массива.
- **Объявление, инициализация, присваивание и выражение:** объявление вводит переменную; инициализация задаёт её первое значение. Присваивание вычисляет выражение справа и записывает результат в переменную слева. Выражение — это код, производящий значение.
- **Выделение памяти и `new`:** выделение памяти создаёт хранилище для объекта. `new` — ключевое слово создания объектов, здесь оно используется для выделения массива.
- **Инициализатор массива, выведенный тип, создание массива с неявным типом и коллекционное выражение:** инициализатор перечисляет начальные значения элементов в фигурных скобках. Вывод означает, что компилятор определяет тип или количество из контекста или значений. Создание массива с неявным типом использует `new[]`, выводя тип элемента из значений. Коллекционное выражение использует квадратные скобки вроде `[6, 8, 5]` и требует подходящего целевого типа.
- **Функция, локальная функция, заголовок, тело и вызов:** функция — именованный исполняемый код; локальная функция объявляется внутри кода другой функции. Её заголовок описывает результат и входные данные; её тело содержит инструкции. Вызов приводит её в исполнение.
- **Тип возвращаемого значения, возвращаемое значение и `return`:** тип возвращаемого значения задаёт вид результата. Возвращаемое значение — это результат вызова. `return` завершает этот вызов и передаёт его результат.
- **Параметр, аргумент, вызывающий код, вызываемая функция и передача по значению:** параметр — входная переменная в объявлении функции. Аргумент — выражение, переданное при вызове. Вызывающий код вызывает вызываемую функцию. Обычная передача копирует значение аргумента в параметр.
- **Локальная переменная, временная переменная, область видимости и время жизни:** локальная переменная принадлежит функции или блоку; временная переменная хранит рабочие данные. Область видимости определяет, где её имя можно использовать, а время жизни — как долго она существует во время выполнения.
- **Блок и фигурные скобки:** блок группирует инструкции внутри `{ }` и ограничивает область видимости объявленных там переменных.
- **Модификатор и `static`:** модификатор — ключевое слово, присоединяемое к объявлению. `static` сохраняется у локальной функции; его подробный смысл в этом уроке явно отложен.
- **Управляющий поток, метка и `goto`:** управляющий поток — это порядок выполнения. Метка именует инструкцию; `goto` передаёт выполнение на неё.
- **Цикл, итерация, тело и состояние:** цикл повторяет тело инструкций. Одно повторение — это итерация. Состояние — изменяющиеся данные, определяющие следующий шаг; здесь это индекс и накапливаемая сумма.
- **Аккумулятор и составное присваивание:** аккумулятор хранит накапливающийся результат. `s += value` прибавляет к прежней сумме и записывает результат обратно; `i += 1` увеличивает индекс на единицу.
- **Логическое значение, условие, защитная проверка и отрицание:** логическое значение — это `true` или `false`; условие вычисляет такое значение. Защитная проверка проверяет, можно ли продолжать работу. Отрицание меняет `true` и `false` местами.
- **Границы и ошибка на единицу:** границы определяют допустимые индексы. Ошибка на единицу выбирает границу на одну позицию раньше или позже.
- **`if`, `break` и недостижимый код:** `if` выполняет свой блок, только когда условие истинно. `break` выходит из объемлющего цикла. У недостижимого кода нет пути выполнения, ведущего к нему.
- **`while`, бесконечный цикл, `for` и `foreach`:** `while` повторяет тело, пока условие истинно; `while (true)` повторяется, пока управление явно не выйдет. `for` собирает инициализацию, условие и обновление в своём заголовке. `foreach` обходит значения элементов напрямую, используя `in` для указания коллекции.
- **`var`:** эта конструкция просит компилятор вывести тип локальной переменной из её инициализатора; она не означает «переменную, ограниченную числами».
- **Только границы области — null и переполнение целых:** null означает отсутствие ссылки на объект; переполнение целых означает, что арифметический результат вышел за диапазон своего целочисленного типа. Работа с тем и другим выходит за рамки реализации, разбираемой здесь.
- **Компилятор, IDE и отладчик:** компилятор проверяет и транслирует исходный код. IDE — среда редактирования, предлагающая подсказки по синтаксису и диагностику. Отладчик позволяет записи прослеживать вызовы и значения.

## Перенос алгоритма в тело с goto

[00:09:23](https://www.youtube.com/watch?v=VhA2OupAYRc&t=563s) Имеющийся базовый код уже выражает шаги суммирования. Сначала урок переносит эту логику с помощью базовой конструкции C# — **`goto`**, передачи управления именованной **метке**, — а затем заменяет её циклами. Заявленная цель — быстро уйти от goto.

Начальный алгоритм, реконструированный из предыдущей процедуры и описанной здесь передачи, выглядит так:

1. Инициализировать аккумулятор нулём и индекс нулём.
2. Проверить, достиг ли индекс конца.
3. Если достиг, завершить, вернув аккумулятор в качестве ответа.
4. Иначе прибавить элемент по индексу, увеличить индекс и повторить проверку.

[00:09:23](https://www.youtube.com/watch?v=VhA2OupAYRc&t=563s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```csharp
// Existing algorithm shape, before wrapping it in a function:
int[] r = [6, 8, 5];
int s = 0;
int i = 0;

CheckIndex:
if (i >= r.Length)
    goto Finished;
s += r[i];
i += 1;
goto CheckIndex;

Finished:
Console.WriteLine(s);
```

[00:09:29](https://www.youtube.com/watch?v=VhA2OupAYRc&t=569s) **Управляющий поток** определяет, какая инструкция выполняется следующей. Метка заканчивается двоеточием; goto именует пункт назначения. Он может перепрыгнуть вперёд к проверке или назад к повторяемой работе. Метки не хранят значений.

Перенесите рабочие инструкции в функцию, читайте длину из её параметра и замените «завершить и напечатать» на **`return`**, который заканчивает вызов и передаёт его результат. В следующем примере намеренно оставлены видны и переход вперёд, и переход назад:

[00:09:29](https://www.youtube.com/watch?v=VhA2OupAYRc&t=569s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```csharp
static int SumNumbers(int[] r)
{
    int s;
    s = 0;
    int i = 0;
    goto CheckIndex; // forward jump: check before any element read

AddElement:
    s += r[i];
    i += 1;

CheckIndex:
    if (i >= r.Length)
        return s;
    goto AddElement; // backward jump: repeat the work
}
```

**Составное присваивание** вроде `s += r[i]` вычисляет прежнюю сумму плюс этот элемент и записывает результат обратно. Аналогично, `i += 1` увеличивает индекс на единицу. Каждая обычная инструкция заканчивается точкой с запятой.

[00:09:37](https://www.youtube.com/watch?v=VhA2OupAYRc&t=577s) **Вызов** приводит функцию в исполнение. Объявите переменную для её возвращаемого значения, передайте свои числа как аргумент и присвойте результат вызова этой переменной. Печать остаётся в вызывающем коде.

[00:09:37](https://www.youtube.com/watch?v=VhA2OupAYRc&t=577s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

## Замена обратного goto на while

[00:12:49](https://www.youtube.com/watch?v=VhA2OupAYRc&t=769s) **Цикл** повторяет тело инструкций; **итерация** — одно повторение. Схему с обратным goto можно переписать как **`while (true)`**, цикл, условие которого всегда истинно.

Чтобы выполнить переписывание:

1. Поставьте `while (true)` перед повторяемыми инструкциями.
2. Поместите повторяемый код метки назначения внутрь её фигурных скобок.
3. Удалите метку и goto, который прыгал обратно к ней.
4. Оставьте проверку завершения перед любым обращением к массиву.

[00:12:49](https://www.youtube.com/watch?v=VhA2OupAYRc&t=769s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```csharp

{

    int i = 0;
    while (true)
    {
        if (i >= r.Length)
            return s;
        s += r[i];
        i += 1;
    }
}
```

[00:13:11](https://www.youtube.com/watch?v=VhA2OupAYRc&t=791s) **Тело** — это блок внутри цикла. Если управление дошло до его закрывающей скобки, оно возвращается к началу цикла, а не переходит к следующему оператору после цикла.

[00:13:34](https://www.youtube.com/watch?v=VhA2OupAYRc&t=814s) У **бесконечного цикла** нет автоматической точки остановки, если его условие всегда истинно. Без выхода тело повторяется вечно, и операторы после цикла никогда не достигаются. В этой суммирующей версии есть явный return, поэтому для показанного массива цикл конечен.

[00:13:52](https://www.youtube.com/watch?v=VhA2OupAYRc&t=832s) В записи этот структурированный цикл рекомендуется вместо повторений на goto и метках. Он делает повторяемую область видимой в одном блоке.

[00:14:01](https://www.youtube.com/watch?v=VhA2OupAYRc&t=841s) У **недостижимого кода** нет пути выполнения. IDE затемняет goto после return, потому что return уже завершил функцию.

[00:14:01](https://www.youtube.com/watch?v=VhA2OupAYRc&t=841s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

## Выбор правильной границы цикла

[00:14:24](https://www.youtube.com/watch?v=VhA2OupAYRc&t=864s) **Условие** вычисляется в **логическое значение**: true или false. **Отрицание** меняет это значение на противоположное. Само по себе изменение условия цикла не сохраняет поведение; проверка остановки и проверка продолжения должны быть логическими противоположностями с соответствующим управляющим потоком.

[00:14:27](https://www.youtube.com/watch?v=VhA2OupAYRc&t=867s) Правильная проверка продолжения — `i < length`; обратная ей проверка остановки — `i >= length`. Эквивалентно для целочисленного индекса остановка на `i > length - 1` означает то же самое. Это не эквивалентно `i >= length - 1`, что остановило бы обработку до последней ячейки.

[00:14:54](https://www.youtube.com/watch?v=VhA2OupAYRc&t=894s) **Границы** определяют допустимые позиции. У массива длины три индексы 0, 1 и 2. Индекс 3 уже за последним элементом. Последний допустимый индекс — `length - 1`.

[00:15:10](https://www.youtube.com/watch?v=VhA2OupAYRc&t=910s) Строгое сравнение `i > length - 1` эквивалентно `i >= length` для целочисленных индексов, потому что между этими границами нет дробного индекса.

[00:15:10](https://www.youtube.com/watch?v=VhA2OupAYRc&t=910s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```text
// For an integer index and length = 3:
last valid index: 2
continue: i < 3       // includes i == 2
stop:     i >= 3      // excludes i == 3
same stop: i > 3 - 1  // i > 2
wrong stop: i >= 3 - 1 // would wrongly stop at i == 2
```

[00:15:25](https://www.youtube.com/watch?v=VhA2OupAYRc&t=925s) «Меньше длины» исключает позицию на единицу за концом, то есть `length`; оно включает последний элемент на позиции `length - 1`. Прочтение этого условия как исключающего последний элемент означало бы **ошибку на единицу**, сдвиг границы на одну позицию.

[00:15:51](https://www.youtube.com/watch?v=VhA2OupAYRc&t=951s) Отделите завершение цикла от возврата результата. **`break`** выходит из цикла, после него может идти return. Перенос положительной проверки продолжения в заголовок while убирает отдельную пару «if и break».

[00:15:51](https://www.youtube.com/watch?v=VhA2OupAYRc&t=951s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```csharp

int i = 0;
while (true)
{
    if (i >= r.Length)
        break;
    s += r[i];
    i += 1;
}
// s now holds the answer; return it from the enclosing SumNumbers body.

// Clearer shape, replacing that loop:

i = 0;
while (i < r.Length)
{
    s += r[i];
    i += 1;
}
return s;
```

[00:16:00](https://www.youtube.com/watch?v=VhA2OupAYRc&t=960s) В форме с бесконечным циклом проверка остановки должна выполняться до работы с индексом. В форме с условием while то же решение принимается в начале цикла. Условие остановки, просто записанное как выражение, не может выйти из цикла; нужно действие выхода или обратная защитная проверка продолжения.

[00:16:22](https://www.youtube.com/watch?v=VhA2OupAYRc&t=982s) **Защитная проверка** — это проверка, разрешающая выполнять тело. Она вычисляется перед самой первой итерацией и снова каждый раз, когда управление возвращается к началу цикла. Поэтому пустой массив не выполняет ни одного чтения элементов и оставляет сумму равной нулю. Это следует из реконструированного кода; показанный в записи числовой пример использует три элемента.

## Сбор состояния цикла в заголовке for

[00:16:59](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1019s) Индекс — это **временное рабочее состояние**, данные, которые меняются только для того, чтобы пройти по этому массиву. Он задаёт защитную проверку и позицию следующего элемента. [00:17:00](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1020s) В версии с while его объявление, проверка и обновление сейчас находятся в разных местах.

[00:17:00](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1020s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```csharp
int i = 0;                 // initial state
while (i < r.Length)        // continuation guard
{
    s += r[i];             // useful body work
    i += 1;                // next-state update
}
```

[00:17:13](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1033s) В записи выделяются четыре структурные части: начальное состояние, условие завершения или продолжения, полезная работа, меняющая накапливаемые данные, и переход к состоянию следующей итерации. Здесь это индекс ноль, проверка границ, прибавление к сумме и увеличение индекса.

[00:17:24](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1044s) **Состояние** не обязано означать один индекс. Оно может включать несколько значений, например два индекса, обновления которых зависят от их текущих значений. В примере суммирования остаётся один.

[00:17:35](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1055s) **Цикл `for`** собирает управление обходом в своём заголовке: начальное состояние A, защитную проверку продолжения B и обновление состояния C. В фигурных скобках находится полезная работа — тело. B решает, может ли начаться ещё одна итерация; C выполняется после каждого завершённого тела, а не только один раз в конце всего цикла.

[00:17:57](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1077s) В записи эта форма предпочитается для данного шаблона, потому что инициализация, проверка и обновление стоят рядом друг с другом, и обход становится легче читать.

[00:18:21](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1101s) Преобразование механическое:

1. Перенесите `int i = 0` в первый слот заголовка.
2. Поместите `i < r.Length` во второй слот.
3. Перенесите `i += 1` в третий слот.
4. Удалите прежние отдельные объявление и увеличение.
5. Оставьте `s += r[i]` внутри тела.

[00:18:21](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1101s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```csharp
int s = 0;
for (int i = 0; i < r.Length; i += 1)
{
    s += r[i];
}
return s;
```

Две точки с запятой в заголовке разделяют его три части. Выполнение: один раз инициализация, затем проверка, тело, обновление, затем снова проверка. Преобразование сохраняет сумму трёх элементов, то есть 19.

[00:18:46](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1126s) Преобразование цикла сохраняет арифметику, но есть разница в **области видимости**: область видимости — это место, где можно использовать объявленное имя. Индекс, объявленный в заголовке for, принадлежит этому for.

[00:20:00](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1200s) Следующий шаг — обход на более высоком уровне: использовать значение каждого элемента, не выписывая индекс, начальный индекс, конечную границу или приращение. **`foreach`** повторяет работу для последовательных элементов.

[00:20:34](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1234s) Объявите переменную для **текущего элемента**, то есть значения, посещаемого на этой итерации, вместо индекса. Затем напишите **`in`**, ключевое слово, связывающее эту переменную с исходным массивом.

[00:20:34](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1234s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

[00:21:01](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1261s) **Локальная переменная** именует данные, доступные в этой части функции. Концептуально форма с индексом сначала создаёт локальную переменную, хранящую текущее значение, а затем использует её. Объявление foreach предоставляет такую локальную переменную напрямую.

```csharp
// Indexed body:
for (int i = 0; i < r.Length; i += 1)

    int element = r[i];

```

[00:21:13](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1273s) **`var`** просит компилятор вывести тип переменной по посещаемым значениям. Для этого `int[]` выведенный тип элемента — `int`. Удалите отдельное объявление элемента и используйте переменную из заголовка напрямую:

[00:21:13](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1273s) Упрощённая реконструкция из видео, опирающаяся на [неизменяемый транскрипт][recorded-transcript], а не на точную закоммиченную программу:

```csharp
static int SumNumbers(int[] r)
{
    int s = 0;
    foreach (var element in r)
    {
        s += element;
    }
    return s;
}

int[] r = [6, 8, 5];
int sum = SumNumbers(r);
Console.WriteLine(sum); // 19
```

[00:21:21](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1281s) В записи сокращённая форма запускается после этого изменения. У неё то же поведение суммирования, что и у прежних версий; транскрипт не проговаривает здесь отдельный новый числовой вывод. Результат 19 следует из тех же трёх входных значений и сложений.

Используйте foreach, когда телу нужны значения, и формы с индексами — когда полезны явные позиции из урока. Развитие материала в записи убирает служебные записи, не меняя интерфейс функции.

[00:22:00](https://www.youtube.com/watch?v=VhA2OupAYRc&t=1320s) **`return`** — это действие, которое заканчивает функцию. В прежнем защищённом теле, если его условие истинно, возврат не даёт последующим операторам выполняться на этом пути. Любой оператор, поставленный сразу после return в том же блоке, **недостижим**, то есть ни один путь управления не может его выполнить.

## Объём урока и что почитать

[00:00:00](https://www.youtube.com/watch?v=VhA2OupAYRc&t=0s) Урок изменяет существующую базовую программу, чтобы реализовать прежний алгоритм суммирования. Он не создаёт новый проект, не устанавливает инструменты и не разрабатывает предыдущую более крупную задачу с обработкой файлов.

Фактическая конструкция охватывает массивы, чтение и запись по индексу, входные данные функции и возвращаемые значения, а также преобразования через while, for и foreach.

Рисунки с адресами объясняют ссылки, смещения элементов и временные переменные. Они не задают точные байтовые адреса и физическое размещение каждой локальной переменной. Изменение размера массива требует другого объекта; замечание о представлении среза не разбирает процедуру получения среза.

Показанные входные данные — целочисленный массив, содержащий 6, 8 и 5, с корректной ссылкой на объект. Поведение пустого массива можно рассудить по заранее проверенной защитной проверке, но запуск с пустым массивом не приводится. Null означает отсутствие ссылки на объект; переполнение целых означает арифметический результат вне диапазона целочисленного типа. Работа с null-входом и политика переполнения в этой записи не разбираются.

Для необязательной практики помимо видео используйте [лабораторную по реализации алгоритма](../../../labs/1_basic/12_algorithms_code.md). В ней требуются функции, реализующие только алгоритм, с выводом в консоль в основном коде, с массивами, создаваемыми вызывающим кодом, и вариантами с while и for. Инструкции про массивы-результаты в ней относятся к алгоритмам, которым нужен выходной массив; сумма в этом уроке возвращает одно число. Необязательные проверки и исключения в лабораторной относятся к более позднему материалу, а не к предпосылкам для понимания этого видео.

[Лабораторная по функциям](../../../labs/1_basic/05_functions.md) и [лабораторная по базовым приёмам](../../../labs/1_basic/10_basic.md) предлагают дополнительные вопросы об отдельных переменных-параметрах, копируемых значениях аргументов и хранении возвращённого результата. ## Записанная история кода

Эта сжатая цепочка следует за состояниями кода из видео в хронологическом порядке. Ни один из просмотренных коммитов не содержит их точного текста программы; [неизменяемый транскрипт][recorded-transcript] подтверждает записанные пояснения, а не претендует на точное восстановление исходников. Соответствующее резюме состояний:

```text
existing sum steps -> array input and int result
new int[count] -> indexed writes -> initializer -> inferred syntax
goto body -> captured call result 19
separate result declaration -> initialized declaration
backward goto -> while(true) -> while(i < Length)
while traversal -> for header -> scope-matched while block
indexed element reads -> foreach element values
```
