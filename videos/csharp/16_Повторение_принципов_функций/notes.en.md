# Reviewing how functions work

[00:00:00](https://www.youtube.com/watch?v=L62Og-Y4poE&t=0s) A function groups instructions under a name. This review follows what happens when that name is called: arguments become local parameter values, the body runs, and execution returns to the caller. It then connects local functions to class methods and explains how an instance method receives its object.

The vocabulary used throughout the lesson is:

- **Function, declaration, body, and instruction:** a function is named work; its declaration defines that work; its body is the block inside braces; an instruction is an action executed by the program.
- **Call, caller, call site, and control flow:** a call starts a function's execution; the caller is the code making the call; the call site is its location; control flow is the order in which instructions execute.
- **Return type, `void`, `int`, and `return`:** the return type describes a call's result; `void` means no result value; `int` is the integer type used here; `return` ends the call and, for a value-returning function, supplies its result.
- **Parameter, argument, and local variable:** a parameter is a named input in the declaration; an argument is an expression supplied at a call; a local variable belongs to a particular block or function invocation.
- **Declaration, initialization, and assignment of a variable:** declaration introduces the variable, initialization supplies its initial value, and assignment stores a value in it.
- **Expression, operand, operator, and expression evaluation:** an expression computes a value; an operand is an input to an operator such as `+` or `*`; evaluation performs the computations needed to obtain the value.
- **Abstraction:** a name and interface let the caller use an operation without inspecting its implementation.
- **Scope and shadowing:** scope is the region where a name can be used; shadowing occurs when an inner name hides an outer name.
- **Positional and named arguments:** positional arguments bind by parameter position; named arguments use `parameterName: expression` to identify the target parameter.
- **Local function, capture, and definite assignment:** a local function is declared inside enclosing executable code; capture gives it access to an enclosing variable; definite assignment means the compiler can establish that a variable has a value before it is read.
- **`static`, by-value input, by-reference access, and compiler lowering:** `static` prevents a local function from capturing enclosing locals or instance state; ordinary parameters receive values; by-reference access reaches an existing variable; lowering is the compiler's transformation of convenient source syntax into an implementation.
- **Class, member, method, field, and access modifier:** a class describes a type; a member belongs to that type; a method is a function declared as a member; a field stores data; an access modifier such as `public` controls where a member can be used.
- **Static class, static method, and static field:** a static class has no instances; a static method has no instance receiver; a static field belongs to the type rather than to an individual object.
- **Top-level statements, entry point, `Program`, `Main`, and `args`:** top-level statements are executable code written outside an explicit method; the entry point starts the program; `Program` and `Main` express the conventional containing class and entry method; `args` represents command-line arguments.
- **Object, instance, receiver, hidden parameter, and `this`:** an object is an instance of a type; the receiver is the object on which a method is called; an instance method conceptually receives that object as a hidden parameter; `this` names the current receiver.
- **The syntax used in the samples:** parentheses delimit parameter or argument lists, braces delimit bodies, a semicolon ends a statement, and a dot selects a member. `Console.WriteLine` prints a line; quoted text is a string; `new` creates an object.

## Make local dependencies explicit with static

[00:09:01](https://www.youtube.com/watch?v=L62Og-Y4poE&t=541s) So far, the declaration is a **local function**, a function nested in surrounding executable code. A **static local function** cannot **capture**, or directly use, the enclosing block's local variables or instance state. Its ordinary local inputs must be supplied explicitly.

```csharp
int outside = 9;
int sum = Add(outside, 1);

static int Add(int a, int b)
{
    return a + b;
}
```

The call visibly supplies `outside`'s value. Trying to read `outside` directly inside this static local function is rejected. `static` therefore helps keep enclosing-local dependencies visible in the argument list; it does not hide those dependencies. [Static local-function rules](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/classes-and-structs/local-functions).

[00:09:13](https://www.youtube.com/watch?v=L62Og-Y4poE&t=553s) Removing `static` permits access to enclosing locals, but the compiler must still establish that a captured variable is assigned before a call that reads it. For example, this explanatory intermediate state is invalid:

{
    return sum;

```

The problem is a **definite-assignment** error detected at compile time, rather than permission to run a read of an uninitialized local.

[00:09:27](https://www.youtube.com/watch?v=L62Og-Y4poE&t=567s) Initialize the enclosing variable before the first call that reads it:

The capture is now allowed: `ReadSum` reads the existing `sum`. Definite assignment concerns whether the read has a value available; the function declaration may still appear later in the file.

## Understand capture as shared variable access

[00:10:44](https://www.youtube.com/watch?v=L62Og-Y4poE&t=644s) Remove the first parameter and read an outer variable instead. The function's result now depends on surrounding state even though that state is absent from its explicit argument list:

{
    return a + b;
}
```

Here **capture** is access to the enclosing variable `a`; it is not the creation of an unrelated parameter with a copied integer.

[00:10:56](https://www.youtube.com/watch?v=L62Og-Y4poE&t=656s) The recording explains **compiler lowering** using an extra reference parameter. Lowering is an implementation transformation performed by the compiler. The following is a conceptual equivalent, not the exact emitted C# or a required source edit:

```csharp

static int SumOperationLowered(ref int capturedA, int b)
{
    return capturedA + b;
}
```

In this model, `ref` supplies **by-reference access** to the existing variable. An ordinary integer parameter receives a value; the reference model can reach the caller's storage.

[00:11:07](https://www.youtube.com/watch?v=L62Og-Y4poE&t=667s) Sharing the variable matters because a capturing function may assign to it. Copying its value into an independent integer would lose that update. To expose this difference, extend the original capturing example:

3. Add `public`, an **access modifier** that permits callers outside this class to use the method. A class method with no access modifier is private by default; `public` is the choice used here, not the only access level C# supports.
4. [00:12:08](https://www.youtube.com/watch?v=L62Og-Y4poE&t=728s) Update the caller to `Functions.SumOperation(1, 2)`. The class name, dot, and method name identify the operation.

[00:12:14](https://www.youtube.com/watch?v=L62Og-Y4poE&t=734s) A **static method** has no object receiver and is often casually called a function. [00:12:20](https://www.youtube.com/watch?v=L62Og-Y4poE&t=740s) It may still read **static fields**, data belonging to the type, so `static` does not promise that its result depends solely on explicit arguments. That is a design goal for this example.

[00:12:34](https://www.youtube.com/watch?v=L62Og-Y4poE&t=754s) Prefer parameters to static variables when supplying information to an operation. Parameters make the data flow visible where the call is written instead of requiring the reader to search for shared state.

## Recognize the entry point behind top-level code

[00:12:43](https://www.youtube.com/watch?v=L62Og-Y4poE&t=763s) The executable lines outside an explicitly written method are **top-level statements**. The compiler supplies a containing `Program` type and a static **entry point**, the method where execution begins. The recording presents this through the familiar `Main` model.

For the simple call above, the equivalent hand-written structure can be illustrated as follows; this is a teaching model, not the exact generated method name or accessibility:

```csharp
class Program
{
    public static void Main(string[] args)
    {
        int sum = Functions.SumOperation(1, 2);
    }
}
// The Functions class from the preceding section supplies SumOperation.
```

[00:12:59](https://www.youtube.com/watch?v=L62Og-Y4poE&t=779s) `Main` conventionally names an explicitly written entry method, and `string[] args` represents the array of command-line strings. You do not have to type this wrapper when using top-level statements. The lesson postpones the meaning of an integer entry-point result and does not develop command-line argument processing.

[00:13:08](https://www.youtube.com/watch?v=L62Og-Y4poE&t=788s) The generated `Program` class is non-static, while its entry method is static. A non-static class can contain static methods; creating an instance of `Program` is unnecessary for entry-point execution.

Precision matters: the generated entry method need not be literally named `Main` or declared `public`. Its signature depends on the top-level code. For the synchronous examples here with no entry-point return value, the model is a `void` entry method; a top-level integer return changes its result type to `int`. The recording's integer wrapper is therefore an illustration rather than a universal compiler output. [Microsoft's top-level entry-point rules](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/program-structure/top-level-statements).

## Give an instance method its object

[00:13:21](https://www.youtube.com/watch?v=L62Og-Y4poE&t=801s) An **instance method** runs for a particular object. In this class-based review, instance methods require a non-static class; static classes cannot contain them. [00:13:25](https://www.youtube.com/watch?v=L62Og-Y4poE&t=805s) Static methods can also be declared on non-static classes.

[00:13:31](https://www.youtube.com/watch?v=L62Og-Y4poE&t=811s) Unlike a static method, an instance method can read the fields of its receiver. A **field** is data stored in an object; the **receiver** is the particular object on which the method is invoked. Think of the receiver as an additional **hidden parameter**: the caller supplies it without listing it among the explicit arguments.

[00:13:49](https://www.youtube.com/watch?v=L62Og-Y4poE&t=829s) Construct an object, set its field, then call its instance method. This short reconstruction uses an `Animal` with a field named `H`:

```csharp
Animal animal = new Animal();
animal.H = 7;
int result = animal.AddToH(2); // 9.

class Animal
{
    public int H;

    public int AddToH(int amount)
    {
        return H + amount;
    }
}
```

1. `new Animal()` creates an **object**, an instance of the `Animal` type.
2. Store its reference in `animal`.
3. Assign 7 to that object's field `H`.
4. [00:14:07](https://www.youtube.com/watch?v=L62Og-Y4poE&t=847s) Write `animal.AddToH(2)`: receiver expression, dot, method name, and explicit arguments.
5. The receiver is passed conceptually as the hidden object parameter. The explicit argument 2 initializes `amount`; reading this receiver's `H` supplies 7, so the result is 9.

[00:13:39](https://www.youtube.com/watch?v=L62Og-Y4poE&t=819s) The hidden parameter represents the object reference, not a copy of the whole `Animal`. Different calls can therefore receive different objects even though they execute the same method body.

## Use receiver expressions and this

[00:14:23](https://www.youtube.com/watch?v=L62Og-Y4poE&t=863s) The receiver need not be a bare variable name. It may be any expression that produces an appropriate object reference. [00:14:31](https://www.youtube.com/watch?v=L62Og-Y4poE&t=871s) A freshly created object can be used immediately:

```csharp
int result = new Animal().AddToH(2);
```

This uses the same `Animal` declaration as the preceding state. [00:14:40](https://www.youtube.com/watch?v=L62Og-Y4poE&t=880s) Creating an object within the call and retaining no reference after the call is legal. For this simplified class, a newly created object's integer field `H` initially has value 0, so this expression returns 2; an explicitly uninitialized local integer, discussed earlier, follows different rules.

[00:14:46](https://www.youtube.com/watch?v=L62Og-Y4poE&t=886s) Inside an instance method, an unqualified field access such as `H` reads the field belonging to the receiver of that invocation. It does not mean an arbitrary field of some other `Animal`.

[00:15:00](https://www.youtube.com/watch?v=L62Og-Y4poE&t=900s) The hidden receiver is available under the keyword **`this`**, meaning the current object. Make that connection explicit by changing the body:

```csharp
public int AddToH(int amount)
{
    return this.H + amount;
}
```

Here `H` and `this.H` select the same field of the current receiver. The dot selects the field from that object.

[00:15:14](https://www.youtube.com/watch?v=L62Og-Y4poE&t=914s) At the caller's top level, use the object expression you actually have, such as `animal.H`; there is no current instance there to name with `this`. Inside the method, `this.H` refers to the object supplied for that particular invocation. It does not permanently mean a caller variable named `animal`.

<details>
<summary>If two Animal objects have different H values, which one does AddToH read?</summary>

It reads H on the receiver of the call. For first.AddToH(2), this refers to first; for second.AddToH(2), this refers to second. The same body runs with a different hidden receiver.

</details>
