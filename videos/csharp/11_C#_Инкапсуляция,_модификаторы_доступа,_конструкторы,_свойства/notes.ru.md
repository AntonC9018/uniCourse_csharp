# Конструкторы инкапсуляции и свойства

[00:00:00](https://www.youtube.com/watch?v=IESVXL16OBA&t=0s) Этот урок превращает свободно записываемое здоровье боевого персонажа в состояние, которое меняется только через осознанные операции. Проследите за изменениями от выделенных методов через приватные поля и конструкторы к свойствам, чьи аксессоры управляют чтением и записью. Финальный разбор объясняет, как новый объект получает начальные значения.

Используемые ниже идеи и термины:

- **Класс, объект, поле и метод:** класс определяет тип; объект — его экземпляр; поле хранит состояние; метод выполняет операцию. Метод экземпляра работает с конкретным объектом.
- **Параметр, аргумент и `this`:** параметр — переменная в объявлении вызываемой сущности; аргумент передаёт её значение при вызове. `this` обозначает текущий объект и служит неявным получателем для операций экземпляра.
- **Рефакторинг и абстракция:** рефакторинг перестраивает код, сохраняя задуманное поведение; абстракция даёт операции имя, чтобы вызывающий код не повторял её реализацию. Изменение, сделанное ради иллюстрации идеи, само по себе не является улучшением проектирования.
- **Контракт или предусловие:** предположение, которое должно выполняться при начале операции, например «игрок жив». **Валидация** проверяет, удовлетворяет ли значение правилу.
- **Утверждение, Debug и Release:** `Debug.Assert` проверяет предположение во время разработки. Сборки Debug обычно включают такие вызовы; сборки Release обычно их не содержат.
- **Модификатор доступа, `public`, `private` и инкапсуляция:** модификаторы доступа управляют тем, где доступны члены. Публичные члены доступны вызывающему коду; приватные ограничены своим объявляющим типом. Инкапсуляция прячет хранимые данные за контролируемыми операциями.
- **Инициализатор объекта и `required`:** инициализатор присваивает доступные члены после создания; `required` требует инициализации члена вызывающим кодом. Он не даёт доступа к приватному члену.
- **Фабричная функция и конструктор:** фабрика — обычная функция, возвращающая объект; конструктор инициализирует новосозданный объект и в объявлении использует имя класса. `new` создаёт и инициализирует объект.
- **Именованный аргумент:** аргумент, помеченный именем своего параметра, например `health: 20`, чтобы смысл был виден без запоминания позиции.
- **Значение по умолчанию, `readonly` и создание с выводом типа:** значения по умолчанию — это начальные значения хранилища, здесь ноль для целых чисел. Поле `readonly` можно инициализировать при объявлении или в соответствующем конструкторе. `new(...)` с выводом типа берёт тип из окружающего объявления.
- **Перегрузка и разрешение перегрузок:** перегрузки предлагают разные списки параметров для одного имени; разрешение выбирает применимую перегрузку по переданным аргументам.
- **Конструктор копирования, фабрика копирования и метод копирования:** три способа создать новый объект из значений существующего.
- **Геттер, сеттер и ограничение диапазона:** геттер возвращает хранимое значение; сеттер изменяет его и может его проверять. Ограничение диапазона заменяет выходящее за границы значение граничным, например отрицательное здоровье — нулём.
- **Свойство и аксессор:** свойство — именованный член, чьи аксессоры `get` и `set` выполняют чтение и запись синтаксисом, похожим на обращение к полю.
- **Автосвойство и резервное поле:** автосвойство имеет аксессоры без тел; компилятор предоставляет его скрытое хранилище, называемое резервным полем. Явные аксессоры могут использовать объявленное вами поле.
- **`value`, PascalCase и подчёркивание в именах:** `value` — неявный параметр сеттера свойства. PascalCase начинает слова с заглавных букв, как в `Health`; приватные поля по соглашению пишутся с ведущим подчёркиванием, как `_health`.
- **Ссылка, динамическая память и временное хранилище в стеке:** ссылка идентифицирует объект; урок рисует объект в динамической памяти, а параметры — во временной памяти, чтобы различить время их жизни. Нарисованные числовые адреса — объяснительные подписи, а не адреса, которые обычная ссылка C# открывает.

Связанная [лабораторная работа про инкапсуляцию](../../../labs/1_basic/17_encapsulation.md) применяет эти идеи к библиотеке. Её дополнительные задачи по фильтрации выходят за рамки этого боевого разбора.

Каждый блок кода ниже — **упрощённая реконструкция состояния связанного видео** с единообразными для ясности именами, а не точный закоммиченный снимок. Единственная неизменяемая ссылка на лабораторную работу указана как связанный пример. ## Подготовьте класс к контролируемым изменениям здоровья

[00:00:05](https://www.youtube.com/watch?v=IESVXL16OBA&t=5s) Начнём с того, что вернём ранее выделенную операцию `Take` обратно в класс персонажа. **Метод** — это операция, объявленная на классе; **метод экземпляра** получает объект, над которым действует, через неявный получатель `this`. Так у инкапсуляции появляется конкретный класс для работы.

Исходная проблема — повторяющаяся печать с жёстко заданным именем игрока. На [00:00:23](https://www.youtube.com/watch?v=IESVXL16OBA&t=23s) выделим эту печать в метод с **параметром** — именем атакованного персонажа. **Аргумент** вызова передаёт «Player» или имя противника. Упрощённое состояние «до и после»:

```csharp
// Before: a fixed label at the call site.
Console.WriteLine($"Player health: {player.Health}");

// After: inside Stat, with Health still public at this stage.
public int Health;
public void PrintHealthOfEnemy(string name)
{
    Console.WriteLine($"{name} health: {Health}");
}
// Call site:
player.PrintHealthOfEnemy("Player");
```

Здесь `int` хранит целое число, `string` — текст, `void` означает, что метод ничего не возвращает, а `Console.WriteLine` печатает строку. Строка со знаком доллара в начале подставляет выражения, записанные в фигурных скобках.

На [00:00:50](https://www.youtube.com/watch?v=IESVXL16OBA&t=50s) перенесём `PrintHealthOfEnemy` ближе к объявлению `Health`. Код, обращающийся к полю, остаётся рядом с этим полем, и связь между состоянием и операциями становится заметнее. Перенос кода и замена фиксированной подписи параметром готовят класс к дальнейшим изменениям.

## Выделите операцию нанесения урона и переименуйте её

[00:01:00](https://www.youtube.com/watch?v=IESVXL16OBA&t=60s) Далее выделим операцию нанесения урона после уже существующих методов и заменим прежние вызовы функции везде, где они использовались. Обычная функция может принимать цель первым явным параметром; соответствующий метод экземпляра получает ту же цель неявно, как `this`. Абстракция — это операция «получить урон», а не само вычитание.

```csharp
// Conceptual function form:
static void ApplyDamage(Stat target, int damage)
{
    target.Health -= damage;
}

// Corresponding member inside Stat:
public void TakeDamage(int damage)
{
    Health -= damage;
}
// Replacement call:
enemy.TakeDamage(player.Attack);
```

`static` помечает операцию без неявного получателя-объекта. `-=` вычитает и присваивает результат. Этот пример изолирует обновление поля; окружающая боевая функция по-прежнему выполняет проверку смерти и печать сообщения.

На [00:01:32](https://www.youtube.com/watch?v=IESVXL16OBA&t=92s) применим выделенную операцию и к игроку. Окружающая логика игрока немного отличается, но общее действие нанесения урона туда подходит. На [00:01:45](https://www.youtube.com/watch?v=IESVXL16OBA&t=105s) переименуем новый член так, чтобы было видно, что урон принимается. **Рефакторинг** перестраивает код, а **абстракция** даёт действию полезное имя. Преподаватель явно вносит это изменение ради следующего объяснения; само по себе изменение кода не доказывает улучшения.

## Найдите предположение о живом игроке

## Покажите некорректное состояние утверждением

[00:03:06](https://www.youtube.com/watch?v=IESVXL16OBA&t=186s) Добавьте **утверждение** — проверку предположения на этапе разработки — в начало функции атаки. `Debug.Assert` получает логическое условие; false означает, что предполагаемый контракт нарушен. Упрощённое состояние из видео:

```csharp
using System.Diagnostics;

static void AttackPlayer(Stat player)
{
    Debug.Assert(player.Health > 0);
    // Existing exchange of attacks follows.

```

На [00:03:24](https://www.youtube.com/watch?v=IESVXL16OBA&t=204s) различаем сборки **Debug**, обычно используемые при тестировании и разработке, и сборки **Release**, обычно используемые для готовой программы. На [00:03:42](https://www.youtube.com/watch?v=IESVXL16OBA&t=222s) цель — ловить ошибки, которые в корректном коде кажутся невозможными, не оставляя эти проверки в обычной сборке Release. Точнее, вызовы `Debug.Assert` зависят от символа компиляции `DEBUG`; его обычно определяет конфигурация сборки. Утверждение не заменяет необходимую проверку во время выполнения.

На [00:04:10](https://www.youtube.com/watch?v=IESVXL16OBA&t=250s) здоровье равно нулю, значит условие «живой игрок» ложно. Сбой сообщается в той точке, где функция атаки иначе продолжила бы работу при неверном предположении. Поведение утверждения при сбое зависит от среды разработки; запись демонстрирует именно его поведение, а не универсальную гарантию исключения.

На [00:04:28](https://www.youtube.com/watch?v=IESVXL16OBA&t=268s) продолжать работу с некорректным состоянием хуже, чем сразу показать сбой. Следующий вопрос — как вообще не дать постороннему коду присваивать `Health`.

## Ограничьте поле модификатором private

[00:04:45](https://www.youtube.com/watch?v=IESVXL16OBA&t=285s) **Модификатор доступа** управляет тем, где член доступен. Заменим `public` на `private` у поля здоровья. Public разрешает внешнее использование; private ограничивает обычный доступ объявляющим типом. Упрощённое изменение:

```csharp
// Before:
public int Health;

// After, inside Stat:
private int Health;

public void TakeDamage(int damage)
{
    Health -= damage; // Still permitted here.
}
```

На [00:05:09](https://www.youtube.com/watch?v=IESVXL16OBA&t=309s) методы, объявленные в `Stat`, по-прежнему могут читать и писать поле, включая фабричный метод, объявленный в том же типе. На [00:05:25](https://www.youtube.com/watch?v=IESVXL16OBA&t=325s) границей служит класс, а не отдельный метод и не отдельный объект: метод `Stat` может обращаться и к приватным полям другого объекта `Stat`.

На [00:05:37](https://www.youtube.com/watch?v=IESVXL16OBA&t=337s) внешний код больше не может ни читать, ни писать `Health`. Редактор отклоняет внешние ссылки на него; имя члена там неприменимо. На [00:05:49](https://www.youtube.com/watch?v=IESVXL16OBA&t=349s) внешнее **чтение** осознанно отложено. Сначала рассмотрим запрет прямой записи — именно это подчёркивается на [00:05:55](https://www.youtube.com/watch?v=IESVXL16OBA&t=355s).

На [00:06:00](https://www.youtube.com/watch?v=IESVXL16OBA&t=360s) вызов нанесения урона по-прежнему работает, потому что он меняет приватное поле косвенно, через метод, имеющий к нему доступ. На [00:06:12](https://www.youtube.com/watch?v=IESVXL16OBA&t=372s) этот метод становится контролируемой точкой входа. Вызывающий код запрашивает операцию; класс владеет деталями обновления.

## Определите инкапсуляцию через операции

[00:06:36](https://www.youtube.com/watch?v=IESVXL16OBA&t=396s) У состояния здоровья есть три полезные операции: напечатать его, уменьшить и проверить, погиб ли персонаж. Они покрывают взаимодействия, нужные примеру. Упрощённое состояние видео, ориентированное на операции:

```csharp
private int Health;
public void PrintHealth(string name)
{
    Console.WriteLine($"{name} health: {Health}");
}
public void TakeDamage(int damage)
{
    Health -= damage;
}
public bool IsDead()
{
    return Health <= 0;
}
```

Здесь `bool` — значение true/false, а `return` сообщает результат метода. Эти операции иллюстративны; следующие этапы уточняют, как проверяются обновления.

На [00:06:54](https://www.youtube.com/watch?v=IESVXL16OBA&t=414s) и [00:07:03](https://www.youtube.com/watch?v=IESVXL16OBA&t=423s) **инкапсуляция** означает сокрытие данных при взаимодействии через методы класса. Это не значит, что данные нельзя изменить вовсе. На [00:07:13](https://www.youtube.com/watch?v=IESVXL16OBA&t=433s) методы дают гранулярный контроль: «получить урон» несёт смысл, которого нет у «перезаписать это целое число». На [00:07:25](https://www.youtube.com/watch?v=IESVXL16OBA&t=445s) эта граница защищает от случайного внешнего присваивания значения, некорректного в текущей ситуации. Класс всё равно должен корректно реализовать свои методы; сам по себе `private` не проверяет целое число.

## Почините создание внутренней фабрикой

[00:07:45](https://www.youtube.com/watch?v=IESVXL16OBA&t=465s) После того как здоровье стало приватным, редактор помечает прежние прямые обращения как ошибки. На [00:07:51](https://www.youtube.com/watch?v=IESVXL16OBA&t=471s) создание тоже требует внимания: **инициализатор объекта** присваивает доступные члены после создания объекта и не может извне класса присвоить приватное поле.

```csharp
// Former external construction:
var enemy = new Stat { Attack = 7, Health = 20 };
// Health is now inaccessible here.
```

На [00:08:09](https://www.youtube.com/watch?v=IESVXL16OBA&t=489s) вводится **конструктор** как механизм инициализации скрытого состояния — примерно так же, как фабрика. Сначала рассмотрим обычную **фабричную функцию**, функцию, возвращающую объект. На [00:08:18](https://www.youtube.com/watch?v=IESVXL16OBA&t=498s) `required` нельзя оставить на этом приватном поле: обязательные члены должны быть достаточно доступны, чтобы вызывающий код мог их инициализировать. Простое удаление `required` не даёт внешнему инициализатору доступа. Уберите некорректное сочетание приватности и `required` и обеспечьте инициализацию внутри типа.

На [00:08:22](https://www.youtube.com/watch?v=IESVXL16OBA&t=502s) обобщим фабрику: пусть она принимает по параметру на каждое инициализируемое значение. На [00:08:30](https://www.youtube.com/watch?v=IESVXL16OBA&t=510s) используем её для создания противника вместо присваивания приватного поля во внешнем месте создания. Упрощённое промежуточное состояние:

```csharp
// Inside Stat:
public static Stat Create(int attack, int health)
{
    return new Stat { Attack = attack, Health = health };
}

// Outside Stat:
var enemy = Stat.Create(7, 20);
```

Этот инициализатор законен внутри `Stat`, потому что этот код имеет доступ к собственному приватному члену. Он опирается на создание без параметров, доступное на этом промежуточном этапе. Следующие правки заменят этот механизм конструктором.

## Сделайте аргументы фабрики читаемыми

[00:08:42](https://www.youtube.com/watch?v=IESVXL16OBA&t=522s) Вызов фабрики `Create(7, 20)` неоднозначен для читателя, который не помнит позиции параметров. На [00:08:49](https://www.youtube.com/watch?v=IESVXL16OBA&t=529s) используем **именованные аргументы**, которые помечают значения именами их параметров.

На [00:09:01](https://www.youtube.com/watch?v=IESVXL16OBA&t=541s) двоеточие связывает имя параметра с передаваемым аргументом. Упрощённое изменение места вызова:

На [00:09:06](https://www.youtube.com/watch?v=IESVXL16OBA&t=546s) переупорядоченный вызов с именованными аргументами работает как прежде: имена сохраняют, какое значение попадёт в какой параметр. На [00:09:24](https://www.youtube.com/watch?v=IESVXL16OBA&t=564s) противник по-прежнему создаётся фабрикой и ведёт себя как ранее проинициализированный напрямую объект. Имена улучшают читаемость, но общая функция создания остаётся. Следующий шаг использует специальную конструкцию инициализации языка.

## Замените фабрику конструктором

[00:09:36](https://www.youtube.com/watch?v=IESVXL16OBA&t=576s) **Конструктор** инициализирует новосозданный объект. Он выполняет ту же роль инициализации, что и фабрика, но вызывается как часть `new`. На [00:09:43](https://www.youtube.com/watch?v=IESVXL16OBA&t=583s) «нет собственного имени» означает, что у него не может быть произвольного имени метода. На [00:09:49](https://www.youtube.com/watch?v=IESVXL16OBA&t=589s) объявите его с именем класса и списком параметров, без типа возврата.

class Stat
{
    public int Attack;
    private int Health;

    public Stat(int attack, int health)
    {
        Attack = attack;
        Health = health;
    }
}
```

На [00:10:02](https://www.youtube.com/watch?v=IESVXL16OBA&t=602s) целочисленные поля сначала имеют своё **значение по умолчанию**, ноль; затем тело конструктора присваивает переданные значения. На [00:10:20](https://www.youtube.com/watch?v=IESVXL16OBA&t=620s) представьте, что конструктор экземпляра получает скрытый получатель-объект `this`, через который может писать поля нового объекта. В обычном синтаксисе C# этот получатель неявен.

На [00:10:34](https://www.youtube.com/watch?v=IESVXL16OBA&t=634s) замените вызов фабрики прямым созданием. На [00:10:56](https://www.youtube.com/watch?v=IESVXL16OBA&t=656s) атака и здоровье теперь попадают внутрь через аргументы конструктора, а не через внешний инициализатор объекта:

```

На [00:11:00](https://www.youtube.com/watch?v=IESVXL16OBA&t=660s) компилятор по-прежнему требует инициализации от вызывающего кода, если `Attack` остаётся `required`. Само по себе присваивание ему в этом конструкторе не сообщает компилятору, что обязанность по обязательным членам выполнена. На [00:11:05](https://www.youtube.com/watch?v=IESVXL16OBA&t=665s) уберём `required` у `Attack` в этом примере, потому что теперь инициализация принадлежит конструктору.

## Используйте конструкторы, не теряя границу доступа

[00:11:29](https://www.youtube.com/watch?v=IESVXL16OBA&t=689s) Одно из преимуществ конструкторов — инициализация полей `readonly`: после разрешённой инициализации их нельзя переприсвоить обычными методами экземпляра. Запись подчёркивает присваивание в конструкторе; инициализатор поля при объявлении тоже допустим.

На [00:11:36](https://www.youtube.com/watch?v=IESVXL16OBA&t=696s) второе преимущество — **создание с выводом типа**: `new(...)` может опускать имя типа, когда окружающий контекст его даёт. Упрощённые альтернативы состояния видео:

```csharp
class Stat
{
    public readonly int Attack;
    private int Health;

    public Stat(int attack, int health)
    {
        Attack = attack;
        Health = health;
    }
}

Stat player = new(attack: 7, health: 20);
```

Объявленный тип переменной `Stat` задаёт тип для `new`. Это отличается от `var`, который просит компилятор вывести тип переменной из её инициализатора.

На [00:12:03](https://www.youtube.com/watch?v=IESVXL16OBA&t=723s) и [00:12:13](https://www.youtube.com/watch?v=IESVXL16OBA&t=733s) приватное поле можно инициализировать через конструктор или через фабричные методы, объявленные внутри того же типа. Они работают, потому что код там может писать это поле. На [00:12:20](https://www.youtube.com/watch?v=IESVXL16OBA&t=740s) ограничение остаётся: внешние вызывающие по-прежнему не могут сами присваивать это поле.

На [00:12:27](https://www.youtube.com/watch?v=IESVXL16OBA&t=747s) рассмотрим компромисс между удобством. Без инкапсуляции класс со всеми публичными полями может использовать инициализатор и не нуждаться в написанном пользователем конструкторе. Когда класс не объявляет конструкторов, компилятор предоставляет конструктор без параметров. Такой подход сохраняет удобство инициализации, но отказывается от контролируемой границы доступа.

## Выберите перегрузки конструкторов и именованные фабрики

[00:12:40](https://www.youtube.com/watch?v=IESVXL16OBA&t=760s) **Перегрузка** конструктора — это ещё один конструктор с другим списком параметров. Добавим перегрузку без параметров, чтобы задать нулевые значения по умолчанию, рядом с версией на два параметра. Значения по умолчанию — это нулевые значения, которые поля получают до выполнения тела; явные присваивания делают очевидным намерение создать объект с нулями.

На [00:12:56](https://www.youtube.com/watch?v=IESVXL16OBA&t=776s) сравним создание без параметров с расплывчатой фабрикой `CreateDefault`. На [00:13:13](https://www.youtube.com/watch?v=IESVXL16OBA&t=793s) уберём эту фабрику и используем явный конструктор. Упрощённое итоговое состояние:

```csharp
public Stat()
{
    Attack = 0;
    Health = 0;
}

public Stat(int attack, int health)
{
    Attack = attack;
    Health = health;
}

Stat empty = new();
Stat enemy = new(attack: 7, health: 20);
```

Явная перегрузка без параметров важна, как только объявлен другой конструктор: компилятор больше не предоставляет неявный конструктор без параметров. Любое последующее перезаписывание значений по умолчанию всё равно должно идти через доступные операции; создание объекта не делает приватное здоровье доступным для внешней записи.

На [00:13:20](https://www.youtube.com/watch?v=IESVXL16OBA&t=800s) и [00:13:28](https://www.youtube.com/watch?v=IESVXL16OBA&t=808s) **разрешение перегрузок** выбирает конструктор без параметров при отсутствии аргументов и конструктор с двумя параметрами для этих двух аргументов. Именно количество аргументов различает эти конкретные перегрузки; в общем случае разрешение перегрузок учитывает также типы параметров и другие правила применимости.

На [00:13:45](https://www.youtube.com/watch?v=IESVXL16OBA&t=825s) конструкторы не могут получить произвольное имя вроде `CreateStrong`: имя в их объявлении должно совпадать с типом. На [00:13:59](https://www.youtube.com/watch?v=IESVXL16OBA&t=839s) именованный вариант создания, смысл которого не различается аргументами, всё ещё может использовать фабричную функцию. Конструкторы полезны, но не обязаны заменять каждую возможную фабрику.

## Скопируйте объект тремя равнозначными способами

[00:14:06](https://www.youtube.com/watch?v=IESVXL16OBA&t=846s) **Конструктор копирования** принимает другой объект того же типа и инициализирует из него поля этого объекта. Конструктор `Stat` может читать приватное здоровье другого объекта `Stat`, потому что приватный доступ принадлежит типу.

На [00:14:24](https://www.youtube.com/watch?v=IESVXL16OBA&t=864s) **фабрика копирования** — такая же допустимая обычная функция, возвращающая ново-созданный объект. На [00:14:42](https://www.youtube.com/watch?v=IESVXL16OBA&t=882s) **метод копирования** использует поля текущего объекта как аргументы конструктора. Упрощённое состояние видео, всё объявлено внутри `Stat`:

```csharp
public Stat(Stat other)
{
    Attack = other.Attack;
    Health = other.Health;
}

public static Stat Create(Stat source)
{
    return new Stat(source.Attack, source.Health);
}

public Stat Copy()
{
    return new Stat(Attack, Health);
}
```

На [00:14:54](https://www.youtube.com/watch?v=IESVXL16OBA&t=894s) покажем их применение на игроке:

```csharp
Stat a = new(player);          // Copy constructor.
Stat b = Stat.Create(player); // Copy factory.
Stat c = player.Copy();       // Copy method.
```

На [00:15:09](https://www.youtube.com/watch?v=IESVXL16OBA&t=909s) это взаимозаменяемые варианты дублирования целочисленного состояния этого примера. Каждый создаёт новый объект; изменение его здоровья не меняет здоровье исходного объекта. Это отличается от присваивания `Stat a = player;`, которое копирует ссылку и указывает на тот же объект.

На [00:15:16](https://www.youtube.com/watch?v=IESVXL16OBA&t=916s) автодополнение IDE показывает конструктор копирования, фабрику и метод копирования как доступные альтернативы. Демонстрация устанавливает равнозначность вариантов, а не требование держать все три в каждом классе.

На [00:15:45](https://www.youtube.com/watch?v=IESVXL16OBA&t=945s) конкретный повод — печать текущего здоровья игрока для отладки внутри цикла. ## Управляйте записью сеттером

[00:16:56](https://www.youtube.com/watch?v=IESVXL16OBA&t=1016s) **Сеттер** — операция, сохраняющая переданное значение. Начнём с `SetHealth`, который присваивает свой параметр; на [00:17:03](https://www.youtube.com/watch?v=IESVXL16OBA&t=1023s) добавим **валидацию** — проверку того, что значение удовлетворяет правилу неотрицательного здоровья. На [00:17:15](https://www.youtube.com/watch?v=IESVXL16OBA&t=1035s) каждое обновление, проходящее через этот сеттер, наталкивается на эту проверку.

На [00:17:24](https://www.youtube.com/watch?v=IESVXL16OBA&t=1044s) измените модификатор доступа сеттера независимо от геттера. На [00:17:28](https://www.youtube.com/watch?v=IESVXL16OBA&t=1048s) сделать его приватным запрещает внешние вызовы, но по-прежнему разрешает вызовы из других методов `Stat`. Упрощённое промежуточное состояние:

```csharp
private int Health;

public int GetHealth()
{
    return Health;
}

private void SetHealth(int health)
{
    Debug.Assert(health >= 0);
    Health = health;
}

public void TakeDamage(int damage)
{
    SetHealth(Health - damage);
}
```

На [00:17:41](https://www.youtube.com/watch?v=IESVXL16OBA&t=1061s) замените прямые записи здоровья в классе вызовами сеттера, чтобы и для этих изменений выполнялась валидация. Само по себе определение сеттера не мешает внутреннему коду обойти его, присвоив поле напрямую.

На [00:18:02](https://www.youtube.com/watch?v=IESVXL16OBA&t=1082s) один вызов нанесения урона может вычислить отрицательное здоровье. В версии с утверждением это нарушает контракт и может остановить или уронить отладочный запуск; сама арифметика над отрицательными целыми не является падением C#. На [00:18:15](https://www.youtube.com/watch?v=IESVXL16OBA&t=1095s) **ограничение диапазона** предлагает другую политику: заменять отрицательные результаты нулём вместо их отклонения.

```csharp
private void SetHealth(int health)
{
    if (health < 0)
    {
        health = 0;
    }
    Health = health;
}
```

Ограничение диапазона изменяет входящий параметр перед сохранением. Валидация отклоняет плохие значения или сообщает о них; ограничение диапазона принимает исправленное граничное значение. Это разные политики. Одни лишь утверждения не обеспечивают отклонение в обычной сборке Release.

## Свяжите чтение и запись в свойство

[00:18:29](https://www.youtube.com/watch?v=IESVXL16OBA&t=1109s) **Свойство** связывает связанные операции чтения и записи под одним именем члена. Его **аксессоры**, `get` и `set`, — операции, похожие на методы, а вызывающий код использует синтаксис, похожий на обращение к полю. На [00:18:43](https://www.youtube.com/watch?v=IESVXL16OBA&t=1123s) запись вводит это обычное написание C#: фигурные скобки после типа и имени члена содержат разрешённые операции. Это похоже на объявление поля, но объявляет свойство.

На [00:18:53](https://www.youtube.com/watch?v=IESVXL16OBA&t=1133s) выберем свойство, доступное для внешнего чтения, с записью, ограниченной классом. На [00:19:04](https://www.youtube.com/watch?v=IESVXL16OBA&t=1144s) сделаем доступ на чтение свойства публичным. На [00:19:12](https://www.youtube.com/watch?v=IESVXL16OBA&t=1152s) получается такое разделение разрешений:

```csharp
public int Health { get; private set; }

// Outside Stat:

// player.Health = 0; // Not allowed: the setter is private.
```

Здесь модификатор `public` стоит у свойства; `get` наследует его, а `private set` ограничивает сильнее. На [00:19:21](https://www.youtube.com/watch?v=IESVXL16OBA&t=1161s) аксессоры — полноценные операции, похожие на методы, и могут иметь явные тела.

На [00:19:29](https://www.youtube.com/watch?v=IESVXL16OBA&t=1169s) различайте имена по мере роста кода: методы используют **PascalCase**, как `GetHealth`, а приватное хранилище по соглашению — строчное имя с ведущим подчёркиванием, как `_health`. Свойства тоже обычно используют PascalCase. Эти соглашения помогают читателю узнавать роли, но не определяют разрешения доступа.

## Поймите, что генерирует автосвойство

[00:19:41](https://www.youtube.com/watch?v=IESVXL16OBA&t=1181s) У **автосвойства** пустые `get;` и `set;` просят компилятор предоставить реализацию и скрытое **резервное поле**, хранилище значения свойства. Обновим операцию нанесения урона, чтобы она использовала свойство:

```csharp
public int Health { get; private set; }

public void TakeDamage(int damage)
{
    Health = Health - damage;
}
```

На [00:19:58](https://www.youtube.com/watch?v=IESVXL16OBA&t=1198s) и [00:20:04](https://www.youtube.com/watch?v=IESVXL16OBA&t=1204s) сгенерированный сеттер просто сохраняет переданное значение. Замена прежнего сеттера с проверкой или ограничением диапазона на такой пустой сеттер убирает его собственную логику. Автосвойства не воспроизводят автоматически валидацию удалённого метода.

На [00:20:13](https://www.youtube.com/watch?v=IESVXL16OBA&t=1213s) сгенерированный сеттер приватен, потому что `set` объявлен приватным. На [00:20:17](https://www.youtube.com/watch?v=IESVXL16OBA&t=1217s) внешнее чтение теперь использует `player.Health`, а не `player.GetHealth()`. Сгенерированный геттер — это аксессор, а не исходный метод с именем `GetHealth`.

На [00:20:42](https://www.youtube.com/watch?v=IESVXL16OBA&t=1242s) доступность свойства управляет его методами-аксессорами, если только аксессор не сделан более ограниченным. На [00:20:53](https://www.youtube.com/watch?v=IESVXL16OBA&t=1253s) созданное компилятором резервное поле имеет скрытое имя, которое в этом примере нельзя сослаться в обычном исходном коде. Видимый член — это свойство.

<summary>Гарантирует ли приватный сеттер автосвойства неотрицательное здоровье?</summary>
Нет. Он ограничивает, кто может писать, но разрешённое внутреннее присваивание всё ещё может сохранить отрицательное число. Сохранение прежнего правила требует явного тела сеттера или другой проверяемой операции.
</details>

## Расширьте аксессоры, чтобы вернуть валидацию

[00:21:04](https://www.youtube.com/watch?v=IESVXL16OBA&t=1264s) Вместо скрытого хранилища автосвойства объявите собственное **резервное поле** и напишите явные тела **аксессоров**. На [00:21:18](https://www.youtube.com/watch?v=IESVXL16OBA&t=1278s) и [00:21:20](https://www.youtube.com/watch?v=IESVXL16OBA&t=1280s) развернём `get`, чтобы он возвращал это поле, и `set`, чтобы он его присваивал. На [00:21:25](https://www.youtube.com/watch?v=IESVXL16OBA&t=1285s) неявный параметр сеттера называется `value`: это входящее значение, а не имя свойства. Упрощённая промежуточная реконструкция здоровья:

```csharp
private int _health;

public int Health
{
    get
    {
        return _health;
    }
    private set
    {
        _health = value;
    }
}

public void TakeDamage(int damage)
{
    Health = Health - damage;
}
```

На [00:21:33](https://www.youtube.com/watch?v=IESVXL16OBA&t=1293s) разберём финальное присваивание: его правая часть читает `Health` через `get`, вычитает урон, а левая часть передаёт результат через `set` как `value`. Значит, аксессоры выполняются, хотя место вызова выглядит как операция с полем.

На [00:21:42](https://www.youtube.com/watch?v=IESVXL16OBA&t=1302s) восстановим валидацию в сеттере и проверим `value`, то есть видимый там входящий параметр. Изменение этого аксессора:

```csharp
private set
{
    Debug.Assert(value >= 0);
    _health = value;
}
```

Присваивание в конструкторе через `Health` может использовать тот же сеттер; прямое присваивание `_health` обошло бы его.

[Связанный закоммиченный пример из лабораторной работы](https://github.com/AntonC9018/uniCourse_csharp/blob/19d6c57ba17ef64ef9c65d22808e2c3f682768c2/labs/1_basic/17_encapsulation.md) тоже ставит утверждение в сеттер. Это вспомогательный пример синтаксиса свойств, а не точный боевой исходник. Его упрощённое ядро:

```csharp
set
{
    Debug.Assert(value != "");
    _nameInclude = value;
}
```

Закоммиченный фрагмент лабораторной работы публично открывает своё резервное поле; эту деталь не стоит копировать, если цель — не дать обойти свойство.

На [00:21:50](https://www.youtube.com/watch?v=IESVXL16OBA&t=1310s) свойства инкапсулируют доступ к полям, и здесь они предпочтительнее отдельных методов геттера и сеттера, потому что обе операции носят одно имя свойства. Утверждаете вы или ограничиваете диапазон — остаётся явной политикой внутри аксессора.

## Различайте поля, параметры и свойства

[00:22:02](https://www.youtube.com/watch?v=IESVXL16OBA&t=1322s) Ведущее подчёркивание по соглашению помечает приватное поле. Оно отличает постоянное хранилище от одноимённого параметра, когда код читают отдельно. **PascalCase** пишет каждое слово с заглавной буквы; свойство вроде `Health` и метод вроде `GetHealth` используют этот стиль. Строчный **параметр** вроде `health` или особый `value` сеттера представляет входящие данные.

Упрощённая версия идей конструктора и резервного поля из видео с правильными именами:

```csharp
private int _health;

public Stat(int attack, int health)
{
    Attack = attack;
    _health = health;
}
```

На [00:22:46](https://www.youtube.com/watch?v=IESVXL16OBA&t=1366s) имя служит подсказкой о смысле. Член в PascalCase может быть публичным полем или свойством; только по капитализации нельзя установить, что это. Присваивание выше делает роли явными: `health` — временный вход, `_health` — хранилище объекта. Это иллюстрирует именование, а не валидацию; запись `Health = health` направила бы инициализацию через сеттер свойства.

## Сохраняйте синтаксис использования, добавляя абстракцию

[00:22:53](https://www.youtube.com/watch?v=IESVXL16OBA&t=1373s) Урок не советует публичные поля в классах с инкапсулированным состоянием, но признаёт, что замена ничем не ограниченного публичного поля таким же ничем не ограниченным свойством может не добавить ни валидации, ни поведения. На этом вводном этапе допустимы оба варианта.

На [00:23:07](https://www.youtube.com/watch?v=IESVXL16OBA&t=1387s) поле позже может стать свойством с добавленной логикой, сохранив обычный синтаксис чтения и присваивания. Упрощённые последовательные объявления и неизменный вызывающий код:

```csharp
// Earlier member:
public int Attack;

// Alternative later member:
public int Attack { get; set; }

// Ordinary usage in either version:
enemy.Attack = 7;
Console.WriteLine(enemy.Attack);
```

Это альтернативные объявления, а не два члена, объявляемые вместе. Сохранение имени позволяет оставить обычное использование в исходнике показанным здесь; это не утверждение, что любое использование полей и свойств взаимозаменяемо.

На [00:23:27](https://www.youtube.com/watch?v=IESVXL16OBA&t=1407s) и [00:23:48](https://www.youtube.com/watch?v=IESVXL16OBA&t=1428s) конкретные преимущества полей перед свойствами и наоборот явно отложены: для такого сравнения ещё слишком рано. На [00:24:06](https://www.youtube.com/watch?v=IESVXL16OBA&t=1446s) использование свойства добавляет границу абстракции: чтение вызывает геттер вместо прямого доступа к хранилищу. На [00:24:22](https://www.youtube.com/watch?v=IESVXL16OBA&t=1462s) простой синтаксис места вызова не показывает, является ли член полем или свойством. Это и есть граница показанной здесь эквивалентности.

## Проследите выделение памяти и аргументы конструктора

[00:24:35](https://www.youtube.com/watch?v=IESVXL16OBA&t=1475s) Завершим небольшим разбором конструктора. **Ссылка** идентифицирует объект; запись изображает объекты в **динамической памяти**, а параметры — во **временном хранилище стека**, чтобы объяснить, какие значения переживают вызов. Считайте это концептуальной моделью хранения, а не гарантией точной физической раскладки среды выполнения.

Упрощённая реконструкция состояния видео:

```csharp
class Test
{
    private int data1;
    private int data2;

    public Test(int data1, int data2)
    {
        this.data1 = data1;
        this.data2 = data2;
    }
}

Test t = new Test(data1: 1, data2: 3);
```

Проследите за созданием по порядку:

1. На [00:24:35](https://www.youtube.com/watch?v=IESVXL16OBA&t=1475s) объявление вводит локальную переменную `t`. До завершения её инициализатора она ещё не получила пригодной ссылки.
2. На [00:24:59](https://www.youtube.com/watch?v=IESVXL16OBA&t=1499s) выделяется память под новый объект. Его объявленные целочисленные поля сначала содержат значения по умолчанию, ноль.
3. На [00:25:08](https://www.youtube.com/watch?v=IESVXL16OBA&t=1508s) следующая операция — инициализация конструктором.
4. На [00:25:09](https://www.youtube.com/watch?v=IESVXL16OBA&t=1509s) учтите три концептуальных входа: скрытый получатель `this` плюс два явных аргумента данных. Здесь **два объявленных параметра**, а не три явных параметра.
5. На [00:25:18](https://www.youtube.com/watch?v=IESVXL16OBA&t=1518s) представим получатель и каждый параметр как ячейки временного хранилища. Параметр — временная входная переменная; поле — хранилище, принадлежащее объекту.
6. На [00:25:29](https://www.youtube.com/watch?v=IESVXL16OBA&t=1529s) различайте почти одинаковые имена. В `this.data1 = data1;` `this.data1` выбирает поле объекта, а `data1` без уточнения выбирает параметр, поскольку он затеняет поле.
7. На [00:25:48](https://www.youtube.com/watch?v=IESVXL16OBA&t=1548s) дайте `this` ссылку на новый объект. Получатель неявен; вызывающий код не пишет для него лишний явный аргумент.
8. На [00:26:24](https://www.youtube.com/watch?v=IESVXL16OBA&t=1584s) переданные значения выражения `new` становятся явными параметрами конструктора, готовыми к первому присваиванию.

Поправка о разрешении имён важна: `data1` без уточнения **не** выбирает поле, когда в области видимости есть одноимённый параметр. Запись `data1 = data1;` присвоила бы параметр самому себе и оставила поле без изменений.

## Завершите создание и сохраните ссылку на объект

[00:26:33](https://www.youtube.com/watch?v=IESVXL16OBA&t=1593s) На иллюстрации адресов из записи `this` содержит ссылку на объект с меткой 8000. Проследите за тем же объектом на протяжении присваиваний:

1. На [00:26:33](https://www.youtube.com/watch?v=IESVXL16OBA&t=1593s) прочитайте получатель, хранящийся в `this`.
2. На [00:26:34](https://www.youtube.com/watch?v=IESVXL16OBA&t=1594s) используйте его, чтобы найти поле `data1` объекта и скопировать туда значение первого параметра.
3. На [00:26:34](https://www.youtube.com/watch?v=IESVXL16OBA&t=1594s) используйте тот же получатель, чтобы найти `data2` и скопировать туда значение второго параметра.
4. На [00:26:37](https://www.youtube.com/watch?v=IESVXL16OBA&t=1597s) после завершения инициализации выражение `new` даёт ссылку на новый объект.
5. На [00:26:42](https://www.youtube.com/watch?v=IESVXL16OBA&t=1602s) сохраните эту ссылку в `t`.
6. На [00:26:45](https://www.youtube.com/watch?v=IESVXL16OBA&t=1605s) временное хранилище параметров больше не нужно; инициализированные значения полей остаются в объекте.

Упрощённый итог предыдущего состояния с конструктором:

```csharp
// Constructor body:
this.data1 = data1; // Field gets 1.
this.data2 = data2; // Field gets 3.

// When new Test(1, 3) finishes:
// t holds the reference to the initialized Test object.
```

На [00:26:38](https://www.youtube.com/watch?v=IESVXL16OBA&t=1598s) проясните замечание записи о попытке что-то вернуть: у конструктора C# нет типа возврата, и он не может использовать `return expression;`, чтобы выбрать результат. Результат успешного `new` — ссылка на созданный объект, а не возвращаемое значение конструктора.

Более поздняя произнесённая адресная метка «88000» не означает ещё одно выделение памяти. Важно, что `this` во время инициализации и `t` после неё обозначают один и тот же ново-созданный объект. Числовые метки вроде 8000 и 88000 — это сокращение на схеме, а не буквальные значения, доступные через обычную управляемую ссылку.

Фраза «временные данные стираются» описывает конец их роли в вызове. Это не обещание, что байты надёжно затираются, и не утверждение, что каждый параметр занимает физическую ячейку стека. Объект сохраняет скопированные целочисленные поля независимо от этих временных входов.

<details>
<summary>Почему поля сохраняются после исчезновения параметров конструктора?</summary>
Конструктор скопировал входные значения в собственное хранилище объекта. Локальная переменная сохраняет ссылку на этот инициализированный объект; поля не зависят от того, что переменные-параметры продолжают существовать.
</details>
