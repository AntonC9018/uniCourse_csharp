# От фиксированных операторов к настраиваемым конвейерам

[00:00:00](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=0s) Цель урока — превратить обычную последовательность операторов C# в программу, действия которой можно хранить, переставлять, просматривать и передавать от вызывающего кода. Собака меняет хозяина, получает новое имя и печатается. Прослеживая этот маленький пример через последовательные рефакторинги, мы увидим, зачем нужен каждый новый объект.

Вот словарь терминов, используемых по ходу урока:

- **Паттерн проектирования:** переиспользуемая схема компонентов для целого класса задач. **Порождающие паттерны** организуют создание объектов; **структурные** — их композицию; **поведенческие** — выполнение. **Композиция** означает объединение объектов, в том числе хранение одного объекта внутри другого.
- **Конвейер (pipeline):** упорядоченная последовательность операций. Позже объект `Pipeline` хранит эти операции и выполняет их. **Chain of Responsibility** — связанный паттерн, названный во вступлении; исполнитель этого урока посещает каждый настроенный шаг.
- **Контекст:** общие данные, доступные во время выполнения. Собака и история владения принадлежат этому контексту. Список инструкций и настройки каждого шага имеют отдельные роли.
- **Рефакторинг:** перестройка кода с сохранением задуманного поведения. **Абстракция** позволяет вызывающему коду обращаться к работе по имени; **инкапсуляция** убирает конкретные действия в одну реализацию за этим именем.
- **Локальная функция и захват:** функция, объявленная в области видимости объемлющей функции или точки входа, может использовать локальные переменные этой области. **Операторы верхнего уровня** дают тело точки входа без явного `Main`.
- **Зависимость:** данные или другой объект, необходимые операции. **Адаптер** предоставляет интерфейс, ожидаемый вызывающим кодом, и передаёт управление существующей логике с теми аргументами, которые ей нужны.
- **Интерфейс и полиморфизм:** интерфейс — общий контракт; полиморфизм позволяет использовать через него разные реализации. **Диспетчеризация** выбирает реализацию во время выполнения. Ключевое слово C# `virtual` отдельно разрешает переопределение метода класса.
- **Объект-шаг:** объект, представляющий действие, которое будет выполнено позже. **Конфигурация времени создания** — данные, сохранённые при создании объекта, например выбранный хозяин или имя. **Фабричный метод** создаёт и возвращает настроенный объект.
- **Инспекция (introspection):** рассмотрение шагов конвейера и того, что они о себе сообщают. **Проверка типа** определяет тип объекта. **Лямбда** — короткая функция; здесь она служит **предикатом**, условием, возвращающим true или false.
- **Декоратор или обёртка:** объект, который хранит совместимый шаг, сохраняет его контракт и добавляет поведение вокруг его действия.
- **Модель и синтаксис коллекций:** `sealed` запрещает наследование класса; `required` требует инициализации члена. **Инициализатор объекта** задаёт члены после `new`. `List<T>` — расширяемая коллекция; **new с выводом типа** выводит создаваемый тип из объявления. **Коллекционное выражение**, например `[]`, задаёт содержимое коллекции. **Массив** имеет фиксированную длину; **индексация с нуля** нумерует первый элемент числом 0.
- **Допустимость null и инициализация:** `null` означает отсутствие ссылочного объекта; `Owner?` выражает, что отсутствие допустимо. **Конструктор** инициализирует объект. **Поле только для чтения** можно присвоить при объявлении или в конструкторе, и позже вызывающий код не сможет его переприсвоить. Аксессоры свойств `get`, `set` и `init` управляют чтением, записью и инициализацией.
- **Управляющий синтаксис и вывод:** `foreach` обходит элементы коллекции; `while` повторяет; `switch/case` выбирает ветвь команды; `break` выходит из неё; `return` возвращает результат или завершает точку входа. `static` связывает член с его типом, `public` открывает доступ, `void` означает отсутствие возвращаемого значения. **Интерполяция строк** подставляет значения в текст; **объединение с null** (`??`) задаёт запасное значение при null.

## Создаём данные собаки и хозяина

[00:01:42](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=102s) Начнём с данных, которые будут менять операции: класса `Dog` с именем. [00:01:49](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=109s) **Sealed-класс** запрещает подклассы — это соответствует классу, объявленному `final` в Java. [00:01:52](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=112s) **Обязательный член** делает инициализацию обязательной при создании. Поэтому имя собаки указывается в её **инициализаторе объекта** — фигурных скобках после `new Dog`.

[00:02:04](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=124s) Добавим `Owner` и список прежних хозяев. [Связанный сохранённый код](https://github.com/AntonC9018/uniCourse_csharp/blob/d6e14fd023172f33faba0c4e0be4e8ea62b0ec82/examples/pipeline/Program.cs) содержит оба класса модели; в этой реконструкции начальная подготовка стоит перед объявлениями, чтобы операторы верхнего уровня оставались в допустимой позиции:

```csharp
List<Owner> previousOwners = new List<Owner>();
var dog = new Dog { Name = "Luke" };

sealed class Dog
{
    public required string Name;
    public Owner? Owner = null;
}

sealed class Owner
{
    public required string Name;
}
```

[00:02:26](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=146s) `List<Owner>` — расширяемая коллекция ссылок на хозяев, основанная на массиве. Сравнение со списками Java носит концептуальный характер: `List` в Java — интерфейс, а `ArrayList` — привычная расширяемая реализация поверх массива. `new List<Owner>()` создаёт пустую коллекцию. [00:02:33](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=153s) **New с выводом типа** избавляет от повторения типа, уже указанного слева. Сохранённый контекст позже использует **коллекционное выражение** `[]` для своего пустого списка. Вот эти варианты записи задают пустой список в данном примере:

```csharp
List<Owner> previousOwners = new(); // Тип берётся из объявления.
var owner = new Owner { Name = "Anton" };

previousOwners.Add(owner);
previousOwners.Remove(owner);
```

[00:02:36](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=156s) `Add` добавляет ссылку на хозяина, в том числе хранящуюся в переменной; `Remove` удаляет совпадающий элемент. Список истории хранит хозяев, а не собак.

[00:02:45](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=165s) Создаём именованную собаку без указания владения. [00:02:56](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=176s) **Допустимость null** выражает возможность отсутствия: `Owner?` позволяет полю представлять состояние «нет хозяина». [00:03:07](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=187s) Сравнение с Java требует осторожности: ссылочные переменные Java тоже могут хранить null. При включённом анализе nullable в C# аннотация `Owner?` сообщает компилятору о намерении; она не вводит запрета во время выполнения, который запретил бы `Owner` хранить null. См. [Nullable reference types в C#](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/null-safety/nullable-reference-types) и [ссылочные переменные в Java](https://docs.oracle.com/javase/specs/jls/se25/html/jls-4.html#jls-4.12.2).

[00:03:17](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=197s) Пропуск значения и допустимость null — независимые вещи. У поля хозяина у собаки нет модификатора `required`, поэтому при создании его можно не указывать, и оно останется null. Напротив, `required Owner?` по-прежнему разрешал бы null, но требовал бы явной инициализации. Сам по себе `required` не проверяет переданное значение. [Правила обязательных членов](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/required) отделяют это требование от предупреждений о состоянии null.

## Пишем первую упорядоченную последовательность

[00:03:27](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=207s) Начнём с обычной смены хозяина. [00:03:32](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=212s) Запланированная последовательность такова: назначить хозяина, что-то сделать с собакой, затем назначить другого хозяина. [00:03:38](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=218s) Присваивание меняет поле напрямую. [00:03:44](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=224s) Переименование собаки даёт промежуточную операцию.

[Связанная сохранённая реализация смены владельца](https://github.com/AntonC9018/uniCourse_csharp/blob/d6e14fd023172f33faba0c4e0be4e8ea62b0ec82/examples/pipeline/Program.cs) записывает прежнего хозяина перед заменой. Если развернуть это правило в начальную последовательность, получится так:

```csharp
var owner1 = new Owner { Name = "Anton" };
dog.Owner = owner1;                 // В начале прежнего хозяина нет.
dog.Name = "Lucy";

var owner2 = new Owner { Name = "Alex" };
if (dog.Owner != null)
    previousOwners.Add(dog.Owner);  // Сохраняем Антона перед заменой.
dog.Owner = owner2;
```

[00:03:57](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=237s) Это уже **конвейер** в обычном смысле: упорядоченная последовательность операций. Его состав зафиксирован порядком операторов. [00:04:07](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=247s) В этом примере переменные-хозяева намеренно не выполняют никакой другой роли: они назначаются собаке и сохраняются в истории при замене.

[00:04:12](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=252s) У первого назначения хозяина нет предыдущего хозяина, которого нужно записать. Более поздние замены сохраняют текущего владельца. Это различие снимает путаницу в словах о «добавлении хозяина»: список — это история владения, поэтому в него попадает **уходящий** хозяин, а не приходящий.

[00:04:24](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=264s) Каждая дополнительная замена повторяла бы проверку на null, добавление и присваивание. Такое дублирование усложняет сопровождение правила владения: каждую копию пришлось бы одинаково исправлять. **Рефакторинг** перестроит эту работу в общую реализацию, сохранив задуманное поведение.

## Выделяем локальную операцию смены владельца

[00:04:35](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=275s) **Инкапсуляция** собирает повторяющиеся операторы в одно тело функции. [00:04:37](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=277s) Сначала сделаем её **локальной функцией**, объявленной в объемлющей области точки входа. [00:04:45](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=285s) Благодаря **захвату** она может читать окружающие переменные `dog` и `previousOwners`, поэтому явные параметры для этих зависимостей пока не нужны.

[Связанный сохранённый код](https://github.com/AntonC9018/uniCourse_csharp/blob/d6e14fd023172f33faba0c4e0be4e8ea62b0ec82/examples/pipeline/Program.cs) содержит более позднюю параметризованную версию этого помощника. В реконструкции показана его прежняя локальная форма:

```csharp
void ChangeOwner(Owner? newOwner)
{
    if (dog.Owner != null)
        previousOwners.Add(dog.Owner);
    dog.Owner = newOwner;
}

ChangeOwner(owner1);
dog.Name = "Lucy";
ChangeOwner(owner2);
```

[00:04:53](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=293s) Проверка на null относится к **прежнему текущему хозяину**. Текущее поле и список истории имеют разный смысл: поле говорит, кто сейчас владеет собакой; список записывает хозяев, вытесненных изменениями. Выделенная операция добавляет запись только тогда, когда уходящий хозяин существовал.

[00:05:04](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=304s) Допустимый аргумент null позволяет вызвать `ChangeOwner(null)`, что снимает владение и оставляет собаку без хозяина. Передача null описывает новое состояние; она не означает, что собака уже была без хозяина. Если текущим был Алекс, Алекс сохраняется до очистки поля. Если хозяина не было, запись в историю не добавляется.

[00:05:15](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=315s) Заменим прямые присваивания полей в местах вызова вызовами помощника. [00:05:26](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=326s) **Абстракция** даёт этой работе имя `ChangeOwner`, через которое вызывающий код запрашивает операцию. Инкапсуляция сохраняет конкретные операторы, написанные один раз внутри. [00:05:46](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=346s) Достаточно вызвать это имя; вызывающий код больше не дублирует его тело.

Текущий хозяин — null. История содержит Антона, затем Алекса. Изначальное отсутствие никогда не является записью хозяина, а снятие существующего хозяина всё равно записывает этого уходящего хозяина.

[00:06:55](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=415s) Перенесём последовательность в функцию отдельного класса. **Операторы верхнего уровня** — это операторы вне этих классов, образующие тело точки входа программы. [Связанный сохранённый код](https://github.com/AntonC9018/uniCourse_csharp/blob/d6e14fd023172f33faba0c4e0be4e8ea62b0ec82/examples/pipeline/Program.cs) сохраняет более позднюю `Functions.Pipeline1`; эта миниатюра представляет первое выделение:

```csharp
Functions.Pipeline1(); // Оператор точки входа.

static class Functions
{
    public static void Pipeline1()

        // Создать собаку и её историю.
```

```csharp
{

}
```

```csharp
sealed class Pipeline
{
    public List<IPipelineStep> Steps = new();

    public void Execute(Context context)
    {
        foreach (var step in Steps)
            step.Execute(context);
    }
}

// Внутри Functions:
public static Pipeline CreatePipeline()
{
    var pipeline = new Pipeline();
    pipeline.Steps.Add(new ChangeNamePipelineStep { Name = "Lucy" });
    pipeline.Steps.Add(new PrintDogPipelineStep());
    return pipeline;
}

// У вызывающего кода:
var configured = Functions.CreatePipeline();
configured.Execute(new Context { Dog = new Dog { Name = "Luke" } });
```

## Просматриваем описания и фильтруем по типу

[00:23:21](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1401s) **Инспекция** рассматривает настроенные действия, а не выполняет их. [00:23:24](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1404s) Обход, печатающий типы шагов, показывает, какие объекты присутствуют, но не раскрывает автоматически все их сохранённые настройки.

[00:23:32](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1412s) Чтобы сообщить о настройках, нужен дополнительный метод описания. Сначала его оставляют на будущее, а затем урок реализует минимальную консольную версию. [00:23:47](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1427s) Добавим `Introspect`, чтобы каждый шаг мог описать себя. [00:24:11](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1451s) При преобразовании принтеров скопированный код и имена правятся, включая `PrintOwners` и печать собаки. В сохранённом результате есть два отдельных типа: `PrintOwnersPipelineStep` печатает историю, а `PrintDogPipelineStep` — собаку.

[00:24:20](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1460s) Добавим `Introspect` в интерфейс, чтобы каждая реализация шага обязана была его предоставить. [Связанные сохранённые интерфейс и классы](https://github.com/AntonC9018/uniCourse_csharp/blob/d6e14fd023172f33faba0c4e0be4e8ea62b0ec82/examples/pipeline/Program.cs) показывают этот контракт и разделение принтеров. Этот фрагмент демонстрирует, как настроенное имя становится доступным для осмотра:

```csharp
interface IPipelineStep
{
    void Execute(Context context);
    void Introspect();
}

sealed class ChangeNamePipelineStep : IPipelineStep
{
    public required string Name;

    public void Execute(Context context)
    {
        Functions.ChangeName_Adapter(context, Name);
    }

    public void Introspect()
    {
        Console.WriteLine($"ChangeName({Name})");
    }
}

// Обход для осмотра:
foreach (var step in pipeline.Steps)
    step.Introspect();
```

**Интерполяция строк** использует `$"..."` и фигурные скобки, чтобы подставить значение в вывод. Здесь описание включает выбранное имя.

[00:24:30](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1470s) Это имя — **конфигурация времени создания**. В записи его тоже называют «контекстом», но `Introspect()` в сохранённом дизайне не принимает контекст выполнения. Он может описать переименование до передачи собаки. Описание — это то, что реализация решит раскрыть; осмотр сам по себе не раскрывает все приватные детали.

[00:24:39](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1479s) Поскольку коллекция содержит объекты узнаваемых типов, вызывающий код может удалить все шаги выбранного вида. Тот же связанный исходник сохраняет этот пример как комментарий:

```csharp
pipeline.Steps.RemoveAll(step => step is PrintOwnersPipelineStep);
```

**Проверка типа** `is PrintOwnersPipelineStep` спрашивает, имеет ли объект этот тип. **Лямбда** `step => ...` — короткая функция, используемая как **предикат**: true отбирает запись для удаления. `RemoveAll` удаляет все совпадения, а `RemoveAt` — одну запись по индексу.

[00:24:57](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1497s) Записанная проверка не находит оставшихся шагов `PrintOwners` после фильтрации, даже если их было добавлено несколько. Другие виды шагов остаются. Это подтверждает состав без выполнения действий конвейера.

**Область:** реализация печатает описания в консоль. Обобщённое представление данных шага или более широкий фреймворк инспекции в видео не завершены.

## Настраиваем шаги через ввод в консоли

[00:25:15](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1515s) Начнём с пустого конвейера и будем многократно читать команду из консоли. Известные типы шагов задают небольшой словарь действий, которые можно создавать во время выполнения. [00:25:34](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1534s) Для `ChangeName` читаем вторую строку с выбранным именем и добавляем настроенный шаг переименования. [00:25:43](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1543s) Порядок ввода шагов становится порядком выполнения.

[00:26:03](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1563s) Добавим команду выполнения. [00:26:13](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1573s) Добавим команду осмотра, чтобы пользователь мог изучить накопленные инструкции до их запуска.

[Связанный сохранённый цикл консоли](https://github.com/AntonC9018/uniCourse_csharp/blob/d6e14fd023172f33faba0c4e0be4e8ea62b0ec82/examples/pipeline/Program.cs) включает эти ветви и команду смены владельца. Эта сокращённая реконструкция сохраняет основную настройку и управляющий поток:

```csharp
var pipeline = new Pipeline();

while (true)
{
    Console.Write("Enter step:");
    switch (Console.ReadLine())
    {
        case "ChangeName":
            pipeline.Steps.Add(new ChangeNamePipelineStep
            {
                Name = Console.ReadLine() ?? ""
            });
            break;
        case "PrintDog":
            pipeline.Steps.Add(new PrintDogPipelineStep());
            break;
        case "PrintOwners":
            pipeline.Steps.Add(new PrintOwnersPipelineStep());
            break;
        case "Introspect":
            foreach (var step in pipeline.Steps)
                step.Introspect();
            break;
        case "Execute":
            pipeline.Execute(new Context
            {
                Dog = new Dog { Name = "Luke" }
            });
            break;
        default:
            return;
    }
}
```

`while (true)` повторяет, пока управление не выйдет наружу. `switch` выбирает `case` по значению команды; `break` завершает эту ветвь, а `default` обрабатывает остальные значения. Здесь `return` выходит из точки входа верхнего уровня. `Console.ReadLine()` читает строку и может вернуть null. **Объединение с null**, `??`, подставляет пустую строку в этом случае.

Полный связанный цикл также принимает `ChangeOwner`, читает имя хозяина, создаёт хозяина и сохраняет его на шаге. Каждая команда `Execute` в этой сохранённой версии создаёт свежий контекст и свежую собаку. Это отличается от предыдущего эксперимента, где один и тот же контекст намеренно переиспользовался.

Повторите записанное взаимодействие:

1. [00:26:24](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1584s) Введите `ChangeName`, затем `123`. Шаг сохранит это имя как будущую работу.
2. [00:26:33](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1593s) Введите `PrintDog` и `PrintOwners`, чтобы добавить печатающие действия.
3. [00:26:34](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1594s) Выберите осмотр. Вывод перечислит настроенные шаги, подтвердив, что ввод построил ожидаемую последовательность.
4. [00:26:35](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1595s) Вызовите выполнение, чтобы запустить эти действия в сохранённом порядке.

Цикл команд — небольшая демонстрация, а не полноценная система проверки ввода или сохранения данных. Нераспознанные команды завершают работу в рассмотренном исходнике.

## Вводим зависимость-декоратор

[00:26:43](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1603s) Представление отдельных шагов объектами также позволяет прикрепить дополнительную работу вокруг одного выбранного действия. [00:26:51](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1611s) **Декоратор**, или обёртка, содержит уже совместимый шаг, реализует тот же контракт и добавляет поведение, делегируя исходную работу. В записи предлагается шаг, который печатает описание внутреннего действия и выполняет его.

[00:27:02](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1622s) Внутренний `IPipelineStep` — это **зависимость**: обёртке он нужен для работы, поэтому его нужно передать при создании обёртки. Это **композиция** — объединение объектов, при котором один хранится внутри другого.

[00:27:34](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1654s) Эту зависимость мог бы принять конструктор или поле, доступное для записи. Проектное решение — запретить вызывающему коду менять её впоследствии. [00:27:37](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1657s) В записи рассматривается открытый обязательный член только с геттером как способ разрешить однократную инициализацию. Здесь нужна синтаксическая поправка: обязательному свойству нужен доступный аксессор `set` или `init`; по-настоящему обязательное свойство только с геттером не может быть инициализировано вызывающим кодом. [Правила обязательных свойств](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/required) устанавливают это ограничение.

[Финальный сохранённый декоратор](https://github.com/AntonC9018/uniCourse_csharp/blob/df46c75bc2516786091ed07ebc48fe9c47b461c7/examples/pipeline/Program.cs) использует вместо этого конструктор и открытое поле только для чтения. Этот фрагмент показывает хранение зависимости; методы даёт следующий раздел:

```csharp
// Члены PrintStep_AndExecute_PipelineStep:
public readonly IPipelineStep Step;

public PrintStep_AndExecute_PipelineStep(IPipelineStep step)
{
    Step = step;
}
```

**Конструктор** инициализирует объект при его создании. **Поле только для чтения** допускает присваивание при объявлении или в этом конструкторе и запрещает последующую замену вызывающим кодом. Сохранённое поле открытое, поэтому вызывающий код может его читать. Фиксация ссылки не замораживает содержимое внутреннего объекта.

Аксессор `get` свойства читает значение; `set` разрешает присваивание; `init` разрешает присваивание при инициализации. Свойство только с геттером, инициализируемое в конструкторе, — ещё один способ открыть ссылку только для чтения. Обязательное свойство с `get; init;` допускает настройку через инициализатор объекта; его не следует описывать как член только с геттером или как универсальную гарантию «ровно одного присваивания».

## Уточняем отчётность вокруг выполнения

[00:27:39](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1659s) Ранний черновик выполнения запускает внутренний шаг, а затем описывает обёртку. [00:27:59](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1679s) Следующая правка добавляет также осмотр внутреннего шага перед его запуском. Это последовательные состояния из видео; их не следует путать с сохранённым финальным телом.

[Финальные сохранённые методы декоратора](https://github.com/AntonC9018/uniCourse_csharp/blob/df46c75bc2516786091ed07ebc48fe9c47b461c7/examples/pipeline/Program.cs) сохраняют описание внутреннего шага перед действием, оставляя осмотр обёртки отдельной операцией. Это сравнение суммирует изменение:

```csharp
// Ранний черновик Execute:
Step.Execute(context);
Introspect();

// Следующий черновик добавляет отчёт до действия:
Step.Introspect();
Step.Execute(context);
Introspect();

// Финальное сохранённое тело Execute:
Step.Introspect();
Step.Execute(context);
```

Сохранённый класс реализует общий интерфейс шага так:

```csharp
sealed class PrintStep_AndExecute_PipelineStep : IPipelineStep
{
    public readonly IPipelineStep Step;

    public PrintStep_AndExecute_PipelineStep(IPipelineStep step)
    {
        Step = step;
    }

    public void Execute(Context context)
    {
        Step.Introspect();
        Step.Execute(context);
    }

    public void Introspect()
    {
        Console.WriteLine("PrintName_AndExecute_ThingBelowMe");
        Step.Introspect();
    }
}
```

Выполнение обёртки описывает внутренний шаг, затем передаёт само действие с тем же контекстом. Осмотр обёртки печатает её собственную метку, а затем описывает своё содержимое. Самоописание после действия из раннего черновика в сохранённом методе выполнения отсутствует. Реализация оставляет отчётность простой; более общий дизайн инспекции остаётся за пределами этой демонстрации.

## Компонуем декорированные шаги и наблюдаем их

[00:28:24](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1704s) Создадим обычный печатающий шаг, а затем построим вокруг него обёртку. [Финальная сохранённая композиция](https://github.com/AntonC9018/uniCourse_csharp/blob/df46c75bc2516786091ed07ebc48fe9c47b461c7/examples/pipeline/Program.cs) включает вспомогательный метод и начинается с обёрнутых шагов переименования и печати. Этот сокращённый пример показывает, как можно декорировать любое совместимое действие:

```csharp
IPipelineStep Wrap(IPipelineStep step)
{
    return new PrintStep_AndExecute_PipelineStep(step);
}

var plainPrinter = new PrintDogPipelineStep();
pipeline.Steps.Add(Wrap(plainPrinter));
pipeline.Steps.Add(Wrap(
    new ChangeNamePipelineStep { Name = "Lucy" }));
```

[00:28:44](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1724s) Исполнитель по-прежнему вызывает тот же контракт шага. Когда он встречает обёртку, описание появляется перед исходным действием. [00:28:45](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1725s) Записанное выполнение подтверждает этот порядок: перед печатью идёт лишняя строка описания. Обычный принтер переиспользуется без правок в его реализации.

[00:29:00](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1740s) Обёртка может принять любой `IPipelineStep`, в том числе другую обёртку. Описание «имени» шага не требует, чтобы каждый класс объявлял буквальное поле `Name`; эта реализация использует `Introspect` как контракт описания.

[00:29:17](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1757s) Обёртывание `ChangeName` или `PrintDog` заставляет это действие сообщать о себе помимо своей обычной работы. [00:29:35](https://www.youtube.com/watch?v=X4IDL3CmV-A&t=1775s) Финальный записанный осмотр показывает внешнее действие-отчёт, содержащее свой внутренний шаг. Выполнение включает строку «Выполняю этот шаг». Это русская строка — наблюдение из записи; сохранённый коммит использует английские строки описаний.

<details>
<summary>Чем прежний адаптер отличается от этого декоратора?</summary>

Адаптер устраняет несоответствие: существующие функции принимают отдельные входы, а исполнитель ожидает шаг на основе интерфейса с параметром Context. Декоратор получает уже совместимый шаг и добавляет отчётность, сохраняя этот контракт.

</details>
