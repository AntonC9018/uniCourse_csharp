# Переменные, типы, объекты и ссылки

[00:00:00](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=0s) Этот урок учит предсказывать, что напечатает короткая программа на C#, отслеживая, что хранится в каждой переменной. Начните с одного числа, перезапишите его, а затем постройте модель памяти для чисел и строк. В конце скопируйте одну переменную в другую и спросите, изменяет ли изменение источника также получателя.

Понадобятся следующие термины:

- **Переменная, идентификатор и ячейка памяти:** переменная — именованное место хранения; её идентификатор — имя в программе; ячейка памяти — прямоугольник, которым это хранилище рисуют.
- **Значение и тип:** значение — информация, которая хранится или копируется. Тип задаёт, какие значения допустимы. `int` обозначает целые числа, `double` — числа с плавающей точкой, `string` — текст.
- **Объявление и инициализация:** объявление вводит переменную с её типом и именем; инициализация задаёт её первое значение.
- **Присваивание и чтение:** присваивание записывает значение в переменную; чтение получает её текущее значение. Присваивание использует `=`, причём получатель стоит слева.
- **Инструкция и литерал:** инструкция — команда в программе; литерал записывает значение прямо в исходном коде, например `123` или `"hello"`.
- **Компилятор и среда выполнения:** компилятор проверяет и переводит исходный код; среда выполнения поддерживает работающую программу и управляет её памятью.
- **Стек и куча:** стек — область временной памяти, используемая в рисунках этого урока для ячеек локальных переменных. Куча — динамическая память для объектов, в записи она тоже называется *куча*.
- **Объект, адрес и ссылка:** объект — экземпляр, содержащий данные; адрес описывает место в памяти; ссылка позволяет программе добраться до объекта. На рисунках ссылки изображаются как адреса объектов.
- **Тип значения и ссылочный тип:** переменная типа значения содержит само значение; переменная ссылочного типа содержит ссылку на объект.
- **Класс:** разновидность типа, экземплярами которой являются объекты; переменные классовых типов хранят ссылки на эти экземпляры.
- **Вывод в консоль и вызов функции:** вывод в консоль — текст, отображаемый программой. Вызов функции просит выполнить операцию; `Console.WriteLine(...)` выводит текстовое представление переданного значения и завершает строку.

Ниже в уточнениях, а не как дополнительные темы видео, встречаются ещё несколько терминов для точности:

- **Неизменяемость:** символы уже существующего строкового объекта изменить нельзя.
- **Сборка мусора:** автоматическое управление памятью, которое может освобождать неиспользуемые объекты и перемещать выжившие, обновляя ссылки.
- **Интернирование строк:** повторное использование строкового объекта для совпадающего текста; литералу необязательно выделять новый объект при каждом выполнении своей строки.
- **Указатель и запись адреса:** указатель представляет адрес памяти. Оператор `&` в C# берёт адрес переменной по правилам указателей; это не универсальный способ получить управляемую ссылку на строковый объект.
- **Упаковка и перегрузка:** упаковка преобразует значение типа значения в объект, содержащий копию. Перегрузка — версия функции, принимающая определённые типы параметров.

Связанная практика: в [лабораторной по переменным](../../../labs/1_basic/04_variables.md) нужно проследить хранение, присваивания и вывод. Там есть и темы за пределами этой записи.

**Границы урока:** цель — понять чтение, перезапись и обычное присваивание. Запись использует упрощённую картинку со стеком и кучей и откладывает внутренности вывода и более сложное поведение ссылок. Точной зафиксированной копии демонстрационной программы из записи в проверенном чекауте найти не удалось. Примеры ниже — упрощённые реконструкции со ссылками на состояния видео; пример из лабораторной явно помечен как связанный. Комментарии с выводом — предсказания по показанным инструкциям, а не утверждения о новом локальном запуске.

## Чтение и перезапись переменной

[00:00:12](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=12s) Начните с объявления переменной с именем `A` и инициализации её значением `123`. **Объявление** вводит тип и идентификатор; **инициализация** задаёт переменной первое значение. Здесь `int` — тип для целых чисел, `A` — идентификатор, а `123` — целочисленный **литерал**, значение, записанное прямо в исходнике.

Упрощённое начальное состояние из видео:

```csharp

Console.WriteLine(A); // 123
```

Точка с запятой завершает каждую **инструкцию**, то есть команду. В **вызове функции** `Console.WriteLine(A)` в скобках находится значение для печати. Запись `A` здесь **читает** текущее значение переменной, а не печатает букву A.

[00:00:27](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=27s) Результат — `123`, потому что именно это значение лежит в `A`, когда выполняется инструкция печати. Само по себе объявление переменной не даёт никакого вывода в консоль.

[00:00:30](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=30s) Чтобы та же переменная хранила другое число, добавьте **присваивание**: имя слева, `=` посередине, новое значение справа. Прежнее значение перезаписывается.

Упрощённое изменённое состояние из видео:

```csharp
int A = 123;
A = 234;
Console.WriteLine(A); // 234
```

[00:00:41](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=41s) Следующий вывод — `234`. Присваивание заменяет хранимое значение; оно не дописывает цифры и не сохраняет прежнее число для следующей печати.

[00:00:45](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=45s) Главная идея: переменная хранит **значение** определённого **типа**. Тип описывает допустимый вид информации, поэтому последующие операции используют её предсказуемо. **Компилятор**, который проверяет и переводит исходный код, следит за совместимостью типов.

[00:00:52](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=52s) Есть две операции, которые нужно различать:

1. Прочитать текущее значение, используя имя переменной.
2. Обновить его, присвоив этому имени совместимое новое значение.

[00:01:14](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=74s) **Стек** — временная память; **куча** — динамическая память, её называют *heap* или *куча*. ## Строковая переменная ссылается на объект

[00:03:21](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=201s) **Ссылочный тип** меняет то, что попадает в переменную. Его значение — ссылка, через которую программа добирается до объекта. Содержимое объекта живёт отдельно от ячейки переменной.

[00:03:33](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=213s) У `string` текст принадлежит **объекту** — экземпляру, содержащему данные символов. **Строковый литерал** записывает текст между двойными кавычками. Кавычки — синтаксис исходного кода, а не часть текста.

Упрощённое состояние после объявления строки:


Этот рисунок не означает свежее выделение памяти при каждом выполнении литерала. **Интернирование строк**, способное переиспользовать объект для совпадающего текста, — деталь реализации за пределами демонстрации. См. [документацию среды выполнения об интернировании строк](https://learn.microsoft.com/en-us/dotnet/api/system.string.intern).

## Объекты, адреса и ссылки

[00:04:04](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=244s) **Адрес** обозначает место в памяти. Схема задаёт каждому объекту расположение и этим расположением объясняет, как его можно найти.

[00:04:14](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=254s) **Ссылка** — это значение, позволяющее программе добраться до объекта. Присваивание строки строковой переменной сохраняет эту ссылку; оно не копирует символы объекта в собственную ячейку переменной.

Упрощённая модель адресов для предыдущего объявления:

```text

```

Подобные `Rhello` — символические ссылки, а не измеренные машинные адреса. Хотя запись считает место объекта фиксированным, управляемые объекты могут перемещаться. **Сборка мусора** — автоматическое управление памятью объектов в среде выполнения — обновляет ссылки при уплотнении памяти. Эта подробность выходит за рамки видео, но не даёт истолковать схему как гарантию вечных адресов. См. [управление памятью в .NET](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/fundamentals).

## Выполним два объявления

[00:06:38](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=398s) В пошаговом рисунке ячейка переменной появляется, когда доходят до её объявления. Это модель выполнения, а не гарантия того, что физическое выделение в стеке происходит ровно на той строке исходника. Более позднее присваивание в `b` опирается на её прежнее объявление.

[00:06:46](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=406s) Проследите первое объявление и инициализацию из предыдущего примера:

1. Введите `a`, чей тип допускает ссылки на строковые объекты.
2. Изобразите начальный текст, `"привет"` в этой реконструкции, как объект в динамической памяти.
3. Положите ссылку на этот объект, названную `Rfirst`, в `a`.

Промежуточное состояние:

```text
a: Rfirst  ---->  "привет"
```

[00:07:06](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=426s) Обычные инструкции в этом примере выполняются сверху вниз. Каждый шаг начинается с состояния, оставшегося после предыдущего шага.

[00:07:17](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=437s) Второе объявление вводит `b` и инициализирует её ссылкой на объект, представляющий `"Hello 1"`. Назовём эту ссылку `Rsecond`:

```text
a: Rfirst   ----> "привет"
b: Rsecond  ----> "Hello 1"
```

Есть две ячейки переменных. В модели есть также два объекта с разным содержимым. Это независимые факты: ячейки переменных и объекты нужно считать отдельно.

## Копируем ссылку

[00:08:01](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=481s) Следующая инструкция — **присваивание**, запись в переменную-получатель. Чтение переменной справа даёт её текущее значение. Для строковой переменной этим значением является ссылка.

Упрощённое состояние после третьей строки:

```csharp
b = a;
// a: Rfirst -> "привет"
// b: Rfirst -> "привет"
```

[00:08:05](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=485s) Теперь обе ячейки содержат `Rfirst`. Прежняя ссылка в `b` перезаписана; присваивание ни копирует данные символов в новый объект, ни делает `b` вторым именем ячейки `a`.

**Связанный зафиксированный учебный пример**, не точное состояние из записи, найден в проверенной [лабораторной по переменным на 52a1e276](https://github.com/AntonC9018/uniCourse_csharp/blob/52a1e27639e0b78319180bee2b1aa492667d8488/labs/1_basic/04_variables.md). Его краткая версия делает то же правило копирования наглядным:

```csharp
string a = "1";
string b = a;
a = "2";
Console.WriteLine(a); // 2
Console.WriteLine(b); // 1
```

<details>
<summary>Предскажите: после b = a перезапись a перезапишет ли b?</summary>

Нет. Присваивание — это разовое копирование хранимой ссылки. У переменных остаются отдельные ячейки, даже когда эти ячейки содержат ссылки на один и тот же объект.
</details>

## Заменяем только ссылку в a

[00:08:16](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=496s) Следующая инструкция присваивает `a` значение `"Hello 2"`. Запись рисует новый объект по другому адресу, а затем перезаписывает ссылку в `a` ссылкой на этот объект.

Упрощённое состояние после четвёртой строки:

```csharp
a = "Hello 2";
// a: Rnew   -> "Hello 2"
// b: Rfirst -> "привет"
```

Проследите изменение по шагам:

1. Получите ссылку, представляющую новую строку.
2. Запишите её в `a`, заменяя там `Rfirst`.
3. Оставьте `b` без изменений, в ней по-прежнему `Rfirst`.

Это изменение ссылки переменной, а не изменение символов прежнего объекта. **Неизменяемость** означает, что эти символы нельзя изменить в существующем строковом объекте. См. [справку C# о строке](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/reference-types). Повторное использование литерала может влиять на момент выделения памяти, но не на результат присваивания.

## Вывод через ссылку b

[00:08:49](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=529s) Финальный вызов читает текущую ссылку `b` и передаёт её операции записи в консоль.

Упрощённое конечное состояние:

```csharp
Console.WriteLine(b); // привет в явной реконструкции выше
```

[00:09:09](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=549s) Операция вывода использует эту ссылку, чтобы получить текстовое представление объекта. Она печатает строку, а не символический адрес и не более поздний текст из `a`.

Результат — исходный текст, который `a` хранила в момент выполнения `b = a`. Если этот исходный текст — `"Hello 1"`, результат — `Hello 1`. При явной инициализации `"привет"` выше это `привет`. Начальный `"Hello 1"` получателя не может пережить перезапись присваиванием `b = a`. Именно это различение делает пример и его предсказанный вывод согласованными.

[00:09:33](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=573s) Точный механизм внутри функции вывода сознательно отложен. На этом этапе полезное наблюдение такое: вывод следует сохранённой ссылке `b`.

## Сравним типы значений и ссылочные типы

[00:09:41](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=581s) Теперь уберём отдельные строковые объекты с рисунка и воспользуемся целыми числами. **Тип значения** хранит своё значение прямо в переменной; **ссылочный тип** содержит ссылку на объект. Поэтому трассировке с целыми числами нужно меньше ячеек.

[00:10:05](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=605s) Инициализируйте целочисленную переменную значением `204`:

```csharp
int a = 204;
// Модель: ячейка a содержит 204.
```

[00:10:24](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=624s) Значение `204` кладётся в саму ячейку. Нет отдельно нарисованного объекта, адрес которого пришлось бы копировать в эту переменную.

[00:10:40](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=640s) Вот почему `int` — **тип значения**: чтение переменной даёт её целочисленное значение.

[00:10:58](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=658s) **Ссылочный тип**, такой как `string`, наоборот, предоставляет содержащуюся в нём ссылку. Обычное присваивание копирует эту ссылку.

[00:11:05](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=665s) **Класс** определяет тип, экземплярами которого являются объекты. Переменная классового типа тоже хранит ссылку на экземпляр, а не его содержимое напрямую.

[00:11:18](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=678s) В этом обычном примере с целочисленным объявлением для `204` не требуется отдельный объект в куче. Это утверждение о примере, а не универсальное правило о том, что целые числа никогда не могут быть частью объектов в куче. Определение касается хранимых значений, а не обязательной физической области памяти. [Документация C# о типах значений](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/value-types) задаёт то же различие.

## Копируем целые числа и меняем источник

[00:11:28](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=688s) Перестроим демонстрацию с двумя переменными, используя целочисленные значения. Первое объявление вводит `A` и записывает в неё `204`.

[00:11:41](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=701s) Второе объявление вводит отдельную ячейку `B` и записывает в неё `305`.

Упрощённая целочисленная демонстрация:

```csharp
int A = 204;
int B = 305;
B = A;
A = 607;
Console.WriteLine(B); // 204
```

[00:11:54](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=714s) Выполните копирование, прочитав значение справа и записав его в переменную слева:

1. Изначально `A` содержит `204`, а `B` содержит `305`.
2. После `B = A` обе содержат `204`. Прежнее `305` в `B` заменено.
3. После следующего присваивания меняется только та переменная, чьё имя стоит слева.

[00:12:04](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=724s) Расшифровка описывает следующее изменение как `A = 607`. [00:12:14](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=734s) Новое значение заменяет прежнее в `A`. Промежуточное состояние теперь — `A: 607` и `B: 204`. Если бы вместо этого `607` записывалось в `B`, это была бы другая программа с другим выводом.

[00:12:22](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=742s) Правило копирования то же, что и для строк: один раз скопировать текущее содержимое источника в получателя. Здесь содержимое — целочисленные значения; раньше это были ссылки. Ни та, ни другая операция не создаёт долговременной связи между ячейками переменных.

<details>
<summary>Предскажите: что окажется в B, если A присвоить 607 до B = A?</summary>

B получил бы 607, потому что присваивание читает значение источника в момент копирования. В показанном порядке B получает 204 и сохраняет его.
</details>

## Вывод и границы урока

[00:12:30](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=750s) Запись откладывает более сложный механизм, стоящий за выводом. [00:12:34](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=754s) Она также заглядывает вперёд, к более поздней работе со ссылками, где различение хранимых значений и хранимых ссылок становится важным.

[00:12:37](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=757s) Объяснение набрасывает вывод целого числа как преобразование значения в динамический объект. [00:12:49](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=769s) Затем этот объект передаётся дальше, и его тип проверяется. Это вводное изложение из записи, а не требование, чтобы каждый вызов с целым числом сначала упаковывал свой аргумент.

**Уточнение для точности, за пределами показанного механизма:** **упаковка** преобразует значение типа значения в объект, содержащий копию, как описано в [документации C# об упаковке](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing). Однако **перегрузка** — это версия функции, принимающая конкретные типы параметров, а у [`Console.WriteLine` есть перегрузка для целого числа](https://learn.microsoft.com/en-us/dotnet/api/system.console.writeline#system-console-writeline(system-int32)). Обычный целочисленный аргумент может использовать её напрямую.

[00:12:53](https://www.youtube.com/watch?v=wjsV9CvZfGI&t=773s) Наблюдаемое правило остаётся простым: печатается значение, которое сейчас хранится в `B`. В явной целочисленной реконструкции это `204`.

Урок закладывает объявления, типизированное хранение, чтение, перезапись, обычное копирование значений и копирование ссылок. Внутренности вывода и сложное поведение ссылок остаются на потом. Сборка мусора, повторное использование литералов, правила указателей и выбор перегрузки, упомянутые выше, — уточнения для точности, а не дополнительные процедуры реализации, преподаваемые в видео.
