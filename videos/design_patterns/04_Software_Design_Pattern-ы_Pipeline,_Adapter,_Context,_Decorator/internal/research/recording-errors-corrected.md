# Recording statements corrected in the note

Each item is a claim in the video that the note contradicts. Timestamps are `internal/transcript.md` moments for upload `X4IDL3CmV-A`. The corrections were written by the `english_authoring` runs (475 and 499).

- 00:03:07 (t=187) — "in Java there is no way to declare a type that may be null": wrong. Java references are nullable by default; C# `Owner?` is an annotation for compiler analysis and does not make a non-nullable reference incapable of being null at run time. The note keeps this clarification next to the `Owner?` introduction.
- 00:17:05 (t=1025) — "in Java you must write override, in C# you don't": wrong on both halves. `@Override` is optional in Java for an interface implementation, and run-time interface dispatch in C# needs neither `override` nor `virtual` on the implementing method. The note marks the comparison as inaccurate and separates it from class-method overriding.
- 00:20:43 / 00:20:52 (t=1243 / 1252) — C# methods non-virtual by default vs Java dynamic dispatch: accurate for *class inheritance*, and the note keeps the recording's point while adding that it does not govern the interface dispatch used for the steps. Supporting detail from the saved code: `Pipeline` is `sealed` and its `Execute` is not `virtual`.
- 00:27:54 (t=1674) — "make it `required` with a get-only accessor so it can be assigned once": does not compile; a `required` property must have a `set` or `init` accessor (checked 2026-10-10, <https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/required>). What the recording actually does at `df46c75bc2516786091ed07ebc48fe9c47b461c7` is a constructor plus a `public readonly IPipelineStep Step` field, which is the rule the note recommends. A `required` property with `get; init;` compiles but still permits object-initializer assignment, so it does not express "set once" either.
