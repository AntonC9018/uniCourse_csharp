# Строки: от объектов к форматированным сообщениям

[00:00:00](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=0s) Этот урок связывает текст, который вы пишете на C#, с объектами, кодами символов и байтами файла, которые его представляют. Начните с неизменяемой строки, посмотрите на один символ как на число, восстановите этот символ, изучите окончания строк и кодировки и, наконец, соберите сообщения с помощью интерполяции и конкатенации.

Термины, которые понадобятся по ходу изложения:

- **Строка, объект, ссылка и динамическая память:** `string` — это объект, содержащий текст; ссылка идентифицирует этот объект. Динамическая память — управляемое хранилище, в котором живут такие объекты.
- **Неизменяемость, изменяемый массив символов:** содержимое неизменяемого объекта не может измениться после создания. Изменяемый `char[]` — это массив, элементы-символы которого можно заменять.
- **Символ, глиф и `char`:** символ — это элемент текста; глиф — его нарисованная форма. `char` в C# — это тип значения, хранящий одну 16-битную единицу кода UTF-16, а не ссылку на объект.
- **Литерал, компилятор и индексатор:** литерал записывает значение прямо в исходном коде; компилятор превращает исходный код в исполняемый. Индексатор использует квадратные скобки, чтобы прочитать элемент по позиции.
- **`int`, `float`, статический тип и перегрузка:** `int` хранит 32-битное целое, а `float` — число с плавающей точкой. Статический тип выражения — это его тип, известный на этапе компиляции. Перегрузки — это разные версии метода или оператора, выбираемые по участвующим типам.
- **Числовое преобразование, приведение и усечение:** преобразование меняет тип значения; неявному преобразованию приведение не нужно, а явное приведение записывает целевой тип в скобках. Усечение здесь означает потерю битов, не помещающихся в более узкий тип, при преобразовании без проверки. «Без проверки» (unchecked) означает, что преобразование вне диапазона допускается и может отбросить биты; проверенное (checked) преобразование, наоборот, его отклоняет.
- **Кодировка, код, ASCII, Unicode и кодовая точка:** кодировка задаёт, как представлен текст. Код символа — это соответствующее ему число. ASCII — это 7-битный набор кодов 0–127. Unicode присваивает символам разных языков кодовые точки — числовые идентификаторы.
- **Бит, байт, десятичная и шестнадцатеричная системы, дамп байтов:** бит — двоичная цифра; байт содержит восемь битов. Десятичная система — основание десять, шестнадцатеричная — основание шестнадцать. Дамп байтов показывает содержимое файла числами, обычно в шестнадцатеричном виде.
- **Управляющая последовательность, управляющий символ, LF, CR и CRLF:** управляющая последовательность записывает в исходном коде специальное значение, например `\n`. Управляющие символы влияют на обработку текста, а не рисуют глиф. Line Feed (LF) — код 10; Carriage Return (CR) — код 13; CRLF — это двухсимвольная последовательность CR, затем LF.
- **BOM и порядок байтов:** Byte Order Mark — необязательный маркер кодировки в начале файла. Порядок байтов описывает порядок байтов в многобайтовых единицах.
- **UTF-8, UTF-16, UTF-32, единица кода, BMP и суррогатная пара:** эти кодировки Unicode используют единицы по 8, 16 и 32 бита. Единица кода — одна такая единица хранения. Базовая многоязычная плоскость (Basic Multilingual Plane, BMP) содержит кодовые точки до U+FFFF; дополнительным кодовым точкам нужна пара единиц UTF-16, называемая суррогатной парой.
- **Alt-код и перенос по словам:** Alt-код — это зависящая от платформы клавиатурная комбинация ввода символа. Перенос по словам визуально складывает длинную строку в редакторе, не вставляя перевод строки.
- **Интерполяция и выражение:** интерполяция подставляет вычисленные значения в строку с помощью `$` и фигурных скобок. Выражение — это исходный код, вычисляющий значение.
- **Конкатенация, `string.Concat`, статический метод и снимок:** конкатенация соединяет фрагменты текста. `string.Concat` — статический метод, вызываемый у типа, а не у экземпляра, который соединяет свои аргументы. Снимок хранит текст, полученный в момент создания.
- **.NET, `Console.WriteLine` и `ToString`:** .NET предоставляет среду выполнения и библиотеки, используемые здесь. `Console.WriteLine` печатает значение вместе с окончанием строки. `ToString` получает текстовое представление значения.

## Строки и неизменяемые объекты

[00:00:00](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=0s) Строка — это объект, представляющий последовательность символов. Её содержимое — это текст: даже число, встроенное в сообщение, в итоге становится символами. Представление строки как массива символов удобно для чтения отдельных позиций, но `string` — это не `char[]`.

[00:00:23](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=23s) Важное различие — изменяемость. Изменяемый массив символов позволяет заменить элемент; неизменяемая строка никогда не позволяет заменить символ внутри существующего объекта. [00:00:32](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=32s) Объект строки живёт в динамической памяти. [00:00:39](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=39s) Переприсваивание переменной заменяет её ссылку, а не содержимое объекта.

Упрощённая версия начального состояния объектов из [00:00:32](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=32s):

```csharp
string a = "Hello world";
string original = a;
a = "Another message";
// original всё ещё ссылается на "Hello world".

char[] letters = { 'H', 'i' };
letters[0] = 'B';          // Допустимо: массив изменяемый.
// original[0] = 'B';      // Ошибка: индексатор строки доступен только для чтения.
```

Здесь объект — это хранимая строка, а ссылка — это связь переменной с ней. После переприсваивания `a` указывает на другую строку; `original` по-прежнему указывает на первую. Именно это различие объяснит, почему соединённый текст не отслеживает последующие изменения переменных.

<details>
<summary>Если две переменные ссылаются на одну строку, изменит ли переприсваивание одной из них другую?</summary>

Нет. Переприсваивание меняет только ссылку этой переменной. Общий неизменяемый объект остаётся прежним.

</details>

[00:02:53](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=173s) Теперь развернём эксперимент: начнём с целого числа 72 и получим соответствующий ему символ.

```

Приведение записывает целевой тип в скобках перед выражением. `int` занимает 32 бита; `char` — 16. Число 72 помещается в оба. [00:03:24](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=204s) Числовое сужение отличается от приведений ссылочных типов, о которых шла речь раньше: при преобразовании без проверки лишние биты могут быть отброшены. Эта потеря и есть называемое здесь **усечение**. Проверенные преобразования могут отклонять значения вне диапазона, поэтому утверждение «приведения всегда отбрасывают информацию» слишком широкое.

[00:03:43](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=223s) Урок откладывает подробные правила усечения; этот пример использует значение в диапазоне и задаёт направление преобразования. [Справочник C# по типу char](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/char) подтверждает двухбайтовое представление и направления преобразований.

## Перевод строки внутри литерала

Console.WriteLine(lfCode);   // 10
```

[00:06:43](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=403s) Печать LF как `char` даёт разрыв строки, а сохранение его как целого печатает 10. Помните, что `WriteLine` добавляет и собственное окончание; поэтому печать LF через него может создать лишнюю пустую строку.

## Окончания строк на разных платформах

[00:06:55](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=415s) Окончание строки — это не всегда один символ. В Linux по соглашению используется LF, а в Windows — CRLF: Carriage Return, код 13, затем Line Feed, код 10. Файлы могут использовать любое из соглашений независимо от операционной системы, в которой их открывают.

Упрощённое сравнение окончаний строк [00:06:55](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=415s):

```csharp
string linuxEnding = "\n";     // Один символ: 10.
string windowsEnding = "\r\n"; // Два символа: 13, затем 10.
```

Здесь `\r` — управляющая последовательность для CR. Добавление её перед `\n` меняет фактическое содержимое строки. Одиночная последовательность `\n` остаётся LF; она не превращается автоматически в два символа только потому, что программа запущена в Windows.

## Чтение байтов текстового файла и BOM

[00:07:16](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=436s) Текстовый файл хранит закодированные байты, а не нарисованные буквы. Дамп байтов — это режим редактора, который показывает эти числовые байты напрямую. Чтобы связать его с предыдущим экспериментом с символами:

1. [00:07:16](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=436s) Откройте текстовый файл в режиме, отображающем значения байтов.
2. [00:07:33](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=453s) Определите систему счисления, прежде чем интерпретировать показанное значение.
3. [00:07:55](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=475s) Найдите перевод строки в начале показанного текста.
4. [00:08:01](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=481s) Учтите необязательный BOM UTF-8, прежде чем определять, где начинается текст.
5. [00:08:22](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=502s) Декодируйте `0D 0A` как CR, за которым следует LF.

[00:07:33](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=453s) **Уточнение о системе счисления:** показанное `45` — шестнадцатеричное, а не десятичное 45. Шестнадцатеричное `0x45` равно 69 в десятичной системе и соответствует прописной `E`. Строчная `e` — шестнадцатеричное `65`, десятичное 101. Обозначение буквы в транскрипте не должно приводить вас к отождествлению строчной `e` с 45.

Упрощённая последовательность байтов для состояния проверки файла [00:08:22](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=502s) делает это различие явным:

```text
EF BB BF | 0D 0A | 45
UTF-8 BOM | CR LF | E

0D hexadecimal = 13 decimal
0A hexadecimal = 10 decimal
45 hexadecimal = 69 decimal
```

[00:07:55](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=475s) Первые символы текста в этой демонстрации — это окончание строки, но они не обязаны быть первыми физическими байтами. [00:08:01](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=481s) Byte Order Mark (BOM) UTF-8 — это необязательный трёхбайтный префикс `EF BB BF`. Он сдвигает позицию, с которой начинаются байты текста.

[00:08:16](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=496s) BOM раскрывается как **Byte Order Mark**, а не «Mask». Порядок байтов — это порядок байтов, образующих многобайтовую единицу; название отражает применение маркера с кодировками, чувствительными к порядку байтов. В UTF-8 выбора порядка байтов нет; там BOM служит сигнатурой кодировки. [00:08:22](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=502s) Следующие байты `0D 0A` — это двухсимвольное окончание строки Windows в этом файле UTF-8. [Объяснение BOM от Unicode](https://www.unicode.org/faq/utf_bom.html#BOM) проясняет это различие.

## Unicode UTF-8 и двухбайтовый char

[00:08:41](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=521s) Русские буквы не попадают в диапазон 0–127 ASCII. [00:08:53](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=533s) Unicode предоставляет кодовые точки — числовые идентификаторы — для символов многих языков. Кодовая точка Unicode и байты, которыми её кодируют, — связанные, но разные понятия.

[00:09:04](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=544s) UTF-8 представлена как обычно используемая кодировка наряду с UTF-16 и UTF-32. Все они представляют один и тот же текст Unicode единицами разного размера. [00:09:09](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=549s) Символы ASCII сохраняют свои однобайтовые значения ASCII **в UTF-8**; это утверждение об одном байте нельзя переносить на UTF-16 или UTF-32. [00:09:20](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=560s) Другие символы UTF-8 занимают два, три или четыре байта.

Следующее сравнение — упрощённый пример представления для обсуждения кодировок [00:09:49](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=589s), а не отдельная закоммиченная программа:

```text
Character      UTF-8 bytes      UTF-16 code unit
H              48               0048
Ж              D0 96            0416
```

Таблица использует шестнадцатеричную запись. У `H` поэтому по-прежнему десятичный код 72, хотя его байт UTF-8 в дампе записан как `48`.

[00:09:49](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=589s) Байт содержит восемь битов. Наименьшая единица UTF-8 — один байт; UTF-16 — шестнадцать битов, то есть два байта. Даже буква ASCII занимает одну двухбайтовую единицу UTF-16. [00:10:10](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=610s) Компромисс по размеру зависит от текста: многие символы BMP, занимающие три байта UTF-8, занимают два байта UTF-16. Символы вне BMP занимают четыре байта и в UTF-8, и в UTF-16; UTF-32 использует четыре байта на кодовую точку, поэтому это не универсальный способ сэкономить место. [Сравнение кодировок от Unicode](https://www.unicode.org/faq/utf_bom.html) даёт правила об одном–четырёх байтах, одной–двух единицах и одной 32-битной единице.

[00:10:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=626s) Это возвращает нас к `char`: это ровно одна единица кода UTF-16, занимающая два байта. BMP, то есть Базовая многоязычная плоскость (Basic Multilingual Plane), охватывает кодовые точки до U+FFFF. Символ BMP, такой как `Ж`, помещается в один `char`; дополнительной кодовой точке нужна суррогатная пара — две единицы кода UTF-16, — и она не может быть представлена одним полным символом в одном `char`. Поэтому «один символ» — полезное начальное описание для этих примеров, но не гарантия для всего текста Unicode. [Определение char в C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/char) описывает модель единиц кода.

[00:09:14](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=554s) Урок не реализует кодировщики и не объясняет их битовые алгоритмы. Практическая граница — различать код символа, его единицы UTF-16 в памяти и его закодированные байты в файле.

## Построение сообщения с помощью интерполяции

[00:11:30](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=690s) Следующая задача — подставлять изменяющиеся значения в читаемый текст, не соединяя каждый фрагмент вручную. **Интерполяция строк** позволяет это: нужно поставить `$` непосредственно перед открывающей двойной кавычкой и поместить выражения в фигурные скобки.

Следуйте построению:

1. Начните с фиксированного сообщения о возрасте, например `"My Age is 12"`.
2. [00:11:39](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=699s) Держите возраст в переменной и замените записанное число на `{age}` внутри интерполированного литерала.
3. [00:11:46](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=706s) Напечатайте сообщение. Записанный результат — `My Age is 12`.
4. [00:12:04](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=724s) Дополните текст строкой `Hello My name is {name}`, подставляя имя в эту позицию.
5. [00:12:29](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=749s) Используйте внутри скобок выражение вроде `h + 10`, когда подставляемое значение должно быть вычислено.

Упрощённый код сообщения о возрасте [00:11:39](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=699s):

```csharp
int age = 12;
string message = $"My Age is {age}";
Console.WriteLine(message); // My Age is 12
```

[00:11:55](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=715s) Интерполяция вычисляет и форматирует значение в составе одного общего сообщения. Обычный текст литерала копируется в результат, а фигурные скобки отмечают выражение, значение которого становится текстом.

Упрощённое состояние с именем и выражением [00:12:04](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=724s), с расширением выражением на [00:12:29](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=749s):

```csharp
string name = "Alex"; // Иллюстративное имя.
int h = 12;
string greeting = $"Hello My name is {name}. My Age is {h + 10}";
Console.WriteLine(greeting);
// Hello My name is Alex. My Age is 22
```

Выражение вычисляет значение: в этом примере `h + 10` даёт 22, и это значение подставляется. Последний вывод — предсказанный результат примера; записанный тест с возрастом выше и есть продемонстрированный результат.

[00:12:20](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=740s) **Уточнение о переносе по словам:** перенос по словам визуально складывает длинную строку в редакторе и не добавляет перевод строки в строку. Транскрипт прямо различает перенесённое отображение и настоящий разрыв строки. Пробелы и другой текст литерала остаются в результате, а явный `\n` создаёт настоящий LF. Обычные строковые литералы в кавычках не могут просто содержать неэкранированный физический перевод строки в исходном коде. Здесь используется обычная интерполированная форма, описанная в [справочнике C# по интерполяции](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/tokens/interpolated).

Нет. Выражение вычисляется в момент создания строки. Чтобы включить новый возраст, постройте сообщение заново.

## Соединение строк и сохранение снимка

[00:12:47](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=767s) **Конкатенация** соединяет существующие фрагменты текста. Статический метод `string.Concat` принимает строковые аргументы и возвращает их объединённый текст. «Статический» означает, что метод вызывается у `string`, а не у конкретного экземпляра строки.

1. [00:12:47](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=767s) Вызовите `string.Concat` с первой и второй строками.
2. [00:12:59](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=779s) Напечатайте результат: в записанном тесте видно первый ввод, сразу за ним второй.
3. [00:13:12](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=792s) Подумайте, остаётся ли результат связанным с переменными.
4. [00:13:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=806s) Переприсвойте первую переменную. Ранее соединённый текст остаётся неизменным.
5. [00:13:44](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=824s) Добавьте `", "` ещё одним аргументом, чтобы вставить разделитель.
6. [00:14:02](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=842s) Сравните такое построение с интерполяцией.
7. [00:14:09](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=849s) Замените явный вызов перегруженным строковым оператором `+`.

Упрощённые состояния начального соединения и переприсваивания [00:12:47](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=767s) и [00:13:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=806s):

```csharp
string a = "Hello";
string b = "World";
string c = string.Concat(a, b);
Console.WriteLine(c); // HelloWorld

a = "Changed";
Console.WriteLine(c); // По-прежнему HelloWorld
```

[00:13:12](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=792s) Снимок хранит текст, полученный в момент построения. `Concat` получает ссылки на текущие строковые объекты, а не продолжающуюся связь с переменными `a` и `b`. [00:13:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=806s) В этом примере из двух непустых строк метод строит новый объект, содержащий сначала символы первого объекта, затем символы второго. Переприсваивание `a` меняет её ссылку, а не исходную строку и не результат соединения.

Упрощённое изменение с разделителем [00:13:44](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=824s), снова с исходными вводами:

```csharp
string a = "Hello";
string b = "World";
string explicitJoin = string.Concat(a, ", ", b);
string interpolated = $"{a}, {b}";
string withPlus = a + ", " + b;
Console.WriteLine(explicitJoin); // Hello, World
```

[00:14:02](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=842s) И интерполяция, и явный вызов `Concat` — допустимые способы построить этот текст. [00:14:09](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=849s) Для строк перегруженный оператор `+` означает конкатенацию, а не численное сложение. [00:14:28](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=868s) Компилятор может превратить это выражение из трёх строк в вызов `string.Concat` с тремя операндами. Именно это объясняет равный результат в данном примере; это не обещание, что любое строковое выражение или форма интерполяции даёт идентичные скомпилированные инструкции.

## Превращение значения в текст с помощью ToString

[00:14:36](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=876s) Объекты .NET наследуют `ToString` — метод, получающий их текстовое представление. [00:14:41](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=881s) Такие значения, как `int`, `char` и `float`, могут использовать его, когда явно требуется строка.

Упрощённое конечное состояние преобразования [00:14:41](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=881s):

```csharp
int age = 12;
char initial = 'H';
float value = 1.5f;
string ageText = age.ToString();       // "12"
string initialText = initial.ToString(); // "H"
string valueText = value.ToString();   // Форматирование зависит от среды.
Console.WriteLine(age);               // Явный ToString не нужен.
```

Здесь `ToString` производит текст, в отличие от приведения `'H'` к `int`, которое даёт числовой код 72. Суффикс `f` записывает литерал типа `float`.

[00:14:44](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=884s) Явное преобразование полезно, когда другой операции требуется `string`. Печать обычно его не требует: у `Console.WriteLine` есть перегрузки для распространённых типов значений и перегрузка `object` для остальных объектов. Метод выбирает подходящую перегрузку и печатает представление. [API WriteLine](https://learn.microsoft.com/en-us/dotnet/api/system.console.writeline) описывает эти варианты. Итоговая граница урока — базовое представление и построение сообщений, а не собственное форматирование или реализация этих методов библиотеки.
