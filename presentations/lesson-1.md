# Начнём с обычных случаев

```csharp
Between(15, 10, 20); // true: явно внутри
Between(5, 10, 20);  // false: ниже интервала
Between(25, 10, 20); // false: выше интервала
```

Операция проверяет, находится ли значение между двумя границами. Вот реализация, используемая в этих примерах:

```csharp
static bool Between(int value, int min, int max)
{
    if (min > max)
        throw new ArgumentException("Bounds are reversed.");

    bool result = value >= min && value <= max;
    return result;
}
```

Обе границы включены. При перепутанных границах выбрасывается исключение.

<!--
Заметки для преподавателя · 2 мин.

«Пятнадцать внутри интервала; пять и двадцать пять — снаружи. Реализация проверяет обе границы и объединяет результаты проверок. А перепутанные границы она отклоняет, выбрасывая исключение. Теперь мы точно видим, что делает эта версия.

Но тому, кто вызывает функцию, видны только её имя и аргументы. Поймёт ли он из этого, включены ли границы? Запомните этот вопрос — к нему вернёмся при разборе следующих вызовов».
-->

# Покажем роли аргументов и поведение границ

**Интерфейс** (interface): то, как другой код взаимодействует с операцией.
**Реализация** (implementation): код, который её выполняет.

<div class="grid grid-cols-2 gap-6">

<div>

Неясные роли:

```csharp
Between(10, 10, 20); // Включена ли нижняя граница?
Between(20, 10, 20); // Включена ли верхняя граница?
Between(15, 20, 10); // А если границы перепутаны?
```

В `Between(10, 10, 20)` то, что числа повторяются, не объясняет их роли. Именованные аргументы делают роли явными:

```csharp
Between(value: 10, min: 10, max: 20);
```

</div>

<div>

Именованные константы объясняют, что означают эти границы в приложении:

```csharp
const int MinimumAllowedTemperature = 10;
const int MaximumAllowedTemperature = 20;
int measuredTemperature = 10;

bool allowed = Between(
    value: measuredTemperature,
    min: MinimumAllowedTemperature,
    max: MaximumAllowedTemperature);
```

</div>

</div>

Имена аргументов объясняют роль каждого параметра. Имена констант объясняют, почему взяты именно эти значения. Но ни имена аргументов, ни имена констант пока не сообщают, включены ли границы.

Сигнатура показывает, как вызывать функцию, но раскрывает не всё её поведение.

<!--
Заметки для преподавателя · 2 мин.

«У обеих десяток разные роли: одна — измерение, другая — нижняя граница. Именованные аргументы позволяют увидеть это, не заглядывая в порядок параметров. Константы поясняют смысл чисел в терминах приложения: это разрешённые температуры, а не произвольные числа.

Реализацию мы видели, поэтому знаем, что равенство допускается. Но одно имя Between этого не проясняет. Следующее изменение сообщит об этом прямо в месте вызова.

Интерфейс — это то, как мы взаимодействуем с чем-то. Сюда входят имена функций и параметры; это не только объявление C#-интерфейса».
-->

# Сформулируем контракт, а имя пусть помогает

**Контракт** (contract): что вызывающие должны соблюсти и на что могут полагаться.

```csharp
BetweenInclusive(value: 10, minInclusive: 10, maxInclusive: 20); // true
BetweenInclusive(value: 20, minInclusive: 10, maxInclusive: 20); // true
BetweenInclusive(value: 25, minInclusive: 10, maxInclusive: 20); // false
```

Для этой функции контракт такой:

- Границы должны быть упорядочены: `minInclusive <= maxInclusive`.
- Обе границы включены.
- Функция возвращает значение, показывающее, находится ли значение внутри интервала.
- Она не меняет внешнего состояния.

```csharp
bool BetweenInclusive(int value, int minInclusive, int maxInclusive);
```

<!--
Заметки для преподавателя · 3 мин.

«Контракт говорит, что нужно передать и что ожидать в ответ. Здесь имена аргументов выделяют значение и обе включительные границы. Десять и двадцать включены, а двадцать пять — снаружи. Границы должны быть упорядочены; как функция проверяет это требование — на следующем слайде».

Для такой крошечной операции контракт почти такой же длины, как реализация. Контракт легко проверить; он не снижает сложность существенно. Два сравнения прямо в коде могут быть вполне разумным решением.

Остальные аспекты контракта разберём на подходящих примерах. Упорядоченность результата покажем на примере удаления дубликатов, а требуемый порядок вызовов — на примере настройки парсера. Вопросы владения ресурсами здесь не нужны.
-->

# Проверяем вход либо фиксируем уже установленное допущение

<div class="grid grid-cols-2 gap-6">

<div>

Граница, которая по контракту должна отклонять неверные значения:

```csharp
if (minInclusive > maxInclusive)
    throw new ArgumentException("Bounds are reversed.");
```

</div>

<div>

Вспомогательный метод для случая, когда вызывающий код уже обеспечил выполнение условия:

```csharp
Debug.Assert(minInclusive <= maxInclusive);
```

</div>

</div>

Публичная точка входа обычно проверяет данные. Внутренний помощник может с помощью `assert` проверять условие, выполнение которого уже обеспечил вызывающий код.

`Debug.Assert` проверяет допущение при отладке; аргументы он не исправляет. В обычной сборке Release эта проверка отсутствует. Если функция обещает отклонять перевёрнутые границы во время выполнения, оставляйте проверку с `throw`.

<!--
Заметки для преподавателя · 3 мин.

«Допустим, min равен двадцати, а max — десяти. Assert обратит наше внимание на эту ошибку при отладке. Он не меняет числа местами, а в обычной сборке Release вызов assert вообще отсутствует.

Если функция обещает выбрасывать исключение при перевёрнутых границах, нужна явная проверка из примера выше. Если каждый вызывающий уже обеспечил упорядоченность границ, внутренний помощник может использовать assert, чтобы поймать ошибку программирования, вместо повторной проверки во время выполнения.

Закрытый доступ сам по себе — не гарантия. Нужно показать, где аргументы были проверены или корректно сконструированы. Короткая проверка может остаться прямо здесь; вынос её в отдельную функцию не обязательно сделает код понятнее».

[Sources]
- https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.debug.assert
-->

# Полезная абстракция прячет существенную операцию

**Абстракция** (abstraction): вид или интерфейс, показывающий выбранные свойства и операции и позволяющий не думать об остальных деталях.

```csharp
RemoveDuplicates(new[] { "Ann", "Bob", "Ann" });
// ["Ann", "Bob"]

RemoveDuplicates(new[] { "Ann", "Bob" });
// ["Ann", "Bob"]
```

Контракт: сохранить каждое имя один раз, в порядке первого появления. Имена сравнивать порядково. Вход не менять.

Что вызывающему больше не нужно реализовывать?

<!--
Заметки для преподавателя · 3 мин.

Предполагаем, что вход и строки в нём — не null. Порядковое сравнение покажите на дополнительном примере: ["Ann", "ann"] сохраняет оба.

Вызывающему нужен смысл удаления дубликатов, а не выбор структуры данных или алгоритма обхода. Теперь покажем функцию, чей контракт существенно проще реализации.

Функция одного применения всё равно может оправдывать себя. Повторное использование — одна из выгод абстракции, а не её определение.
-->

# Вызывающий и реализация работают на разных уровнях

**Уровень абстракции** (abstraction level): объём деталей реализации, с которым работает кусок кода. Более высокоуровневая операция избавляет вызывающего от её низкоуровневых шагов.

<div class="grid grid-cols-2 gap-6">

<div>

Вызывающий:

```csharp
var uniqueNames = RemoveDuplicates(names);
```

Вызывающий просит уникальные имена.

</div>

<div>

Одна из реализаций:

```csharp
static IReadOnlyList<string> RemoveDuplicates(
    IReadOnlyList<string> names)
{
    var seen = new HashSet<string>(
        StringComparer.Ordinal);
    var unique = new List<string>();
    foreach (var name in names)
    {
        if (seen.Add(name))
            unique.Add(name);
    }
    IReadOnlyList<string> result = unique;
    return result;
}
```

Реализация работает со множеством, выполняет обход и накопление.

</div>

</div>

<!--
Заметки для преподавателя · 4 мин.

Разберите ["Bob", "Ann", "Bob"]. Результат — ["Bob", "Ann"]. Предварительная сортировка нарушила бы заявленную гарантию порядка.

Объясните только нужную операцию HashSet.Add: она сообщает, новый ли это элемент. Реализация самого множества прячет дальнейшие детали. Уровни абстракции относительны.

Вид входа «только для чтения» выражает, что операция лишь читает коллекцию. Объясните тип как вид для чтения и получения количества, не углубляясь здесь в реализацию итераторов и вопросы владения. Создаётся новый список-результат.

Последняя локальная переменная введена по соглашению преподавателя для отладки: так результат удобно проверить в отладчике до возврата. Простой однострочный метод может оставаться методом с телом-выражением.
-->

# Смена записи — ещё не сокрытие реализации

Одно значение, разная запись:

```csharp
int a = 255;
int b = 0xFF;
```

<div class="grid grid-cols-2 gap-6">

<div>

Более высокоуровневая операция:

```csharp
var unique = RemoveDuplicates(names);
```

</div>

<div>

Низкоуровневый шаг внутри неё:

```csharp
if (seen.Add(name))
    unique.Add(name);
```

</div>

</div>

Полезный уровень избавляет вызывающего от деталей. Одно лишь другое имя даёт очень мало.

<!--
Заметки для преподавателя · 2 мин.

Единой нумерации уровней абстракции нет. Этот вызов находится выше по уровню, чем реализация на основе множества и цикла. Само множество — абстракция над хранением и механизмами поиска.

BetweenInclusive может чуть иначе выражать намерение, чем два сравнения, но её реализация и так проста. Не приписывайте каждой функции одинаковую пользу.

Компиляция — ещё одна знакомая связь: операции исходного языка реализуются более низкоуровневыми инструкциями. Перевод между представлениями не обязательно ведёт вверх по уровню.

# Имена выражают смысл в системе

**Семантическое значение** (semantic meaning) — то, что значение или операция значит в системе: что представляет, измеряет или сообщает.

<div class="grid grid-cols-2 gap-6">

<div>

Расплывчатые имена:

```csharp
int right = 18;
bool indicator = true;
```

</div>

<div>

Имена со смыслом приложения:

```csharp
int rightSensorTemperature = 18;
bool temperatureWithinAllowedInterval = true;
```

</div>

</div>

Что измеряет `right`? О чём сообщает индикатор?

`Right` может быть осмысленной физической позицией среди показаний датчиков. В другом контексте это просто расплывчатый ярлык. `TemperatureWithinAllowedInterval` фиксирует факт приложения. Оба хранятся в обычных типах C#, но имена сообщают разные знания.

Имя сообщает о намерении; оно не гарантирует его соблюдения. Поле `temperatureWithinAllowedInterval` всё равно нужно корректно вычислить.

<!--
Заметки для преподавателя · 2 мин.

«Тип int говорит, какие значения можно хранить. Температура ли восемнадцать, количество или позиция — он не говорит. Часть этого смысла даёт имя.

Right — не обязательно плохое имя. В объекте Readings с датчиками Left, Center и Right физические позиции могут быть вполне ясны. Вне этого контекста rightSensorTemperature сообщает больше.

Имена булевых переменных различаются иначе. Indicator почти ничего не говорит о смысле true. TemperatureWithinAllowedInterval фиксирует сообщаемый факт. Это имя знает о температурном правиле нашего приложения. Код, устанавливающий этот факт, нужно разместить там, где находится это правило.

Более описательное имя само по себе не создаёт более высокий уровень абстракции. Оно помогает понять, что значит существующее значение».
-->

# Нормализуем представление интервала

**Нормализация** (normalization): привести эквивалентные входы к одному согласованному представлению.

Для целочисленных интервалов храним включительное начало и исключительный конец. Выбор границ влияет только на создание интервала.

<div class="grid grid-cols-2 gap-6">

<div>

```csharp
var interval = Interval.Create(
    min: 10, max: 20,
    minBoundary: Boundary.Inclusive,
    maxBoundary: Boundary.Exclusive);
// Хранится как [10, 20).

interval.Contains(15); // true
interval.Contains(25); // false
interval.Contains(10); // true
interval.Contains(20); // false
```

</div>

<div>

Эти входы представляют одни и те же целые числа и хранят одни границы:

| Входной интервал | Нормализованное хранение |
| --- | --- |
| [10, 20) | [10, 20) |
| [10, 19] | [10, 20) |
| (9, 20) | [10, 20) |
| (9, 19] | [10, 20) |

</div>

</div>

<!--
Заметки для преподавателя · 4 мин.

«Включительная граница означает, что граница разрешена. Исключительная — что нет. Каждая строка здесь содержит целые числа от десяти до девятнадцати.

Для исключённого начала сдвиньтесь вперёд к следующему целому числу. Для включённой границы сдвигаемся вперёд к первому целому вне интервала. После этого объекту больше не нужно помнить флаги границ.

Это работает, потому что мы имеем дело с целыми числами. Добавление единицы не сохранило бы смысл интервала с плавающей точкой».
-->

---

# Инвариант сохраняет нормализованные границы корректными

**Инвариант** (invariant): условие, которое тип устанавливает при создании и сохраняет своими операциями.

Здесь: `StartInclusive <= EndExclusive`. Равные границы — пустой интервал.

<div class="grid grid-cols-2 gap-6">

<div>

```csharp
public readonly struct Interval
{
    public long StartInclusive { get; }
    public long EndExclusive { get; }

    private Interval(
        long startInclusive, long endExclusive)
    {
        StartInclusive = startInclusive;
        EndExclusive = endExclusive;
    }
    // Дальше — фабрика и Contains.
}
```

</div>

<div>

Отклонив перевёрнутые границы и неверные значения перечисления, фабрика нормализует их:

```csharp
long startInclusive = (long)min
    + (minBoundary == Boundary.Exclusive ? 1 : 0);
long endExclusive = (long)max
    + (maxBoundary == Boundary.Inclusive ? 1 : 0);

// Все пустые интервалы — как [0, 0).
if (startInclusive >= endExclusive)
    return default;

var result = new Interval(startInclusive, endExclusive);
return result;
```

</div>

</div>

<!--
Заметки для преподавателя · 4 мин.

«Фабрика один раз проверяет вход и преобразует его. Каждая последующая операция может полагаться на упорядоченные нормализованные границы. Ошибка создания выявляется здесь, рядом с причиной, а не распространяется с неверным значением по программе.

Входные данные публичного метода имеют тип int. Внутри используем long, чтобы включительное int.MaxValue могло стать исключительной границей на единицу больше без переполнения. Приведение происходит до сложения.

Интервал без целых чисел внутри становится пустым интервалом [0,0). Тогда и значение по умолчанию — корректный пустой интервал. Полная фабрика, включая проверки, — в эталонной реализации.

`readonly struct` удерживает эти значения вместе без отдельного объекта в куче на каждый интервал. Свойства только для чтения не дают вызывающим менять одну границу независимо».
-->

# Инкапсуляция держит трактовку границ внутри интервала

**Инкапсуляция** (encapsulation): тип держит представление закрытым и открывает только разрешённые вызывающим операции.

<div class="grid grid-cols-2 gap-6">

<div>

Добавьте этот метод внутрь `Interval`:

```diff
+ public bool Contains(int value)
+ {
+     bool result = value >= StartInclusive
+         && value < EndExclusive;
+     return result;
+ }
```

</div>

<div>

Вызывающие используют операцию:

```csharp
bool allowed = interval.Contains(reading);
```

</div>

</div>

`Contains` использует одни и те же два сравнения для любого интервала. Исходный выбор границ он не проверяет.

<!--
Заметки для преподавателя · 4 мин.

«Для [10,20) пятнадцать удовлетворяет обоим сравнениям. Двадцать не проходит второе. Один и тот же метод используем, даже если вызывающий исходно передал (9,19]. Фабрика уже преобразовала этот вход при создании.

Любая функция, получающая Interval, может полагаться на корректность его границ. Она не повторяет проверку и не толкует заново флаги границ. Это знание принадлежит Interval.

Знаки «плюс» отмечают добавленный код. Временная переменная result позволяет проверить ответ в точке останова до возврата».
-->

# Локальные рассуждения опираются на контракты зависимостей

**Локальные рассуждения** (local reasoning): понимание куска кода по его собственной логике и контрактам того, что он использует.

```csharp
var unique = RemoveDuplicates(names);
ShowNames(unique);
```

Для входа `["Bob", "Ann", "Bob"]` показ получает `["Bob", "Ann"]`.

Чтобы понять этот код, нужно знать:

- Что возвращает `RemoveDuplicates` и меняет ли он вход.
- Что `ShowNames` делает с результатом.

Алгоритм удаления дубликатов и реализацию показа знать не нужно.

# Вызывающий не должен перечислять все поля

```csharp
record struct Readings(int Left, int Center, int Right);
```

<div class="grid grid-cols-2 gap-6">

<div>

Внутри обновления экрана:

```csharp
bool allowed = interval.Contains(readings.Left)
    && interval.Contains(readings.Center)
    && interval.Contains(readings.Right);
SetIndicator(allowed);
```

</div>

<div>

Внутри обработки тревоги:

```csharp
bool allowed = interval.Contains(readings.Left)
    && interval.Contains(readings.Center)
    && interval.Contains(readings.Right);
if (!allowed)
    SoundAlarm();
```

</div>

</div>

Добавление датчика означает, что нужно вспомнить каждый список полей.

<!--
Заметки для преподавателя · 3 мин.

У этих трёх значений разные физические позиции, но операция применяется ко всем трём одинаково. Экран и тревога не должны каждый перечислять представление.

Новое поле может не нарушить компиляцию обоих фрагментов, хотя ни один его не проверяет. Попросите студентов найти дублирующееся знание, а не просто посчитать повторы строк.

Не вводите для этой задачи массивы, индексацию, LINQ или абстракции итераторов. Именованной операции достаточно для первого урока.
-->

# Положим по-полевую операцию в одно место

```csharp
static bool AllWithin(Readings readings, Interval interval)
{
    bool result = interval.Contains(readings.Left)
        && interval.Contains(readings.Center)
        && interval.Contains(readings.Right);
    return result;
}
```

<div class="grid grid-cols-2 gap-6">

<div>

Экран:

```csharp
bool allowed = AllWithin(readings, interval);
SetIndicator(allowed);
```

</div>

<div>

Тревога:

```csharp
if (!AllWithin(readings, interval))
    SoundAlarm();
```

</div>

</div>

Помощник владеет перечислением полей. Оба вызывающих формулируют операцию одним вызовом.

<!--
Заметки для преподавателя · 3 мин.

Оставьте фиксированный struct. Новый контейнер или итератор для демонстрации улучшения не понадобился. Помощник может находиться рядом с типом Readings или в смежном модуле операций; физическое место менее важно, чем владение этой зависимой от представления операцией.

Добавление датчика всё равно потребует обновить AllWithin. Ответственность централизована, а не волшебно устранена. Для существующей коллекции равнозначных показаний ту же операцию мог бы реализовать обычный цикл. Представление в виде коллекции — отдельное решение.

Одного совпадения типов полей мало для обоснования: CustomerId, Age и RetryCount — все целые, но одного осмысленного множества измерений не образуют.
-->

<!--

# Используем вид параметра под задуманный доступ

Чтение коллекции:

```csharp
IReadOnlyList<string> RemoveDuplicates(IReadOnlyList<string> names);
```

Намеренное изменение коллекции:

```csharp
void SortInPlace(List<string> outNames)
    => outNames.Sort(StringComparer.Ordinal);
```

```csharp
IReadOnlyList<string> names = new List<string> { "Bob", "Ann" };
// names.Add("Eve"); // Не компилируется: здесь нет Add.
```

Сигнатура должна ясно показывать разрешённый доступ.

<!--
Заметки для преподавателя · 3 мин.

Изменение — поддерживаемое проектное решение, а не дефект по умолчанию. Используйте имя операции и интерфейс параметра, сообщающие, что может измениться. Префикс outNames — соглашение преподавателя об именовании намеренно записываемых параметров; это не модификатор out языка C#.

IReadOnlyList ограничивает изменение коллекции через этот вид. Он не гарантирует глубокую неизменяемость произвольных элементов, исключительного владения или снимка, который никто другой не изменит. Здесь строки избавляют от второго обсуждения об изменяемых элементах.

На следующем слайде — короткий конкретный пример, почему вид и лежащий под ним объект различаются. Не вводите оговорку как необъяснённую терминологию владения.
-->

# Две ссылки видят одно изменение

```csharp
var owner = new List<string> { "Bob", "Ann" };
IReadOnlyList<string> readOnlyView = owner;

SortInPlace(owner);

Console.WriteLine(readOnlyView[0]); // Ann
```

Вид «только для чтения» не может сортировать список, но видит изменение владельца.

Параметр «только для чтения» ограничивает то, что разрешено принимающему коду. Разделяемый объект он не замораживает.
