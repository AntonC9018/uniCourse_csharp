# Назначение и словарь

[00:00:00](https://www.youtube.com/watch?v=mj771Sd298c&t=0s) Научитесь читать и проектировать функцию через то, что должен знать её вызывающий код, что она обещает и что скрывает. Продвинутые лабораторные предполагают [redacted] навыки и предварительное знакомство с архитектурными идеями, такими как абстракция, связанность, инварианты и интерфейсы. Этот урок применяет эти идеи через проверку диапазона, удаление дубликатов и проверку показаний датчиков; это не введение в программирование на C# с нуля.

Используемый ниже словарь:

- **Интерфейс, сигнатура и прототип:** видимые вызывающему коду имя, тип возврата, а также имена и типы параметров операции. Здесь «интерфейс» не означает конкретно объявление `interface` в C#.
- **Реализация:** инструкции, выполняющие операцию. **Параметр** — именованный вход в объявлении; **аргумент** — значение, переданное при вызове.
- **Интервал и границы:** диапазон между нижней и верхней границами. **Включённая** граница принадлежит интервалу; **исключённая** — нет. `[a,b]` включает обе границы; `[a,b)` исключает верхнюю.
- **Именованный аргумент:** синтаксис C# `parameterName: value`, указывающий получающий параметр. **Именованная константа** даёт фиксированному значению осмысленное имя; **магическая константа** — литерал, назначение которого не объяснено.
- **Контракт:** то, что вызывающий код должен передать и на что может рассчитывать. **Контракт входа**, или **предусловие**, задаёт обязанности вызывающего кода; **контракт выхода** задаёт гарантии операции, включая допустимые эффекты.
- **Внешнее состояние и побочный эффект:** данные или наблюдаемая активность за пределами возвращаемого значения; их изменение, включая вывод на консоль, — побочный эффект.
- **Проверка (guard):** проверка, защищающая предусловие. **Утверждение (assertion)**, такое как `Debug.Assert`, проверяет предположение для этапа разработки. **Символ компиляции DEBUG** управляет включением таких вызовов утверждений; обычная **сборка Release** их не содержит.
- **Публичный API и исключение об аргументе:** API — это интерфейс, предлагаемый другому коду; публичный API библиотеки обязан учитывать вызывающий код, находящийся вне контроля автора. Исключение об аргументе сообщает о некорректных аргументах во время выполнения. **NuGet** распространяет пакеты библиотек .NET.
- **Удаление дубликатов, или дедупликация:** сохранение одного вхождения каждого различного значения по заданному правилу равенства.
- **Связанность (coupling):** зависимость одной части программы от другой; здесь она названа как предварительный контекст, а не разбирается как отдельная тема.
- **Абстракция:** осмысленная операция или модель данных, позволяющая её пользователю не обращать внимания на детали реализации. **Уровень абстракции** описывает, какую часть нижележащего механизма обрабатывает данный фрагмент кода.
- **HashSet, List и компаратор:** множество отслеживает различные элементы, список накапливает упорядоченную последовательность, а компаратор задаёт равенство или порядок. **Порядковое (ordinal)** сравнение строк использует значения символов и различает регистр; **OrdinalIgnoreCase** регистр игнорирует.
- **Семантическое именование:** имя значения или операции отражает её смысл в программе.
- **Нормализация:** приведение разных представлений одного смысла к единой внутренней форме.
- **Инвариант:** условие, установленное при создании и сохраняемое каждой операцией в течение всего времени жизни объекта.
- **Фабрика, приватный конструктор и свойство только для чтения:** фабрика создаёт проверенные объекты; приватный конструктор ограничивает прямое создание; свойство только для чтения открывает чтение, не открывая сеттер.
- **Инкапсуляция:** операции, зависящие от представления, и создание объектов остаются под контролем типа, наружу открывается только тот доступ, который нужен вызывающему коду.
- **Локальное рассуждение:** понимание функции по её собственной логике, её явным входам и контрактам вызываемых ею операций.
- **Косвенность (indirection):** достижение действия через другое имя или вызов с добавлением уровня, за которым может понадобиться проследить.
- **Зависимость, конфигурация и глобальное состояние:** зависимость — то, что нужно операции; конфигурация задаёт настройки; глобальное состояние доступно без передачи в качестве аргумента.
- **Мутация и операция на месте:** мутация изменяет существующие данные; операция на месте записывает в переданный объект, а не создаёт независимую замену.
- **Представление только для чтения или span:** интерфейс входа, предоставляющий чтение, но не запись через это представление. Он не «замораживает» объект, который другая ссылка всё ещё может изменить.
- **Ссылка и псевдоним:** ссылка идентифицирует объект; псевдоним — другая ссылка на тот же объект. Копирование ссылки не копирует содержимое объекта.

## Сформулируйте контракт входа и выхода

[00:03:18](https://www.youtube.com/watch?v=mj771Sd298c&t=198s) **Интерфейс** — это то, что пользователь знает, не читая инструкции тела; **реализация** — это сами инструкции. [00:03:42](https://www.youtube.com/watch?v=mj771Sd298c&t=222s) **Контракт** — это всё, на что вызывающий код может рассчитывать при вызове операции. [00:03:55](https://www.youtube.com/watch?v=mj771Sd298c&t=235s) В текущем вызове включаемость минимума и максимума остаётся невысказанной частью этого контракта.

[00:04:07](https://www.youtube.com/watch?v=mj771Sd298c&t=247s) Измените имя функции и имена параметров так, чтобы семантика границ стала видимой. [Связанная презентация о включающем контракте](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#3-state-the-contract-and-make-the-name-help) допускает равные границы; реконструкция здесь сохраняет более строгое предусловие записи `minInclusive < maxInclusive`:

```csharp
static bool BetweenInclusive(
    int value, int minInclusive, int maxInclusive)
{
    // Контракт входа: minInclusive < maxInclusive.
    return value >= minInclusive && value <= maxInclusive;
}

BetweenInclusive(value: 10, minInclusive: 10, maxInclusive: 20);
```

`>=` и `<=` принимают равенство. `&&` требует выполнения обоих сравнений. Имя `BetweenInclusive` и суффикс `Inclusive` делают обе гарантии по границам видимыми в месте вызова.

[00:04:18](https://www.youtube.com/watch?v=mj771Sd298c&t=258s) Контракт также говорит, что функция требует от вызывающего кода. [00:04:32](https://www.youtube.com/watch?v=mj771Sd298c&t=272s) Для функции из этой записи нижняя граница должна быть меньше верхней. Неупорядоченная или равная пара нарушает выбранный контракт входа; это ошибка вызывающего кода. Это выбор API, а не математическое утверждение, что одноточечный включающий интервал невозможен. [00:04:47](https://www.youtube.com/watch?v=mj771Sd298c&t=287s) Теперь обе границы обещаны включёнными.

[00:04:56](https://www.youtube.com/watch?v=mj771Sd298c&t=296s) Гарантия выхода — правильный логический ответ на вопрос «находится ли это значение внутри интервала?». [00:05:09](https://www.youtube.com/watch?v=mj771Sd298c&t=309s) Она также обещает отсутствие изменений **внешнего состояния**: ни вывода на консоль, ни изменения посторонних данных. Это были бы **побочные эффекты** — наблюдаемые действия за пределами возврата вердикта.

[00:05:26](https://www.youtube.com/watch?v=mj771Sd298c&t=326s) Разделите контракт на:

- **Контракт входа:** предположения, которые функция вправе делать об аргументах, здесь `minInclusive < maxInclusive`.
- **Контракт выхода:** предположения, которые вызывающий код вправе делать об операции, здесь — корректная принадлежность, обе границы включены и отсутствие изменений внешнего состояния.

[00:05:34](https://www.youtube.com/watch?v=mj771Sd298c&t=334s) Нарушение требования входа — ошибка вызывающего кода. [00:05:36](https://www.youtube.com/watch?v=mj771Sd298c&t=336s) Возврат неверного вердикта, исключение обещанной границы или изменение постороннего состояния нарушают контракт выхода функции.

## Защитите контракт

[00:05:53](https://www.youtube.com/watch?v=mj771Sd298c&t=353s) **Проверка (guard)** защищает контракт входа до начала реальной работы. Это может быть утверждение для установленного предположения разработки или обычная проверка в начале тела.

[Связанная презентация о валидации](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#4-validate-an-input-or-assert-an-established-assumption) разделяет утверждения и отклонение во время выполнения. Примеры ниже сохраняют строгий порядок границ из записи:

```csharp
// Внутреннее предположение при разработке:
Debug.Assert(minInclusive < maxInclusive);

// Публичная валидация во время выполнения:
if (minInclusive >= maxInclusive)
    throw new ArgumentException(
        "The minimum must be smaller than the maximum.");

bool result = value >= minInclusive && value <= maxInclusive;
```

Это два механизма для сравнения; они не обязаны присутствовать в каждой функции.

[00:06:02](https://www.youtube.com/watch?v=mj771Sd298c&t=362s) **Поправка:** в произнесённом примере говорится, что минимум должен быть больше максимума. Это противоречит ранее сформулированному контракту. Правильное утверждение — `minInclusive < maxInclusive`; проверка некорректного входа отвергает `minInclusive >= maxInclusive`.

[00:06:09](https://www.youtube.com/watch?v=mj771Sd298c&t=369s) **Утверждение**, такое как `Debug.Assert(condition)`, проверяет предположение и сообщает о неудачном утверждении во время разработки; оно не исправляет аргументы. [00:06:16](https://www.youtube.com/watch?v=mj771Sd298c&t=376s) Предполагаемое применение — выявить ошибку программирования при разработке и тестировании программы.

[00:06:33](https://www.youtube.com/watch?v=mj771Sd298c&t=393s) В записи говорится, что утверждения удаляются после написания программы и прохождения тестов. Точнее, включение зависит от **символа компиляции DEBUG**, а не от того, прошли ли тесты. Вызовы `Debug.Assert` опускаются, когда этот символ отсутствует, как в обычных сборках Release.

[00:06:45](https://www.youtube.com/watch?v=mj771Sd298c&t=405s) Это делает утверждения непригодными как единственную защиту **публичного API**, то есть интерфейса, используемого кодом вне вашего контроля. [00:06:55](https://www.youtube.com/watch?v=mj771Sd298c&t=415s) При поставке библиотеки пользователи скачивают пакет и вызывают её функции со своими аргументами. ## Реализуйте удаление дубликатов

[00:09:48](https://www.youtube.com/watch?v=mj771Sd298c&t=588s) Чтобы реализовать действие более высокого уровня, отслеживайте встреченные имена в **HashSet**, коллекции различных элементов, и накапливайте первые появления в **List**, упорядоченной растущей последовательности.

[Связанная реализация через множество и цикл](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#6-the-caller-and-implementation-work-at-different-levels) возвращает представление списка только для чтения. Этот адаптированный пример возвращает новый массив, обсуждённый в записи:

```csharp
static string[] RemoveDuplicates(string[] names)
{
    var seen = new HashSet<string>(StringComparer.Ordinal);
    var result = new List<string>();

    foreach (string name in names)
    {
        if (seen.Add(name))
            result.Add(name);
    }

    return result.ToArray();
}
```

3. [00:10:30](https://www.youtube.com/watch?v=mj771Sd298c&t=630s) Для повторяющегося имени `Add` возвращает `false`. Добавление под защитой не выполняется, поэтому результат не получает второй копии.

[00:10:37](https://www.youtube.com/watch?v=mj771Sd298c&t=637s) **Компаратор** определяет, какие значения считаются равными. `StringComparer.Ordinal` сравнивает строки по значениям символов и различает регистр: `"Ann"` и `"ann"` остаются разными именами. ## Группируйте и нормализуйте целочисленные интервалы

[00:12:30](https://www.youtube.com/watch?v=mj771Sd298c&t=750s) Замените независимые аргументы начала и конца **абстракцией интервала**, несущей обе границы вместе. [00:12:51](https://www.youtube.com/watch?v=mj771Sd298c&t=771s) Теперь вызывающий код может думать об одном интервале вместо запоминания двух несвязанных позиционных значений. [00:13:05](https://www.youtube.com/watch?v=mj771Sd298c&t=785s) Сохраните его один раз и используйте повторно для последующих проверок.

[Связанная презентация о нормализации интервала](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#8-normalize-the-intervals-representation) использует выбор границ при создании. Упрощённые вызовы ниже показывают переход:

```csharp
// Раньше: отдельные границы повторяются в каждом вызове.
BetweenInclusive(value: temperature, minInclusive: 10, maxInclusive: 19);

// Позже: построить интервал и переиспользовать его.
var interval = Interval.Create(
    min: 10, max: 19,
    minBoundary: Boundary.Inclusive,
    maxBoundary: Boundary.Inclusive);

bool allowed = interval.Contains(temperature);
```

`Boundary` — это выбор между включающим и исключающим поведением на границах. `Create` — это **фабрика**, операция, строящая интервал через контролируемую логику. `Contains` запрашивает у абстракции вердикт о принадлежности.

[00:13:19](https://www.youtube.com/watch?v=mj771Sd298c&t=799s) Вызывающему коду не нужно знать, использует ли хранение четыре поля, два нормализованных поля или два элемента массива. [00:13:41](https://www.youtube.com/watch?v=mj771Sd298c&t=821s) **Нормализация** меняет представление, сохраняя смысл. [00:13:57](https://www.youtube.com/watch?v=mj771Sd298c&t=837s) Здесь все входы становятся включённым началом и исключённым концом.

[00:14:04](https://www.youtube.com/watch?v=mj771Sd298c&t=844s) Включённая целочисленная верхняя граница 19 становится исключённой верхней границей 20. Каждое представление содержит ровно целые числа от 10 до 19:

| Переданный целочисленный интервал | Нормализованный интервал |
| --- | --- |
| `[10, 19]` | `[10, 20)` |
| `[10, 20)` | `[10, 20)` |
| `(9, 19]` | `[10, 20)` |

Квадратные скобки включают границу; круглые — исключают. Исключённая нижняя граница переносится на следующее целое число, делая хранимую нижнюю границу включённой. Включённая верхняя граница переносится на следующее целое число, делая хранимую верхнюю границу исключённой.

[00:14:35](https://www.youtube.com/watch?v=mj771Sd298c&t=875s) Это преобразование зависит от целочисленной предметной области. Прибавление единицы не сохраняет смысл интервала значений с плавающей точкой. Запись оставляет проектирование интервалов с плавающей точкой за пределами этого примера; она не преподносит общий алгоритм нормализации для плавающей точки.

## Установите инвариант и сохраняйте его

[00:14:37](https://www.youtube.com/watch?v=mj771Sd298c&t=877s) **Инвариант** — это условие, которое тип устанавливает при создании и которое все его операции обязаны сохранять. Публичный метод ни в коем случае не должен оставлять объект в состоянии, нарушающем его. [00:15:00](https://www.youtube.com/watch?v=mj771Sd298c&t=900s) Для нормализованного интервала инвариантом является `StartInclusive <= EndExclusive`. Равные нормализованные границы описывают пустой интервал, поскольку ни одно целое число не может быть одновременно не меньше такого начала и меньше такого конца.

[00:15:16](https://www.youtube.com/watch?v=mj771Sd298c&t=916s) Используйте приватный конструктор и фабрику. **Приватный конструктор** не позволяет внешним вызывающим создать непроверенный объект напрямую. **Фабрика** проверяет запрос, нормализует границы и создаёт объект только после установления инварианта.

[Связанный пример инварианта и полная реализация](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#9-an-invariant-keeps-the-normalized-bounds-valid) используют структуру только для чтения и нормализуют пустые интервалы к значению по умолчанию. Эта упрощённая адаптация класса, напротив, отвергает некорректную нормализованную пару; это не точная транскрипция той реализации или видео:

```csharp
public sealed class Interval
{
    public long StartInclusive { get; }
    public long EndExclusive { get; }

    private Interval(long startInclusive, long endExclusive)
    {
        StartInclusive = startInclusive;
        EndExclusive = endExclusive;
    }

    public static Interval Create(
        int min, int max,
        Boundary minBoundary, Boundary maxBoundary)
    {
        if (min > max)
            throw new ArgumentException("Bounds are reversed.");

        long start = (long)min
            + (minBoundary == Boundary.Exclusive ? 1 : 0);
        long end = (long)max
            + (maxBoundary == Boundary.Inclusive ? 1 : 0);

        if (start > end)
            throw new ArgumentException("Invalid normalized interval.");

        return new Interval(start, end);
    }

    // Contains добавляется в следующем разделе.
}
```

Фрагмент предполагает корректные значения `Boundary`. Связанная полная реализация также проверяет эти аргументы перечисления. Её внутренние границы типа `long` предотвращают переполнение, когда включённое `int.MaxValue` должно стать исключённой границей на единицу больше; приведение выполняется до сложения. Это деталь реализации, взятая из более позднего вспомогательного источника, а не дополнительное утверждение о том, что демонстрирует запись.

Проследите за шагами фабрики:

1. [00:15:16](https://www.youtube.com/watch?v=mj771Sd298c&t=916s) Проверьте запрошенные границы до создания объекта.
2. [00:15:34](https://www.youtube.com/watch?v=mj771Sd298c&t=934s) Нормализуйте нижнюю границу: включённую оставьте как есть; к исключённой целочисленной нижней границе прибавьте единицу.
3. [00:15:34](https://www.youtube.com/watch?v=mj771Sd298c&t=934s) Нормализуйте верхнюю границу: исключённую оставьте как есть; к включённой целочисленной верхней границе прибавьте единицу.
4. [00:15:48](https://www.youtube.com/watch?v=mj771Sd298c&t=948s) Проверьте, что нормализованное начало не превосходит нормализованного конца. Не создавайте объект, нарушающий инвариант.
5. [00:15:55](https://www.youtube.com/watch?v=mj771Sd298c&t=955s) Верните объект, границы которого уже проверены и открыты только для чтения.

[00:15:53](https://www.youtube.com/watch?v=mj771Sd298c&t=953s) Запись сознательно оставляет открытым поведение при нарушении инварианта. Выброс исключения, сообщение об ошибке создания или другая реакция должны соответствовать требованиям проекта. Приведённое исключение — один иллюстративный выбор, а не предписанный результат урока.

[00:15:55](https://www.youtube.com/watch?v=mj771Sd298c&t=955s) **Свойство только для чтения**, записываемое как `{ get; }`, открывает геттер, но не публичный сеттер. После возврата из фабрики клиенты не могут независимо заменить границу. [00:16:08](https://www.youtube.com/watch?v=mj771Sd298c&t=968s) Поскольку границы остаются неизменными, а их порядок установлен при создании, инвариант выполняется в течение всего времени жизни объекта.

Почему проверять в фабрике, а не повторять ту же проверку в каждом вызывающем коде?

<details>
<summary>Ответ</summary>

Фабрика владеет созданием. Каждый успешно созданный интервал тогда несёт одну и ту же гарантию, поэтому вызывающий код и последующие операции могут полагаться на его инвариант вместо того, чтобы устанавливать его заново. Ограничение последующих записей — часть сохранения этой гарантии.

</details>

[00:19:07](https://www.youtube.com/watch?v=mj771Sd298c&t=1147s) Извлеките операцию, владеющую и перечислением, и проверками.
```csharp
static bool AllWithin(Readings readings, Interval interval)
{
    return interval.Contains(readings.Left)
        && interval.Contains(readings.Center)
        && interval.Contains(readings.Right);
}

// Обновление экрана:
bool allowed = AllWithin(readings, interval);
SetIndicator(allowed);
```

`Readings` — это тип данных датчиков, поля которого проверяет операция. `AllWithin` должна обещать, что проверено **каждое** релевантное показание; её имя было бы вводящим в заблуждение, если бы реализация молча пропускала одно из них.

Это всё ещё код, который нужно поддерживать: добавление датчика требует обновления централизованного помощника. Польза в том, что каждая функция экрана или тревоги больше не повторяет это знание о полях. Для извлечения в этом уроке не требуется новый проект коллекции или итератора.

## Взвесьте цену косвенности

[00:19:44](https://www.youtube.com/watch?v=mj771Sd298c&t=1184s) Примените ту же технику извлечения к проверке входа: перенесите валидацию в `CheckArguments`, передайте ей параметры функции и поручите ей выбросить исключение. [Связанное сравнение извлечения проверки](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#14-another-call-can-help-or-just-make-you-look-elsewhere) показывает, почему этот дополнительный уровень может дать немного. Пример сохраняет строгий контракт входа из записи:

```csharp
// До: проверка видна непосредственно.
if (minInclusive >= maxInclusive)
    throw new ArgumentException("Invalid bounds.");

// После: другой вызов скрывает ту же проверку.
CheckArguments(value, minInclusive, maxInclusive);

// Отдельный помощник:
static void CheckArguments(
    int value, int minInclusive, int maxInclusive)
{
    if (minInclusive >= maxInclusive)
        throw new ArgumentException("Invalid bounds.");
}
```

Эти фрагменты «до и после» — альтернативы, а не инструкции выполнять обе проверки. [00:19:46](https://www.youtube.com/watch?v=mj771Sd298c&t=1186s) Помощник сохраняет валидацию связанной с операцией, но теперь её понимание требует ещё одного перехода; `value` для этой конкретной проверки границ вообще не нужен.

[00:20:00](https://www.youtube.com/watch?v=mj771Sd298c&t=1200s) Извлечение иногда может согласовать валидацию с уровнем абстракции остальной, более крупной функции. [00:20:22](https://www.youtube.com/watch?v=mj771Sd298c&t=1222s) В этом крошечном примере оно скрывает по сути одно уже понятное действие. Читатель получает имя и новый слой для навигации без существенного снижения сложности.

[00:20:36](https://www.youtube.com/watch?v=mj771Sd298c&t=1236s) Абстракция может помочь, а может навредить. [00:20:45](https://www.youtube.com/watch?v=mj771Sd298c&t=1245s) Операции, ранее бывшие встроенными, теперь видны только если проследить по новому имени. [00:21:04](https://www.youtube.com/watch?v=mj771Sd298c&t=1264s) Это **косвенность**: достижение реальной операции через другой вызов или имя. [00:21:26](https://www.youtube.com/watch?v=mj771Sd298c&t=1286s) Здесь она, вероятно, не приносит пользы, но это суждение об этом примере, а не запрет на помощники валидации.

Сравните изменения:

- `AllWithin` убирает из вызывающего кода повторяющееся знание о расположении датчиков и задаёт гарантию полноты.
- `CheckArguments` лишь перемещает короткую проверку. Читатель должен проследить за ней, чтобы узнать, что именно проверяется.

Спросите, какое знание экономит извлечение, какой контракт оно устанавливает и какую дополнительную навигацию добавляет. Помощник заслуживает своего места благодаря этим выгодам, а не просто потому, что извлечение возможно.

## Сделайте зависимости конфигурации явными

[00:22:33](https://www.youtube.com/watch?v=mj771Sd298c&t=1353s) Функция может скрывать не только алгоритм, но и входные данные. **Конфигурация** задаёт настройки; **зависимость** — это то, что нужно функции для работы. Чтение конфигурации из **глобального состояния** добавляет зависимость, которой нет в списке параметров.

[00:22:41](https://www.youtube.com/watch?v=mj771Sd298c&t=1361s) Вместо этого передавайте нужную конфигурацию явно. [Связанная презентация о явных входах](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#16-make-the-necessary-input-visible) иллюстрирует это различие. Сокращённая реконструкция:

```csharp
// Скрытый вход:
bool IsAllowed(int temperature)
    => temperature <= Settings.MaximumTemperature;

// Видимый вход:
bool IsAllowed(int temperature, int maximumTemperature)
    => temperature <= maximumTemperature;
```

Эти объявления — альтернативы. Результат первой функции зависит и от её видимого аргумента, и от той глобальной настройки, которая случайно присутствует. Вторая задаёт эту настройку как вход. Само по себе чтение глобального состояния не обязано его менять: скрытая зависимость и побочный эффект — разные понятия.

[00:22:50](https://www.youtube.com/watch?v=mj771Sd298c&t=1370s) Ещё одно предложенное решение группирует настройки в абстракцию и помещает туда операцию `IsValid`. Зафиксированное предложение связано с [советом презентации о содержательных абстракциях конфигурации](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#16-make-the-necessary-input-visible); нижеследующее — схематическая адаптация, а не зафиксированный точный код:

```csharp
// settings передаётся этой операции, а не берётся глобально.
bool IsAllowed(int temperature, TemperatureSettings settings)
    => settings.IsValid(temperature);
```

`TemperatureSettings` обозначает тип, владеющий правилом для температуры; `IsValid` инкапсулирует проверки. Его реализация может скрывать, какие именно настройки участвуют, тогда как сигнатура функции по-прежнему показывает, что объект настроек необходим.

[00:23:06](https://www.youtube.com/watch?v=mj771Sd298c&t=1386s) Эта абстракция может скрывать и логику валидации, и её зависимость от конкретных настроек. [00:23:09](https://www.youtube.com/watch?v=mj771Sd298c&t=1389s) Это означает, что читатель больше не видит каждую конкретную настройку во внешней функции. Зависимость от объекта настроек по-прежнему важна и должна оставаться явной.

[00:23:22](https://www.youtube.com/watch?v=mj771Sd298c&t=1402s) Оборачивание глобального чтения в метод не устраняет зависимость от глобальных данных. Самодостаточная функция вместо этого получает свою конфигурацию через параметр. [00:23:31](https://www.youtube.com/watch?v=mj771Sd298c&t=1411s) Это поддерживает **локальное рассуждение**: всё, что нужно операции, подаётся локально, поэтому её понимание не требует восстанавливать всё глобальное окружение вызывающего кода.

[00:23:51](https://www.youtube.com/watch?v=mj771Sd298c&t=1431s) Запись отдаёт предпочтение абстракции настроек, передаваемой вместе с нужными настройками, неявному глобальному поиску. Используйте абстракцию, чтобы инкапсулировать осмысленное правило; используйте сигнатуру, чтобы сделать зависимость видимой. ## Выразите мутацию и наблюдайте общие данные

[00:24:03](https://www.youtube.com/watch?v=mj771Sd298c&t=1443s) Типы параметров могут сообщать части контракта. **Представление только для чтения** предоставляет чтение без операций записи через это представление. Запись противопоставляет такой вход, включая span только для чтения, изменяемому списку. Более поздняя [презентация о доступе через параметры](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#17-use-a-parameter-view-that-matches-the-intended-access) использует `IReadOnlyList` для того же различения; это связанный выбор типа, а не точное записанное объявление.

```csharp
// Формы объявлений, а не полные реализации:
IReadOnlyList<string> RemoveDuplicates(IReadOnlyList<string> names);

void SortInPlace(List<string> names);
```

`IReadOnlyList` предоставляет чтение и подсчёт без операций записи в коллекцию через этот интерфейс. `List` предоставляет мутацию. **Span только для чтения** аналогично даёт представление, не предлагающее запись элементов через этот span; он не обязан быть взаимозаменяем с каждым интерфейсом коллекции.

[00:24:16](https://www.youtube.com/watch?v=mj771Sd298c&t=1456s) Когда `RemoveDuplicates` обещает не изменять свой вход, дубликаты остаются в исходных данных и исчезают только из нового возвращённого результата. Короткий пример, связанный с [контрактом дедупликации](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#5-a-useful-abstraction-can-hide-a-substantial-operation):

```csharp
var original = new List<string> { "Ann", "Ann" };
var unique = RemoveDuplicates(original);
// original по-прежнему содержит две записи.
// unique содержит одну запись.
```

[00:24:41](https://www.youtube.com/watch?v=mj771Sd298c&t=1481s) `SortInPlace` — это **операция на месте**: она сортирует, переписывая собственное содержимое переданного списка. Поэтому ей нужен доступ на запись, а не вход только для чтения из записи. Имя и контракт должны раскрывать эту **мутацию** — изменение существующего объекта.

[00:24:53](https://www.youtube.com/watch?v=mj771Sd298c&t=1493s) Изменяемый параметр означает, что вызывающий код должен допускать возможную мутацию, если контракт не говорит иного. [00:25:11](https://www.youtube.com/watch?v=mj771Sd298c&t=1511s) **Поправка:** в произнесённом обсуждении также пытаются вывести отсутствие мутации из типа возврата. Ни возврат значения, ни возврат `void` не устанавливают, изменяется ли вход. Функция может вернуть новое значение и изменить вход либо вернуть `void` и оставить вход нетронутым. Пользуйтесь заявленным контрактом операции, её осмысленным именем и доступом, предоставляемым типом параметра, вместе взятыми.

[00:25:18](https://www.youtube.com/watch?v=mj771Sd298c&t=1518s) **Ссылка** идентифицирует объект. Передача списка как обычного параметра копирует значение ссылки, а не содержимое списка; это не механизм параметров `ref` в C#. **Псевдоним** — это вторая ссылка на тот же объект.

[Связанная демонстрация общих ссылок](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#18-two-references-can-observe-the-same-change) показывает следствие. Это упрощённый пример включает операцию сортировки:

```csharp
static void SortInPlace(List<string> names)
    => names.Sort(StringComparer.Ordinal);

var original = new List<string> { "Bob", "Ann" };
IReadOnlyList<string> secondReference = original;

SortInPlace(original);
Console.WriteLine(secondReference[0]); // Ann
```

[00:25:32](https://www.youtube.com/watch?v=mj771Sd298c&t=1532s) Печать через исходную ссылку или вторую ссылку наблюдает отсортированное содержимое: обе указывают на один объект, поэтому первым элементом теперь является `"Ann"`. Это иллюстративная реконструкция записанного результата с псевдонимами, а не прогон тестов, выполненный для этих заметок.

Представление только для чтения ограничивает то, что его владелец может делать через это представление. Оно не делает лежащий в основе общий объект неизменяемым и не мешает другому владельцу его изменить. Эта точная граница — часть понимания контракта входа.

Предскажите исходный список после не мутирующего удаления дубликатов и после сортировки на месте.

<details>
<summary>Ответ</summary>

Удаление дубликатов оставляет исходные записи, включая дубликаты, без изменений и возвращает отдельный результат. Сортировка на месте изменяет переданный список; каждый его псевдоним наблюдает изменённый порядок.

</details>

## Решите, какие абстракции заслуживают своего места

[00:25:47](https://www.youtube.com/watch?v=mj771Sd298c&t=1547s) Вернёмся к примеру с датчиками. Абстракция над данными позволяет вызывающему коду перестать рассуждать о её конкретных полях. [00:25:54](https://www.youtube.com/watch?v=mj771Sd298c&t=1554s) Её контракт должен обещать, что учтены все релевантные поля.

[Связанное итоговое сравнение вызывающих кодов](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#19-compare-the-knowledge-required-by-two-callers) спрашивает, какое знание устраняет помощник. Компактная версия:

```csharp
// Зависящий от представления вызывающий код:
bool allowed = interval.Contains(readings.Left)
    && interval.Contains(readings.Center)
    && interval.Contains(readings.Right);

// Вызывающий код, полагающийся на контракт всех показаний:
bool allAllowed = AllWithin(readings, interval);
SetIndicator(allAllowed);
```

[00:26:06](https://www.youtube.com/watch?v=mj771Sd298c&t=1566s) Без абстракции четвёртый датчик требует изменения каждого вызывающего кода, который перечисляет поля. [00:26:19](https://www.youtube.com/watch?v=mj771Sd298c&t=1579s) С ней зависящее от полей перечисление меняется в одной централизованной операции. Вызывающий код продолжает полагаться на её гарантию полноты. Это конкретное изменение объясняет ценность абстракции.

[00:26:24](https://www.youtube.com/watch?v=mj771Sd298c&t=1584s) Добавление ещё одной обёртки вокруг `SetIndicator` может оказаться бессмысленным, если она лишь даёт другое имя тому же действию. [00:26:38](https://www.youtube.com/watch?v=mj771Sd298c&t=1598s) Обёртка становится осмысленной, когда у индикатора есть конкретная предметная цель, например показание того, корректна ли настройка максимальной температуры.

[Связанное обсуждение семантического именования](https://github.com/AntonC9018/uniCourse_csharp/blob/7e53c72e223132cbd1278019f2b05d3654e658f5/presentations/source-notes.md#7a-names-can-express-meaning-in-the-system) поддерживает это различение; эта обёртка, специфичная для записи, — упрощённая иллюстрация, а не точное состояние из того источника:

```csharp
void SetMaxSetTemperatureIndicatorValue(bool value)
{
    SetIndicator(value);
}
```

[00:26:49](https://www.youtube.com/watch?v=mj771Sd298c&t=1609s) Эта обёртка оправдана лишь тогда, когда её имя и место отражают реальное предметное намерение. Обёртка, которая лишь переименовывает уже ясное действие, добавляет косвенность без этой пользы. Семантический смысл, централизованное знание о представлении и полезные контракты — вот конкретные причины вводить абстракцию; само по себе введение ещё одного слоя причиной не является.

Что должна обещать `AllWithin` и почему обёртка индикатора с семантическим именем — отдельное решение?

<details>
<summary>Ответ</summary>

AllWithin должна проверять каждое релевантное показание относительно интервала, а не скрытое подмножество. Она централизует знание о полях датчиков. Обёртка индикатора заслуживает своего места только тогда, когда называет реальный смысл в приложении; централизация перечисления полей сама по себе не оправдывает обёртку каждого последующего вызова.

</details>

Урок остаётся в рамках локального рассуждения о функциях и этих небольших примеров. Специализированный тип датчиков отложен при первом упоминании; проектирование интервалов с плавающей точкой выходит за пределы примера нормализации целых чисел; политика сбоев фабрики зависит от требований проекта. Валидация публичной библиотеки обсуждается, чтобы объяснить, почему утверждений только для разработки недостаточно, а не чтобы преподносить упаковку библиотек. Полная архитектура системы или универсальное правило о том, когда следует извлекать любого помощника, не устанавливаются.
