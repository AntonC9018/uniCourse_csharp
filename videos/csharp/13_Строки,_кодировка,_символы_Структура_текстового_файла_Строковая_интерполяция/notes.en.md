# Strings from objects to formatted messages

[00:00:00](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=0s) This lesson connects the text you write in C# to the objects, character codes, and file bytes that represent it. Start with an immutable string, inspect one character as a number, reconstruct that character, examine line endings and encodings, and finally build messages with interpolation and concatenation.

The terms used along the way are:

- **String, object, reference, and dynamic memory:** a `string` is an object containing text; a reference identifies that object. Dynamic memory is the managed storage in which such objects live.
- **Immutability, mutable character array:** an immutable object's contents cannot change after construction. A mutable `char[]` is an array whose character elements can be replaced.
- **Character, glyph, and `char`:** a character is a text element; a glyph is its drawn shape. C# `char` is a value type holding one 16-bit UTF-16 code unit, rather than a reference to an object.
- **Literal, compiler, and indexer:** a literal writes a value directly in source; the compiler translates source into executable code. An indexer uses square brackets to read an element by position.
- **`int`, `float`, static type, and overload:** `int` holds a 32-bit integer and `float` a floating-point number. An expression's static type is its type known during compilation. Overloads are different versions of a method or operator selected according to the types involved.
- **Numeric conversion, cast, and truncation:** a conversion changes a value's type; an implicit conversion needs no cast, while an explicit cast writes the target type in parentheses. Truncation here means losing bits that do not fit during unchecked narrowing. “Unchecked” means that an out-of-range conversion is allowed to discard bits; checked conversion instead rejects it.
- **Encoding, code, ASCII, Unicode, and code point:** an encoding specifies how text is represented. A character code is its associated number. ASCII is the 7-bit set of codes 0–127. Unicode assigns code points, numerical identifiers, to characters across languages.
- **Bit, byte, decimal, hexadecimal, and byte dump:** a bit is a binary digit; a byte contains eight bits. Decimal is base ten, hexadecimal base sixteen. A byte dump displays file contents as numbers, commonly hexadecimal.
- **Escape sequence, control character, LF, CR, and CRLF:** an escape sequence spells a special value in source, such as `\n`. Control characters affect text handling rather than drawing a glyph. Line Feed (LF) is code 10; Carriage Return (CR) is code 13; CRLF is the two-character sequence CR then LF.
- **BOM and byte order:** a Byte Order Mark is an optional encoding marker at the start of a file. Byte order describes the ordering of bytes in multi-byte units.
- **UTF-8, UTF-16, UTF-32, code unit, BMP, and surrogate pair:** these Unicode encodings use units of 8, 16, and 32 bits. A code unit is one such storage unit. The Basic Multilingual Plane (BMP) contains code points up to U+FFFF; supplementary code points need a pair of UTF-16 units, called a surrogate pair.
- **Alt code and word wrap:** an Alt code is a platform-dependent keyboard input shortcut for a character. Word wrap visually folds a long editor line without inserting a newline.
- **Interpolation and expression:** interpolation inserts evaluated values into a string using `$` and braces. An expression is source code that computes a value.
- **Concatenation, `string.Concat`, static method, and snapshot:** concatenation joins text pieces. `string.Concat` is a static method, called on the type rather than an instance, that joins its arguments. A snapshot holds the text obtained at construction time.
- **.NET, `Console.WriteLine`, and `ToString`:** .NET supplies the runtime and libraries used here. `Console.WriteLine` writes a value followed by a line ending. `ToString` obtains a value's textual representation.

## Strings and immutable objects

[00:00:00](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=0s) A string is an object representing a sequence of characters. Its content is text: even a number embedded in a message ultimately becomes characters. Thinking of a string as a character array is useful for reading individual positions, but a `string` is not a `char[]`.

[00:00:23](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=23s) The important difference is mutability. A mutable character array lets you replace an element; an immutable string never lets you replace a character inside the existing object. [00:00:32](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=32s) The string object lives in dynamic memory. [00:00:39](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=39s) Reassigning the variable replaces its reference, not that object's contents.

A simplified version of the opening object state at [00:00:32](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=32s) follows:

```csharp
string a = "Hello world";
string original = a;
a = "Another message";
// original still refers to "Hello world".

char[] letters = { 'H', 'i' };
letters[0] = 'B';          // Allowed: the array is mutable.
// original[0] = 'B';      // Error: a string's indexer is read-only.
```

Here an object is the stored string, and a reference is the variable's connection to it. After reassignment, `a` identifies another string; `original` still identifies the first one. This distinction will explain why concatenated text does not track later variable changes.

## Platform line endings

[00:06:55](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=415s) A line ending is not always one character. Linux conventionally uses LF, while Windows conventionally uses CRLF: Carriage Return, code 13, followed by Line Feed, code 10. Files can use either convention independently of the operating system on which they are opened.

Simplified line-ending comparison [00:06:55](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=415s):

```csharp

string windowsEnding = "\r\n"; // Two chars: 13, then 10.
```

Here `\r` is an escape sequence for CR. Adding it before `\n` changes the string's actual content. The single escape `\n` remains LF; it does not automatically turn into two characters just because the program runs on Windows.

## Unicode UTF-8 and the two-byte char

[00:08:41](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=521s) Russian letters do not appear in ASCII's 0–127 range. [00:08:53](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=533s) Unicode supplies code points—numerical identifiers—for characters from many languages. A Unicode code point and the bytes used to encode it are related but distinct ideas.

[00:09:04](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=544s) UTF-8 is introduced as the commonly used encoding, alongside UTF-16 and UTF-32. They represent the same Unicode text using differently sized code units. [00:09:09](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=549s) ASCII characters retain their single-byte ASCII values **in UTF-8**; that single-byte statement must not be extended to UTF-16 or UTF-32. [00:09:20](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=560s) Other UTF-8 characters take two, three, or four bytes.

The following comparison is a simplified representation example for the encoding discussion [00:09:49](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=589s), not a separately committed program:

```text
Character      UTF-8 bytes      UTF-16 code unit
H              48               0048
Ж              D0 96            0416
```

The table uses hexadecimal. `H` therefore still has decimal code 72 even though its UTF-8 byte is written as `48` in the dump.

[00:09:49](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=589s) A byte contains eight bits. UTF-8's smallest unit is one byte; UTF-16's is sixteen bits, or two bytes. Even an ASCII letter occupies one two-byte UTF-16 unit. [00:10:10](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=610s) The size tradeoff depends on the text: many BMP characters that take three UTF-8 bytes take two UTF-16 bytes. Characters outside the BMP take four bytes in both UTF-8 and UTF-16; UTF-32 uses four bytes per code point, so it is not a universal space-saving option. [Unicode's encoding comparison](https://www.unicode.org/faq/utf_bom.html) gives the one-to-four-byte, one-or-two-unit, and single-32-bit-unit rules.

[00:10:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=626s) This returns us to `char`: it is precisely one UTF-16 code unit occupying two bytes. The BMP, or Basic Multilingual Plane, covers code points up to U+FFFF. A BMP character such as `Ж` fits in one `char`; a supplementary code point requires a surrogate pair, two UTF-16 code units, and cannot be represented as one complete character in one `char`. Thus “one character” is a useful starting description for these examples, but not a guarantee for all Unicode text. [The C# char definition](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/char) states the code-unit model.

[00:09:14](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=554s) The lesson does not implement encoders or explain their bit-level algorithms. The practical boundary is to distinguish a character's code, its in-memory UTF-16 units, and its encoded file bytes.

## Joining strings and keeping a snapshot

[00:12:47](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=767s) **Concatenation** joins existing text pieces. The static method `string.Concat` takes string arguments and returns their combined text. “Static” means that the method is called on `string`, not on a particular string instance.

1. [00:12:47](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=767s) Call `string.Concat` with the first and second strings.
2. [00:12:59](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=779s) Print its result: the recorded test shows the first input followed immediately by the second.
3. [00:13:12](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=792s) Consider whether the result remains connected to the variables.
4. [00:13:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=806s) Reassign the first variable. The previously joined text remains unchanged.
5. [00:13:44](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=824s) Add `", "` as another argument to insert a separator.
6. [00:14:02](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=842s) Compare that construction with interpolation.
7. [00:14:09](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=849s) Replace the explicit call with the overloaded string `+` operator.

Simplified initial join and reassignment states [00:12:47](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=767s) and [00:13:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=806s):

```csharp
string a = "Hello";
string b = "World";
string c = string.Concat(a, b);
Console.WriteLine(c); // HelloWorld

a = "Changed";
Console.WriteLine(c); // Still HelloWorld
```

[00:13:12](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=792s) A snapshot holds the text obtained when it was built. `Concat` receives references to the current string objects, not a continuing connection to the variables `a` and `b`. [00:13:26](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=806s) In this two-nonempty-string example, it builds a new object containing the first object's characters and then the second object's characters. Reassigning `a` changes its reference, not the original string or the joined result.

Simplified separator change [00:13:44](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=824s), using the original inputs again:

```csharp
string a = "Hello";
string b = "World";
string explicitJoin = string.Concat(a, ", ", b);
string interpolated = $"{a}, {b}";
string withPlus = a + ", " + b;
Console.WriteLine(explicitJoin); // Hello, World
```

[00:14:02](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=842s) Both interpolation and an explicit `Concat` call are valid ways to build this text. [00:14:09](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=849s) For strings, the overloaded `+` operator means concatenation rather than numerical addition. [00:14:28](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=868s) The compiler can turn this three-string expression into a `string.Concat` call with the three operands. That explains the equivalent result for this example; it is not a promise that every string expression or interpolation form has identical compiled instructions.

<details>
<summary>If a becomes Changed, what must you do to obtain Changed, World?</summary>

Construct a new result using the current a and b. The existing result is an immutable snapshot and cannot update itself.

</details>

## Converting a value to text with ToString

[00:14:36](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=876s) .NET objects inherit `ToString`, a method that obtains their textual representation. [00:14:41](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=881s) Values such as `int`, `char`, and `float` can use it when a string is explicitly required.

Simplified final conversion state [00:14:41](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=881s):

```csharp
int age = 12;
char initial = 'H';
float value = 1.5f;
string ageText = age.ToString();       // "12"
string initialText = initial.ToString(); // "H"
string valueText = value.ToString();   // Formatting depends on the environment.
Console.WriteLine(age);               // No explicit ToString needed.
```

Here `ToString` produces text, unlike casting `'H'` to `int`, which produces the numeric code 72. The `f` suffix writes a `float` literal.

[00:14:44](https://www.youtube.com/watch?v=dTbrzEXPH-s&t=884s) Explicit conversion is useful when another operation requires a `string`. Printing usually does not require it: `Console.WriteLine` has overloads for common value types and an `object` overload for other objects. It selects the applicable overload and prints the representation. [The WriteLine API](https://learn.microsoft.com/en-us/dotnet/api/system.console.writeline) documents these alternatives. The final lesson boundary is basic representation and message construction, not custom formatting or the implementation of those library methods.
