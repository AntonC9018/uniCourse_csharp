# Установка .NET SDK без прав администратора

[00:00:00](https://www.youtube.com/watch?v=QsO1HedgKt8&t=0s) **.NET SDK** содержит инструменты, необходимые для компиляции исходного кода на C#. Этот урок показывает, как:

- установить SDK без прав администратора;
- сделать команду `dotnet` доступной в новых консолях;
- собрать вручную минимальный проект и сгенерировать один из шаблона;
- настроить необязательный редактор.

Связанный урок: [Установка .NET и создание первого проекта](../../../labs/1_basic/01_install.md).

Понятия, используемые в разборе:

- **Консоль:** текстовое окно команд. **PowerShell** — консоль Windows, используемая здесь.
- **Скрипт:** файл с командами. `.ps1` — расширение скрипта PowerShell; **расширение** имени файла — это суффикс после последней точки.
- **Путь:** расположение файла или папки. `cd` меняет текущую папку; **относительный путь** начинается из этой папки, а **полный путь** включает диск и папки.
- **Политика выполнения:** правило PowerShell для запуска скриптов.
- **Переменная окружения:** именованная настройка, наследуемая программами. `PATH` перечисляет папки, в которых ищутся команды; `DOTNET_ROOT` указывает на папку установки .NET.
- **Проект:** папка с исходниками и настройками сборки. `Program.cs` содержит исходник на C#; файл `.csproj` содержит настройки проекта в формате **XML**, редактируемом тексте с вложенными тегами.
- **Исполняемый файл:** программа, которую можно запустить. **Библиотека** поставляет код для другой программы.
- **Шаблон:** образец, генерирующий стартовые файлы.
- **IDE:** редактор со средствами разработки. VS Code и Rider — два упомянутых здесь редактора.

## Сохранение скрипта установщика

Чтобы установить .NET без прав администратора, используйте [установочный скрипт PowerShell от Microsoft](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-install-script). Видео иллюстрирует эти шаги подготовки:

1. [00:00:30](https://www.youtube.com/watch?v=QsO1HedgKt8&t=30s) Скачайте скрипт и сохраните его через Ctrl+S.
2. Проверьте имя сохранённого файла. Если оно заканчивается на `.ps1.txt`, удалите только конечное `.txt`, чтобы PowerShell видел скрипт `.ps1`. Этот упрощённый пример следует [записанному сохранению и переименованию](https://www.youtube.com/watch?v=QsO1HedgKt8&t=30s); скачанный файл не имеет снимка в репозитории:

   ```text
   dotnet-install.ps1.txt  →  dotnet-install.ps1
   ```

[00:00:47](https://www.youtube.com/watch?v=QsO1HedgKt8&t=47s) Если расширения имён файлов скрыты, откройте File Explorer и включите **View → Show → File name extensions**. Затем удалите лишний суффикс `.txt` — до или после сохранения файла.

## Переход к скрипту в PowerShell

1. [00:01:01](https://www.youtube.com/watch?v=QsO1HedgKt8&t=61s) Откройте меню «Пуск» Windows, найдите **PowerShell** и нажмите Enter.
2. [00:01:21](https://www.youtube.com/watch?v=QsO1HedgKt8&t=81s) Используйте `cd` (**change directory**), чтобы перейти в папку со скриптом. Передайте путь к папке, а не имя файла скрипта. Эта упрощённая команда иллюстрирует [записанную навигацию](https://www.youtube.com/watch?v=QsO1HedgKt8&t=81s):

   ```powershell
   cd "C:\Users\Student\Downloads"
   ```

[00:01:37](https://www.youtube.com/watch?v=QsO1HedgKt8&t=97s) **Относительный путь** начинается из текущей папки PowerShell, поэтому `cd Downloads` работает, когда Downloads находится прямо внутри неё. **Полный путь** называет диск и папки, как в примере выше. Любая форма подойдёт, если она определяет папку скрипта.

[00:02:00](https://www.youtube.com/watch?v=QsO1HedgKt8&t=120s) Если скрипт находится на диске D, а PowerShell — на диске C, введите `D:`, чтобы перейти в текущее расположение на диске D, затем используйте `cd`, чтобы перейти в папку. Это [записанная смена диска](https://www.youtube.com/watch?v=QsO1HedgKt8&t=120s):

```powershell
D:
cd "D:\Downloads"
```

В PowerShell команда `cd "D:\Downloads"` также может сменить диск и папку одной командой: `cd` — это псевдоним для `Set-Location`, который принимает пути на других дисках ([справочник PowerShell о расположении](https://learn.microsoft.com/en-us/powershell/scripting/samples/managing-current-location)).

[00:02:15](https://www.youtube.com/watch?v=QsO1HedgKt8&t=135s) Если Explorer показывает сокращённый путь, используйте его опцию копирования пути. Скопированный **путь к файлу** включает имя файла; удалите это имя, прежде чем передавать содержащий его каталог в `cd`. После этого PowerShell находится рядом с установщиком.

<details>
<summary>Прогноз: что произойдёт, если скопированный путь всё ещё заканчивается именем файла скрипта, когда его передают в <code>cd</code>?</summary>

`cd` попытается войти в это имя файла, как будто это папка. Удалите имя файла и оставьте содержащий его каталог.
</details>

## Запуск установщика

[00:02:33](https://www.youtube.com/watch?v=QsO1HedgKt8&t=153s) Прямой запуск скрипта может завершиться неудачей из-за **политики выполнения** PowerShell. Если это произошло, настройте политику для текущего сеанса и повторите попытку. Расшифровка не сохранила точную команду с экрана. В справочнике Microsoft по [`Set-ExecutionPolicy`](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/set-executionpolicy) описана область **Process**, которая действует только на текущий процесс PowerShell. Этот пример сопровождает [записанную неудачу и настройку](https://www.youtube.com/watch?v=QsO1HedgKt8&t=153s); это не расшифровка:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

[00:03:00](https://www.youtube.com/watch?v=QsO1HedgKt8&t=180s) При повторном запуске установщика выберите поддерживаемый канал SDK.

> **Запись (.NET 9):** В видео выбран SDK 9.0. Без этого выбора его установщик выбрал бы .NET 8, который, по словам урока, тоже был пригоден. [Записанный выбор](https://www.youtube.com/watch?v=QsO1HedgKt8&t=180s) представлен упрощённой командой `.\dotnet-install.ps1 -Channel 9.0`; точная команда с экрана не сохранена в снимке репозитория.

Для новой установки поставьте .NET 10 SDK. По состоянию на сентябрь 2026 года [.NET 10 — активный LTS-выпуск](https://dotnet.microsoft.com/en-us/platform/support/policy), поддерживаемый до 14 ноября 2028 года. Та же политика относит .NET 9 к поддержке в режиме обслуживания до 10 ноября 2026 года; он ещё не снят с поддержки. В [справочнике по скрипту установки](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-install-script) описан параметр `-Channel` для выбора основной версии:

```powershell
.\dotnet-install.ps1 -Channel 10.0
```

[00:03:11](https://www.youtube.com/watch?v=QsO1HedgKt8&t=191s) Если PowerShell просит подтверждения, выберите **R** для **Run once**. После установки `dotnet` работает в этой консоли.

## Делаем dotnet доступным в новых консолях

[00:03:32](https://www.youtube.com/watch?v=QsO1HedgKt8&t=212s) Проверьте `dotnet` в консоли установки и в новой консоли. В записи он работает в первой, но сначала отсутствует во второй. Установщик добавляет своё расположение в путь поиска команд текущего сеанса, а не в постоянный пользовательский `PATH` ([справочник по скрипту установки](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-install-script)). Этот упрощённый [записанный тест](https://www.youtube.com/watch?v=QsO1HedgKt8&t=212s) показывает различие:

```text
installation console: dotnet  → found
new console:          dotnet  → not found yet
```

[00:04:01](https://www.youtube.com/watch?v=QsO1HedgKt8&t=241s) Добавьте каталог, содержащий `dotnet.exe`, в пользовательский **Path** — список каталогов, в которых Windows ищет команду, введённую без полного пути:

1. Скопируйте каталог установки, содержащий `dotnet.exe`.
2. Откройте редактор переменных окружения Windows и выберите пользовательский **Path**.
3. Нажмите **Edit**, затем **New**, вставьте этот каталог и подтвердите.

Используйте каталог из вашей установки. Этот пример стоит рядом с [записанным изменением PATH](https://www.youtube.com/watch?v=QsO1HedgKt8&t=241s):

```text
User Path:  C:\Users\Student\.dotnet
```

[00:04:55](https://www.youtube.com/watch?v=QsO1HedgKt8&t=295s) Откройте новую консоль и введите `dotnet`. Windows сможет найти и запустить `dotnet.exe`, потому что его каталог теперь в пользовательском `PATH`.

<details>
<summary>Почему первая консоль находила <code>dotnet</code>, а новая — нет?</summary>

Сессия установщика имела доступ к своему пути установки. Новой сессии нужен был каталог с `dotnet.exe` в пользовательском `PATH`.
</details>

## Создание минимального проекта

[00:05:05](https://www.youtube.com/watch?v=QsO1HedgKt8&t=305s) Создайте **папку проекта** там, где хотите хранить программу и настройки её сборки. [00:05:10](https://www.youtube.com/watch?v=QsO1HedgKt8&t=310s) Начните с двух разных файлов:

- **`Program.cs`:** исходный текст на C#, содержащий операторы программы.
- **`<project-name>.csproj`:** настройки проекта, читаемые SDK.

Эти короткие примеры иллюстрируют их роли. Они адаптированы к целевому фреймворку .NET 10 для новой установки; запись не сохранила точную копию своих файлов проекта:

```csharp
// Program.cs — simplified example
Console.WriteLine("Hello, World!");
```

```xml
<!-- Example.csproj — simplified intermediate state for .NET 10 -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
  </PropertyGroup>
</Project>
```

[00:05:50](https://www.youtube.com/watch?v=QsO1HedgKt8&t=350s) Файл `.csproj` — это редактируемый **XML**: `Project` охватывает настройки, `PropertyGroup` группирует их, а `TargetFramework` называет версию .NET, на которую нацелен проект. В примере используется [`net10.0`](https://learn.microsoft.com/en-us/dotnet/standard/frameworks) для текущей рекомендации; это не расшифровка файла с экрана.

[00:06:21](https://www.youtube.com/watch?v=QsO1HedgKt8&t=381s) Консоль тоже может сгенерировать эти файлы. Сначала разберите файлы, собранные вручную; команда генерации появится позже в уроке.

[00:07:03](https://www.youtube.com/watch?v=QsO1HedgKt8&t=423s) Добавьте `OutputType` со значением `Exe` в `.csproj`, чтобы проект собирался как **исполняемый файл** — программа, которую можно запустить, а не как **библиотека**, которая поставляет код для другой программы. Это упрощённое изменение сопровождает [записанное изменение проекта](https://www.youtube.com/watch?v=QsO1HedgKt8&t=423s) и использует цель .NET 10 для нового проекта:

```xml
<PropertyGroup>
  <OutputType>Exe</OutputType>
  <TargetFramework>net10.0</TargetFramework>
</PropertyGroup>
```

Промежуточный проект имел исходник и целевой фреймворк; теперь он дополнительно объявляет запускаемый тип выходных данных. Запись не показывает здесь отдельного успешного запуска собранного вручную проекта.

## Генерация проекта из шаблона

[00:07:39](https://www.youtube.com/watch?v=QsO1HedgKt8&t=459s) В новой пустой папке выполните `dotnet new console`. Шаблон `console` генерирует минимальное консольное приложение. [Записанный вызов](https://www.youtube.com/watch?v=QsO1HedgKt8&t=459s) показывает этот шаг:

```powershell
dotnet new console
```

[00:08:11](https://www.youtube.com/watch?v=QsO1HedgKt8&t=491s) Осмотрите сгенерированные файлы. Шаблон автоматически создаёт `Program.cs` и файл `.csproj`. Это упрощённое дерево подводит итог [записанному сгенерированному состоянию](https://www.youtube.com/watch?v=QsO1HedgKt8&t=491s); это не точный зафиксированный снимок:

```text
new-project/
├── Program.cs
└── new-project.csproj
```

<details>
<summary>Самопроверка: в каком файле операторы C#, а какой файл указывает SDK, как их собирать?</summary>

`Program.cs` содержит операторы C#. XML-файл `.csproj` содержит настройки проекта, включая исполняемый тип выходных данных.
</details>

## Настройка необязательного редактора

[00:08:36](https://www.youtube.com/watch?v=QsO1HedgKt8&t=516s) VS Code необязателен: SDK и консоли уже достаточно для работы с проектом. Видео также рекомендует **Rider** как альтернативную **IDE**, но не учит её настройке. Для оставшейся демонстрации используется VS Code.

1. [00:09:15](https://www.youtube.com/watch?v=QsO1HedgKt8&t=555s) В представлении Extensions в VS Code установите **C# Dev Kit** для поддержки разработки на C#. Это меняет настройку редактора, а не `Program.cs` или файл проекта.
2. [00:09:42](https://www.youtube.com/watch?v=QsO1HedgKt8&t=582s) Различайте две **переменные окружения**: `PATH` позволяет консоли находить `dotnet` по имени, а `DOTNET_ROOT` указывает расширению C# в этом видео на каталог установки. В [руководстве Microsoft по установке на Windows](https://learn.microsoft.com/en-us/dotnet/core/install/windows) описана настройка обеих для пользовательской установки.
3. [00:09:52](https://www.youtube.com/watch?v=QsO1HedgKt8&t=592s) Создайте пользовательскую переменную с именем `DOTNET_ROOT` с тем же каталогом, что добавлен в `PATH`. Используйте папку, содержащую `dotnet.exe`, а не имя файла исполняемого файла. Это иллюстративное значение сопровождает [записанное изменение переменной](https://www.youtube.com/watch?v=QsO1HedgKt8&t=592s):

   ```text
   DOTNET_ROOT = C:\Users\Student\.dotnet
   ```

4. [00:10:14](https://www.youtube.com/watch?v=QsO1HedgKt8&t=614s) Закройте и снова откройте VS Code, чтобы он получил новую переменную. Урок заканчивается этой ожидаемой настройкой редактора; отдельной успешной сборки или запуска в VS Code не показано.

```text
project/
├── Program.cs
└── project.csproj
```
