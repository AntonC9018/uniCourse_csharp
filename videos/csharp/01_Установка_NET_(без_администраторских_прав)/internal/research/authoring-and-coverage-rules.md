# Authoring and coverage rules this folder established

Established while the English note was authored and repaired
(`english_authoring` run 10, session
`01a0e32e-78a0-7a23-bd75-3a67186ca95a`; run 9 was blocked on the same ledger
problems, session `01a0e31f-ca19-79a2-9af4-97ca5d39a0d5`).

- Every ledger entry must be covered at a note heading, and each entry's
  timestamp link `https://www.youtube.com/watch?v=QsO1HedgKt8&t=<floor(startMilliseconds/1000)>s`
  must literally appear in the note. Run 10 verified all 26 anchors,
  intervals, ids, and timestamp links programmatically before completing.
- A note section that contains a fenced code sample must also contain a
  citation link — an uncited sample is a validation fault.
- An immutable code reference (`github.com/<owner>/<repo>/blob/<40-hex>/…`)
  must have a simplified sample beside it in the same section. Run 10's first
  completion failed exactly on this for the pinned lab link; the fix added the
  `project/ ├── Program.cs └── project.csproj` file-pair sample to the
  "Recorded code trail" section. Reason: a pinned link with no visible sample
  gives the reader nothing to compare against the recording.
- Ledger identity rules (the draft failed all of these): top-level keys are
  exactly `schemaVersion` (1), `courseVideoId`, `uploadId`,
  `transcriptSha256`, `teachingPoints`; each point carries
  `startMilliseconds`/`endMilliseconds` (the draft's `videoId`, `startMs`,
  `endMs` were the blockers). `transcriptSha256` is the sha256 of
  `internal/transcript.vtt` — `584fad9d8c8e0faa2d3e64af349bc72dc36ca0b109568a82e44a7b87edfe1cab`,
  the same hash as the canonical VTT blob — which ties the ledger to the exact
  caption revision it was audited against.
- The AI disclaimer line ("This note was generated by AI … Check the video and
  the cited sources when accuracy matters.") is mandatory at the top of every
  note file.
- Coverage strategy for a screen-recording lesson: the transcript preserves no
  exact on-screen commands or project files (Set-ExecutionPolicy switch,
  installer invocation, `PATH`/`DOTNET_ROOT` values, hand-built `.csproj`
  states). Each is therefore given as a simplified illustrative command placed
  beside the recorded video moment and explicitly labeled "not a
  transcription" / "no repository snapshot" — no commit is invented for them,
  and the "Recorded code trail" section lists the recorded moments in order
  with a final-state sample instead.
