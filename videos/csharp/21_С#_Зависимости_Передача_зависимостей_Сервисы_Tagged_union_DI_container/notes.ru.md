# Цель и термины

[00:00:26](https://www.youtube.com/watch?v=z5CUTiubzwU&t=26s) Цель этого урока — сделать **зависимости** программы видимыми: определить, что нужно небольшому преобразованию элементов, решить, как это передать, и изменить структуру, не потеряв проверенный результат. Путь намеренно идёт по шагам: встроенные правила, выделенная функция, набор настроек, сервисы, альтернативные поведения, закрытое объединение и, наконец, автоматическая сборка зависимостей. Это максимально простой пример; более сложная и реалистичная ситуация разбирается в отдельном видео.

Дальше по тексту используются такие термины:

- **Элемент, поле, свойство, инициализатор, required и float:** элемент — это вход с именем и ценой; поле хранит данные; свойство открывает доступ к члену через аксессоры; инициализатор присваивает члены при создании; required требует инициализации члена; float — тип числа одинарной точности, используемый для цен.
- **Параметр, аргумент, сигнатура, прототип и контекст:** параметр объявляет вход, аргумент передаёт его значение, сигнатура описывает форму входа/выхода вызываемой сущности, прототип объявляет эту форму без тела, а контекст — это окружающая информация, необходимая для выполнения операции.
- **Зависимость, прямой вход и конфигурация:** зависимость — то, что нужно операции; прямой вход — значение, обрабатываемое в данном вызове; конфигурация задаёт правила обработки. Урок также различает зависимости-сервисы.
- **Список, словарь, множество и запасное значение:** список хранит упорядоченную коллекцию; словарь сопоставляет ключи значениям; множество поддерживает проверку принадлежности; запасное значение используется, когда по ключу ничего не найдено.
- **Единственная ответственность, абстракция, инкапсуляция и рефакторинг:** единственная ответственность назначает компоненту одну связную задачу; абстракция открывает полезный контракт; инкапсуляция прячет за ним представление или зависимости; рефакторинг меняет структуру, сохраняя задуманное наблюдаемое поведение.
- **Nullable-результат и null:** элемент, допускающий null, может быть элементом или null; null означает, что это преобразование не дало элемента.
- **xUnit, Verify, снимок, регрессия, async и await:** xUnit запускает тесты; Verify сравнивает сериализованный фактический вывод с подтверждённым снимком — сохранённым ожидаемым результатом; регрессия — нежелательное изменение поведения; async допускает асинхронное ожидание, а await ждёт завершения.
- **Сервис, конструктор, private, readonly и static:** сервис связывает операцию с её контекстом на уровне класса; конструктор инициализирует экземпляр; private скрывает член от внешнего доступа; readonly ограничивает переприсваивание поля; static принадлежит типу, а не экземпляру.
- **record struct:** тип значения с генерируемыми компилятором членами, ориентированными на данные; здесь он используется как компактный набор настроек.
- **Делегат, группа методов, лямбда, захват, срез и чистая функция:** делегат — вызываемое значение с объявленной сигнатурой; группа методов — имя совместимого метода; лямбда — анонимная функция; захват даёт ей доступ к окружающим переменным; срез выбирает часть строки или последовательности; чистая функция определяет свой ответ по своим входам без внешних побочных эффектов.
- **Интерфейс, реализация, полиморфизм и Strategy:** интерфейс задаёт операции; реализация даёт им тела; полиморфизм позволяет одному вызову прийти к разным реализациям; Strategy выбирает операцию, предоставляя реализацию.
- **Открытая и закрытая иерархии:** в открытую иерархию потребители могут добавлять реализации; закрытая иерархия перечисляет поддерживаемые альтернативы.
- **Меченое объединение, вариант, диспетчеризация, приведение, шаблон типа и dynamic:** меченое объединение представляет ровно одну выбранную альтернативу; каждая альтернатива — вариант; диспетчеризация выбирает операцию варианта; приведение восстанавливает известный тип; шаблон типа проверяет и называет типизированное значение; dynamic откладывает выбор члена до времени выполнения.
- **Класс, структура, ссылочный тип, тип значения, стек, куча и упаковка:** класс — ссылочный тип; структура — тип значения; ссылки определяют объекты, а значения хранят своё содержимое; стек и куча описывают память; упаковка копирует значение в объектное представление в управляемой куче.
- **Внедрение зависимостей, инверсия управления и инверсия зависимостей:** внедрение подаёт зависимости извне; инверсия управления возлагает ответственность за их выбор и создание на внешний код; инверсия зависимостей выражает зависимость через абстракцию.
- **DI-контейнер, IoC-контейнер, провайдер сервисов и граф зависимостей:** DI- и IoC-контейнер называют механизм сборки зависимостей; провайдер — построенный объект разрешения сервисов; граф описывает, какие объекты требуют каких других.
- **Коллекция сервисов, регистрация, дескриптор, фабрика, метод расширения, аргумент обобщённого типа и билдер:** коллекция хранит изменяемые регистрации; дескриптор определяет, как предоставляется тип сервиса; фабрика создаёт экземпляр; метод расширения добавляет вызываемый синтаксис к существующему типу; аргумент обобщённого типа выбирает тип в угловых скобках; билдер превращает конфигурацию в готовую пригодную модель.
- **Singleton, scope и область видимости scoped:** регистрация singleton переиспользует один экземпляр в пределах провайдера; scope группирует один контекст выполнения; scoped-сервисы переиспользуются внутри этой области.
- **Options, IOptions, IOptionsSnapshot и конвейер:** Options группирует связанные настройки в именованный тип; IOptions — типизированная обёртка для доступа к опциям; IOptionsSnapshot предоставляет опции, кэшированные для области; конвейер — последовательность шагов обработки.

Для практики смежная [лабораторная работа про зависимости](../../../labs/2_design/05_dependenices.md) применяет эти идеи к чтению, преобразованию и записи данных. Это отдельное задание, а не свидетельство шага установки или промежуточного состояния кода в этой записи.

Все примеры ниже — короткие учебные образцы. Неизменяемая ссылка определяет сохранённое состояние, которое было изучено; если живая правка не сохранена точно, ссылка явно помечена как релевантная или финальная. Метки времени в видео указывают на переходное состояние.

```csharp
public class Item
{

}

// Внутри исходной функции обработки списка:
var answer = new List<Item>();
```

[Сохранённая версия на параметрах](https://github.com/AntonC9018/uniCourse_csharp/blob/2e88085eed097ef2a1e1345951fa37665caf0756/examples/dependencies_simplified/code/Code.cs) имеет такую упрощённую форму:

```csharp
static List<Item> ProcessItems(
    List<Item> items, float minPriceCutoff, float maxPriceCutoff,
    Dictionary<string, string> nameRemap)
{
    var answer = new List<Item>();
    foreach (var item in items)
    {
        if (item.Price <= minPriceCutoff) continue;
        if (item.Price >= maxPriceCutoff) continue;
        var name = nameRemap.GetValueOrDefault(item.Name, item.Name);
        answer.Add(new Item { Name = name.ToUpper(), Price = item.Price });
    }
    return answer;
}
```

**Конфигурация** — это настройки, управляющие обработкой. Здесь она включает пороги и сопоставление. **float** — числовой тип порогов. GetValueOrDefault использует второй аргумент, когда ключа нет; это не отменяет перевод в верхний регистр. В сохранённом Item есть обязательные поля Name и Price: **required** требует их инициализации.

```csharp
var result = Helper.ProcessItems(
    items, minPriceCutoff: 5.0f, maxPriceCutoff: 50.0f,
    nameRemap: new Dictionary<string, string> { ["Anton"] = "Mark" });
await Verify(result);
// Ожидаемые имена: MARK, FORK, LOWER-CASE
// Ожидаемые цены: 40.0, 26.0, 40.0
```

**Регрессия** — нежелательное изменение установившегося поведения. «Без изменений» здесь означает «не пересопоставлено»: Fork всё равно превращается в FORK, потому что перевод в верхний регистр выполняется безусловно после поиска. В сохранённом тесте **async** допускает асинхронное ожидание, а **await** ждёт завершения Verify. Именованные аргументы явно указывают свои параметры; суффикс f делает числовой литерал float.

Файл received, полученный при первом запуске, не доказывает, что его содержимое корректно: изучите его, прежде чем делать подтверждённым базовым уровнем. Последовательность успех/провал/подтверждение выше описывает запись; эти заметки не утверждают, что был выполнен новый локальный прогон тестов.

## Выделяем преобразование одного элемента

```csharp
public readonly struct RemapNameService_TaggedUnion
{
    private readonly object _impl;
    public RemapNameService_TaggedUnion(RemapNameService mapper)
        => _impl = mapper;
    public RemapNameService_TaggedUnion(RemapNameService_RemovePrefix prefix)
        => _impl = prefix;

    public string RemapName(string name)
    {
        if (_impl is RemapNameService a) return a.RemapName(name);
        if (_impl is RemapNameService_RemovePrefix b) return b.RemapName(name);
        throw new InvalidOperationException("Invalid union state");
    }
}

// Transient alternative from the recording, not the saved implementation:
// return ((dynamic)_impl).RemapName(name);
```

**Шаблон типа**, например is RemapNameService a, проверяет тип и вводит переменную этого типа. Здесь меткой служит тип времени выполнения; явной целочисленной метки нет. В примере запасная ветвь бросает исключение; в сохранённом коде вызывается Debug.Fail и возвращается null. Ни одна из запасных ветвей не создаёт нового допустимого варианта.

Аргумент о невозможном состоянии верен только при корректном построении с данными. Нулевые аргументы и, раз это структура, её значение по умолчанию могут оставить без пригодного варианта. Урок не добавляет полной проверки этих случаев.

```csharp
// Separate optional arguments: the order also defines priority if both exist.
static string Remap(string name, Dictionary<string, string>? map, string? prefix)
{
    if (map != null) return map.GetValueOrDefault(name, name);
    if (prefix != null && name.StartsWith(prefix)) return name[prefix.Length..];
    return name;
}

// Schematic stored-dependency dispatch:
if (storedDependency is string)
{
    var prefix = (string)storedDependency;
    return name.StartsWith(prefix) ? name[prefix.Length..] : name;
}
if (storedDependency is Dictionary<string, string>)
{
    var map = (Dictionary<string, string>)storedDependency;
    return map.GetValueOrDefault(name, name);
}
```

Это альтернативные фрагменты, а не одна объединённая функция. При отдельных необязательных аргументах случаям «оба присутствуют» и «оба отсутствуют» нужна определённая семантика. Объединение выражает именно выбор одного из вариантов, а не эти дополнительные комбинации. Приведение сырой зависимости также заставляет потребителя снова знать о её представлении.

```csharp
using var serviceProvider = services.BuildServiceProvider();
```

Оставшаяся коллекция — это данные о принадлежности игнорируемым именам, HashSet<string>, как определил сохранённый конструктор. Переключение между пересопоставлением по словарю и удалением префикса — отдельный выбор поведения, способный изменить ожидаемые имена.

Тот же [финальный конструктор потребителя](https://github.com/AntonC9018/uniCourse_csharp/blob/d80428c0f252c626af6927783c16b777dc7f1425/examples/dependencies_simplified/code/Code.cs) поддерживает такую упрощённую альтернативу на [00:50:56](https://www.youtube.com/watch?v=z5CUTiubzwU&t=3056s):

```csharp
// Before building the provider:
services.AddSingleton(new HashSet<string> { "ignored" });

// After building, with every constructor dependency registered:
var processor =
    ActivatorUtilities.CreateInstance<ProcessItemService>(serviceProvider);
```

Это альтернативная настройка, а не указание дописывать регистрацию в уже построенный провайдер. Сначала регистрируйте, потом стройте, потом разрешайте или конструируйте.

<details>
<summary>Почему CreateInstance может конструировать цель, для которой GetRequiredService не работает?</summary>

GetRequiredService ищет зарегистрированный ключ сервиса. CreateInstance конструирует запрошенную конкретную цель, используя разрешённые провайдером зависимости плюс явные оставшиеся аргументы. Цель может быть незарегистрированной; зависимости всё равно должны быть доступны.

</details>

## Пусть контейнер собирает граф

[00:51:18](https://www.youtube.com/watch?v=z5CUTiubzwU&t=3078s) Более сложная схема — A нуждается в B и C, причём B тоже нуждается в C. Порядок создания и разделение становятся менее очевидными. [00:51:29](https://www.youtube.com/watch?v=z5CUTiubzwU&t=3089s) Контейнер выполняет сборку без явных вложенных вызовов конструктора по всем зависимым объектам.

[00:51:49](https://www.youtube.com/watch?v=z5CUTiubzwU&t=3109s) Зарегистрируйте потребителя через AddSingleton и получите его из провайдера. [Финальный сохранённый тест](https://github.com/AntonC9018/uniCourse_csharp/blob/d80428c0f252c626af6927783c16b777dc7f1425/examples/dependencies_simplified/tests/Tests.cs) использует такую упрощённую форму:

```csharp
services.AddSingleton<ProcessItemService>(sp =>
    ActivatorUtilities.CreateInstance<ProcessItemService>(
        sp, new HashSet<string> { "ignored" }));

using var serviceProvider = services.BuildServiceProvider();
var processor = serviceProvider.GetRequiredService<ProcessItemService>();
```

Разрешаемая провайдером цель теперь зарегистрирована, в отличие от более ранней демонстрации только с CreateInstance. Централизованная сборка убирает повторяющуюся обвязку, а потребитель по-прежнему объявляет, что ему действительно нужно.

[Сохранённый сервис цены в стиле Options](https://github.com/AntonC9018/uniCourse_csharp/blob/d80428c0f252c626af6927783c16b777dc7f1425/examples/dependencies_simplified/code/Code.cs) и [его регистрации](https://github.com/AntonC9018/uniCourse_csharp/blob/d80428c0f252c626af6927783c16b777dc7f1425/examples/dependencies_simplified/tests/Tests.cs) дают такую упрощённую версию:

```csharp
public class PriceCutoffConfig
{
    public required float MinPrice { get; set; }
    public required float MaxPrice { get; set; }
}

public class PriceCutoffService
{
    private readonly PriceCutoffConfig _config;
    public PriceCutoffService(PriceCutoffConfig config) => _config = config;
    public bool AllowsPrice(float price)
        => price > _config.MinPrice && price < _config.MaxPrice;
}

var config = new PriceCutoffConfig { MinPrice = 5, MaxPrice = 50 };
services.AddSingleton(config);
services.AddSingleton<PriceCutoffService>();
```

**Свойство** открывает доступ через get и set; это аксессоры в классе конфигурации. Его обязательные свойства должны быть инициализированы при создании. **Инициализатор** задаёт значения в фигурных скобках. Приватное поле readonly хранит ту же ссылку на конфигурацию, но записываемые свойства конфигурации всё ещё можно менять.

**IOptions<T>** — типизированная обёртка, через которую потребитель обращается к опциям. Объект конфигурации сам по себе не является такой обёрткой. Этот шаг показывает, что конфигурация может участвовать во внедрении через конструктор как обычная типизированная зависимость.

[00:53:43](https://www.youtube.com/watch?v=z5CUTiubzwU&t=3223s) Посмотрите на сопутствующий пример приложения. Сохранённое приложение находится в папке примера lab5. **Конвейер** — последовательность шагов обработки; здесь он читает элементы, преобразует их и пишет результат.

1. [00:53:51](https://www.youtube.com/watch?v=z5CUTiubzwU&t=3231s) Создайте конвейер и выберите конфигурацию для каждого контекста.

4. [00:54:27](https://www.youtube.com/watch?v=z5CUTiubzwU&t=3267s) Заново задайте конфигурацию для нового контекста вызова.

[Сохранённое приложение-конвейер](https://github.com/AntonC9018/uniCourse_csharp/blob/d80428c0f252c626af6927783c16b777dc7f1425/examples/lab5_example/Program.cs) создаёт новую асинхронную область для каждого Run. [Сохранённый билдер](https://github.com/AntonC9018/uniCourse_csharp/blob/7f31c6acd0e759a957c51c40ddb9031b1399d17d/examples/lab5_example/Orchestration/OrchestrationBuilder.cs) разрешает снимок опций, вызывает на его значении обратный вызов конфигурации и затем создаёт ридер через его фабрику. Упрощённая версия этого общего контекста:

```csharp
services.AddOptions<RandomReaderFactoryOptions>()
    .Configure(options => options.GeneratedCount = 3);

await using var serviceProvider = services.BuildServiceProvider();
await using var scope = serviceProvider.CreateAsyncScope();

var snapshot = scope.ServiceProvider
    .GetRequiredService<IOptionsSnapshot<RandomReaderFactoryOptions>>();
snapshot.Value.GeneratedCount = 10;

// Фабрика читателя, использующая опции этой области, видит обновлённое значение.
```

**async** и **await** поддерживают асинхронное завершение; await using освобождает провайдер и область через их поддержку асинхронного освобождения. **Scope** — один контекст выполнения, а **временная жизнь scoped** означает переиспользование внутри него. Вызывающий билдера выбирает опции до создания ридера, а потребитель получает опции через контейнер.

Только временная жизнь scoped не перезагружает и не меняет конфигурацию. IOptionsSnapshot кэширует значение опций внутри области; он не пересчитывает новый объект при каждом чтении в той же области. Демонстрация выбирает новое значение для контекста, а не реализует инфраструктуру перезагрузки файлов конфигурации. [Релевантные сохранённые фабрики ридера/писателя](https://github.com/AntonC9018/uniCourse_csharp/blob/306f4dda13a4582f96ba2d76c3c130728a064df4/examples/lab5_example/ReaderWriter/Factories.cs) разделяют настройки для разных операций. Фабрика случайного ридера читает опции своей области при создании ридера; упрощённый фрагмент:

```csharp
var count = _count.Value.GeneratedCount;
return new RandomReader(count, _generators);
```

Поэтому независимые выполнения конвейера не обязаны делить один изменяемый глобальный выбор.

<details>
<summary>Означает ли снимок Verify то же самое, что IOptionsSnapshot?</summary>

Нет. Verify сравнивает фактический вывод с подтверждённым тестовым базовым уровнем. IOptionsSnapshot предоставляет настройки приложения, связанные с областью. Одно проверяет поведение; другое поставляет конфигурацию для выполнения.

</details>
