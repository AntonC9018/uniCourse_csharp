The vocabulary used along the way is:

- **Function or method**: a named piece of executable code. A **parameter** supplies input to it; a **return value** supplies its result. **Static** methods do not require an instance of their containing class; **void** means no return value.
- **Enum**: a type with named constants representing choices. An **enum member** names one choice; a **cast** explicitly converts a value to another type.
- **Dispatch**: choose and call an implementation from an action value. A **switch** chooses a branch by that value; **Debug.Fail** reports an unexpected condition to debugging infrastructure.
- **Parsing**: interpret text as a value, such as an integer. **TryParse** reports success or failure; an **out parameter** receives a result. **Validation** checks whether a successfully parsed value is permitted.
- **Input loop**: repeat a request until acceptable input arrives. **continue** starts its next iteration; **break** exits it. A **helper** extracts a repeated task into a reusable function.
- **List or array**, collectively a **collection**: an ordered group of entries. An **index** is a zero-based position. A list's **Count**, or an array's **Length**, gives its number of entries.
- **Class, object, field, and property**: a class defines a kind of object, an object is one instance, a field stores part of its data, and a property exposes a value through a member. Here an **Option** object groups a label, description, and action.
- **Namespace and using directive**: a namespace groups type names; a using directive lets code refer to those types without repeating the namespace prefix.
- **Nullable annotations and references**: null means an absent reference. A question mark in string? allows an absent string value. The null-forgiving operator ! suppresses a nullable warning without changing the value. A ref parameter gives a function access to passed state by reference.
- **nameof**: a compile-time operator producing a symbol's name as text. **==** compares strings by their contents. **Reflection** inspects program metadata at run time; it is mentioned but not implemented.
- **Refactoring**: change code organization while retaining its intended behavior. **Registration** fills the menu collection. **Configuration** decides which entries exist. Passing this configuration into the menu separates content from control flow and reduces **coupling**, the dependencies between parts.
- **Public and private**: access modifiers controlling where a member can be named. **Encapsulation** keeps implementation details behind a small public interface.
- **Compiler**, **IL**, **bytecode**, and **DLL**: the compiler translates source into Intermediate Language, a lower-level instruction representation; bytecode encodes such instructions numerically. The compiled .NET DLL (Dynamic Link Library) holds IL and metadata. **dotnet build** builds the project; **dotnet run** builds as needed and launches it.
- **Runtime**, **JIT**, **machine code**, **CPU architecture**, and **address**: the runtime executes .NET programs; its just-in-time compiler translates IL into instructions for the actual processor. A CPU architecture defines its instruction set and encodings. An address identifies a location in process memory. **SharpLab** displays compiler output, including IL and readable assembly listings.
- **Local function**, **capture**, **lowering**, and **name mangling**: a local function is declared inside another function; capture gives it access to surrounding variables. Lowering rewrites source constructs into generated methods and state. Name mangling gives generated members distinct internal names.
- **Delegate** and **Action**: a delegate is a typed callable object referring to a method and, when needed, target state. The built-in Action type takes no arguments and returns nothing. A **method group conversion** turns a method name used as a value into a compatible delegate. **Shadowing** makes a nearer declaration take precedence over another name. **Caching** reuses a previously created object.

## Select from the options collection

[00:14:28](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=868s) Replace the handwritten name comparisons with a loop over entries. A matching name returns that entry's action immediately. Use this procedure for each attempted choice:

1. Print the available options and read the raw input.
2. Look for a name match; return its stored action if found.
3. Otherwise try parsing the input as an integer; retry if parsing fails.
4. Validate that integer as a collection index; retry if it is outside the bounds.
5. Return the action stored in the entry at that index.

```csharp
static Action ReadAction(List<Option> options)
{
    while (true)
    {
        for (int i = 0; i < options.Count; i++)
            Console.WriteLine(i + " or " + options[i].Name
                              + ": " + options[i].Description + ".");

        string? input = Console.ReadLine();
        foreach (Option option in options)
            if (option.Name == input)
                return option.Action;

        if (!int.TryParse(input, out int index))
        {
            Console.WriteLine("Invalid option");
            continue;
        }
        if (index < 0 || index >= options.Count)
        {
            Console.WriteLine("Invalid option");
            continue;
        }
        return options[index].Action;
    }
}
```

foreach visits each object in the collection. return ends the reader immediately; it does not execute the action itself.

## Understand function addresses

[00:25:00](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1500s) In a running **process**, an instance of the executing program, compiled functions have executable instructions in memory. An **address** identifies a location there. [00:25:17](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1517s) Different functions have their own code locations.

[00:25:34](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1534s) A source-level function name lets the compiler resolve a call. At the machine level the call transfers control to code; it does not search the user's input for that source name. ## Separate local function code from captured state

[00:26:48](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1608s) A **local function** is declared inside another function. It can **capture** surrounding variables, meaning it uses those variables through compiler-generated access to their state. The important distinction is between its executable code and the state belonging to a particular invocation of the surrounding function.

[00:26:56](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1616s) **Lowering** rewrites source constructs into generated methods and state. In the illustrated direct-call case, the compiler can pass captured locals through a generated structure by reference. A schematic reconstruction, not exact compiler output, is:

```csharp
struct CapturedValues
{
    public int a;
    public int b;
}

static void GeneratedSamOperations(ref CapturedValues values)
{
    Console.WriteLine(values.a + values.b);
}
```

ref here means the generated method accesses the passed state by reference, allowing it to refer to the same captured variables rather than independent copies.

[00:27:11](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1631s) The generated implementation is hidden from ordinary outside source code. [00:27:21](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1641s) **Name mangling** supplies a generated internal name so two local functions with the same source name in different enclosing methods do not collide.

[00:27:37](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1657s) Calling the enclosing function again does not require a newly authored copy of the local function's executable code. [00:27:49](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1669s) Its invocation instead receives or accesses the appropriate captured state. [00:28:00](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1680s) Generated calls ultimately reach executable code; [00:28:09](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1689s) code locations let functions be referred to indirectly.

The video's “becomes static” description fits its illustrated transformation, not every local function. Depending on captures and delegate conversion, lowering can use other generated state and instance methods. Per-call state can differ even when the method implementation is reused. The lesson does not require learning every lowering strategy.

## Use the built in Action delegate

[00:28:39](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1719s) Delete the locally declared Action enum. [00:28:44](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1724s) That declaration had **shadowed** the standard-library Action name: it took precedence in the code's name lookup. [00:29:03](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1743s) After removal, Action resolves to the built-in delegate type.

[00:29:09](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1749s) A **delegate** is a typed callable object. The declaration of the built-in Action is conceptually:

```csharp
// Standard-library type, shown for explanation; do not redeclare it.
public delegate void Action();
```

[00:29:10](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1750s) **void** means the referenced function returns nothing. The empty parameter list () means it accepts no arguments. These are separate properties; void does not mean “no parameters.”

The field's type now refers to a function value rather than an enum identifier. The reconstructed change is:

```csharp
class Option
{
    public string Name = "";
    public string Description = "";
    public Action Action = null!;
}
```

The null! placeholder uses the **null-forgiving operator** ! to suppress a nullable warning for this shortened field-based sample; the value is still null. Each registered entry must assign a real delegate before it can be selected and invoked.

[00:29:28](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1768s) Invoking an Action transfers execution to its referenced method and returns to the caller when that method completes. The address model explains the transfer, while C# handles the managed callable object:

```csharp
static void ExecuteAction(Action action)
{
    action();
}
```

The parameter type establishes which function signature is allowed. There is no switch left to translate an enum value into a function.

## Register private methods as delegates

[00:29:43](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1783s) Extract the action implementations into MenuOptions. [00:29:57](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1797s) Make them **private**, visible by name only from their own class, because outside menu code now invokes a stored delegate.

[00:30:05](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1805s) Replace each enum-valued assignment with the method itself. This is a **method group conversion**: a method name used as a value is converted into a delegate with a compatible signature. A shortened resulting video state is:

```csharp
static class MenuOptions
{
    public static void AddOptions(List<Option> options)
    {
        options.Add(new Option {
            Name = nameof(Addition),
            Description = "Add two integers",
            Action = Addition
        });
        // Greeting and RandomNumber are registered in the same way.
    }

    private static void Addition()
    {
        int a = ReadIntIn("A");
        int b = ReadIntIn("B");
        Console.WriteLine(a + b);
    }

    // ReadIntIn and the other private operations live here too.
}
```

Notice Action = Addition has no parentheses. It stores a callable reference. Addition() would execute the method immediately, and its void result could not be assigned to the field.

[00:30:11](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1811s) The delegate object refers to the target method and, where applicable, a target object. [00:30:20](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1820s) Here the targets are static methods, so no instance of MenuOptions is needed. The field stores a reference to a delegate object, not an enum number or an exposed raw address.

[00:30:26](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1826s) The recording discusses reusing delegate objects for static methods. [00:30:50](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1850s) **Caching** means retaining and reusing an already-created object. Modern C# compilers can cache static method-group conversions, avoiding repeated allocation at a conversion site. This is an optimization, not a language-wide guarantee of exactly one delegate object per method for the whole program. Different conversion sites and other construction forms can produce distinct objects.

[00:31:16](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1876s) nameof is not a run-time function that receives a delegate. Its macro-like role in this explanation is substitution during compilation: the label becomes "Greeting", while the action field receives the callable reference.

[00:31:29](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1889s) Even a static method that does nothing can be registered if its signature matches Action. ## Invoke the selected action through polymorphism

[00:31:42](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1902s) The reader still searches names and validates indexes exactly as before. It returns the entry's action field; only that field's representation and the invocation step have changed.

[00:31:49](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1909s) Run the delegate version. The same menu entries appear, and selecting the first reaches its referenced operation. Action itself receives no arguments; an operation such as Addition can still ask for input and call its own helpers with arguments.

[00:31:55](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1915s) Main retains the same sequence. [00:32:02](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1922s) The selected value now holds a callable reference rather than a number awaiting translation. The final flow reconstructed from the video is:

```csharp
List<Option> options = new();
MenuOptions.AddOptions(options);
Action selected = ReadAction(options);
ExecuteAction(selected);

static void ExecuteAction(Action action)
{
    action();
}
```

[00:32:11](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1931s) This representation gives flexibility: actions can be defined elsewhere and registered without adding dispatcher branches. [00:32:22](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1942s) The configuration class exposes only AddOptions to its caller. [00:32:39](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1959s) It could be moved to a separate file while its implementations remain private.

[00:32:44](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1964s) The contents of the selected variable determine what runs. [00:32:53](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1973s) The invocation site does not know which concrete function was registered and then chosen by the user.

[00:33:01](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1981s) This is **polymorphism**: one call site can run different implementations selected at run time. [00:33:05](https://www.youtube.com/watch?v=nKGsQISMrbQ&t=1985s) Here action() invokes the callable object stored in its parameter. It can reach Addition, Greeting, RandomNumber, or a newly registered compatible method. This is the lesson's delegate-based example of the broader idea.
